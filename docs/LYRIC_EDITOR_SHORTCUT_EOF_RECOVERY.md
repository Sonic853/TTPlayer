# 歌词编辑快捷键与播放结束行为修复

日期：2026-09-29。依据 `../reverse/decompiled/TTPlayer.exe.pseudo.c` 中原版 5.7.9 的分支、命令表以及重建版实际窗口回归。

## 1. 快捷键为什么失效

原版存在编辑器局部快捷键和应用程序可配置快捷键两个层次。

| 原版位置 | 证据及作用 |
| --- | --- |
| `0044CB58` | 创建五项加速键：Ctrl+X/C/V/Z/Y，分别发送剪切、复制、粘贴、撤销、重做命令 |
| `00449DA8` | 查找／替换窗口激活时先交给 `IsDialogMessageW`；编辑框获得焦点时调用局部 `TranslateAcceleratorW`，返回是否已处理 |
| `0046228D` | 根据配置生成另一份应用程序加速键表，保存在主窗口 `+0x4358` |
| `DAT_0053ABF8` | 54 项默认绑定中，F9 → `0x8048` 插入标签，F10 → `0x8049` 替换标签，Ctrl+Delete → `0x804A` 删除标签 |
| `00446ED7` | 将这些命令分派到歌词编辑的对应处理函数 |

重建版把分发合并到 `PlayerWindow::PreTranslateMessage`，却照搬了局部函数的直接返回：编辑框聚焦时，即使局部加速键表没有匹配，也直接返回 `false`。应用程序表位于同一函数的后面，因而永远收不到 F9、F10、Ctrl+Delete 及用户自定义按键。

修复为：局部表确实处理时才返回，否则继续查找设置中的应用程序绑定。没有匹配的字符和方向键仍交给 RichEdit。查找／替换窗口的优先处理和隔离保留；Ctrl+F8/F9/F10 逐字编辑扩展仍使用局部表。没有硬编码第二套 F9/F10 默认绑定，因此重新分配或取消快捷键继续有效。

注意：原版默认 Ctrl+S 是停止播放。此次没有把它改成保存；测试中的保存命令使用单独配置的 Ctrl+Shift+S，验证自定义绑定路由。

## 2. 编辑歌词时，歌曲结束应当怎样处理

关键不在普通的下一首选择函数，而在其之前的播放结束通知。

`00461F87` 收到当前声音对象的结束通知后，先执行 `0045C0C6` 的停止状态处理。只有下列条件全部满足，才发送 `0x7EC` 或建立曲间等待定时器 `0xB`：

1. 主窗口 `+0x1F58` 的另一阻止切换状态为零；该字段不应误认成 RichEdit 或查找窗口句柄；
2. `+0x1FE8` 为零，即歌词 RichEdit 不存在。歌词窗对象基址为主窗口 `+0x1C24`，RichEdit 字段位于歌词窗 `+0x3C4`；
3. `+0x4368` 允许继续播放。

后续 `00461F24 → 0045BD69` 才根据播放模式选择下一项。因此编辑期间自然结束时，应保留当前歌曲及编辑状态，所有播放模式都不自动切歌或重播，也不因结束事件触发歌词保存策略。

重建版 UI 定时器发现音频由活动变为 stopped 后，无条件调用 `AdvanceAfterNaturalEnd`。该函数又可能进入 `PlayCurrent`、`Stop` 和 `FinishLyricDocument`，引起编辑器退出、保存提示或未保存标记被清除。

### 修复

- 在自动结束分支进入模式选择前检查歌词编辑器／查找窗口，保留编辑内容、选择位置、撤销记录与修改标志，只刷新停止状态。
- 补充等待边界保护：曲间等待已开始、随后打开编辑器时，等待到期不再播放，避免自动切歌销毁刚进入的编辑文档。这是重建版对延迟队列的保护，不把原版 `00461E35` 对 `+0x1F58` 的判断误解为编辑器句柄检查。
- 同一首歌显式重新播放时，重建版虽需重开已结束的解码器，但不结束当前歌词文档。对应原版 `0045BF4B` 对保留声音对象的重播路径。
- 退出编辑后不会补发先前被取消的自动切歌；正常非编辑播放模式不变。

## 3. 测试发现的 RichEdit 生命周期问题

加入真实 Ctrl+X/Ctrl+Z 编辑回归后，发现部分系统在退出进程时触发 OLE 访问异常。`DestroyLyricEditor` 卸载 `Riched20.dll` 时，RichEdit 创建的 OLE 剪贴板对象／回调可能仍然存在。

现在按进程保留一份模块引用，窗口仅借用该句柄，销毁编辑器不卸载模块。引用数量不会随反复打开编辑器增长；进程退出时由系统回收。修复前主机回归退出码为 `0xC000041D`，修复后主机、XP 和 Win7 的完整编辑回归均正常退出。

## 4. 验证和范围

本地 `tests/ui/lyric_main_menu_tests.cpp` 使用隔离目录、原版资源和实际 RichEdit／查找窗口，验证：

- F9 插入一次、F10 替换、Ctrl+Delete 删除整标签；
- 自定义快捷键与解除原绑定、普通输入和方向键透传；
- Ctrl+X/Z 和逐字快捷键；自定义保存命令实际写盘；查找窗口不误触发歌词编辑；
- 五种播放模式 × 三种歌词保存策略：通过真实 UI 定时器分支注入解码结束状态，确认不切歌、不重播、不保存，编辑器及内容、光标、撤销、修改标志保留；
- 编辑期间到期的曲间等待被取消，同曲重新打开经过文档保留分支；
- 剪切后关闭编辑器、重新打开、退出程序正常。

以上在主机、XP SP3、Win7 SP1 均通过。自然结束回归注入音频状态以覆盖 UI 策略，不是每个音频输出后端的完整播放时长测试。普通模式另以 `playback_navigation_tests` 覆盖列表、媒体库、随机历史、跨列表及空列表行为。

测试仅保存在本地 `rebuild/tests`，不上传、不加入 Actions。Release 继续使用现有统一兼容构建，API 导入检查覆盖 XP／Win7。
