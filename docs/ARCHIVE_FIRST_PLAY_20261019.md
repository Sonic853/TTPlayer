# 大压缩包首播与延后信息修复（2026-10-19）

## 1. 修复范围

反馈截图是 RAR 4.x 整轨专辑包，包含约 514.9 MB 的 WAV、CUE 和 cover.jpg。本次依据 5.7.9 的实际机器码与原版伪代码，修复重建版调用层强制等待完整成员的问题。压缩包保持只读。

原版证据与完整四类问题分析见 [原版反馈分析](ORIGINAL_FEEDBACK_REVIEW_20261019.md) 第 2–4 节。特别是 WAV 函数 004E82CA 的伪代码遗漏了 data 成功分支；实际 004E8395–004E83AD 比较并接受 data，然后计算时长，没有以尾部 LIST 标签作为首播前提。本次没有照抄失真的反编译分支。

## 2. 实现

### 2.1 首段音频与后补内容分开

- PcmFileSource::OpenWave 在 fmt 和首个有效 data 都已获得后完成打开，保留 RIFF 长度、格式、块对齐和数据边界验证。
- RecoveredFileSource 对归档 WAV 延后完整标签读取；所有归档的外置封面查找均不再阻塞打开。
- 每个解码源拥有自己的可取消信息线程。先等音频成员后台解压和 CRC 完成，再读取尾部标签、枚举封面；不会提前抢占 RAR 的全局引擎锁。
- 解码源关闭时停止并回收该线程。结果只写入所属解码源，通过版本号传递到引擎和界面，避免换歌后旧结果覆盖新歌。
- 暂停时仍能发布已完成的信息。CUE 继续拥有每首的标题、艺术家与增益，只继承底层音频的封面。
- 插件已提供的内嵌封面优先。现有 MP3 标签／ReplayGain 的播放前处理不受影响；本次没有将所有格式强行变成头信息读取。
- 最终 CRC 错误、加密验证及取消机制保留，未移除 ttpcomm 内保护 UnRAR 全局状态的互斥锁。

相关实现：[audio_engine.cpp](../src/audio/audio_engine.cpp)、[audio_engine.h](../include/ttplayer/audio/audio_engine.h)。

### 2.2 播放列表的初步信息与最终校验

- 新增仅取 WAVE fmt/data 描述的读取模式，完整文件属性仍使用原有完整读取路径。
- 归档尚未完成时，独立信息进程返回 S_FALSE，表示初步结果；最终 CRC 成功才返回 S_OK。
- 列表可先更新已知标签和格式，继续保留 duration_ms=-2 的待验证标记。保持同一任务，间隔 250 ms 重试；最终成功或失败后再推进下一项。
- 初步结果不会进入最终元数据缓存。归档／CUE 原有的整项元数据缓存限制仍保留，成员流缓存负责复用解压数据。
- 同一 CUE 的重试复用解析快照，避免每次重读几百字节的 CUE 又被 RAR 音频解压锁阻塞。快照检查实际各卷的路径、文件身份、大小和时间；不只检查第一卷。
- 前台归档正在打开或解压时，暂退独立信息会话并保留待办任务，让播放优先。保留插件隔离，不在 UI 线程等待第三方解码器结束。

相关实现：[builtin_file_info.cpp](../src/audio/builtin_file_info.cpp)、[file_info_worker.cpp](../src/app/file_info_worker.cpp)、[player_window_playlist_info.cpp](../src/ui/player_window_playlist_info.cpp)。

### 2.3 异步打开完成与界面更新

原先 AudioEngine::Play 已对归档返回异步打开，但界面的 PollNetworkPlayback 只接受网络地址。现在也处理归档逻辑路径，正常完成时长、标签和打开状态更新；仅封面变化、标题为空的后补结果也能更新窗口预览与 SMTC。

真实窗口回归还覆盖暂停更新、重复轮询、封面单独完成与切换到本地曲目后的隔离。

## 3. 测试

测试代码、项目、生成样本与日志仅在 rebuild/tests/original_feedback_20261019。不提交测试子模块、测试源码、测试产物，不加入 Action。

### 3.1 受控样本

每个正常样本含 128 MiB PCM WAV，音频数据后有 LIST/INFO 标题，另含两首 CUE 和 cover.png：

- RAR4 stored：验证旧格式路径；不是反馈原包的压缩方法复现。
- RAR5 压缩：验证解压生产者与异步封面互斥。
- deflate ZIP：验证另一引擎路径。
- CRC 错误 ZIP：头可读，但最终必须失败。

未收到反馈中的实际 RAR 文件，因此没有对该约 500 MB 专辑原包测量，也不把生成样本的速度视为用户机器的承诺。

计时使用 GetTickCount64，0 ms 只表示不足计时刻度，不代表没有耗时。核心断言是首段读取时解压尚未完成，而不是对特定机器设定绝对速度门槛。

XP 少一项 DWM 封面位图断言，因为没有该功能；解码源的封面字节断言在三个系统均执行。全部通过：

- 首段 PCM、块对齐、WAV 时长；
- 后补尾部标题和封面；
- CUE 子曲目复用同一任务 ID，CUE 标题不被 WAV 标题覆盖；
- 解压尾部 CRC 错误传播；
- 取消及信息线程回收，本机不足计时刻度，两个虚拟机各 16 ms；
- WAV 与 CUE 均先返回 S_FALSE、之后返回 S_OK；
- 只读能力、同一会话连续重试与正确最终标签。

虚拟机目录为 C:\TTPlayerArchive20261019。日志为 host.log、XP-result.log、Win7-result.log、ui-host.log、XP-ui-result.log、Win7-ui-result.log。

## 4. 保留边界

- 本次不修改 ttpcomm.dll ABI、压缩算法或缓存预算。
- 前台与独立信息进程尚未共享跨进程缓存；当前通过优先调度避免首播期间同时解压。播放结束后的独立查询仍可能重新解压一次。
- 尚未实现共享固实字典和下一曲预取；首次访问后部固实成员或首次定位至尚未产生的数据，仍须解压前缀。
- 加密成员继续在密码及完整性验证完成后提供内容。
- WAV 以外的插件元数据读取若必须访问尾部，仍可能等待；不能把 WAV 快速路径的结论扩大到所有格式。
- 保留完整属性检查和最终错误处理；没有增加压缩包写回。
