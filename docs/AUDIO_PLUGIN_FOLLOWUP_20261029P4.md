# 音频插件剩余兼容修复：2026.10.29p4

本轮更新 `ttp_aac.dll`，继续使用同一份 x86/SSE2、VC-LTL／YY-Thunks 构建供原版 5.7.9 和重建版使用。Windows 11、XP SP3、Win7 SP1 均完成回归与真实宿主播放；Windows 11 按用户要求承担现代系统验证，没有独立 Windows 10 实机结果。

## 已修复

### 1. 原始 AAC 定位后的音频偏移

旧实现仅部分重置 FAAD 并预热一个压缩帧。真实 48 kHz 双声道 LC 连续播放输出 770,048 字节，定位到开头后却输出 778,240 字节，多出 1,024 个双声道采样帧。非零位置也不能恢复与连续播放一致的 PCM，Main／LTP／SBR 的历史状态同样受到影响。

现在记录实际 PCM 坐标：前向定位继续当前解码状态，后向定位新建解码器并恢复完整历史；ADTS 保留压缩帧粒度，ADIF 保留采样点定位。定位取消后保存目标，允许恢复读取或用新位置替换；部分数据已被读取、一连两次取消、Stop／Start、无效缓冲容量均有回归覆盖。

八类真实 LC／HE／HEv2／Main／LTP ADTS 样本，每类 25 组，共 200 组。定位后的完整尾部与连续播放对应范围逐字节相同。详见 [定位与 PCE 修复](../../ttp_aac/docs/RAW_SEEK_PCE_20261029P4.md)。

向后定位的耗时随目标位置增加，内存不缓存整首 PCM；后续若要减少长文件定位耗时，需要验证完整解码状态快照，不能重新退回一帧预热。

### 2. ADTS 帧内 PCE 声道配置

合法 ADTS 可把 `channel_configuration` 设为零，将声道配置放在帧内 PCE。旧适配层在初始化尚未解码 PCE 时就拒绝零声道，导致真实 Main／LTP 文件的 ADTS 重封装无法打开。

现在仅允许这一合法配置延迟发现声道，在首个有效 PCM 帧解码后再发布格式；最终格式的非零声道和有效采样率检查继续保留。本地及未知长度流均通过。Main 完整 5,780,480 帧、LTP 完整 911,360 帧，与原 MP4 和先前验证的参考 PCM 逐位相同。

### 3. 原生 7350 Hz AAC-LC

补齐 FAAD2 的第 13 个核心频率、预测带和长短窗频带表项，输出保持实际 7350 Hz。按标准使用 8 kHz 一组频带几何，不能将输出声明改为 8000 Hz。仅新支持的 7350 停止隐式倍频，既有低采样率行为与 PCM 保持不变。

真实编码的单声道、双声道、六声道样本覆盖四种长短窗序列，MP4／ADTS／Decoder 均通过。与独立 FFmpeg 完整 PCM 对比，最大 float 绝对误差为 **2.38419e-7**；既有 8／11.025／12／16／22.05／24 kHz 回归逐位一致。

7350 的真实 SBR、LD 频带等没有完整实现，继续明确拒绝，避免访问缺失表项或输出错误音频。本轮共新增 61 项频率相关回归。详见 [7350 Hz 分析、标准依据与边界](../../ttp_aac/docs/NATIVE_7350_RATES_20261029P4.md)。

## 尚未完成的范围

- **Main 耦合通道与 SSR**：本轮继续分析，未直接启用实验宏。耦合分支只是跳过数据；私有负对照虽然输出成功，五声道却出现明显误差。SSR 还缺少实际增益曲线并存在缓冲／状态问题。原插件对真实耦合样本也未产生有效音频。详细实施步骤见 [Main／SSR 剩余分析](../../ttp_aac/docs/MAIN_COUPLING_SSR_REMAINING_20261029P4.md)。
- **更多 AAC 组合**：LD480 有声输入、7350 Main／LTP／960 帧有声样本、任意表外显式频率、真实 7350 SBR、扩展 AOT 仍未完成验证或实现，不能从共享表项推断全部兼容。
- **既有容器边界**：分片保存仍要求现有空间足够；ADIF VBR 时长仍估算，未知长度流不可随机定位；动态 ASC、多 sample description、DRM／在线 DASH 仍不在已验证范围。
- **其它插件**：MOD／VQF 的其余范围见 [p2](AUDIO_PLUGIN_FOLLOWUP_20261029P2.md)，RM 与 XM 数值差异见 [p1](AUDIO_PLUGIN_FOLLOWUP_20261029P1.md)；本轮只更新 AAC，不能视为其它边界自动解决。
