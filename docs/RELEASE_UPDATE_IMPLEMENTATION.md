# 软件更新实现与验证

更新日期：2026-09-25。

## 使用方式

“选项 → 常规 → 软件更新”包含检查周期、更新源、立即检查、打开更新器，以及 GitHub / Gitee 发布页链接。

- 新配置的自动检查周期为 **不检查**。已有配置中的检查周期继续保留；立即检查不受该开关限制。
- 更新源默认 **Gitee**，可以切换 GitHub。
- “打开更新器”和“立即检查”位于同一行，尺寸一致。发布页链接采用与左下角一致的纯蓝色、无下划线样式，访问后仍为蓝色。
- 更新器为独立 C++ 程序 `TTPUpdater.exe`，显示当前版本、最新版本、更新源、下载进度和状态。打开后立即检查，点击“立即更新”才安装。

播放器和更新器均采用目前统一的 x86 Release 构建，支持 XP SP3、Win7 及现代 Windows。当前发行包为 `TTPlayerRebuild-yyyy.MM.dd[pN].zip`，内含：

```text
TTPlayerRebuild.exe
TTPUpdater.exe
SHA256SUMS.txt
```

两个 EXE 必须一起复制到原播放器目录。发行包仍依赖原播放器的运行资源；它不是全新安装所需的完整资源包。旧设计文档中的现代版 / XP 版双包划分已不适用于当前构建。

## 检查和通知

读取 GitHub / Gitee 的 Release API，解析 `tag_name`，只接受严格的 `yyyy.MM.dd`、`yyyy.MM.ddpN` 日期版本。比较 `(年, 月, 日, 修订号)`，因此 `p10 > p2`，跨日比较也不会出现拼接数字或浮点精度问题。

忽略草稿、预发行、非法日期、缺少附件、重复附件、超大附件；必须同时存在版本名称匹配的播放器 ZIP 与 `SHA256SUMS.txt`。不是仅发现一个 Git Tag 就提示可安装。分页具有条数、次数和重复页上限。

后台检查在工作线程中进行；成功检查记录日期，失败后间隔一小时重试，手动检查不受重试间隔限制。默认关闭时不会发出自动更新请求。同一来源和版本的自动通知只显示一次。

| 系统 | 新版通知 |
| --- | --- |
| Windows 8 及以上 | `Shell_NotifyIcon(NIF_INFO)` 系统通知，点击后打开软件更新选项；显示形式由系统控制 |
| XP / Win7 | 根据原版 `00455308`、`00455C99`、`00462D2A` 恢复右下角 HTML 通知窗口，提供选项和关闭入口 |

旧式通知的 HTML 正文仅为“请点击选项前往更新”。正文使用 HTML 字符引用，解决 XP 上 ATL / MSHTML 系统代码页导致的中文乱码。系统通知创建失败时使用该窗口作为回退。

这不是完整照搬旧更新协议；保留原版通知入口和主要布局，新版查询与安装均使用新实现。

## HTTPS、代理与 Token

优先从安装目录的 `AddIn/ttp_https.dll` 加载 HTTPS 组件，复用播放器网络设置中的代理类型、服务器、端口、用户名和密码。更新器在临时目录运行时仍从安装目录读取配置和 DLL。

- 没有可用组件时，Win7 / 现代 Windows 使用系统 WinHTTP；能否联网取决于系统 TLS、证书和网络环境。
- XP 缺少可用组件时，播放器“立即检查”和更新器显示 **“缺少 HTTPS 组件，请前往发布页手动下载更新”**。
- 组件已经开始 TLS 校验后的证书或握手错误直接报告，不通过回退绕过验证。
- Win7 原生路径兼容 IE 显式代理及 PAC 设置；SOCKS 代理使用 HTTPS 组件。

组件新增向后兼容的 ABI 3 流式下载接口，ABI 1 / 2 保持不变。歌词 `get()` 仍限定 2 MiB；新下载接口支持已知长度、分块和正常 TLS 关闭定界，调用方把更新包限制为 64 MiB。旧 ABI 2 组件仍可下载原有小包，大包应升级 HTTPS 组件。

所有客户端请求均先匿名访问。若构建中包含专用只读 Token，仅在 Gitee 返回 401 / 403 / 404 时对 Gitee 请求重试，不把该 Token 发送至 GitHub。

Actions 构建前运行 `cmake/prepare_update_access.py`：实际匿名请求 Gitee API、下载校验文件和完整 ZIP，并验证 SHA-256。匿名成功则生成空凭据；失败才读取用户已允许公开分发的 `GITEE_TOKEN_UPDATER`，并先验证带 Token 的访问。生成头文件位于构建目录，日志不打印 Token，头文件不进入发行附件。发布 Release 的 `GITEE_TOKEN` 与检查更新的 Token 分开。

2026-09-25 实测 GitHub、Gitee 的公开 API、摘要和 `TTPlayerRebuild-2026.09.24.zip` 均可匿名下载；两边 ZIP 均为 1,406,426 字节，SHA-256 一致：

```text
faa08ab6e4e760ff5f82c728a13e980b60b5bfe42f4026f582274c47ab367c58
```

本次构建不包含 Token。没有使用或读取用户的私有发布 Token。

## 下载、替换和恢复

1. 更新器把自身复制到独立临时目录运行，以便更新安装目录内的 `TTPUpdater.exe`。同一安装目录只允许一个更新器工作。
2. 创建独立下载目录，下载外层校验文件及 ZIP，验证长度和 ZIP SHA-256。
3. 只解压固定白名单文件，拒绝路径越界、重复条目、重叠数据、加密 ZIP、截断、CRC 错误和超限数据。再验证包内 EXE 的 SHA-256、产品文件名、x86 架构及版本。XP 额外检查 PE 子系统版本。
4. 在关闭播放器前检查安装目录写入权限。只对该目录的播放器发送正常退出请求并等待真实进程结束；不会强制结束进程。歌词保存中或窗口正在退出时可拒绝请求。
5. 在目标卷暂存并校验文件，使用 `ReplaceFileW` 替换播放器，旧文件保存为 `TTPlayerRebuild.exe.bak`。下一次成功更新时 `.bak` 保存更新前的那个版本。
6. 若包内含更新器则暂存后替换，并保留 `TTPUpdater.exe.bak`；历史仅含播放器的包也可以解析。创建新版进程立即失败时恢复旧 EXE；后续启动异常会保留 `.bak` 并报告。下载与解压目录在本次尝试结束时清理。

取消下载和校验失败不会进入安装。文件被占用、目录不可写、播放器拒绝退出、超时都会报告错误。替换文件期间暂时禁用取消，避免人为中断文件事务。`ReplaceFileW` 特定失败状态可能已移动旧文件，因此另有恢复处理，依据 [Microsoft 的失败状态说明](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)。

HTTPS 与双层摘要用于传输和文件一致性验证；本版未增加独立发布签名、离线 ZIP 选择、断点续传或断电恢复日志。启动验证包含进程创建和初始消息循环检查，不代表已验证所有播放功能。

## 本地验证

测试代码仅存于本地 `tests/update`、`tests/lyrics`，不上传，不在 Actions 运行。Actions 仅构建、审计、检查公开下载可用性和打包产品文件。

- 版本日期 / 修订号边界、异常 JSON、真实 Release 解析、摘要及 ZIP 损坏 / 路径越界 / 重复条目。
- 使用真实播放器 EXE 验证替换、禁止降级和连续更新时的 `.bak` 内容。
- 新配置默认不检查，保存的周期与来源保留；选项子页切换及两个操作按钮位置、尺寸。
- 3 MiB 已知长度 / 分块 / EOF 流式下载、截断、超限、写入失败、中途取消，以及旧 HTTPS ABI 契约回归。
- XP、Win7 通过新组件匿名下载两个来源的实际发行 ZIP，并验证 SHA-256。
- Win7、Windows 11 无组件时通过 WinHTTP 匿名下载两个来源的实际发行 ZIP。
- XP、Win7 在隔离目录使用本地 HTTPS 接口夹具完成更新器 UI 的下载、代理参数传递、旧进程正常退出、替换、备份、自身替换及新进程启动。该测试没有发布测试版本或修改用户的实际安装目录。
- XP 缺失 HTTPS 组件的提示、XP / Win7 旧式通知、选项页与更新器截图检查。
- 播放器和更新器均通过 XP / Win7 静态导入审计。发行包由明确的三个文件组成，不使用整个构建目录的通配符。

源码入口：`src/update/`、`src/updater/`、`src/ui/player_window_update.cpp`、`src/ui/update_notice.cpp`。ZIP 解压使用固定的 zlib 1.3.2，构建时校验下载摘要，许可证保留于 `docs/licenses/zlib-LICENSE.txt`。
