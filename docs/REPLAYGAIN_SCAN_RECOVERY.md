# 扫描增益信息恢复与验证

日期：2026-09-30。

依据：[原版扫描增益信息分析](ORIGINAL_REPLAYGAIN_SCAN_ANALYSIS.md)。本次落实该分析第 10.3 节的建议，修复扫描输入幅度、窗口操作和标签保存，并明确保留的边界保护。

## 1. 修复结果

### 手动扫描与播放扫描使用相同幅度

原版 `004B0560` 把 16 位 PCM 除以 `32768`，以满幅约为 `±1` 的 double 样本交给 `ttpcomm.dll`。重建版播放处理链采用与输出编码配对的半幅域，之前直接把其样本交给分析器，导致自动扫描的峰值约少一半、增益通常高约 6.02 dB。

新增 `PlaybackReplayGainAnalyzer::AnalyzePcm`。手动扫描和播放扫描共用 `replay_gain_scanner.cpp::ConvertSamples`；播放链从未施加增益、EQ 的源 PCM 取样。局部 EQ／DSP／输出编码的幅度约定没有整体翻倍。

- 整数 PCM 支持 8、16、24、32 位。
- 浮点 PCM 支持 32、64 位；有限的超满幅值保留，不预先裁到 `±1`。非有限源样本沿用转为零的处理。
- 增益计算仍调用原版 DLL 的 50 ms 窗口、滤波器及直方图算法。

### 暂停、继续、取消和窗口生命周期

原版资源 222、按钮 `0x88B` 对应暂停／继续。此前重建版把该按钮和取消按钮一起处理，导致点暂停直接关闭。

- 拆分原资源的“暂停|继续”文字，并正确切换状态。
- 使用条件变量，在打开文件前、解码块之间和提交标签前响应暂停／取消。
- 不复刻原版 `SuspendThread`；采用协作等待，避免把线程挂起在插件或堆锁内部。
- 取消会先唤醒暂停的线程。正常关闭等待后台完成、文件句柄释放后再销毁窗口，期间界面消息仍正常处理。
- 正在取消时再次执行扫描，会显示同一窗口；不启动重复扫描。
- 主窗口强制销毁时请求取消；后台持有自己的模块和插件引用。尚未结束时阻止新扫描，避免同文件重叠访问。
- 接入非模态对话框消息处理，使 Tab／Esc 等按键交给对话框管理器。
- 补上百分比变化时的界面刷新，保留“全成功／跳过后自动关闭、有错误时保留结果”的行为。

暂停在当前插件调用返回后生效。若第三方解码器一直不返回，普通取消窗口会继续等待；没有使用强行终止线程的方法。这与正常解码器的暂停／取消回归是不同边界。

### 标签与写入规则

- 增益使用六位有效数字加 ` dB`，峰值使用六位有效数字，恢复 `%g dB`／`%g` 的精度策略，并固定小数点区域设置。
- CUE 和普通 reader 都按“两项原始标签字符串非空”判断跳过，匹配原版；不再要求 CUE 标签先成功解析成数字。
- 手动扫描可清除只读属性后保存；播放自动扫描保留只读属性并报告写入失败。
- 保留插件元数据写入的错误检查，不把失败项标记为完成。
- 提交前拒绝非有限 gain、非有限 peak 和负 peak。

## 2. 明确采用的边界修正

| 边界 | 本次行为及理由 |
| --- | --- |
| 右声道有声、左声道静音 | 原版 DLL 实测返回 peak=0。宿主统计所有输入声道的绝对样本峰值，增益继续使用原版 DLL 的结果 |
| 多声道输入 | 峰值取原始各声道最大值，位于 DLL 下混之前；不以某个下混声道的峰值代替源峰值 |
| 合法的 0 dB 增益 | 允许保存，避免原版“等于零就不写”的缺陷 |
| 有完整分析窗的静音 | 允许有效结果和 peak=0；零峰值本身不是错误 |
| 小于一个 50 ms 分析窗 | 不写入结果；DLL 对空直方图也返回零，不能把它当成测得的 0 dB |
| 手动停止、切换、跳转或读取失败 | 保留完整曲目保护；自动扫描只在正常 EOF 后提交。seek 到零也不恢复原版的历史例外 |

这里的峰值是 **sample peak（样本峰值）**，没有过采样，不是 true peak（重建波形峰值）。保留的原版增益计算与修正后的峰值可能有意不同于原版错误结果。

本次没有改写自动增益应用的整条非线性／EQ／DSP 链，也没有增加专辑增益批量扫描；这些不能由“扫描结果对齐”推导为全部完成。

## 3. 运行验证

本地测试源在 `tests/audio/replay_gain_recovery_tests.inc`，由 `tests/audio_recovery_tests.cpp` 的 `--replay-gain` 模式执行。测试源码、合成音频和日志留在本地 `tests`，没有推送，也没有加入发行包或 Actions 流程。

### 原版 DLL 对照

测试直接调用随原版分发的 `ttpcomm.dll` 虚表作为对照，再比较重建版手动扫描、分块播放分析，以及实际静音播放到 EOF 后保存的标签。不是仅对新实现做自比较。

| 合成 PCM | 原版增益 / dB | 修复后的手动／播放扫描 |
| --- | ---: | --- |
| 8 位单声道，8 kHz | -5.45 | 一致 |
| 16 位立体声，44.1 kHz | -3.75 | 一致 |
| 24 位立体声，48 kHz | -3.64 | 一致 |
| 32 位单声道，96 kHz | -3.34 | 一致 |
| float32 立体声，44.1 kHz | -3.75 | 一致 |
| float64 立体声，44.1 kHz | -3.75 | 一致 |
| 16 位立体声，192 kHz | -6.05 | 一致 |

以上使用 440 Hz、幅度 0.28 的一秒音频；8 位量化后的峰值为 0.28125，其余约为 0.28。增益允许 0.011 dB 的量化容差，未序列化峰值对比容差为 `1e-12`。

右声道单独发声时，原版 DLL 的 gain 为 -0.74 dB、peak 为 0；修复后保留 -0.74 dB，peak 约为 0.28。另验证了浮点超满幅、短窗、静音、非有限提交拒绝、零增益、标签精度、只缺一个标签和已有非数值字符串标签等情况。

### 完整播放与真实对话框

- 实际 AudioEngine 静音播放一秒 CUE／WAV，到 EOF 后异步写入的 gain／peak 与原版对照一致。
- 实际提前停止和 seek 后播放到 EOF 均未提交不完整曲目的标签。
- 原资源 222 对话框执行暂停、继续、暂停后取消，验证暂停期间进度稳定。
- 取消关闭后，以独占方式打开源 WAV 成功，确认解码文件句柄已经释放。
- 验证单例、取消后重开、跳过项自动关闭，以及错误项保留窗口。
