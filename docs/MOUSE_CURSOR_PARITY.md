# 鼠标指针样式：原版调用链与重建修复

2026-09-17。对照对象为 `reverse/decompiled/TTPlayer.exe.pseudo.c`、原版
`TTPlayer.exe` 和配套 `ttpres.dll`。这里的“样式”主要指鼠标指针形状；
按钮的普通／悬停／按下图像、提示文字仍由各自的绘制和工具提示路径负责。

## 1. 原版并不是所有控件都使用箭头

### 统一的推按钮处理

`004B591D` 是线程窗口消息钩子。收到 `WM_CREATE` 时，它通过
`004B5858` 检查 `Button` 类和按钮类型，交给
`004C119B → 004C1343 → 00466427` 安装子类。
`00466427` 将 `+0x48` 初始化为 `004501D2` 返回的手形；
`004664CD` 在 `WM_SETCURSOR` 中设置该光标。

因此，是否有图标并不是决定条件。选项底部“全部保存／全部重置”、
查找、属性、转换、关联、消息框等窗口中符合条件的文字推按钮也走这一路径。
按钮低四位类型中，0（普通）、1（默认）和 8（旧式用户按钮）符合筛选；
复选框、单选框、分组框及 11（所有者绘制）不走这一通用分支。
禁用按钮在真实鼠标命中时由父窗口接管，不能留下表示可点击的手形。

重建版以前恢复了钩子的提示窗口和菜单边框分支，却跳过了按钮分支。
本次补回已有 `ThreadMessageHooksRuntime` 中的按钮光标子类，只处理光标和
销毁清理，不接管按钮绘制、键盘输入、命令及图像列表所有权。
钩子限于播放器的 UI 线程，不修改系统 `Button` 类或其他程序。

### 皮肤控件

| 原版控件 | 构造／处理入口 | 指针规则 |
| --- | --- | --- |
| SkinButton | `0040A156 → 0040862C`、`0040A445` | 手形 |
| SkinIcon | `00415F2F → 00415CB8`、`004160C2` | 手形 |
| SkinSlider | `00451CEF → 004501D2`、`00452518` | 整个滑块客户区为手形，不仅是滑块小图 |
| HyperLabel | `0040C563`、`0040C68D → 0040C20D` | 命中文本区域时手形；按字体和左右对齐收窄横向命中范围 |
| 可点击 Static 子类 | `0042C258 → 0042A88C` | 客户区手形 |
| VisualCtrl | `00457672`、`0045813C → 00457727` | 缺少封面的可点击提示为手形；其它区域交给默认处理 |

上述几个手形加载器在 NT 系统上都使用系统 `IDC_HAND`（`0x7F89`）。
伪代码中创建单色替代光标的分支针对更早的非 NT 系统，不需要为 XP／Win7
另造一套手形，也不需要增加新版系统 API。

### 歌词有两套专用资源光标

`0043EB87` 对三个成员赋值：

| 成员 | 来源 | 用途 |
| --- | --- | --- |
| `+0xD0` | `ttpres.dll / 0x455`，即 1109 | 有歌词内容时的悬停光标 |
| `+0xD4` | `ttpres.dll / 0x454`，即 1108 | 捕获鼠标、拖动歌词时的光标 |
| `+0xD8` | `0043E7E0`，系统手形 | 特定提示／链接条目 |

`00442C5A` 根据内容、链接命中和拖动状态选择上述成员；`00442A13`
在鼠标移动时也更新悬停光标。`004425F7` 开始拖动时直接使用 `+0xD4`。
**水平和垂直滚动共用相同的资源光标**，滚动轴只影响位移计算。

直接读取原资源得到两者均为 32×32 单色光标：1109 热点为 `(9,8)`，
1108 热点为 `(10,12)`。修复使用 `LoadCursorW(ResourceModule(), id)`，
保留原图案和热点，未重新画图。资源缺失时才使用系统箭头／移动光标兜底。

没有歌词、仅显示普通默认文字时交回箭头。关闭“允许拖动歌词”阻止拖动，
但不把已有歌词的悬停资源改成箭头。至少两行歌词、捕获、取消及寻址规则
沿用已有恢复。普通、迷你、全屏和透明全屏输入层共用这项修正。

| 播放列表评分热点 | 手形 | 保留原有评分区域命中 |

| 普通／迷你／全屏歌词正文及正文空白 | 1109；拖动时 1108 | 修正错误的箭头／系统方向光标 |
| 普通歌词窗口关闭、置顶、桌面歌词按钮 | 手形 | 修复以前强制箭头的问题 |
| 歌词编辑器、列表重命名、各对话框输入框 | 系统文本光标 | 父窗口收到子 HWND 的请求时让其自行处理 |
| 歌词编辑器原生工具栏、页签、组合框箭头、列表表头 | 原生控件默认规则 | 不强制手形 |
| 桌面歌词正文 | 手形；边缘为方向缩放 | 保留 `0041A0D1` 和锁定穿透逻辑 |
| 桌面歌词浮动栏按钮、图标 | 手形 | 补齐子控件处理；浮动栏背景保持箭头 |
| 选项、查找、关联、属性、转换等窗口的普通推按钮 | 手形 | 由恢复的线程钩子统一处理，包含之后创建的模态和动态按钮 |
| 选项／视觉设置／转换窗口的颜色及图文按钮 | 手形 | 共享按钮子类也直接处理，保持独立对话框宿主可用 |
| 选项歌词搜索顺序、皮肤信息、关联管理链接 | 手形 | 修复对话框消息结果丢失，见下节 |
| 菜单、提示窗口、复选框、单选框、普通标签、页签 | 系统默认规则 | 不对所有窗口统一设置手形 |

鼠标捕获期间不把相邻控件误认为当前操作对象；评分与窗口边缘处理不能吞掉
来自原生 Edit 子窗口的请求。`WM_SETCURSOR` 中同时核对消息来源 HWND 和
`HTCLIENT`，避免用客户区指针覆盖非客户区或子窗口的指针。

## 3. 对话框链接的第二个问题

原版运行对照发现，重建版选项第 7 页的 2087、2089、2091，以及第 12 页的
1066、1067、2109，代码虽然调用了 `SetCursor(IDC_HAND)`，鼠标实际仍显示箭头。

原因是 `DLGPROC` 返回 TRUE 只表示“消息已处理”。对于 `WM_SETCURSOR`，
还必须通过 `DWLP_MSGRESULT` 向 Static 的默认窗口过程返回 TRUE；否则 Static
继续执行默认光标逻辑，再覆盖为箭头。WTL 对话框适配器保留了这套 Win32
返回规则，因此这是调用方遗漏结果值，并非 WTL 或操作系统绘制异常。

本次修复选项页及歌词关联对话框中的相同问题。选项外壳使用的普通窗口
子类仍直接返回 TRUE，并校验子窗口归属、客户区及启用状态。

## 4. 验证与边界

修复后原版采样 462 个可见位置，重建版采样 428 个位置；按窗口、控件 ID、
类名和标题能够配对的 **322 次采样全部一致**。主窗口因重建版采用集中绘制，
另外按原版子控件坐标检查 **15 个位置，全部一致**，包括按钮、音量、图标、
状态文字、可视化和 LED。比较包含光标掩码与热点，并非只检查代码调用。
重复页脚属于不同页面采样；不能把采样次数称为不同控件种类数量。

现代版与 XP／Win7 版 Release 均构建通过。两版分别通过 6 组回归：
`fullscreen_lyric_drag_tests`、`options_drawing_tests`、`lyric_association_tests`、
`wtl_behavior_tests`、`desktop_lyrics_tests`、`skin_rebind_tests`；
两版还分别通过选项 15 页的 `--drawing-audit` 检查。
旧系统 EXE 的 x86／子系统 5.01 检查通过，18 个 DLL 的 641 个静态导入
同时通过 XP 5.1.2600 和 Win7 6.1.7600 清单校验。

- 本地检查实际线程钩子：全部 16 种 Button 类型，各自启用／禁用／重新启用；
  验证动态创建、原生默认过程及销毁路径。
- 本地检查主窗口、均衡器、歌词及播放列表按钮，空列表禁用项，以及多个父窗口下
  的真实 Edit 子窗口，防止手形／缩放光标覆盖文本光标。
- 普通、迷你、透明全屏歌词继续用实际鼠标输入检查捕获、水平／垂直拖动及取消；
  光标断言改为原始资源句柄，不再把旧实现的方向光标当作预期。
- 颜色／图文按钮同时覆盖启用、按下、禁用和经典／主题绘制。
- 原版／重建版各自在临时目录运行，用真实鼠标位置和 `GetCursorInfo` 读取
  全局可见光标，并确认目标 HWND；结果保存在本地 `out/cursor-audit/`。
- 测试源码只修改本地 `tests/`；不推送测试子模块，也不让 Actions 执行测试。

原版的私有歌词提示／链接条目尚未完整重建，不能把时间歌词行伪装成这些链接。
浏览器页面、第三方插件内部自绘控件和未触发的网络服务窗口不能凭通用规则
声称已经逐个运行验证。真实 XP／Win7、不同鼠标主题和混合 DPI 仍需要对应环境
实机检查；静态导入检查不等于旧系统运行测试。
