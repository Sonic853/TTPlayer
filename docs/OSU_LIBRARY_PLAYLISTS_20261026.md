## 1. 操作与可选插件

- 播放列表左侧列表的**空白处**右键增加“显示osu列表”“显示osu!lazer列表”，分别控制 `osu!` 和 `osu!lazer` 专用列表，默认不勾选。
- 勾选后后台读取；读取期间列表标题显示“读取中”，成功后一次替换内容。可独立取消、重新勾选，修改歌曲路径并离开输入框后重读。重复操作不会创建重复列表；取消任务的旧结果不能覆盖新结果。
- 在“选项 → 媒体库 → osu!”中设置程序和歌曲路径，保留此前 `storage.ini` 优先解析规则与环境变量。
- 没有可用的 `AddIn/ttp_osu.dll` 时，隐藏两个菜单项和 osu! 子页，媒体库恢复原来的页面布局；原先保存的路径与开关仍保留。
- 已安装旧版、仅支持 OSZ/视觉的 DLL 时，路径页可见，两个歌曲库菜单灰显。使用此功能需同时更新 EXE 和 DLL；安装、更新、移除 DLL 后重启播放器。
- 隐藏正在播放的列表会保留其当前播放队列，音乐继续。普通列表和普通 TTBL 文件不受影响；游戏列表每次启动从来源重建，不写成普通 TTBL。

## 2. stable 的读取

DLL 读取 Songs 下谱面的 `[General] AudioFilename`、`[Metadata]`、`[Events]`。优先 Unicode 标题/艺术家，同一集合的多个难度引用同一音频时只保留一首；不同音频保留多首，不把音效文件当歌曲。保留代表谱面和背景路径，缺少音频的谱面跳过。

解析在 `[HitObjects]` 前停止，避免加载整份大谱面。限制文本、目录和记录规模；拒绝越界路径、绝对引用、设备路径和重解析链接。中文路径和大小写引用均覆盖旧系统测试。实际本机 stable 库读取 10 首。

## 3. lazer 的读取

使用已分析的 `RealmBeatmapSet → Beatmaps/Metadata → RealmNamedFileUsage → RealmFile.Hash` 映射，读取未删除集合。由歌曲路径 `files` 的父目录定位 `client.realm`，按 `files/首字符/前两字符/完整 SHA256` 找到音频、背景及谱面；同集合按音频去重，不合并不同集合的元数据。

固定 **Realm Core 20.1.2**，与本机已分析的 Realm .NET 20.1.0 对应。构建时下载 Core 和对应 SHA-2 子模块归档，验证 SHA256；只静态链接 Storage，不依赖游戏、CLR、.NET 或 Realm.dll。源码和第三方声明由插件仓库中的构建配置、许可证文件追溯。

数据库以拒绝写/删除共享的只读句柄读成内存快照，再交给官方 Group 解析，不使用游戏的迁移、修复、备份或 RealmAccess 初始化路径。上限 **256MiB**；锁定、超限、损坏或不兼容字段返回错误，不迁移游戏库，也不创建 `.lock` / `.management`。游戏占用数据库时，关闭 lazer 后取消勾选、再勾选即可重试。未来 schema 不保证自动兼容。

实际本机 lazer 库读取 2 首，读取前后数据库 SHA256 一致。修正了 XP 下大小写比较兼容层的行为差异，避免音频文件名大小写不同而漏曲。

## 4. 宿主与文件保护

- 新增 DLL 导出 `ttp_osu_library_query`，序号 3、ABI 1。宿主只调版本化接口、复制回调记录，在后台任务中读取；不链接 Realm，也不重复实现游戏解析。
- 专用列表使用保留槽位 `0x1ffe/0x1fff`，普通保存、压缩恢复和 active slot 持久化忽略这些临时槽位。至少保留一个普通列表。
- 曲目保留来源身份、谱面标题/艺术家/专辑、代表谱面及背景。真实音频参数/时长仍正常更新，防止后台标签读取把 lazer 哈希文件名显示为曲名，或覆盖同音频不同谱面的元数据。
- 无扩展名音频沿用内容探针选择解码器。游戏曲目不触发错误后缀改名；文件属性标签/封面、嵌入歌词、物理删除、重命名和增益写入入口限制为只读。读取失败不改游戏文件。
- 播放游戏曲目时局部关闭自动增益扫描，用户原设置不变，切回普通歌曲恢复。运行中重新应用选项也遵守这个限制。
- 游戏曲目的歌词默认保存和下载转入配置目录下 `Lyrics/osu/<来源身份>/`，可重新搜索/读取；不覆盖游戏目录中原有歌词。嵌入歌词编辑导出为外置副本，另存为也拒绝游戏目录。
- 歌词关联窗口仍允许关联游戏原有歌词，但禁用其重命名和删除，并在实际提交时复查；播放器缓存中的副本可正常改名、关联。
- 拖出游戏曲目只允许复制/链接；停用可能返回移动操作的 Shell“发送到”入口，避免破坏游戏引用。允许从资源管理器查看原文件位置。
- 星环视觉从代表谱面读取节拍，背景优先顺序为音频内嵌图、谱面背景、全屏备用图片。此变更不表示 SMTC/任务栏等其它图片入口均已接入谱面背景。

## 6. 边界

目前是按需读取，不监视游戏数据库实时变化；新安装或删除歌曲后重新勾选列表刷新。无效根目录显示错误，读取失败保留旧内容；首次读取失败则为空列表。没有自动打开游戏、修改游戏库、数据库迁移和写回功能。超大 Realm、后续不兼容 schema 和持续占用需要明确报错，不能用目录猜测代替索引。

## 7. 最终验证与发行文件

最终 Release 完成后，Windows 11 本机和 XP、Win7 虚拟机均运行并通过：

- `--osu-library-lists`：初始行即显示谱面标签、后台取消/切换/重读、两种来源实际 WaveOut 播放、隐藏播放队列、普通列表的数量/active slot/TTBL 保存隔离，以及音频、Realm、游戏原歌词字节保持。
- 同一完整窗口用例覆盖自动增益局部禁用/普通曲目恢复、实时选项重配、下载缓存搜索、歌词编辑和内嵌文本转存、关联窗口原文件保护及缓存副本重命名。程序创建真实 HWND 并调用最终 DLL，不仅是接口模拟。
- `--osu-library-absent`：独立无插件运行目录中无菜单、无游戏列表、无子页/路径控件；原媒体库控件可用，保存和关闭不清空已有路径。
- `--osu-library-options`：设置、子页、路径与 `storage.ini` 回归。
- `--osu-fallback`：两种星环和两种全屏布局中，内嵌封面优先于游戏背景，游戏背景优先于备用图；覆盖暂停、停止、空图、坏图、替换、取消及相对路径。
- `--osu-lyric-fade`：两种星环、分区/叠加布局的歌词渐变、进退场、暂停/停止、中断和重入回归。

人工查看 Win11、XP、Win7 实际列表截图，初始标题/艺术家显示正常。验证过程发现初始导入只填了曲目字段而未填标准标签表，导致首次绘制仍显示文件名/哈希；已在入列前调用统一标签恢复函数，并加入首次绘制断言。备用图测试原来的模拟元数据未设置当前解码源身份，也已同步测试夹具到宿主的当前源快照契约，并新增游戏背景的实际 DLL 像素检查。

主程序静态导入审计为 22 DLL / 747 项，可选插件为 7 DLL / 175 项，均满足 XP/Win7 清单。核心 ZIP、可选 ZIP、包内摘要、Release 字节一致性及新导出校验通过；核心包不含可选插件或测试。
