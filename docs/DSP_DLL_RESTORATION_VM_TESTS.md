## 3. 验证中修正的测试宿主问题

### 3.1 OctiMax 的运行库终止弹窗

用户截图中的 `loader_probe.exe — abnormal program termination` 来自 OctiMax 的静态构造函数。测试宿主在加载插件前将 HKCU/HKLM 重定向到空白临时注册表，隐藏了 Winsock 的系统配置，导致 `WSAStartup(0x0202)` 失败并进入 CRT abort；原始文件与恢复文件均受影响。

改为先初始化系统 Winsock，再隔离插件的注册表写入后，两份 OctiMax 均通过本机以及 XP、Win7 验证。修复在测试宿主内完成，没有修改 OctiMax 算法或绕过其初始化。

### 3.2 临时注册表父键类型

旧测试根使用 `REG_OPTION_VOLATILE`，插件尝试创建普通持久子键时会收到 `ERROR_CHILD_MUST_BE_VOLATILE`。这会误触发 Enhancer 的“无法访问注册信息”和 SO3D 的配置写入错误。

最终测试改用独立普通测试根 `HKCU\Software\TTPlayerDspRestoreTests\Probe-进程号-时钟值`，在进程内重定向 HKCU/HKLM；正常结束后删除该次测试根。之前的易失父键不能直接复用，所以使用了新的独立根目录。实际插件配置和系统 HKLM 没有被这些测试写入。

### 3.3 公共控件与首次运行提示

测试宿主预先初始化公共控件。ViPER 首次运行的 `Info` / `OK` 提示表示找不到参数文件，将使用默认参数；测试记录提示并返回“确定”。其它错误提示仍记录为非零失败，不会自动当作通过。

### 3.4 Init 的非零返回值

[原版伪代码](../../reverse/decompiled/TTPlayer.exe.pseudo.c)的 `FUN_00427edc` 在第 40725 行调用模块 `+0x10` 的 Init，随后保存活动模块，没有根据其整数返回值分支。重建版 `InvokeInitializeSeh` 已遵循这一行为。

NEQ 的 Init 尾部保留了 `EnumThreadWindows` 的返回结果；SO3D 的正常路径返回 `1`。初版测试按“非零失败”判断，导致两者被误报。最终测试记录返回值，按原版行为继续执行 PCM 和 Quit；两者的原始／恢复版均完成后续检查。没有修改 DLL 返回值或屏蔽异常。

## 4. 测试隔离与证据

两台虚拟机使用独立目录 `C:\DSP-Restore-20260928`，保留正确的原文件名。测试包同时包含原始和恢复文件，来源 SHA-256 记录在本地清单中。

测试宿主为无额外 VC 运行库依赖的 x86 程序，子进程限时 15 秒。错误弹窗会转换为日志和失败退出，避免阻塞用户桌面。最终测试没有触发错误弹窗或超时。

本地证据位于 `rebuild/tests/artifacts/dsp_restore/vm`：

- `files.json`：测试文件名及原始／恢复 SHA-256。
- `XP-final.log`、`Win7-final.log`：最终 148 个用例的完整日志。
- `validation.json`：解析后的逐文件、逐模式结果及日志 SHA-256。
- `XP-suite.log`、`Win7-suite.log`：初轮记录，保留发现的问题。
- `*-isolation-error.log`、`*-init-return.log`：测试环境调整的中间记录，没有计入通过结果。

测试源码、测试 EXE、文件包和日志均仅放在本地 `rebuild/tests`；不加入 Actions、不放入发行包、未提交。

## 5. 结论边界

本次确认了 12 个恢复 DLL 在 XP、Win7 下可加载、可换址，并可按原版调用方式完成默认配置的音频处理和退出。

未覆盖播放器内的长时间实际播放、所有 Config 窗口和预设交互、不同位深／声道、随机音效的完整等价性，也没有恢复通用 `registry.json` 接入任务。现有按原始 DLL 哈希识别的兼容分支，不能自动视为支持恢复后的新哈希。

## 6. 对重建版的后续改进建议

> 后续实施已完成通用接管、错误状态及配置回归，见 [DSP 通用共享注册表接入](DSP_GENERIC_REGISTRY_INTEGRATION.md)。以下保留实施前的依据；旧的三插件白名单和固定导入槽限制已移除。

用户询问本次测试是否发现值得优化的产品功能。以下是对当前源码的复核，不代表已实施：

| 优先级 | 建议 | 已有证据及预期结果 |
| --- | --- | --- |
| 1 | 完成通用 DSP 文件注册表接入 | `plugin_registry.cpp:1283` 的 Supports 仅识别 3 个文件名及固定原始哈希。恢复后的 Enhancer 不会命中；其它恢复 DLL 也未自动接管。应按已验证的导入信息建立调用映射，继续所有插件共享 `registry.json`、缺失读取回退系统、写入落 JSON 的规则。 |
| 1 | 支持 `OriginalFirstThunk == 0` 的合法 PE | `plugin_registry.cpp:1345` 当前直接抛错，而本批 UPX 恢复文件已经实际证明该布局可以正常运行。通用接入应读取磁盘名称元数据并对应运行时 IAT；不能简单删除检查后把函数地址当名称。还需处理动态解析和相关依赖模块。 |
| 2 | 提高“未接管”和失败诊断的可见性 | `winamp_dsp.cpp:645` 附近目前只对未适配 Ozone 提示；其它未命中适配的插件继续原生注册表行为。建议在插件设置中明确显示配置存储方式，错误区分未适配、文件只读、导入表不支持、Init/PCM/Quit 阶段，并显示具体插件。 |
| 3 | 评估可选的插件进程隔离 | 当前 `Init/Config/Modify/Quit` 都在宿主内的持久线程执行，SEH 能处理部分异常，但无法兜住第三方主动 ExitProcess/CRT abort 或死锁。可以评估独立 DSP 宿主与共享内存传输；需要实测音频延迟、界面归属和状态连续性，不应直接把限时强杀线程搬进播放器。 |
| 验证项 | 补齐配置窗口、首次运行、附属资源与持久化回归 | 本轮是默认配置的回调验证。ViPER 有首次运行提示，SPS/DeFX 默认旁路；不能从本轮通过推出所有预设和设置窗口已正确。应在原版／重建版分别验证启停、切歌、采样率变化、设置保存及重启恢复。 |

**无需因本轮误报修改的产品逻辑：**原版和重建版已经忽略 Init 整数返回值，不应改成非零禁用；当前两倍 DSP 缓冲区容量也应保留。OctiMax 的 Winsock 失败及 volatile 父键错误来自测试宿主的全局注册表隔离，不是已证实的播放器缺陷。测试中的 MessageBox 拦截只用于无人值守记录，不应加入播放器全局行为。

建议实施顺序：通用文件注册表接入及合法导入表兼容 → 状态与错误诊断 → 配置持久化回归 → 按实际收益决定是否引入可选进程隔离。本次没有根据这份建议继续修改生产代码。
