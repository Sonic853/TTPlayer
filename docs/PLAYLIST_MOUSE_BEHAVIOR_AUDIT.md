# 播放列表目录与歌曲列表的鼠标行为核对

日期：2026-09-27。

本次接续 [重命名完成行为修复](PLAYLIST_RENAME_COMPLETION.md)，检查左侧 `PlayLists`
目录和右侧 `Files` 歌曲列表。依据为原版伪代码、原版独立副本实测，以及与原版相同样式的
系统 `SysListView32` 控件对照。系统控件内部行为不能仅从播放器自身伪代码推出，因而使用
运行同一系统上的真实控件作为参照，而不把重写一套相同公式当成验证。

## 发现的问题及修复

### 1. 右键选中状态与菜单不同步

右键由底层 ListView 处理，但旧代码只在键盘、滚动和显式 `LVM_SETITEMSTATE` 等消息后
读回控件状态；右键产生的 `NM_RCLICK` 又被同步保护直接丢弃。结果是控件内部已改变选择，
皮肤绘制和菜单仍使用旧模型。

64 个左右键／两栏／四组修饰键／选中项、未选中项及空白的对照中，修复前有 17 个右键
场景出现选中集合或焦点行差异，32 个左键场景没有该差异。

修复在 `NM_RCLICK` 到达时读回选中集合、焦点行、选择锚点和滚动位置，然后再打开菜单。
目录选择变化同步切换当前列表。菜单不再自行将命中歌曲改成单选：原版菜单只读取控件
已经确定的状态，Ctrl／Shift 右键的选择语义应保留。

读回必须发生在菜单打开前，不能等右键过程返回后才处理；菜单命令可能已经删除、重命名
或切换条目。原有皮肤绘制分支保留，避免在菜单的嵌套消息循环中出现白底黑字。

### 2. 歌曲拖动到列表边缘不能滚动

旧实现先拒绝歌曲矩形外的位置，随后才检查是否越过上下边缘，因此滚动分支不可达。
修复接受原版的上下 2 像素边缘，并在拖到最后可见行且下方还有歌曲时滚入下一行。
拖动取消、未达到系统拖动阈值、关闭拖放时仍不能提交重排。

### 3. 滚轮策略与底部边界

旧实现固定使用 `delta / 120 * 3`，忽略不足一格的滚动量和系统每格滚动设置。
现在普通滚轮交给底层 `SysListView32` 处理，再同步滚动位置；Ctrl／Shift 滚轮按原版
列表不滚动的语义消费，避免父窗口再次解释为另一种输入。控件将未消费消息交回父窗口时，
同步保护会阻止再次转入同一原生调用。

皮肤占用整个客户区，自行绘制滚动条；底层控件在数量变化后仍可能保留隐藏滚动条的空间。
因此读回顶行时按皮肤实际的完整行数限制最大位置，不能把原生内部多预留的一行传给绘制。
这解决了高度恰为完整行整数倍时，滚到底后多出空白的问题。

### 4. 键盘打开右键菜单的相邻问题

Shift+F10／菜单键原先取焦点行的底边作为弹出点，重新命中测试会落在下一行。
改用焦点行内部的位置，保留焦点行对应的菜单。

## 回归记录

测试输出保存在 `out/test-artifacts/playlist-rename-20260927/`。

最终结果：本机 Windows、XP SP3、Win7 SP1 均通过 154 项鼠标对照、重命名和滚轮边界回归。
本机另外通过框选／菜单、WTL、列表契约 3 组回归，以及窗口拖动、列表模型与存储相关子集。
XP、Win7 最终输出分别为 `xp-final.txt`、`win7-final.txt`。

- 鼠标对照：64 个左右键选择场景，加 90 个滚轮场景，共 154 项；另验证边缘拖动、取消和禁用拖放。
- 重命名：默认皮肤、LX-iPlay；包括非空 Enter、Esc、空名称 Enter／空白／真实失焦、纯空格、
  首尾空格、滚轮结束编辑、TTBL 保存重载。用户询问的三个边界均在测试内。
- 滚动边界：6 种高度、5 种数量，与真实 ListView 比较底部、完整／部分行、滚轮、滚动条滑块及显示选中行。
- 既有框选／菜单回归、WTL 行为、列表契约和列表模型／星级／拖动子集同时复查。

### 测试程序异常说明

本轮曾弹出 `playlist_wheel_tests.exe` 内存读取错误。该程序是本地测试工具，未放入发行包。
测试夹具由简化子窗口改为真实 ListView 后，控件创建期间会查询 owner-data 模型，而夹具原先
在创建控件之后才建立播放列表；空模型访问导致异常。已将模型准备提前，并初始化测试所需的 WTL 运行环境。
修复后的测试可完成滚轮与边界回归，不能将此前异常的运行计为通过。

此外，尝试运行全部 `ttplayer_tests` 时，既有 `startup-settings` 测试仍断言
`check_update_days == 7`，与当前设置默认值 `-1` 不符。这项无关的旧断言失败单独记录；
本次列表模型、列表存储、星级手势及窗口拖动相关子集通过，不宣称全部历史测试均通过。
