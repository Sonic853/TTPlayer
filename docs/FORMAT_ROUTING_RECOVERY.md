# 文件实际格式与后缀不一致：综合恢复

日期：2026-09-23。范围：原版千千静听 5.7 的宿主伪代码、现有 AddIn ABI、
重建版普通和 XP／Win7 构建。MP3→FLAC 的原版界面基线见
[先前分析](EXTENSION_MISMATCH_ANALYSIS.md)。

## 1. 原版的处理层次

`004C5757 / 004C7EDB` 取得扩展名；`004CBA11` 读取开头 16 字节并恢复流位置；
`004CBC1F` 用纠正后的提示筛选 factory，实例打开失败时继续尝试普通后备候选。
解析得到的压缩格式再交给 `004CD045` 选择解码器。

后缀只影响候选资格，不证明内容有效。提示纠正只发生在内存中，不改名、不转码。
原版也不是让所有插件无条件尝试所有文件。

### 各种格式的差别

| 实际内容 | `004CBA11` 的处理 | 错后缀之后的路径与限制 |
| --- | --- | --- |
| APE，以 `MAC` 开头 | 提示改成 `.mac` | APE factory 可以被选中；插件仍需验证完整文件 |
| Musepack，以 `MP+` 开头 | 改成 `.mpc` | 仅确认这三个字节的旧签名分支；不能据此涵盖所有 MPC 版本 |
| TTA，以 `TTA` 开头 | 改成 `.tta` | 进入 TTA 读取器；如果前面还有标签，不能假定该签名仍位于偏移 0 |
| RealMedia，以 `.RMF` 开头 | 改成 `.ram` | 提示不等于已安装 RealMedia 解码器 |
| ISO BMFF，偏移 4 为 `ftyp` | 改成 `.mp4` | 是容器提示；不能据此断言音轨一定为 AAC，仍由读取器检查轨道和编码 |
| ASF，开头为完整 ASF GUID | 改成 `.wma` | 同样是容器提示；实际音频编码由 ASF 读取器返回 |
| ID3 标签开头 | 仅在原提示为空指针或 `.wma` 时改 `.mp3` | ID3 本身不是 MPEG 帧；MP3 读取器还要扫描正文 |
| MPEG 音频帧开头 | 仅在空提示或 `.asf/.wma/.ra/.ram/.rm` 时改 `.mp3` | `.flac`、`.wav` 等不在此纠正范围 |
| FLAC、Ogg | 没有通用文件头纠正分支 | 正确后缀匹配专用插件；错后缀能否成功依赖通用系统后备 |
| RIFF/WAVE、AIFF/AIFC、AU/SND | 没有通用提示纠正分支 | 容器读取器或系统后备负责实际解析；系统可能优先依据错误后缀选错源过滤器 |
| ADTS AAC | 没有统一 ADTS→`.aac` 分支 | 不应把 MPEG 同步字检查扩大成 AAC 检查；错后缀主要依赖系统后备 |

以上文件头都只是有限提示。例如 `.flac` 内装 MP3，原版并不先改成 `.mp3`。
FLAC 插件拒绝后，通用读取器才有机会解码。反过来 FLAC 改成 `.mp3`，原版也没有
保证会回头选择 FLAC 插件。

MIDI、CD-DA 和 CUE 有各自的专用入口。CUE 的 `004E323B` 还会对引用的音频文件
尝试原扩展名、`.ape`、`.tak` 等；这是 CUE 解析的特定分支，不是任意文件改后缀策略。
本次没有把 MIDI 的非 PCM 播放或 `.cda` 光盘定位改成通用文件猜测。

### 通用读取器和终止条件

原版 `004C9364 → 004C946E → 004C931C → 004E86B3` 构造最后的
`DirectShow Audio Reader`。其 factory 扩展名约束为空，`004E8BD6` 创建过滤器图，
`AddSourceFilter` 打开真实路径；`004E92C4 / 004E93AD` 沿连接取得实际媒体类型。

普通格式不支持可以尝试下一候选；`004C84CD` 中的取消和传输错误要提前终止。
重建版还明确把文件不存在、访问/共享失败、内存不足等列为终止错误。

原版信息预读的 `004E8912` 有系统扩展名登记检查，播放位则跳过该检查。这意味着
原版自身也可能“预读无信息，点击后能播放”。本次为了列表和属性的一致性，信息后备
使用可建立音频连接的读取路径验证，不再照搬这个预读扩展名限制。这是明确的兼容性改进。

## 2. 本次代码恢复

### 格式提示与读取器选择

- 新增 `audio/format_probe`，集中恢复上述 16 字节提示表、大小写处理、流位置恢复。
- `PluginManager` 不再因为原后缀没有插件匹配就跳过文件头探测；实际路径和 `IStream::Stat`
  保持原文件名，仅内部 factory 筛选提示改变。
- 空约束的 factory 参加候选枚举，不向文件对话框增加空过滤项。
- 新增 `RecoveredFileSource`，仅在候选 `Open` 成功后保留它。专用插件普通失败后，
  释放实例，继续 PCM 容器/DirectShow/原有系统读取器；取消和严重错误停止。
- 保留普通版 Media Foundation 以及旧系统 Windows Media 的既有能力作为系统补充。

### DirectShow 音频后备

新增 `directshow_source.cpp`：自有 PCM 输入过滤器接收系统解码的数据，以有上限的队列
提供 `Read/Seek`；不连接系统音频输出设备。音量、淡入淡出、DSP、均衡器、WaveOut/
DirectSound/ASIO 仍由原有播放器输出链执行。

处理完整 PCM 帧对齐、EOF、图错误、动态媒体类型、跳转时清队列、关闭时解除生产线程等待。
属性查询只建立音频图，未调用 Run。没有把视频渲染到界面，也没有依赖已废弃的 qedit
SampleGrabber 组件。

这是恢复原版 DirectShow 后备职责，不是宣称其内部 COM 结构、每个过滤器的输出数值
或所有错误路径都与原二进制逐指令相同。

### 属性、标签与损坏文件

- 修复 MP3 信息函数找不到 MPEG 帧仍返回成功的问题。
- 参照 `004E5303` 计算帧长，并验证相邻帧的版本、层和采样率，避免把一个孤立同步字
  当成 MP3；VBR 允许相邻帧码率不同。
- 修正 Layer I/II/III 的格式标记和帧采样数；WAV 缺少有效格式或数据不再算读取成功。
- Shell 属性只作为已验证读取路径的字段补充，不能单独证明文件可解码；编码名称不再
  根据错误文件后缀强行命名。
- MP3 标签/封面写入在同一个源文件句柄上再次验证 MPEG 内容。真实 MP3 即使后缀错误
  仍能安全编辑；其他内容伪装为 `.mp3` 不会进入 MP3 标签改写。

### 测试中发现的 WMA 分块问题

原 DMO 解码器的 slot 4 给出完整输出缓冲区需求。重建版此前将调用者较小的读取大小
直接传给 slot 8，WMA 在 8192 字节请求下发生 `0xC00D36B1`，而 65536 字节请求成功。

现在按解码器要求取完整输出，再缓存并分批提供；缓存未读完时不送入新压缩包；Seek/
Reset 清掉缓存。测试验证大小两种请求得到相同字节数和 PCM 哈希。这也保留了 CUE 和
转换器短读取的边界，不会因扩大输出缓冲而丢掉多取的音频。

## 3. 验证方式和结果范围

测试源码仅位于本地私有 `tests/`，未上传、未提交子模块引用，Actions 未增加测试任务。
所有音乐都使用生成样本或用户歌曲的副本，没有改写用户音乐。

矩阵含 80 个文件：12 种格式（MP3、MP2、WAV、AIFF、AU、FLAC、Ogg、TTA、ADTS AAC、
AAC/MP4、WMA、APE），包括有 ID3 的 MP3、无 ID3 的 MPEG 副本、交叉错误后缀和两份损坏文件。
每份分别检查 8192/65536 字节请求的完整解码，以及元数据读取。

DirectShow 另测从 EOF 跳回 0、跳到中段、队列有数据时关闭；格式探测单测覆盖 MP+、RMF、
ASF 等签名、短文件头、URL 提示及流位置恢复。MP+ 和 RMF 在本次没有真实解码样本，
其结论限于宿主提示规则。

本地详细结果保存在 `out/test-artifacts/extension-mismatch-20260923/`。
系统过滤器不同可能造成解码延迟、时长估计和 PCM 数值差异；这里只要求同一环境、同一路径
在不同读取块大小下不丢样本，不声称不同 Windows 的解码输出逐位相同。

XP 测试目录为原版 Ogg/ASF 等插件提供其已有的 `msvcr110.dll` 依赖；它是原插件依赖，
不是本次给播放器或重建 AAC 插件增加的新依赖。测试也检查了无插件时的系统后备路径。

其他回归：普通/兼容构建的格式探测和内置文件属性测试通过；普通构建的 mp3PRO 源、
PCM 输出转换、转换/CUE 恢复测试通过。覆盖错后缀 MP3 标签写回、损坏文件拒写、标签和
封面回归。兼容 EXE 通过 XP/Win7 静态导入审计：x86、子系统 5.01、19 个 DLL、655 个导入。

这轮为共享播放源的完整解码测试及文件信息测试，没有把它描述为全部 GUI、音频设备或
所有过滤器组合的实测，也没有重复上一轮的原版界面操作。

## 4. 与原版一致性边界

恢复的是“有限文件头纠正 → 候选读取器实际验证 → 普通失败继续后备”的流程，
不是增加一个覆盖所有音乐格式的万能文件签名表。

因此，在没有相应系统过滤器的 XP/Win7 上，FLAC 或 Ogg 改错后缀仍可能失败。
要让这类情况也总是成功，需要另加可靠内容识别并重新排序专用插件；这属于超出原版
`004CBA11` 的功能扩展，本次未把它冒充原样恢复。
