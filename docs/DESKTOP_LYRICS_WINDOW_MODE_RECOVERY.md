# 桌面歌词最小化及正常／迷你模式返回修复

日期：2026-09-25。

## 1. 问题与原因

本次处理两组有关联的问题：

1. 主窗口最小化（含任务栏、菜单及隐藏到系统栏）后，桌面歌词绘图层跟着隐藏；点击桌面歌词“返回窗口模式”时，主窗口也需要恢复。
2. 正常模式进入桌面歌词，再切换迷你模式并返回窗口歌词，或者按相反方向操作，歌词窗口没有恢复为当前模式的布局和显示状态。
3. 窗口歌词显示时最小化，在托盘菜单切换桌面歌词，再双击托盘还原主窗口，两个歌词窗口同时显示（正常／迷你模式均受影响；补充修复见第 6 节）。

重建版保留同一个窗口歌词 HWND，正常／迷你模式分别保存 `LyricWnd`／`LyricWnd2` 对应的位置、大小、置顶及可见设置。`ToggleMiniMode()` 在桌面歌词开启时跳过 `ApplyActiveLyricWindowState()`，而原来的 `LeaveDesktopLyricMode()` 仅根据当前可见标志执行 `ShowWindow()`。因此，隐藏的窗口歌词会继续保留切换前的尺寸、区域及控件布局；当前模式可见标志关闭时，返回命令也无法重新开启它。

原生回归中复现：正常歌词窗口为 `(70,90)-(470,490)`；切到迷你后返回，仍是这个 400×400 区域，而不是已保存的迷你歌词位置及与迷你主窗口一致的高度。修复后得到 `(90,110)-(330,135)`，反向切换恢复正常模式区域。

最小化问题另有原因：User32 会向被拥有窗口发送 owner 隐藏通知。重建版已经实现原版桌面歌词隐藏绘图层的处理，但遗漏了主窗口最小化后异步重新显示桌面歌词的命令链。恢复主窗口时，User32 还可能恢复此前自动隐藏的绘图层，需要再次核对用户的显示意图。

需要区分原版与本次增强：`0044D48D` 本身不能证明会恢复最小化主窗口；本次在返回命令入口显式恢复主窗口，是用户要求的行为补充。对于异步 `-2` 消息，本次还检查最新的桌面模式、关闭状态和用户可见设置：用户已关闭歌词时保持隐藏，已离开桌面模式或开始退出时不重新显示。还原主窗口后同样排队同步，防止系统自动恢复绘图层产生残留。

Windows 的 `WM_SHOWWINDOW` 定义参见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-showwindow)：`SW_PARENTCLOSING` 与 `SW_PARENTOPENING` 分别关联 owner 最小化和恢复。这是原生窗口消息行为，不应通过移除 owner 来规避。

## 3. 实现变更

- `player_window.cpp`：在桌面模式下，最小化／恢复后投递歌词状态同步；保留 `-2` 的非切换语义，并防止排队命令覆盖用户随后关闭歌词的选择。
- `player_window_lyrics.cpp`：返回前完成尚未结束的模式切换淡入淡出；关闭桌面模式；开启当前模式歌词；恢复对应的矩形、区域、布局、字体、滚动计时器及置顶，再走窗口显示淡入流程。
- `player_window.h`：`ApplyActiveLyricWindowState()` 增加可选的 `apply_visibility` 参数，使布局恢复可以在显示之前完成，其他既有调用保持默认行为。
- 返回命令复用主窗口还原方法，兼容最小化与隐藏到系统栏。

测试代码只保留在本地 `rebuild/tests/ui/desktop_minimize_tests.inc`，使用真实原生窗口、原版资源和实际桌面工具栏命令，不加入发行包，不修改 Actions 的 `BUILD_TESTING=OFF`，不提交测试子模块指针。

## 6. 补充：最小化期间从托盘切换桌面歌词，恢复后两种歌词同时显示

### 原因与原版依据

Windows 会记住 owner 最小化前可见的 owned popup。窗口歌词在主窗口最小化后已被系统隐藏，此时 `EnterDesktopLyricMode()` 再调用 `ShowWindow(SW_HIDE)`，并不保证清除系统保存的自动恢复状态。主窗口恢复后，系统发送 `WM_SHOWWINDOW(TRUE, SW_PARENTOPENING)`，默认处理可能重新显示窗口歌词。上一轮恢复命令仅同步桌面控制层和绘图层，没有重新隐藏窗口歌词，因此出现二者同时显示。

修复前原生测试已复现：恢复完成时 `window=1 desktop=1`。日志位于 `out/test-artifacts/desktop-tray-switch-20260925/baseline.txt`。

原版 `00446ED7` 把 `WM_SHOWWINDOW (0x18)` 分发至 `0044C2E7`。该函数在隐藏、桌面模式（`DAT_00547B24 != 0`）或歌词不可见时，将窗口歌词 layered alpha 设置为 0；仅在窗口模式且歌词可见时恢复配置的 alpha 并通知重绘。因此不能仅依赖进入桌面模式时执行一次隐藏，也不能把系统的 owner 自动恢复视为用户请求显示窗口歌词。

### 修复

1. `HandleLyricMessage()` 补齐显示消息的模式约束：桌面歌词开启时，不把 `SW_PARENTOPENING` 的自动显示请求交给默认窗口过程，避免系统恢复的瞬间显示窗口歌词。
2. 主窗口排队的 `0x7D64/-2` 恢复处理同步完整的歌词模式：先隐藏意外恢复的窗口歌词，再按最新可见设置恢复桌面歌词。隐藏顺序必须在桌面重显之前，因为窗口歌词仍是桌面控制窗口的 owner。
3. 保留“返回窗口模式”的显式显示路径及正常淡入淡出；不拦截普通 `ShowWindow`，不修改可见设置，不改变窗口所有权链。

这里恢复的是原版根据当前歌词模式屏蔽错误窗口的行为。重建版使用“阻止 owner 自动显示＋异步同步完整模式”，没有直接照搬原版所有 alpha 写入：实际隐藏窗口还可避免透明窗口的命中区域和可见状态产生分歧。
