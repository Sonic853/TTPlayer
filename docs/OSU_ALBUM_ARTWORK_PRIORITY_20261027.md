# osu 专辑封面与星环背景的显示优先级

## 1. 原因与最终行为

前一轮修复保留了后台回读后的谱面背景路径，但只有两种星环使用该路径。专辑封面视觉、文件属性的封面页、任务栏预览仍读取音频内嵌图片，导致谱面背景没有显示为专辑封面。

按用户最新要求，两类显示采用不同优先级：

| 显示位置 | 第一选择 | 第二选择 | 都不可用时 |
| --- | --- | --- | --- |
| 节拍星环、星环 lazer | 对应谱面背景 | 音频内嵌图片 | 全屏备用图片；仍不可用则使用配置的背景色 |
| 专辑封面视觉、文件属性封面页、任务栏预览 | 音频内嵌图片 | 对应谱面背景 | 保留该界面原有的无封面行为；全屏专辑封面可使用备用图片 |

首选图片损坏或无法解码也会继续尝试下一项。SMTC 沿用任务栏封面位图，因此取得相同的封面选择结果。

## 2. 实现

- `osu_library_artwork.h` 统一从有 osu 来源标记的曲目取得 DLL 已解析的背景路径，并只在 UI 图片快照中合并谱面信息；不把这些字段或背景写入音频标签。
- 专辑封面视觉在内嵌图片不可用时加载谱面背景，缓存包含背景路径。同一音频被不同谱面引用、背景路径变化时也会刷新；停止播放或清空来源时清除旧路径。
- 文件属性的读取任务采用相同顺序填充封面预览，保持游戏音频和封面只读。
- 播放打开和后续元数据更新都给任务栏传递谱面信息，避免只在首次播放时正确。
- 图片读取按内容处理，无扩展名的 lazer 哈希文件也可读取；单个文件上限 64 MiB，继续使用既有 WIC/GDI+ 解码及尺寸限制。
- 两种星环在素材线程中优先加载谱面背景。专用 stable/lazer 列表使用已解析路径；OSZ 使用对应音频的谱面背景，不以音频封面代替有效背景。
- 普通歌曲没有 osu 来源标记，不启用这条谱面背景回退。此次无需修改或更新 `ttp_osu.dll`。

## 3. 验证

在 Windows 11 本机完成：

- `fullscreen_album_tests`：真实 HWND 专辑封面像素比对。覆盖 stable/lazer、无扩展名背景、内嵌图片优先、坏图回退、同音频切换背景、缺失背景、无来源标记、暂停与尺寸变化，以及任务栏用封面位图。
- `--osu-fallback`：两种星环 × 两种全屏布局，验证背景优先于内嵌图片、坏背景回退至内嵌图片、同音频背景更换及备用图变化。包含合成 OSZ 的背景优先检查。
- `--osu-library-lists`：真实后台信息任务、导入/重读、WaveOut 播放、封面快照和背景位图验证。当前实际 lazer 库 2 首 MP3 的标题和时长保持正确；有背景的歌曲可解码其哈希图片。
- `osu_file_properties_tests`：33 项真实文件属性检查通过，包括无扩展名音频、背景预览字节与位图、只读写入保护。
- Release 构建、XP/Win7 静态导入审计、发行 ZIP 字节一致性和 SHA256 检查通过。没有进行本轮 XP/Win7 虚拟机或 Windows 10 实机测试。
