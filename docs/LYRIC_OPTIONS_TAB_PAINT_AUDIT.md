# 歌词秀模式页空白与原版绘制对照

## 结论

本次“窗口模式／桌面模式”切换空白已定位到重建版的同级子窗口层级错误。
子页及其控件仍存在、可见标志正常、下拉框已填入数据，但位于标签控件后方。
这属于程序的窗口管理和绘制遮挡问题，现有证据不支持将其归因于系统故障。

已据此修复模式页的生命周期、层级、尺寸和外层选项状态；修复范围见下文。

## 原版伪代码证据

伪代码文件：`../reverse/decompiled/TTPlayer.exe.pseudo.c`。

| 环节 | 原版证据 | 修复前重建版 |
| --- | --- | --- |
| 初始化 | `004974F0` 创建桌面页 385、窗口页 384，保留两个窗口，显示窗口页 | `InitializeOptionsPage` 的 256 分支只创建当前模式 |
| 子页定位 | `00495F5C`、`00496A32` 均调用 `004052F1(..., HWND_TOP, 1)`；该函数最终调用 `SetWindowPos`，`1` 为 `SWP_NOSIZE` | `PositionNestedDialog` 指定 `SWP_NOZORDER`，不将新子页提升到标签控件前方，且按显示区域调整尺寸 |
| 点击切换 | `00490276` 将标签 2256 的 `TCN_SELCHANGE` 交给 `00497779`；后者对两个已存在的子页调用 `ShowWindow(SW_HIDE/SW_SHOW)` | `switch_nested` 提交旧页、销毁，再创建新页 |
| 控件状态 | `00497779` 在桌面模式禁用外层控件 `0x7E5`、`0x7E8`（2021、2024），切回窗口模式重新启用 | 当前切换路径未更新这两个控件的启用状态 |

原版并非完全依赖系统默认绘制：模式页使用原生对话框和控件，同时有应用自己的颜色按钮处理。
例如窗口模式的 `00496D3A` 更新颜色按钮位图；重建版使用 `WM_DRAWITEM` 和 `DrawColorButton`。
因此，使用相同资源或接入 WTL 不能证明绘制流程、交互状态或最终像素已完全恢复。

## 修复前的本地诊断

在 `tests/ui/options_drawing_tests.cpp` 增加 `--nested-tabs` 诊断入口：

```powershell
build/Release/options_drawing_tests.exe .. --nested-tabs
```

通过向真实标签控件发送鼠标按下、松开消息，连续执行“桌面 → 窗口 → 桌面 → 窗口”。
四次结果一致：

- 当前子页句柄每次更换，说明实际走了销毁／重建路径。
- 子页、下拉框均存在且标记为可见，下拉框各有 2 项内容。
- `ChildWindowFromPointEx` 在子页内部位置返回标签控件，而非子页。
- 子页样式为 `0x50000044`；标签样式为 `0x54000040`，包含 `WS_CLIPSIBLINGS`。
  标签可以避让处于它前方的同级窗口，但当前子页位于它后方。
- 仅在诊断中将子页提升至 `HWND_TOP`，同一位置即可命中子页，无须重建控件或更换系统主题。
- 两种模式下 2021、2024 均保持启用，和原版切换处理不同。

修复前“原始层级正确”的断言失败，已经用作本次回归用例。
测试只保存在本地 `tests/`，不上传，不加入 Actions。

## 已完成的修复

- `PositionNestedDialog` 把子页置于 `HWND_TOP`，使标签的同级裁剪排除子页区域。
  网络设置页复用此定位函数，也修正其潜在遮挡。
- 歌词秀按原版顺序一次创建 385、384 两页，保存两个 HWND；定位使用 `SWP_NOSIZE`，
  保留资源尺寸。`SelectOptionsLyricMode` 仅切换显示／隐藏，不再销毁并重建页面。
- 桌面模式禁用 2021、2024，窗口模式恢复启用；保留两项各自的勾选值。
- 原有控件通知仍即时更新设置；离开模式时保留提交和延迟应用边界，外层页提交覆盖两个子页。
  子页销毁及属性表关闭时清理 HWND；全部重置原有流程销毁属性表后重新初始化，避免旧页覆盖重置值。

回归用例检查鼠标和键盘切换、定向入口、离开属性页后返回、资源尺寸、同级遮挡、隐藏状态、
两个页面的编辑值、关闭重开和子窗口释放。验证同一属性表内两个页面的 HWND 始终不变。
用例不再手动提升层级，完全检查生产路径的行为。

本次确认的是上述两页的窗口管理和绘制差异，未据此宣称整个选项窗口已完成像素级对照。

## 验证结果

- 普通 Release：模式页专项通过；WTL 行为、WTL 迁移、换肤及启动 4 项相关回归通过。
- XP／Win7 Release：模式页专项及 WTL 迁移、启动通过，均在当前 Windows 宿主运行。
- 兼容 EXE 的 18 个 DLL、644 项静态导入通过 XP／Win7 审计；未进行旧系统实机检查。
- 原有完整 `options_drawing_tests` 在本次生产代码修改前就失败于系统关联页的
  Vista／Win7 文案断言。本次使用独立 `--nested-tabs` 入口，不将完整套件计入通过数。
- 测试源码仅留在本地 `tests/`；Actions 保持 `BUILD_TESTING=OFF`。
