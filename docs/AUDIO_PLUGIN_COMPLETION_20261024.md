# 音频插件后续补全与验收（2026-10-24）

最新进展见 [2026.10.24p1 后续修复与验收](AUDIO_PLUGIN_FOLLOWUP_20261024.md)：原版多声道输出原因、AAC 多段编辑、OGG 流与声道、DTS Express、RM／VQF 恢复，以及 TTA／MOD／ASF 对照。以下保留当时版本的记录与摘要。

## 结论与范围

本轮按前次审计顺序处理取消恢复、保存可靠性、AAC 裁剪、多声道格式、标签接口和定位性能。修改了 11 个插件及重建播放器的通用标签服务；`ttp_mod` 保持原有默认兼容内核，本轮只做运行回归。

插件发行版本为 `2026.10.24`，继续独立构建，支持 XP／Win7。没有增加新的外部解码 DLL，也没有修改 Winamp DSP 链。`ttpcomm` 仅增加可静态使用的 SDK 头文件，本轮无需替换其运行库。

**这些结果不代表所有插件与历史二进制完全等价。** 特别是原版 EXE 在 Win7／Win11 对本轮 5／7 声道样本的接收问题仍待继续分析；重建版可以播放这些样本。已修复项、实测范围和剩余边界如下。

## 2. 取消与错误恢复

### 已复现的问题

FFmpeg AVIO 和 Musepack demux 在底层流取消后可能保留错误状态。仅把 Stop 标志清零不能恢复下一次 Read；还有读取已经消耗输入字节、但宿主未收到 PCM 的情况。

### 修复策略

- 五个受影响插件为 AC3DTS、MPC、TAK、RM、VQF。
- 记录**已经成功交付**的样本位置，重新打开解码器并精确重放到该位置。
- 连续取消和恢复过程中再次取消，均不覆盖最初的恢复位置。
- MPC 一次失败 Read 即使已经填入部分临时 PCM，仍恢复到该次调用入口，避免丢音。
- 无法定位的输入不能承诺无损恢复；不伪造恢复成功。
- 普通读失败仍作为错误处理，不自动当成取消或 EOF。

测试包括取消前消耗 0／13 个字节、延迟 0／1 次回调、一次／连续两次取消，恢复后的完整 PCM 与无故障基线一致。VQF 另覆盖有／无 SetCallback 的预热路径。

## 3. AAC 裁剪和 PCM 格式

### AAC

有效的 iTunSMPB 优先于按 movie timescale 舍入的编辑时间；否则读取单段、正常速率且在编码范围内的 elst。只在确认有效裁剪范围的 MP4 AAC 上使用 Reader 内部解码与精确裁剪；没有该范围的旧路径继续使用原有压缩 Reader＋Decoder 接口。

首个 FAAD 重叠预热帧只计入时间轴一次。时长、读取和定位采用同一裁剪范围。测试覆盖 LC、HE、HEv2、不同采样率、单／双／六声道，以及 elst v0/v1 和 iTunSMPB 的 **137 样本非帧对齐偏移**；裁剪结果逐字节等于基线对应片段。

### 有效精度与声道

新增 `ttpcomm/sdk/include/ttpcomm/pcm_format.h`，由插件各自携带相同头文件副本以便独立构建。多声道输出同时提供有效位数、PCM／float 子类型和真实声道掩码；只有确定布局时才填掩码。

FLAC 20-bit／96 kHz／6 声道用独立 libFLAC 编码生成，验证了 288000 个样本值及 24-bit 容器中的左对齐。已有 24-bit／多声道路径也保留精度。格式描述的修正不等于对系统输出设备、原版宿主混音器或 Winamp DSP 能力作出更大承诺。

## 4. 元数据与保存

- **MPC：** APEv2 NUL 分隔值逐项枚举，兼容 Get 返回合并文本；新增前封面、后封面等二进制条目，保存其他未知标签。覆盖 PNG 增加／重开／删除及超限拒绝。
- **ASF：** 枚举非默认语言为 `Title[lang=N]` 等名称。无后缀键优先默认语言；明确后缀只修改该语言。测试分别修改默认和日语 Title，其他语言保持原值；拒绝没有属性名的语言后缀。
- **APE／TAK：** 仅在宿主提供可选 `MetadataCommit` 时暴露提交代理。提交结果可重复查询，失败后析构不重试；旧宿主仍走原释放路径，原有虚表不变。
- **重建播放器：** `StandardContent` 提供相同可选 IID，记录通用标签服务的保存失败并返回真实提交结果。既有逐项写入语义保留，没有暗中改成延迟整批事务。
- **RM：** 同时写失败和回滚失败时，保留原始备份和新文件暂存；注入磁盘满后，检查原始备份逐字节相同，重复 Commit／Release 不再次写盘。恢复文件位置通过调试输出报告。

原接口“最终释放时保存却没有错误返回值”的限制仍存在；可选接口让支持它的新宿主获得结果，并不改写原 EXE 的接口。

## 5. 性能与资源上限

TAK 索引最多 4096 项，达到上限时保留稀疏记录并增加间隔。RM／VQF 每个 Reader 最多缓存 4 MiB 已交付 PCM，近期回退命中时零源读取，越界时回到原准确路径；分配失败只放弃可选缓存。公共实现位于 `ttpcomm/sdk/include/ttpcomm/pcm_history.h`。

WebM 仍遍历包索引，但不再为识别模式而读取整包音频。上述优化没有承诺任意超长文件都能瞬间打开或随机跳转。

## 6. 三系统验收

使用 Windows 11 本机、XP SP3 x86、Win7 SP1 虚拟机。按用户要求以 Win11 代为现代 Windows 验证，**没有独立 Win10 实测**。

| 验证 | 结果 |
| --- | --- |
| 最终接口／PCM／取消／元数据／提交／定位组合 | 三系统各 33 个顶层用例通过，`FAILURES=0` |
| PCM 样本数与 FNV64 | 19 组在三系统完全相同 |
| 旧宿主 Seek 返回成功但位置恒为 0 | 模拟流下 Opus 与 Vorbis 完整解码、定位回零通过；原版 Opus 实际播放通过 |
| AAC 单段编辑和 iTunSMPB | 本地精确切片对照通过；三系统结果相同 |
| RM／VQF 近期回退 | 零源读取，返回 PCM 等于基线；远距离回退也等于基线 |
| 元数据失败 | RM 双失败保留恢复文件；APE／TAK 委托提交成功／失败／不支持三模式均通过 |
| 宿主实际加载 | 三系统分别核对原版与重建版的插件路径、无错误弹窗、播放进度和正常退出；特殊未通过项见下一节 |
| XP／Win7 静态导入检查 | 修改后的插件及播放器构建通过 |
| 播放器通用标签服务 | `builtin_file_info_tests` 本地通过 |

顶层 33 项内有重复取消、提交失败等子组合，不能把它当成所有格式分支的覆盖率百分比。宿主探针“加载成功”还会另外核对播放时间；发现窗口存在但进度为 0 的情况，不记为播放通过。

测试代码、故障样本和运行记录仅保存在 `rebuild/tests/plugins_complete_20261024`；不上传测试代码，Actions 不运行这些私有测试，运行包不含测试。

## 7. 本轮新发现的原版宿主边界

1. **Opus 位置查询已修复。** 原宿主在数据读取后查询位置仍返回 0，opusfile 按已消费的前缀长度检查时返回 OP_EINVAL。现在由读取字节数和绝对定位维护 64 位位置；原版／重建版在三个系统均实际播放通过。
2. **5／7 声道仍有系统相关差异。** DTS-HD MA 96 kHz／5 声道、HRA 48 kHz／7 声道在插件完整解码测试与重建版三系统播放中通过；原版 XP 可以播放，原版 Win7／Win11 本次输出配置下进度为 0。原版 Reader Open 成功，之后取 Format，没有进入 Read。Win11 的另两条 5／7 声道 FLAC 也失败，6 声道 AAC／FLAC／DTS-HD MA 则通过。因此问题不局限于 DTS 解码核心，仍需针对原 EXE 的格式接受／输出协商继续定位。本轮没有擅自降为立体声或增加虚构声道来掩盖问题。
3. **真实 DTS-HD 样本有损坏尾部。** MA／HRA 的完整 3.008 秒片段完成验收；MA 的 float64 PCM 与独立 FFmpeg 参考逐字节相同，HRA 最大绝对差约 `7.45e-8`。完整下载文件的坏尾部仍报告错误，未将它们计为完整文件通过。DTS Express 无实测样本。

真实 DTS 样本来源为 [FFmpeg DTS 样本目录](https://samples.ffmpeg.org/A-codecs/DTS/)。音频仅留作本地验证，不放入源码或发行包。

## 8. 发行内容与后续顺序

输出目录：`rebuild/build/Release`。11 个修改插件的运行包为 `ttp_名称-2026.10.24.zip`，内部只包含 `AddIn/ttp_名称.dll` 和 `SHA256SUMS.txt`；需要对应源码的工程沿用独立 `-source.zip`。许可证继续保存在各仓库／对应源码中。`AUDIO_PLUGINS_20261024_SHA256SUMS.txt` 汇总本轮 DLL、运行包及源码包，不覆盖其他发行物的校验清单。

本轮没有发布远程 Release 或提交 Git。`ttp_mod` 本轮没有代码修改，不另生成同内容的新版本运行包。

后续优先顺序：

1. 定位原版 EXE 在 Win7／Win11 对 5／7 声道 PCM 的格式接受与输出协商，确认可选兼容策略，不改变高规格 PCM 默认精度。
2. 补 DTS Express、AAC 多段编辑／复杂 Profile、TTA 原生 32-bit 和更多历史格式的真实样本。
3. 扩展大文件、非定位网络流及故障注入矩阵；为 RM／VQF 缓存之外的长距离跳转设计更完整索引。
4. 扩大 MOD 效果命令／UMX、ASF DMO／多值编辑、RM 编码变体的原版动态对照。

这些条目是明确保留的后续工作，不应因本轮常规用例通过而从项目差异列表删除。
