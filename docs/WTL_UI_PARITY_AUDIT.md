> 2026-09-21 补充：相关功能已在 XP SP3 / Win7 SP1 虚拟机中执行回归。覆盖项、修复和未覆盖边界见 [虚拟机验证记录](XP_WIN7_VM_VALIDATION.md)。下文保留原日期的历史结论。

日期：2026-09-16。审计代码基线：`bceb648`。

后续实施已开始修复本文列出的缺口。本文保留审计时的基线，当前实现与验证边界见
[按建议顺序恢复界面的记录](WTL_UI_RECOVERY.md)，不要将下文的基线缺口直接视为现状。

## 结论

**当前不能认定全部界面结构与逻辑均与原版伪代码一致。**

WTL 10.01 已实际用于消息循环、窗口绑定、原生列表、属性页、菜单跟踪和
ActiveX 宿主。接入并未自动恢复原版应用的全部窗口关系、绘制和业务状态机。
现状是：已恢复并验证多项原版行为，仍有明确缺口，同时保留用户指定的扩展。

需要分别判断三件事：

1. **库是否实际接入**：是；不是只有头文件依赖。
2. **可见窗口结构和交互是否完全等价**：否，查找窗口等仍有明确差异。
3. **原版 C++ 类继承、成员布局是否逐项重建**：没有；当前使用适配层。
   私有对象布局不同本身不等于用户可见功能有问题。

本次是静态源码与伪代码审计，结合已有专项验证记录；没有修改生产逻辑，
也没有在本次重新执行历史测试。以下结论不表示已穷举全部窗口和所有消息组合。

## 1. WTL 实际承担的工作

| 部分 | 当前实现 | 与原版的关系 |
| --- | --- | --- |
| 消息循环 | `PlayerMessageLoop`、`CMessageFilter`、`CAppModule` | `004B54F2` 排除的五类消息已对应。WTL 默认未排除 `WM_TIMER`，当前覆写已补上。 |
| 五个播放器窗口 | 主窗口、播放列表、歌词、均衡器、可视化分别绑定 `WindowBinding<PlayerWindow>` | 每个 HWND 有独立 ATL 绑定，业务共享 `PlayerWindow`；原有处理函数仍负责消息语义，不是原私有类层次的逐类复刻。 |
| 播放列表两栏 | `CWindowImpl<..., CListViewCtrl>`，以 `SysListView32` 为基础 | 对应 `00425DEC`、`00482BAF`。原生默认消息、模型状态投影和皮肤绘制共同工作。 |
| 对话框与属性页 | `CDialogImpl`、`CPropertySheetImpl`、`CPropertyPageImpl` 适配资源回调 | 保留资源模块、SDK 回调结果及销毁时机；页面业务仍在原重建回调内。 |
| 弹出菜单 | 定制 `CCommandBarCtrlImpl`、`CDynamicUpdateUI` | WTL 管跟踪与钩子，自绘和动态命令交回播放器。临时命令栏及嵌套原生回退是当前架构，不等同于恢复原对象图。 |
| 媒体库树 | `CTreeViewCtrl` | 只封装树控件；扫描、分类、查询、监视和持久化由重建业务实现。 |
| 上传浏览器 | `CAxWindow` | 已迁移 ActiveX 宿主；外层窗口与页面填充、导航逻辑仍由应用处理。 |

主要代码：`include/ttplayer/ui/wtl_runtime.h`、`wtl_window.h`，
`src/app/application.cpp`，`src/ui/wtl_dialogs.cpp`、`wtl_menu.cpp`、
`player_window_playlist_native.cpp`。

桌面歌词仍用三个 Win32 窗口过程；关联、颜色配置、转换配置等部分对话框仍调用
`DialogBoxParamW`。这种混用不能单独作为缺陷证据：ATL／WTL 本来就建立在 Win32
之上，应比较窗口所有者、样式、消息返回值、绘制和实际交互。

## 3. 当前代码可直接确认的缺口

### 3.1 歌词保存选项尚未完整驱动运行时行为

原版 `0044A6E6` 同时检查普通歌词文档的修改标记和 RichEdit 的 `EM_GETMODIFY`，
读取 `LyricSaveMode`，决定不保存、询问或直接保存，并按文档类型发送 `0x8022`
或 `0x8031`。成功后的相应分支还检查 `AutoSaveLyricTag` 并调用 `0044C708`。

当前 `lyric_save_mode`、`auto_save_lyric_tag` 的引用仅见配置读写、选项初始化及
控件提交。`PlayerWindow::LeaveLyricEditor` 根据调用参数 `prompt_to_save` 决定
是否询问，没有读取该保存模式；普通显示模式的修改也未完整接入离开文档的保存流程。

因此，选项能显示和持久化，不能证明所选策略已经生效。这是业务逻辑缺口，
不是 WTL 默认绘制造成的问题。

代码：`src/ui/player_window_lyrics.cpp:2699`，
`src/ui/player_window_options.cpp:4520`、`:5252`，
`src/settings/settings.cpp:1146`。详细边界见 [歌词菜单恢复](LYRIC_MENU_RECOVERY.md)。

### 3.2 播放列表查找窗口结构不同

原版 `00486056 → 0048ABBD` 设置普通／快速模式标志，调用
`DialogBoxParamW(..., 0xCB, ...)`，即资源 **203** 的专用对话框。

当前 `ShowPlaylistFindDialog(bool quick)` 的两种入口均调用 `FindTextW`，使用
系统非模态查找框；快速标志只参与重建后的搜索行为。即使部分匹配规则和失败提示
已经恢复，对话框模板、控件以及消息循环入口仍明确不同。焦点、输入更新和关闭
行为应沿原专用对话框继续核对，不能仅换成 WTL 的查找框包装就认定等价。

代码：`src/ui/player_window_playlist.cpp:4830`。

### 3.3 转换按钮尚未使用原版共享绘制规则

选项按钮已经恢复 `0046E0C9` 的间距、状态和相关主题绘制。
但 `InstallConvertBitmap` 仍设置 `BCM_SETIMAGELIST`，左右边距固定为 3，带文字
时左对齐；未使用该原版图文排版实现。因此不能将选项按钮的像素验证推广到转换
配置／进度按钮。应先核对原版对应按钮的安装调用，再复用已恢复的规则。

代码：`src/ui/playlist_transforms.cpp:62`。见 [转换恢复的边界](CONVERSION_RECOVERY.md)。

### 3.4 网络菜单及 URL 设置没有完整后端

`HandleLegacyPlaylistNetworkCommand` 恢复了曲目筛选及部分报告对话框，但 FreeDB、
下载和报告提交最终进入后端不可用提示，没有执行原私有服务工作流。

URL 播放使用 Media Foundation；原 netacc 的代理、缓存、边听边下载等完整链路
未恢复。这里不能扩大成“代理全部失效”：歌词搜索与歌词 HTTP 实现确实读取代理配置；
缺口是播放器 URL 来源及对应的旧网络功能。

代码：`src/ui/player_window_playlist_network.cpp:113`、
`src/audio/audio_engine.cpp:250`、`src/lyrics/online_search.cpp:104`、
`src/lyrics/lyric_http.cpp:65`。见 [主要功能恢复第 8 节](MAJOR_FEATURE_RECOVERY.md)。

### 3.5 播放中的内嵌歌词写入路径不同

原版 `004AD25D` 可取得正在使用的 reader；当前 `WriteEmbeddedLyrics` 另外调用
`OpenReaderForMetadata`。若播放中的只读句柄拒绝另一写句柄，操作会失败。
现有代码保留播放状态，并不代表已恢复原共享 reader 的全部写入能力。

代码：`src/ui/player_window_lyrics.cpp:3154`。这同时影响菜单操作结果与保存策略，
需要结合音频 reader 的所有权和调用线程处理，不能只调整 UI 启用状态。

## 4. 应保留的有意差异

这些差异不应在“恢复原版”时擅自回退：

- 按用户指定，普通版不超过 5000 首时采用三轮后台随机索引，超过时单轮循环；
  XP／Win7 版始终单轮循环。原版单索引越界重建规则不同。
- 单曲循环下手动上一首／下一首首尾相接，是用户指定行为。
- 任务栏专辑封面预览、全屏封面／歌词拖动、歌词服务列表编辑等扩展。
- 元信息、插件与设备探测的隔离执行，以及现代文件选择器。
- 转换使用协作暂停和成功后提交临时输出，避免原直接删除目标造成失败时丢失文件。

见 [随机播放规则](RANDOM_PLAYBACK_ROUNDS.md)、[播放导航](PLAYBACK_NAVIGATION_FIXES.md)、
[WTL 接入范围](WTL_10_01_MIGRATION.md)。

## 5. 已有验证能证明什么

- 最近选项修复记录覆盖 15 个外层页面，歌词／网络子页切换、保留编辑、隐藏页提交
  及关闭重开。旧审计表中的按钮、常规页箭头和网络子页问题已由该文末后续修复处理。
- 选项按钮对照记录为 24 个实例 × 2 种外观 × 4 种几何尺寸 × 5 种状态，
  **960／960 组 RGB 零差异**。它只证明这些按钮和输入状态；几何缩放没有切换
  系统 DPI 或字体，不能称作全界面高 DPI 验收。
- 先前普通版／兼容版的 WTL 和 UI 回归是在当前 Windows 宿主执行。
  静态导入审计及宿主运行均不能替代 XP／Win7 实机验证。
- 没有对所有界面的窗口树、所有者关系、Tab／Enter／Esc、嵌套菜单、异步回调、
  关闭重开和全部系统外观建立穷举对照，因此不应给出“全部完成”或百分比。

历史验证详见上述专项文档；本次没有新增测试代码或改变 Actions。

## 6. 建议后续顺序

1. **先补歌词保存策略及写标签链路**：以 `0044A6E6` 为入口，覆盖普通模式和编辑模式，
   明确换歌、关闭、保存失败时的状态处理，并核对共享 reader 的能力边界。
2. **恢复播放列表专用查找窗口**：从资源 203 和原消息处理器还原普通／快速模式，
   对照实时输入、无匹配、焦点、快捷键和关闭流程。
3. **扩展其它对话框的绘制核对**：从转换按钮开始，逐处确认原绘制调用，再复用已经
   验证的按钮实现；不因同样是按钮就全部套用。
4. **补跨窗口交互验收**：菜单和对话框嵌套、模式切换、窗口销毁后的异步结果、换肤，
   再在 XP／Win7 和真实 DPI 环境检查。
5. **单独处理旧网络功能边界**：区分缺失客户端实现与外部服务依赖；不能把有菜单、
   有设置或者显示失败提示当作功能恢复完成。

总体目标应是逐条恢复有证据的用户可见行为。把剩余 Win32 调用改写成 WTL 包装，
本身既不能补上上述业务缺口，也不能证明与原版一致。
