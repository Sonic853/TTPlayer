# 视觉对照测试主动中止修复

日期：2026-09-27。

## 崩溃证据

Win7 Application 事件 1000 记录的程序是：

```text
C:\TTPlayerTray\baidu-effects-20260927\baidu_visual_parity.exe
异常：40000015
模块：C:\Windows\syswow64\msvcrt.dll
偏移：0006683c
```

`0x40000015` 对应程序主动中止。本次弹框来自旧的本地视觉对照测试程序，不能作为播放器绘制代码发生访问越界的证据。

测试入口用 assert 检查 argc、DLL 加载和导出。当 VirtualBox MCP 把 EXE 路径再次放入第一个参数时，旧程序可能把它当作参考 DLL 目录，后续加载失败就执行断言中止。无参数启动也会直接触发断言。原事件没有保存源代码行号，因此不能仅凭事件确定当次命中了哪一条断言。

另外，测试调用 SoundCore 的固定内部偏移和 VisualEffect 的固定序号，原来没有先核对参考 DLL 的版本；对不匹配的 DLL 这样调用也不可靠。

## 修复

本次只修改本地 `tests/player_visual` 下的测试程序和构建配置，没有修改视觉效果算法：

- 识别并去掉 MCP 重复的 EXE 参数。
- 参数不足时打印用法并返回 64，不触发断言或 Windows 故障报告。
- DLL 不存在或版本不符时返回 65；用 SHA256 锁定已分析的 VisualEffect、SoundCore、ttpcomm 样本。
- 将参考目录转换为绝对路径，按该目录查找 DLL 依赖，修复相对路径启动时加载失败。
- 加载失败显示 Windows 错误码；内部测试条件失败返回文字诊断。
- 捕获测试中参考 DLL 的访问违例、非法指令及 C++ 异常，保留非零退出码，不把失败伪装为通过。
- 默认使用与发行程序相同的 XP 兼容运行库策略，并复制启动所需的 ttpcomm.dll 到测试输出目录。

新构建名称统一为 `player_visual_parity.exe`。XP、Win7 虚拟机中的旧报错对话框已处理；旧测试调用路径也更新为相同修复二进制，避免旧脚本继续启动有问题的副本。

## 验证

本机、XP、Win7 均通过两种初始化顺序：效果先初始化、频谱先初始化。
每种顺序通过 880 组帧/尺寸 RGB 对照和 96 组配色/透明度/尺寸对照；重建频谱与参考频谱输出的不同项为 0。

输出中的 `FFT: 57 differing bins` 是两个原始音频组件之间的历史比较结果；用于判定重建实现的 `Native FFT` 为 0，不将两者混为同一结论。

无参数、缺少参考 DLL 的情况现在返回明确错误，不弹“已停止工作”。通过 VirtualBox MCP 的正常调用同时验证了重复 EXE 参数处理。

测试源码、构建及诊断文件保留在本地 `rebuild/tests`，没有上传，没有加入 Action，也没有放入发行包。
