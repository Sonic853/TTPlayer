# 空列表歌词与播放失败提示恢复

## 结论

这两处缺失均来自 UI 状态和绘制分支，与 `CreateFile2` 兼容问题无关。

- 空列表时，原版歌词窗口显示资源中的播放器名称和版本。本地原版实际显示为 **千千静听 5.7 正式版**。
- 文件无法打开时，原版在主窗口信息区显示 **无法打开 - 文件无效或不存在**，状态区显示 **状态: 无效**。该分支没有消息框。
- 错误信息停止滚动，5 秒后恢复默认信息并清空状态；允许失败后继续播放时，另一个定时器在 3 秒后请求下一首。

依据为 `../reverse/decompiled/TTPlayer.exe.pseudo.c`，以下函数名保留反编译入口地址。说明中的字段名称是根据调用关系整理的语义名称，不把反编译器的寄存器临时变量当成真实 C++ 参数。

## 一、空列表歌词

### 原版控制流程

| 入口 | 与问题相关的行为 |
|---|---|
| `0044A0E8` | 清理歌词；没有当前歌词对应歌曲时，将 `DAT_00547500` 写入 LyricCtrl；有歌曲时写入 `004AE7FD` 得到的显示名称。 |
| `0045CA57` | 主窗口没有当前播放项时，恢复默认标题和信息，同时调用上述歌词恢复流程。 |
| `00441C7E` | 无歌词行且无提示项时调用 `0043FB27`；有歌词行时才调用歌词绘制器和边缘渐隐函数。 |
| `0043FB27` | 读取窗口文字，用控件 `+0x84` 的普通文字颜色、完整客户区矩形执行 DrawText。高亮色位于 `+0x88`，此路径不使用它。 |

原版将横向滚动设置转换为内部 `+0x6c == 0`。此时 DrawText 基础标志为 `0x821`，文字横向居中，TextAlign 决定上、中、下对齐；纵向模式基础标志为 `0x824`，文字纵向居中，TextAlign 决定左、中、右对齐。

`00441C7E` 将 `004416E0` 的边缘渐隐放在“有歌词行”的分支内部。默认标题和无歌词曲名不应被渐隐。

### 默认字符串不能混用

在隔离目录复制并运行原版 EXE、ttpcomm.dll、ttpres.dll，使用空播放列表枚举窗口：

```text
TTPlayer_PlayerWnd       千千静听 5.7 正式版
  MultiLabel            千千静听 5.7 正式版
TTPlayer_LyricWnd
  LyricCtrl             千千静听 5.7 正式版
```

这一结果与资源 `0x80`（名称）和 `0x8299`（版本）的组合一致。桌面歌词另走 `0044A0E8 → 004170B3`，使用 `0x80 + 空格 + 0x86`，即 **千千静听 尽听精彩**。

### 重建版的问题与修复

旧绘制条件是 `lyrics_.lines.empty() && PlaybackTrackForUi()`，没有歌曲时两个绘制分支均不执行；控件创建、ClearLyrics 和 RefreshPlaybackUi 也分别写入空字符串。

现在以 `DefaultPlayerTitle()` 和 `LyricFallbackText()` 统一默认文字来源，在控件创建时立即写入，并在清理和 UI 刷新时保持一致。无歌词分支使用普通文字颜色、完整客户区、原版轴向对齐规则；边缘渐隐只处理有时间轴的歌词。桌面歌词保留自己的默认标语。

## 二、播放错误

### 原版不是弹窗分支

`0045AD86` 从播放器 `+0x4350` 所指对象的 `+0x50` 取得错误码。其错误分支可整理为：

```cpp
reason = Resource(MapError(reader_result, is_network));
ResetScrollingInfo();                 // 004092CC
SetWindowText(info_hwnd, reason);      // player + 0x1a04
SetWindowText(status_hwnd, "状态: 无效"); // resource 0x8285
SetTimer(player_hwnd, 0x10, 5000);
MarkItemInvalid();
ReleaseSoundAndPlayingItem();
if (continuation_enabled && !StopWhenFail)
    SetTimer(player_hwnd, 0x0b, 3000);
```

| 错误码 / 条件 | 资源 ID | 原版中文 |
|---|---|---|
| `0x8004006F` | `0x8290` | 无法获得网络资源 |
| `0x80040070` | `0x828F` | 无法连接到网络媒体 |
| `0x80040071` | `0x8291` | 无法打开网络媒体 |
| 其他网络源错误 | `0x8291` | 无法打开网络媒体 |
| 其他本地文件错误 | `0x828E` | 无法打开 - 文件无效或不存在 |

原版实测：在隔离目录通过命令行打开损坏 WAV，启动后第 2 秒，主窗口 MultiLabel 显示上述本地错误，LabelCtrl 显示“状态: 无效”，没有错误消息框；第 8 秒，MultiLabel 已恢复版本标题、状态为空。提示计时从解码失败开始，而不是从进程启动开始。

`0046010E` 收到错误恢复定时器 `0x10` 后，先检查是否已有新的声音对象。如果没有，则用 `DAT_00547500` 恢复默认信息，清空状态字符串。收到失败跳曲定时器时，先取消该定时器，再投递 `0x7EC` 播放继续消息。

### 重建版的问题与修复

旧版只在 `report_error && StopWhenFail` 时打开消息框，没有更新信息区；允许继续播放时，又在下一个 250 毫秒 UI tick 立即跳曲，错误原因无法稳定呈现。

修复后：

1. 所有播放请求共用内嵌错误提示，删除仅控制弹窗的 `report_error` 参数。
2. 错误说明进入主窗口信息队列，暂停其三种滚动定时器；换肤重建信息时保留有效错误。
3. 恢复 5 秒提示、3 秒失败跳曲两个独立定时器，`StopWhenFail` 只控制跳曲。
4. 提示状态与音频引擎的 `failed` 状态分开，避免 5 秒后被周期刷新重新写成“无效”。
5. 已打开的解码器随后发生读取错误时，只在失败转换处显示一次提示。
6. 新播放请求、切换播放项、停止、关闭都会取消旧提示和待跳曲状态；通过提示起始时间校验，防止队列中残留的旧定时器消息提前结束新提示。
7. 为解码源和 AudioEngine 保留类型化 HRESULT；私有 reader 和 Media Foundation 的错误码随诊断传递。UI 不解析英文错误文本。

## 三、验证与分发

新增 `tests/ui/idle_error_tests.cpp`，使用独立临时运行目录和真正的 PlayerWindow，避免修改用户配置、皮肤配置和播放列表。验证内容：

- 空列表初次创建、启动恢复、周期刷新、清空列表后的歌词文字。
- 普通与迷你模式，横向/纵向、左中右/上中下对齐；逐像素比较普通颜色、矩形裁剪及无边缘渐隐的结果。
- 有歌曲但无歌词时的曲名显示；桌面歌词默认标语。
- 损坏 WAV、缺失文件的主窗口原因和状态；提示期间重建信息、滚动保持暂停。
- 5 秒恢复且不重复提示；3 秒前保持错误歌曲、到期后播放有效 WAV；新的成功播放不会被旧提示覆盖。
- 模拟异步 reader HRESULT，验证状态转换、停止取消和手动重试。

相关回归还包括 `runtime_paths_tests`、`fullscreen_lyric_render_tests`、`lyric_menu_tests`，覆盖启动路径、透明全屏歌词及歌词菜单。

普通 Release 和 XP/Win7 兼容包均重新构建；兼容包仍执行 XP/Win7 完整静态导入检查。本次运行测试的宿主是当前 Windows，没有声称已在真实 XP/Win7 系统运行。兼容检查详情以包内 `legacy-imports.json` 和 `SHA256SUMS.txt` 为准。
