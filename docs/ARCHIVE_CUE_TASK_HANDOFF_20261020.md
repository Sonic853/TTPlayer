# 实际 RAR：CUE 任务交接、信息复用与缓存修复

日期：2026-10-20。前置分析：[实际 RAR 样本审计](ARCHIVE_REAL_RAR_SAMPLE_AUDIT_20261019.md)第 7、8 节。

## 1. 样本与原版依据

继续使用用户提供的 RAR5，以及按相同成员、目录结构和内容生成的 RAR4。二者包含同一份约 491 MiB 的整轨 PCM WAV、12 轨 CUE 和封面，没有修改原包及包内文件。

- RAR5 SHA-256：`487915a68df9c453342274688be737dd21cd9be9605aeb349acc90e0885336cf`。
- RAR4 SHA-256：`09bb967139a64a1bb0019003028f2fcea65276f77133d9741ec762b9de8a5377`。

原版 5.7.9 证据沿用前置审计，原版 EXE SHA-256 为 `c7999ea5823469c1684148cac1bd196009824348ccac5cdd45978f8fb574e28c`：

- `004DFDED` 复用当前成员任务；`004C4CA8` 等待所需前缀，而非每次等全成员。
- `004E323B` 读取 CUE 并分别换算起止位置；`004E2F69` 使用 `MulDiv(frame, 1000, 75)`。
- 原版实际导入该 RAR4 为 12 个 CUE 子轨加整轨 WAV，拒绝该 RAR5。

本轮与已保存的原版函数实测结果对照，不将新增重建版测试称为重新运行原版。RAR5、可等待远端定位、64 位范围和只读保护继续保留。

## 2. 修复内容

### 2.1 进行中的整轨任务交接

新增播放会话级 `ArchivePlaybackSession`，持有独立取消上下文的归档消费者。下一曲明确引用同一 WAV 时，先保留该消费者，再停止旧解码器；新解码器接管后释放旧引用。

接入普通重开、WaveOut／WASAPI 串行淡出和 DirectSound successor 路径。通过已校验的 CUE 快照解析目标，不能因为两轨来自同一 CUE 就假设引用同一音频；明确 FILE 与备用候选不同的情形采用保守策略。

WAV 前缀一旦打开就向引擎登记任务，不必等待 CUE 远端位置可读。因此末轨仍在打开／等待解压时，切回前面的子轨也能交接同一任务。

真正 Stop、取消待切曲和错误清理会释放会话。源析构先释放解码器和普通流，再释放独立消费者，使最后消费者能取消未完成任务。播放线程在引擎锁内再次检查 Stop，防止停止完成后重新发布解压任务。

### 2.2 前台验证结果回填列表

新增有界的进程内 WAV 信息缓存。只有整成员 CRC 成功且已读取完整 WAV 信息，才发布最终格式、整轨时长和标签。

播放列表协调线程先查询缓存，再决定是否启动隔离信息进程。CUE 行由明确引用的整轨信息与 CUE 端点推导，不另开 WAV 解压流。待验证令牌覆盖“进度到 100% 至最终信息发布”的间隙；取消或任务放弃会清除令牌。

最多 32 项、总信息 4 MiB、单项 1 MiB，不保存封面。插件、MPEG 标签策略和不确定的 CUE 候选继续走原隔离信息路径。

### 2.3 目录、CUE 和图片缓存

身份包括全部实际分卷的文件标识、大小、修改／创建／变更时间，以及密码和分卷映射会话代数。手选替代分卷后，如果原路径重新出现，旧身份也失效。

- 小成员总预算 16 MiB、单项最多 4 MiB、最多 128 项。
- 目录总预算 4 MiB，归档身份最多 32 组。
- 命中仅检查已知文件身份，不再次枚举或解压归档。
- 取消、CRC／密码失败不保存结果；相同密码 IPC 包不会反复使缓存失效。
- 小文件仍使用 `cache=false`，不淘汰当前大音频任务。
- 封面仍在音频 CRC 完成后按需读取，内嵌封面优先。

### 2.4 短 CUE 晚到的校验错误

短子轨结束后，当前引擎仍拥有归档会话，直到用户停止或换到其他成员。尾部 CRC 失败可通过源错误接口和引擎 `State`／`LastErrorResult` 报告，不因子轨已返回 EOF 而丢失。

真正 Stop 取消并清除该会话。旧会话错误不会在换到其他音频后归到新曲目上；损坏成员的信息不进入已验证缓存。

### 2.5 CUE 毫秒显示

`CueFrameToMilliseconds` 按最近毫秒分别换算端点再相减，并避免乘法溢出。播放源、CUE 信息和文件信息进程使用同一规则。

实际样本第 2、3、10 轨恢复为 258627、184907、251014 ms，末轨仍为 173307 ms。定位、裁剪仍按 CD frame／采样帧计算；测试直接对照 WAV 相应位置的 PCM 字节。

私有测试程序须与播放器一样，将 `ttpcomm.dll` 作为启动依赖，链接 ordinal 3 并保留 `__imp__srand48`。XP 仅用 LoadLibrary 加载含静态 TLS 的 DLL，会使测试的线程状态失真。初次分卷映射失败来自私有测试装配遗漏；补正后通过。播放器已有此启动配置，无须为此修改产品逻辑。最终旧系统验收采用补正后的程序。

## 4. 性能与保留的边界

Windows 11 完成测试装配补正后的 14 组实际样本测量：RAR4 即时重叠切第二轨约 611 ms、显式交接约 632 ms；RAR5 约 161／163 ms，均复用同一任务，约 11% 时已有第二轨 PCM。前置审计的 RAR4 重叠切换约 7.7～8.4 秒且等到 100%。RAR4／RAR5 第一轨首段 PCM 分别约 22.49／13.64 ms。

已缓存 CUE、目录和封面合计读取约 0.53 ms，此时大 WAV 仍在 0%。这是未清空系统文件缓存的本机诊断测量，不是冷启动或声卡首音的性能承诺。

首次直接跳第 12 轨仍需顺序产生约 94% 的 WAV 数据；缓存不能消除压缩格式本身的要求。当前仍使用大成员临时文件，不是几秒音频的环形缓冲。

其他边界：

- 未将所有插件元数据改为跨进程共享，不确定的 CUE 备用候选不强行复用。
- 不改动 UnRAR 全局锁，不新增压缩包写回。
- 未测量冷磁盘缓存、物理内存峰值或听觉首音。
- DirectSound 会话传递已作代码路径审阅；实际输出交接验证以静音 WaveOut 为准，不声称所有输出设备均已实机测试。
