# 播放列表失焦滚轮与底部滚动边界

> 2026-09-21 补充：相关功能已在 XP SP3 / Win7 SP1 虚拟机中执行回归。覆盖项、修复和未覆盖边界见 [虚拟机验证记录](XP_WIN7_VM_VALIDATION.md)。下文保留原日期的历史结论。

日期：2026-09-16。修复列表失去键盘焦点后的滚轮响应，以及滚到底时末行位置、底部留白与原版不一致的问题。

## 原版伪代码依据

工作区 `../reverse/decompiled/TTPlayer.exe.pseudo.c`：

| 地址 | 核对结果 |
| --- | --- |
| `00482BAF` | 分别创建 `PlayLists`、`Files`，样式为 `0x50015205`、`0x50015001`；媒体库使用独立的 `LibraryTree`。 |
| `00425DEC` | ListCtrl 包装器明确指定基础窗口类 `SysListView32`。原版的列表有原生控件滚轮处理。 |
| `0047B218 → 0041D32C` | 已核对的列表消息映射没有“滚轮必须先取得键盘焦点”的判断；未处理消息继续走原生控件过程。 |
| `0042D982 → 0042DA95` | 标签编辑包装器收到 `WM_MOUSEWHEEL (0x20A)` 时关闭编辑窗口、使列表失效，并将 handled 置零，允许后续处理滚轮。 |
| `00449DA8` | 主窗口消息过滤先处理编辑器/对话框、快捷键和提示；这段代码没有按鼠标位置转发到播放列表的专用分支。 |
| `00460D1D` | 主窗口自身的滚轮分支调整音量，不是曲目列表滚动。 |
| `0041CB83` | 通过 `LVM_GETTOPINDEX (0x1027)`、`LVM_GETITEMRECT (0x100E)` 查询原生列表的首行和行矩形，用于列表边界命中。 |
| `0041D05C` | 拖动图像相关处理同样查询原生列表首行和行矩形，没有另设一套“向上取整页数”的底部范围。 |

因此，不能把原版描述为“用全局鼠标钩子强制滚动任何后台列表”。原版这部分依赖原生列表控件
以及系统的消息派发。重建版使用自绘 ListCtrl，必须补齐对应输入路由，不能只复制控件样式。

## 失焦滚轮的原因与修复

1. `PreTranslateMessage` 没有把发给其他本线程控件的滚轮转交鼠标下的列表。
   键盘焦点位于主窗口、编辑框或另一个面板时，列表的滚轮处理可能根本不执行。
2. `HandlePlaylistMessage` 用“鼠标在目录区 **或者** 焦点属于目录区”判定滚动目录。
   因而焦点还在左侧目录、鼠标已经移到右侧曲目时，仍可能滚动目录，曲目区看起来没有响应。

对应修复：

- 在消息过滤入口仅处理 `WM_MOUSEWHEEL`，使用其 `lParam` 中带符号的屏幕坐标命中实际窗口。
- 根据命中位置选择曲目、目录、原生媒体库树或经典 LISTBOX；转发一次后消费原消息。
  原消息已发给目标控件时直接正常派发，避免滚动两次。
- 曲目区与目录区按鼠标位置优先判断，键盘焦点不再覆盖鼠标所在面板。
  指针位于两区之外时保留原接收控件的后备处理。
- 子控件转交滚轮时保留接收 HWND 和屏幕坐标，不套用按钮消息的客户区坐标转换。
- 不调用 `SetFocus`、`SetActiveWindow` 或 `SetForegroundWindow`；保留输入焦点、选择和播放状态。
- 隐藏、禁用、被其他窗口遮挡的列表不接收额外转发；模态禁用和鼠标捕获也不被绕过。

本次路由处理应用收到的消息，不安装跨进程鼠标钩子，不修改系统的非活动窗口滚动设置。
整个应用在后台时是否能收到滚轮，仍由 Windows 的输入派发决定；不能将本次修复解释为
在 XP／Win7 上强制截取其他应用收到的滚轮。

## 滚动到底时位置不一致的原因与修复

原版使用 `SysListView32`，完整页行数和最后一页的位置由系统控件处理。伪代码确定了控件类型及其调用关系，
不能据此声称在原版 EXE 中找到了系统控件内部的页数公式。因此另建同样式的真实 ListView，实测
`LVM_GETCOUNTPERPAGE`、`LVM_GETTOPINDEX`、`LVM_GETITEMRECT` 和 `WM_VSCROLL/SB_BOTTOM` 作为对照。

问题出在 `MakePlaylistGeometry`：原来用向上取整的 `visible_rows` 同时表示绘制行数和完整页行数。
列表高度不是 16 像素行高的整数倍时，底部半行也被计入整页，导致最大滚动位置少一行。

例如，80 首曲目、列表区域高 136 像素（8 行半）：

| 项目 | 修复前 | 原生控件与修复后 |
| --- | --- | --- |
| 完整页行数 | 9 | 8 |
| 滚到底后的首行（从 0 计数） | 71 | 72 |
| 最后一行的顶部／底部（相对列表客户区） | 128／144，底部被裁掉 8 像素 | 112／128，完整显示 |
| 最后一行下方留白 | 0 | 8 像素 |

修复将两种数量分开：

- `page_rows` 按完整行向下取整，用于滚动范围、滚动条显示和拖动、目录滚动、窗口缩放后的边界、
  选中曲目／播放曲目的完整显示以及翻页步长。
- `visible_rows` 继续向上取整，用于绘制、命中测试、提示和可见曲目的信息读取，保留底部半行。
- 自绘 ListCtrl 的 `LVM_GETCOUNTPERPAGE` 返回完整行数；`LVM_SETITEMCOUNT` 采用同样的范围收缩规则。
- `LVM_ENSUREVISIBLE` 区分是否允许部分可见：参数为 TRUE 时已露出的半行保持位置；FALSE 时将整行露出。

窗口正常最小尺寸由皮肤背景限制。对异常小于一行的列表区域，内部滚动仍保留至少一行的防护，
避免滚动到最后一项之后；此极小区域的防护不声称逐项复制原生控件的零整行页行为。

## 验证

新增 `playlist_wheel_tests`，使用真实 HWND、实际命中测试和生产消息过滤/滚动代码，
不需要原版资源、私有测试目录或音频设备。测试覆盖：

- 编辑框持有焦点时滚动曲目区；目录/曲目焦点与悬停区域交叉。
- 已正确寻址的滚轮只处理一次，直接子窗口消息也按悬停区域滚动。
- 焦点、激活窗口、多选状态、当前播放项保持稳定。
- 隐藏、禁用、模态窗口、遮挡、鼠标捕获及列表区域外的消息。
- 原生媒体库树和经典列表的失焦滚动。
- 6 种客户区高度（128、129、136、143、144、160 像素）× 5 种曲目数量（0、1、8、9、80），
  对照真实 ListView 的完整页数、底部首行和末行矩形。系统字体导致行高不同时，按行单位对应容量和矩形。
- 缩放／布局、曲目数量变化、滚轮到底、滚动条拖到底、选中行显示、允许／不允许半行可见，以及目录底部范围。

配置 `-DTTPLAYER_BUILD_WHEEL_TESTS=ON`，构建 `playlist_wheel_tests`，执行：

```powershell
ctest --test-dir <构建目录> -C Release -R '^playlist_wheel_tests$' --output-on-failure
```

测试保留在本地 `tests/`，不上传且不在 Actions 中执行。旧系统构建的本地测试在当前 Windows 主机上运行，
另外执行 XP SP3 / Win7 导入审计；不等同于旧系统实机验证。
