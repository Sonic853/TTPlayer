# 窗口层级与选项窗口

换肤后续修正见 [SKIN_REBIND_LIFECYCLE.md](SKIN_REBIND_LIFECYCLE.md)：主窗口须先结束
暂停重绘，再进入原生布局和附属窗口绑定，不能在临时清除 `WS_VISIBLE` 的中间状态同步层级。

## 原版依据与复现

本次对照 5.7.9 的 `reverse/decompiled/TTPlayer.exe.pseudo.c`，并在宿主机的
独立临时目录运行原版与重建版，使用默认皮肤和合成配置读取实际 HWND 的
owner、`WS_EX_TOPMOST`、可见性以及从前至后的 Z 顺序。没有读取用户播放列表、
播放音乐或改写用户配置；6.1.20 未用作非皮肤功能参考。

| 原版地址 | 本次相关行为 |
| --- | --- |
| 00467B9B | 按歌词、均衡器、播放列表的顺序创建附属窗口，最后显示的播放列表在均衡器前面。 |
| 004A3A66、00464B6C | 正常／迷你模式使用独立置顶开关，通过 `SetWindowPos` 的 `0x13` 操作调整窗口所属层级。 |
| 0044D3DC、0041964D | 歌词独立置顶，以及桌面歌词三个 HWND 的置顶处理。 |
| 0044F073、0046CD66 | 附属窗体从其它线程被激活时，对其 owner 发出 `HWND_TOP / 0x13` 请求；同线程切换及失活不执行该操作。 |
| 0045D531、00468BE7 | 创建以播放器为 owner 的非模态选项页，并提升选项窗口。 |

修复前确认的差异：

- 主窗口已置顶时打开选项，再取消主窗口置顶，原版选项随之回到普通层，重建版
  的选项仍为 `WS_EX_TOPMOST`。先前测试只检查七个播放器 HWND，漏掉了选项。
- 默认皮肤启动时，重建版把均衡器显示在播放列表前面，与原版相反。
- 固定按“播放列表、均衡器、歌词、对话框”逐个切换层级，会反转已有的兄弟窗口顺序。
- 单看置顶位不够：一个原先独立置顶的歌词窗口，在主窗口改为置顶后可能仍有
  正确的置顶位，却被放到了 owner 后面；窗口阴影引起的隐藏／再显示也可能触发此问题。
- 三种附属窗体缺少原版的跨线程激活 owner 处理。

## 修复方式

`ApplySkinWindowTopMost` 统一收集当前 UI 线程中的播放器窗口、桌面歌词，以及
owner 链属于播放器的带标题对话框。选项、文件信息、转换、查找以及嵌套选择框
使用其 owner 的有效置顶状态；普通／迷你歌词和桌面歌词保留各自独立设置。

先记录原来的层级和 Z 顺序，再按 owner 在前、同级窗口由后至前的顺序应用。
owner 发生层级变更时，即使子窗口置顶位没变也重新确认其位置，避免 owner 反而
遮住子窗口。无状态变更且顺序正常时不移动窗口。阴影、显示及模式重绑定后，
如果窗口确实落在 owner 后面，只将它放回 owner 正前方，不强制提到所有对话框前面。

重建版的异步隐藏／重绑定仍保留 `SWP_NOOWNERZORDER` 保护，显式同步遗留对话框；
不能简单将全部调用改成 `0x13`，那会重新引入异步迷你／桌面歌词转换时的相互降层问题。
但主窗口的置顶命令不是普通状态刷新：004A3A66 明确追加调用 0041964D。因此该命令
在完成状态同步后，额外按 `0x13` 调整桌面歌词组及其 owner；即使置顶位相同也执行，
恢复原版切换置顶时普通歌词与选项窗口的前后顺序。其它刷新不使用这一重排入口。
全屏绘制面、原生弹出菜单、提示气泡及 tooltip 不作为普通对话框强制继承层级。
没有新增持续抢占前台的定时器，也不修改用户保存的置顶开关或重建主窗体。

注意：原版在“主窗口不置顶、普通歌词独立置顶”时，选项也不置顶，可能被置顶歌词
遮挡。这是独立开关的既有语义，不应把选项无条件改成全局置顶。

## 回归范围

扩展 `src/ui/window_topmost_tests.cpp`：

- 真实选项窗口、其可见／隐藏嵌套对话框、歌词所属对话框的置顶继承。
- 打开选项时反复置顶／取消、切换皮肤、迷你模式、三种全屏返回，以及关闭按钮。
- 实际兄弟窗口顺序、可见附属窗口在 owner 前面、无变化时不重排。
- 使用另一个 GUI 线程的测试窗口，检查跨线程激活收到原版的 owner 层级请求，
  同线程切换／失活不提升 owner。User32 会把 `HWND_TOP` 解析为实际的插入位置，
  因此测试不将 WINDOWPOS 中的句柄硬编码为零。
- 原有普通／迷你独立开关、桌面歌词、隐藏／显示、阴影、最小化／恢复及设置应用回归。

全屏回归使用小尺寸绘制面验证 HWND 分离／恢复，不代表完整的多屏视觉截图对照；
嵌套选择框使用原生有标题 HWND 检验 ownership，不自动操作用户真实文件选择窗口。

循环测试必须像正式消息循环一样持续处理窗口消息。早期测试连续数秒只同步调用
窗口函数，没有处理消息队列；实测 `IsHungAppWindow` 在约 5 秒后变为真，系统的
挂起窗口接管会干扰 HWND 层级测量。测试已补充有界消息泵和未挂起断言，不通过
给正式程序添加额外置顶调用来掩盖测试环境问题。
