# 高规格 PCM 输出、处理与 Plugins-out 分析

日期：2026-10-20。

本轮实现高精度 PCM 和原样输出；按要求，Winamp 部分只分析 `Plugins-out` 的实际 DLL。未修改 `winamp_dsp.cpp`、插件注册表兼容层或这些 DLL，也未向它们试送高位深数据。

## 一、使用方式

进入 **选项 → 音频设备 → 处理模式**：

| 模式 | 行为 | 可选输出 |
| --- | --- | --- |
| 原版兼容，默认 | 保留原均衡器、环绕、SSRC、量化器和现有 Winamp PCM16 桥接 | 原有全部后端 |
| 高精度处理 | 双精度中间数据，现代 EQ／环绕，按设置重采样；设备量化前应用增益；Winamp 旁路 | WASAPI 共享／独占、ASIO、Kernel Streaming |
| 原样输出 | 保持源采样率、声道数和可表示精度；旁路 EQ、环绕、ReplayGain、SSRC、Winamp、音量／平衡、淡入淡出和抖动 | WASAPI 独占、ASIO、Kernel Streaming |

原样输出中的音量旁路也包括播放器的静音设置：该模式不通过改变样本实现音量控制。暂停和停止仍可用。需调整音量时使用高精度处理或外部设备控制。

配置保存为 `TTPlayer.xml` 的 `Device/@PcmMode`：0、1、2。缺失时为 0；越界值钳制为 0–2。切换模式不会清空旧的位深、抖动、重采样、插件或均衡器设置。设备页参数在重新打开输出后生效，当前流的模式固定到关闭。

高精度模式自动协商设备精度，不使用旧的“输出格式”位深下拉框。整数目标至少 24 个有效位；也允许 float32／float64。设备不支持时明确失败，不静默回退为 16 位。启用抖动后使用最终整数有效位上的 TPDF；旧的四种噪声整形选择仅用于原版兼容模式。

原样模式可以无损扩展容器，如 PCM16 到 PCM24，但禁止降低可表示精度、改变采样率或声道数。整数 PCM32 不能交给只保留约 24 位整数精度的 float32 端点。有限浮点的同宽输出保留原始字节，包括负零和最小次正规数；NaN／Inf 明确拒绝。

设备属性表增加模式、支持范围、Winamp 旁路、抖动和最近实际路径。支持的重采样选择扩充到 352800、384000、705600、768000 Hz；这些选择不代表任意声卡均能接受。

## 二、实际处理顺序

高精度路径：

```text
原格式解码 PCM（保留有效位与声道掩码）
  → double 半幅域（±0.5 对应外部 ±1）
  → ReplayGain 线性增益
  → 现代 10 段均衡器／环绕
  → 可选 SSRC
  → float64 全幅传输缓冲
  → 设备增益
  → 最终设备格式编码／整数舍入和可选 TPDF
```

中间 float64 缓冲不是一次整数再量化。启用效果时保留正常浮点 headroom，整数范围的削波只在最终编码发生。Winamp 不进入此路径。

原样路径：

```text
解码器原生 PCM → 保值格式协商 → 原样复制或保值容器转换 → 设备
```

该路径不绕经半幅 double，因此不会因 float64 次正规数先除以二而丢失最低有效信息。这里的“原样”以解码器交付的 PCM 为起点；不会把有损编码变为无损，也不证明硬件 DAC、驱动内部或外部混音没有处理。

WASAPI 共享模式仍经过系统混音器。属性表记录的是应用实际打开的流格式，并同时显示系统混音格式；它不是 DAC 的测量结果。

## 三、ttpcomm 与均衡器

新增音频服务通过已有 `ttpcomm_query_runtime(version=2)` 查询独立表。旧 ABI 1、67 个原始导出及 4 个扩展导出保持不变，原均衡器／环绕的 ordinal 103／104 实现也没有替换。

新服务包含：

- PCM8／16／24／32、有效位和 24-in-32、float32／64 最终编码。
- 每声道增益先于整数量化，最近偶数舍入，独立 PRNG 的 TPDF。
- 采样率自适应 FIR／FFT EQ，处理全部声道；参数切换逐帧交叉渐变。
- 按采样率分配的 16 ms 环绕延迟，不受旧 1024 样本上限影响。
- EOF 补齐并去除 FIR 群延迟，输出总帧数等于输入总帧数；定位 reset 清除历史和尾部。

内置现代 EQ／环绕支持 1–32 声道、1000–768000 Hz。现代环绕只混合前两个声道，其它声道通过 EQ；不宣称它逐样本复刻原版 Dolby 私有算法。

**现代 EQ 保持固定时间长度，但没有解决有限 FIR 的全部低频精度限制。** 32–64 Hz 频段设 +6 dB 时，48 Hz 实测约 +1.835 dB；44.1–384 kHz 的响应已基本一致，不再随高采样率持续变弱。如需窄低频更接近滑块目标，仍需更长滤长或另一种 EQ 设计。详见 `ttpcomm/docs/AUDIO_RUNTIME_ABI2.md`。

新 DLL 可继续服务原接口，但原版 EXE 不调用新音频表。**只向原版播放器替换 ttpcomm.dll，不会自动使原版整条音频链升级为上述新模式。**

## 四、三个输出后端

| 后端 | 本轮处理 | 边界 |
| --- | --- | --- |
| WASAPI | 完整 EXTENSIBLE 格式、有效位、声道掩码；最终编码在短渲染缓冲处完成 | 原样仅独占；共享可能由系统重采样 |
| ASIO | 浮点、大端／小端、16/18/20/24-in-32 驱动布局、逐声道编码 | 有效位容器按 ASIO 右对齐；多声道按索引映射，实际布线需核验 |
| Kernel Streaming | 独立高精度／保值格式候选，禁止新模式隐式丢声道或 16 位降级 | 实际 pin 必须接受目标格式；驱动可拒绝 |

WAVE EXTENSIBLE 的有效位在容器中左对齐，ASIO 的部分 Int32 类型需要右对齐，二者没有混用。

高精度 ASIO／KS 增益在最终编码前应用。它们仍保留现有后端的开头／暂停／停止过渡限制，没有将开头为零的过渡增益直接烘入长预填缓冲；因此不宣称所有后端的淡入淡出已统一。原样模式所有渐变均旁路。

WaveOut／DirectSound 继续用于原版兼容模式。MIDI 合成播放也要求原版兼容模式；本轮新模式针对解码后的 PCM。

## 五、Plugins-out 结论

完整哈希、入口、伪代码与指令证据见 [Plugins-out 分析](PLUGINS_OUT_HIRES_PCM_ANALYSIS_20261020.md)。

- CompWide、Dee、Enhancer、JammiX、SoftAmp、ViPER 明确要求 PCM16。
- DeFX、OctiMax 没有完整位深判断，但核心固定按 16 位读写，不能据此认定支持高位深。
- SuperEQ、NEQ 存在 24 位路径；Vinyl 存在 24／32 位整数路径，只能列为后续实测候选。
- 当前 SPS 0.36 的 PCM24 立体声右声道读写偏移错误，不能启用其 24 位分支。
- CompWide 的采样率字段截为 16 位；JammiX 拒绝 99 kHz 及以上。这些限制与位深独立。

“支持某种参数”与“该效果在高采样率正确生效”分开判断。本轮没有运行或修补这些插件。

## 七、构建和交付

- `ttpcomm` 与播放器仍独立构建。必须配套部署本轮新 `ttpcomm.dll`，不能只换 EXE。
- SDK 新增 `audio_api.h`／`audio_client.h`，同步更新快照清单。
- DLL 增加只读 RCDATA 504：音频 ABI 2、encoder/effects 能力。CI 下载和打包静态核验该资源，不执行测试 DLL。
- 如远端最新 TTPlayerComm 发行版尚未包含音频 ABI 2，播放器 Action 明确失败并要求先发布新版核心，避免生成缺少新功能的包。本轮没有推送或发布远端 Release。
- 本地配套程序、核心和通用发行包输出至 `rebuild/build/Release`；发行包不包含测试、源码、用户配置或 Plugins-out DLL。
