# 播放列表字体与音频设备表头恢复

日期：2026-09-29。

## 结论

两处问题均来自重建版实现遗漏：

- 播放列表仅改变绘制字体，绘制、命中与分页仍使用固定的 16 像素行高；用于键盘和滚动的原生列表还使用另一套 Tahoma 字体，强制向 16 像素校准。
- 音频设备属性表创建列时只有 `LVCF_WIDTH`，未设置 `LVCF_TEXT` 和列名，所以“属性”“值”为空。不是主题将文字绘制为背景色。

## 原版证据

伪代码来源：`../reverse/decompiled/TTPlayer.exe.pseudo.c`。必要的省略参数另以原始 EXE 字节及 `ttpres.dll` 字符串资源核实。

| 原版函数 | 实现与恢复依据 |
| --- | --- |
| `00482BAF` | 创建 `LibraryTree`、`PlayLists` 和 `Files`。后两者的样式为 `0x50015205`、`0x50015001`，使用报告列表及 owner-data 模式。 |
| `00425DEC` | ListCtrl 基类是 `SysListView32`，并非固定行高的自定义文本表格。 |
| `0048301E` | 全量应用、字体按钮 `0x40C` 等路径，从 `DAT_00547CC8` 的 LOGFONT 创建字体，保存到 `+0x594`，再向 `+0x4E8`、`+0x50C`、`+0x548` 三个控件应用字体。 |
| `004052D6` | 上述封装实际发送 `WM_SETFONT (0x30)`；字体变化交由原生控件处理。 |
| `0041D32C` | 列表消息包装不截断 `WM_SETFONT`，默认消息继续进入原生控件。 |
| `0041CB83`、`0041D05C` | 通过 `LVM_GETTOPINDEX`、`LVM_GETITEMRECT` 查询实际首行和行矩形。选中背景图片高度不决定列表行高。 |
| `00499498` | 音频设备页初始化 `0x428` 控件，即十进制 1064；拆分字符串资源并创建两列，宽度分别为 100、200。 |
| `004C1B58`、`00413585` | 资源列表拆分与插入列的公共封装。检查 `00499498` 原始指令确认资源参数为 `0x8156`，分隔符为 `0x7C`（竖线）；资源内容为“属性\|值”。 |
| `0049989D` | 设备选择改变后重新填写属性行；首行标签取 `0x813C`，后续标签按输出类型取 `0x812A`～`0x812D`。表头不是设备查询结果的一部分。 |

因此原版的规则是“选定字体 → 原生列表计算行高 → 按实际行矩形绘制和交互”。不能将一次默认字号测出的 16 像素作为所有字号的固定值，也不能把宋体某个字号在新系统测出的额外间距固定套用到 XP。

## 修复内容

### 字体与行高

1. 提取统一的 `PlaylistFontDescriptor`，绘制、原生列表和媒体库树使用同一份 LOGFONT 设置，包括字体名、正负高度、字重等。
2. 原生列表不再使用替代 Tahoma 字体。字体设置变化时执行 `WM_SETFONT`，以 `LVM_GETITEMRECT` 测量行高，并缓存到该控件状态。
3. 空列表测量时临时设置一个原生 owner-data 行，测量后恢复零行；不向歌曲模型添加虚假曲目，也不修改模型选择或缓存的曲目数。
4. `MakePlaylistGeometry` 接收实际行高。全部生产调用点同步更新，包括绘制、命中、评分位置、框选、拖动插入位置、提示矩形、重命名编辑框、滚动条和可见曲目信息读取范围。
5. `LVM_GETCOUNTPERPAGE`、`LVM_HITTEST`、`LVM_GETITEMRECT`、`LVM_SETITEMCOUNT`、`LVM_ENSUREVISIBLE` 和原生滚动状态回读使用一致的行高。完整页数仍向下取整；绘制数量包含底部半行。
6. 媒体库树在字体改变后及时更新；皮肤重建产生新树窗口时，即使字体设置未变，也将缓存字体应用到新窗口。

初始化前的 16 像素仅作为尚未创建列表 HWND 时的默认值；真实列表布局使用已测量的行高。皮肤的选中背景继续按行平铺，不将图片高度当作行高。

### 音频设备属性表

- 从原有本地化资源 `0x8156` 分别读取“属性”“值”，使用 `LVCF_TEXT | LVCF_WIDTH` 创建两列。
- 保留原版 100、200 的列宽和现有属性值查询路径。
- 表头初始化先于设备选择有效性判断。没有选中设备时保留表头、清除旧属性行，避免空表头或过期设备信息。

## 验证

测试代码与日志仅保留在本地 `tests/`，没有加入 Actions 或发行 ZIP。

### 新增回归

`options_drawing_tests --playlist-font-device` 使用真实窗口、原版资源，以及单独创建的原生 `SysListView32` 作为几何对照。覆盖：

- 宋体高度 `-13 → -24 → -36（粗体）→ +24 → -10 → -13`，包含放大、缩小、恢复字号和正高度。
- 空列表更改字体后添加歌曲；左右两栏的行矩形、完整页数、点击命中、滚轮及滚动到底部。
- 有歌曲时直接更改字体，保留歌曲多选、焦点、选择锚点和滚动位置。
- 媒体库树字体、重建控件后的字体重绑、大字号重命名框高度。
- 音频设备表头文字、列宽和取消设备选择后的刷新。

本机 Windows build 26200、XP 和 Win7 均通过新增回归。字体高度为 `-24`、测试列表客户区高 195 时：

| 环境 | 原生对照行高 | 重建版行高 | 完整页数 |
| --- | ---: | ---: | ---: |
| 本机 build 26200 | 28 | 28 | 6 |
| Win7 | 28 | 28 | 6 |
| XP | 25 | 25 | 7 |

这些数值是本次环境与字体的实测结果，不是生产代码中的常量。Windows 10 未另设独立环境进行运行验证。

### 相关回归与范围

- 本机、XP、Win7 的 `playlist_wheel_tests` 全部通过：六种客户区高度、五种曲目数量，以及失焦滚轮、分页、底部边界、滚动条拖动、EnsureVisible 和选择保持。
- 本机鼠标交互回归：与原生控件对比 154 个用例，差异为零；拖动边界、取消和禁用拖动检查通过。
- 本机播放列表重命名回归：默认皮肤及 LX-iPlay、空白点击、Enter、Esc、空名称、空白名称、焦点转移与持久化。
- XP、Win7 的失焦滚轮测试在用户登录后执行；最终 Release EXE 在两台虚拟机均通过 `--smoke-test`。
- 本次不宣称所有字体、DPI、主题和全部皮肤像素完全相同；恢复的是原版用实际原生字体度量驱动列表的机制。

本地证据目录：`tests/artifacts/playlist-font-device-20260929/`。发行输出目录：`build/Release/`。
