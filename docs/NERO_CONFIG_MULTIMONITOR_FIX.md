# Nero HE-AAC 配置窗口在左侧副屏被拉长

日期：2026-10-06

## 结论

这是旧 Nero `Aac.dll` 对负屏幕坐标的计算错误。副屏在主屏左侧、两个屏幕均为 100% 时即可触发，与 DPI 缩放比例不同无关。

修复前，原版播放器搭配原版 `ttp_aac.dll`、重建版播放器搭配重建 AAC 插件，都能在本机真实左侧副屏复现：正常窗口为 **602×406**，左屏变成 **1791×406**，右边界恰好被扩大到屏幕坐标 **24**。用户截图中的宽度不同，是因为配置窗口当时的横坐标不同。

重建版现在在调用编码器配置接口时兼容这项旧组件缺陷。恢复后的窗口及 25 个子控件的位置、尺寸，与原版在主屏上的正常布局一致。602×406 是本机测量结果，代码没有写死此尺寸。

## 原版调用链

| 模块 / 地址 | 行为 |
| --- | --- |
| `TTPlayer.exe!0047D9A4` | 读取转换窗口中选定的编码器，转到配置调用 |
| `TTPlayer.exe!004CD21E` | 获取编码器工厂，调用 vtable `+0x1C`，即 `Configure(HWND)`，最后释放接口 |
| 原版 `ttp_aac.dll!600035FB` | 检查父窗口，获取 Nero 配置接口，再调用其配置函数 |
| `Aac.dll!100130C4` | 初始化原生配置对话框，测量复选框文字，调整分组框和整个窗口大小 |
| `Aac.dll!10011F54` | 调整单个复选框大小，返回它的**屏幕右边界坐标** |

原宿主没有对 Nero 配置对话框执行额外的宽度计算。重建 `ttp_aac/src/nero.cpp` 的调用约定与原二进制一致：Nero 配置接口 GUID 为 `{F50907A0-C032-4935-A3E0-832003E44F06}`，slot 3 是只有 `this` 的调用，不能把父窗口另加为参数来解决布局问题。

分析依据包括原播放器、原 AAC 插件的伪代码，以及实际分发的 `Aac.dll` 反汇编和反编译结果。该 Nero DLL 的 SHA-256：

```text
e0aca6cae0e7464fdc4d139210046b920275417cabd47636af73ea3055d59626
```

## 为什么只在左侧副屏突出出现

`10011F54` 的步骤是：取文字、隐藏控件、测量文本、调整复选框宽高、重新显示，最后调用 `GetWindowRect` 返回 `rect.right`。宽度包含文本宽度、4 像素余量和系统菜单复选标记宽度。

`100130C4` 测量五个控件：`0x139B`、`0x1398`、`0x139C`、`0x13A8`、`0x139D`。其中包括隐藏或禁用状态的控件。原逻辑等价于：

```cpp
maxRight = max(0, check1.right, check2.right, check3.right,
                  check4.right, check5.right);
group.right  = max(group.right,  maxRight + 8);
dialog.right = max(dialog.right, maxRight + 24);
width = right - left;
```

主屏或右屏的控件右边界为正数，结果正常。左屏的五个右边界都为负数时，`maxRight` 错误地成为 0。于是分组框右边界变为 8，窗口右边界变为 24，形成大块横向空白。高度、左侧图片及大多数控件的位置并没有改变，符合报错截图。

本机复现中，窗口左边界为 `-1767`，错误宽度为 `24 - (-1767) = 1791`。正确计算需要保留真实的负数右边界。

## 修复实现

新增 `src/plugins/nero_config_layout.h/.cpp`，由 `PluginManager::ConfigureEncoder` 的局部作用域管理。

1. 配置调用期间安装当前 UI 线程的窗口消息钩子，观察 `WM_INITDIALOG`。Nero 可以在进入配置接口后才加载，因此在对话框创建时确认 `Aac.dll`，避免过早检测而漏掉修复。
2. 同时检查窗口类 `#32770`、模块实例 `Aac.dll`、分组框 `0x13B2`；只为匹配的对话框及分组框安装临时子类处理。
3. 在它们的 `WM_WINDOWPOSCHANGING` 中读取五个复选框的真实屏幕右边界。最大值从最小有符号数开始计算，不把负数截断为 0。
4. 仅当五个右边界全为负、请求保持位置不变、宽度正好符合上述错误公式、且高度保持不变时，替换该请求的宽度。分别保留分组框 8 像素、窗口 24 像素的原有余量。
5. 控件销毁时移除子类；配置接口返回时也清理仍存活的子类和线程钩子。支持同线程嵌套配置作用域。

宽度计算使用 64 位中间值并检查输出范围。原有字体测量、窗口定位、预设、参数、确定/取消返回值继续由 Nero 处理。没有修改旧 DLL 二进制，也没有增加系统注册表设置或全局钩子。

旧组件独立运行、或放回原版播放器后，仍保留它自身的布局缺陷；本次兼容处理位于重建版宿主。

## 实测结果

Windows 11，三个真实显示器均为 100%，工作区分别为：

- 主屏：`(0,0)-(1920,1170)`。
- 右屏：`(1920,0)-(3840,1170)`。
- 左屏：`(-1920,0)-(0,1170)`。

| 版本 / 位置 | 外框尺寸 | 结果 |
| --- | --- | --- |
| 原版播放器 + 原版 AAC 插件，主屏 | 602×406 | 正常基准 |
| 原版播放器 + 原版 AAC 插件，左屏 | 1791×406 | 复现旧组件错误 |
| 修复前重建版，左屏 | 1791×406 | 复现用户问题 |
| 修复后重建版，左屏 | 602×406 | 关闭、确定、取消三次均通过 |
| 修复后重建版，主屏 | 602×406 | 同上 |
| 修复后重建版，右屏 | 602×406 | 同上 |

三块屏幕上共 9 次打开 Nero 配置，窗口保持响应，返回后转换窗口正常恢复可操作状态。比较全部 25 个子控件相对于外框的位置和尺寸，三屏均与原版主屏基准完全相同；其中分组框恢复为 390×327。另检查靠近主屏原点的位置，以及左屏 APE、WMA 配置窗口的打开与关闭。

Release 构建成功，构建后的 XP／Win7 静态导入检查通过（20 个 DLL、714 个导入）。本轮没有重新进行 XP／Win7 虚拟机界面测试，也没有测试混合 DPI 或所有 Nero 语言版本；不将静态检查表述为这些场景的实机验证。

本地脚本、截图、控件矩形及日志位于 `tests/nero_dialog/`，没有加入发行包或 Action 测试流程。运行测试使用隔离程序副本及生成的短 WAV，不修改用户音频和原始插件文件。

## 使用

使用新构建的 `build/Release/TTPlayerRebuild.exe`，保留现有运行目录的 DLL 和 AddIn。此问题无需用户调整显示器位置或缩放比例。
