# FLAC 44.1 kHz／16 bit 播放噪声的分析与修正方案

后续状态：已按本分析完成实现及三系统验证，见 [FLAC 内 DTS 修复与验收](FLAC_DTS_IMPLEMENTATION_20261029.md)。以下保留最初分析阶段的结论与范围。

日期：2026-10-29。反馈仅为“有的文件播放沙沙声，FLAC Audio 44100 Hz 16 Bits 1.25 Mbps”，没有音频、声道数、播放器／插件版本、输出设备或效果设置。本轮进行源代码审查与离线构造验证，**没有将构造样本的原因直接认定为反馈文件的原因，也没有修改生产解码代码或发行包**。

## 参数能够说明什么

44.1 kHz／16 bit 是正常的 PCM 精度，不属于需要特殊高规格输出才能播放的格式。若为双声道，解压后的 PCM 码率为 `44100 × 16 × 2 = 1,411,200 bit/s`。1.25 Mbps 若表示十进制压缩码率，约为该值的 88.6%，本身并不非法；声道数尚未提供，不能默认它一定是双声道。

`ttp_flac/src/reader.cpp` 用文件总大小和时长估算码率，包含标签、封面等开销。高码率不等于位深声明错误、需要更大声卡带宽、一定损坏或一定含 DTS。不能按 1.25 Mbps 阈值选择解码器。

FLAC 无损还原编码前的 PCM 样本值；如果编码前这些值原本就承载压缩数据，FLAC 解压仍然会恢复这些数据。[Xiph 官方说明](https://www.xiph.org/flac/features.html)规定了无损还原、帧 CRC 和音频 MD5 的职责。DTS 承载在 FLAC 等无损 PCM 容器中的情形是实际存在的：[foobar2000 DTS 组件官方说明](https://www.foobar2000.org/components/view/foo_input_dts)明确列出 FLAC、WAV、WV、TAK。

## 已确认的兼容缺口

现有链路：

```text
FLAC 文件
  → ttp_flac / libFLAC 解压
  → Reader 声明 PCM16
  → PluginManager 判断已经是 PCM，不创建第二级 Decoder
  → 均衡器／音效／输出转换
```

三个相关入口：

- `ttp_flac/src/reader.cpp` 的 `metadata_callback`、`write_callback`、`Format`：返回 PCM，16-bit 样本按小端交错输出；libFLAC 的 int32 工作缓冲不代表返回 PCM32。
- `rebuild/src/plugins/plugin_manager.cpp` 的 `OpenReader`：只有格式不是 PCM／IEEE float 时才通过 `OpenDecoder` 接上解码器。
- `rebuild/src/audio/audio_engine.cpp` 的 DTS-WAV 检测与阻断只针对外层 WAVE 数据。当前没有在 FLAC 解压之后再检查压缩载荷的通用层。

所以“FLAC 里装着 DTS-CD 数据”时，FLAC 解码本身完全正确，但还缺一次 DTS 解码。将这些压缩比特直接当作音频采样，会把噪声送入后续链路。把文件改名为 `.dts` 也不能解决：文件外层仍然是合法 FLAC。

## 本轮实测

全部测试在 Windows 11 本机离线运行；不连接音频输出设备，不播放噪声。私有材料在 `rebuild/tests/flac_noise_issue_20261029`。宿主探针重新链接当前 `ttplayer_core`，并使用当前构建的插件和 ttpcomm。

| 组别 | 内容 | 实际结果 |
| --- | --- | --- |
| 8 组普通 FLAC | 44.1 kHz／16 bit，1／2／6／8 声道；正弦、全范围随机值、14 有效位随机值、正负极值、静音；512／1152／4096／16384 块大小，0／8／12 压缩等级 | 插件 PCM 与原始字节一致；宿主转换到 double 后精确一致；关闭效果的最终 PCM16 输出亦逐字节一致 |
| 4 组 DTS 载荷 FLAC | 16-bit 大／小端、14-bit 大／小端；由先前生成的 5.1 DTS 测试音频构造 | FLAC 解压正确，却按 2 声道 PCM 进入输出，缺口可复现 |
| 同一载荷的 WAVE 对照 | 与上述 FLAC 解压后的字节完全相同 | 被识别为 DTS，正确进入现有插件并输出 6 声道 |
| 2 组损坏输入 | FLAC 音频帧位翻转、末尾截断 | 返回失败，没有作为完整正常文件接受 |

14-bit little-endian DTS 载荷的构造 FLAC 估算码率约 **1.276 Mbps**，与反馈描述的码率处于相近区间，但这不是反馈文件的指纹，更不是根因证明。不能为了得到同一个显示码率调整判断阈值。

测试所用 FLAC DLL SHA-256：`21c799147723a50283e70676a99f299e018a1744f390556f75dae819a307dd69`。其与当前 `rebuild/build/Release/AddIn/ttp_flac.dll` 相同。完整 DLL、探针摘要和数值结果保存在私有 `results.json`。

这里确认了普通输入的基线和嵌套 DTS 的可复现缺口，**没有覆盖反馈者的声卡、DSP 插件、所有合法 FLAC 编码特性或其实际旧版本**。8 组普通文件通过不能证明所有普通 FLAC 都不存在其它问题。

## 推荐修正顺序

### 1. 无损解码后、任何 DSP 之前检测载荷

增加可复用的载荷识别逻辑，首先覆盖 DTS-CD 的 44.1／48 kHz、PCM16 双声道载体。只读原始字节，检测时不得先施加音量、ReplayGain、均衡器、重采样或 Winamp 效果，否则帧头和有效比特会被改变。

建议采用有上限的预读缓存，跨 Reader 分块保存未完成头部；16-bit BE／LE、14-bit BE／LE 均需支持。判定至少基于连续多个完整帧、相符的长度／采样率／声道参数及实际解码成功，不以单个同步字、文件名、标签或码率判定。普通 PCM 未命中时必须将所有预读字节原样回放。

预读上限及开头静音策略要明确，并记录“未探测到”与“数据不足”，不能把有限前缀探测写成能覆盖任意长静音或从任意位置开始的码流。已可靠识别的载荷必须在第一批音频送设备前接入正确解码器；插件缺失时明确停止并提示，不回退播放压缩噪声。

### 2. 复用 ttp_ac3dts，不复制 DTS 解码核心

对重建宿主，适合在 Reader 数据与 PCM 效果之间加通用解码后处理层；FLAC、APE、TAK 等可共用检测，实际解码仍使用现有 `ttp_ac3dts` Decoder ABI。低层帧探测可集中维护在共享代码／ttpcomm SDK，避免每种无损插件各抄一份解析器。

不能直接拿外层 FLAC 的“两声道”初始化 DTS 输出，否则可能被解码器按双声道处理。须先从可信 DTS 帧得到真实采样率、声道数和布局，并核验现有 Decoder 工厂的输出掩码及格式协商，再把真正的 PCM 交给音效和输出后端。

若同时要求原版 EXE 获得此能力，宿主后处理层本身无效，因为旧 EXE 不会调用新代码。可在 FLAC Reader 的播放打开路径中预探测，再以旧 ABI 声明 DTS 压缩格式并交付已解压的载荷，复用原宿主 Reader→Decoder 链。这个分支仍需独立验证延迟打开、格式查询、原解码器工厂与格式缓冲容量；不能仅替换 ttpcomm 就声称原版已支持。纯检测的共享实现应避免给独立 AddIn 新增必须安装的现代 DLL。

### 3. 同时解决定位、时长、结束和标签

- 保存外层 FLAC 标签、封面与文件属性，显示可补充 `FLAC / DTS`，扩展名仍保持 `.flac`。
- 内层 DTS 的声道和采样率用于真实输出；不能把外层载体时钟直接当作解码时钟。
- 特别是 14-bit 装包，外层 PCM 字节数与内层样本数的比例不能凭常数猜测。索引应记录 FLAC 解压字节／采样位置、DTS 帧边界与累计解码样本。
- 定位回退到有效帧边界，重置内层状态，完成必要预热并丢弃到目标样本。暂停、取消、重复 EOF、短读以及 CUE 起点均需处理。
- 检测只发生在原始数据阶段；成功后 ReplayGain、EQ、Winamp、SSRC 和音量作用于真正解码的 PCM。

### 4. 验收与噪声保护

验收矩阵应包括：普通 FLAC 前后 PCM 完全一致；偶然单个 DTS 同步字不误判；四种 DTS 装包；跨块帧头；开头静音；短文件；完整与截断尾帧；CUE／seek；缺插件；并发 Reader；XP／Win7／Win11。若采用原版兼容 Reader 路径，还需原版宿主实测。

对损坏 FLAC 保持 CRC 错误返回和输出长度校验。当前流式播放没有开启全文件 MD5 检验；完整性检查可独立增加，但必须考虑定位后无法建立全文件摘要的语义。MD5 检验不能识别“完整无损保存的 DTS 载荷”，所以不是该缺口的修复方法。

## 在没有用户文件时仍应保留的其它解释

| 可能来源 | 如何区分 | 修正方向 |
| --- | --- | --- |
| 实际使用旧插件／旧主程序 | 收集 EXE、ttp_flac、ttpcomm 版本和摘要 | 先复核是否已包含现有 PCM、多声道、输出格式修复 |
| Winamp 效果或增益设置导致失真 | 同文件关闭 DSP／EQ／环绕／ReplayGain 对照，保存阶段 PCM | 只修出错阶段，不改 FLAC 解码倍率 |
| 输出格式、驱动或缓冲欠载 | 对比 WaveOut／DirectSound／WASAPI；观察是否与负载、定位或设备切换相关 | 根据真实设备格式及写入日志修正协商、帧对齐或欠载恢复 |
| 文件本身录有底噪或已损坏 | 独立解码、完整性校验、不同播放器对照 | 区分文件内容、解码错误和输出错误，不能静默滤除内容 |
| 其它合法 FLAC 边界 | 有最短可复现片段后与 libFLAC 参考逐字节比较 | 按具体 frame／subframe 证据修正，不凭显示参数猜测 |

当前最少仍需知道：受影响文件的声道数、播放时声音是全程噪声还是叠加底噪、播放器及三个关键 DLL 版本、输出后端、是否启用音效，以及其它播放器是否正常。没有样本也能先按上述层次排查；但无法据此给这条未知文件 issue 下“已彻底修复”的结论。
