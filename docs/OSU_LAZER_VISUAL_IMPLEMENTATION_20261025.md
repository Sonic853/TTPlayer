## 后续更新：歌词视觉同屏的进退场渐变

### 原因与行为

全屏视觉与歌词分别由两个 HWND 绘制。DLL 的开场、退场只改变视觉画面，原有歌词动画定时器又仅在播放时刷新歌词，因此不能自动跟随视觉动画隐藏。

现为“节拍星环”和“星环lazer”的“歌词视觉同屏”增加歌词渐变：

- 开场开始后，歌词按约200ms的平滑曲线淡出，并在开场期间保持隐藏。
- DLL 报告开场结束后，歌词按约200ms淡入；根据实际动画状态判断结束，不另写一套动画时长。
- 退场开始时淡出，直至全屏窗口恢复前保持隐藏，避免最后一帧闪出歌词。
- 暂停或停止时照常执行；重复退出不重启渐变。切换效果、切换全屏模式、关闭开场选项、取消退出和恢复普通窗口后均清理或恢复透明度。
- 未开启进退场动画时歌词正常显示；缺少动画状态接口的旧插件不触发渐变。没有新增持久化设置，进退场默认关闭保持不变。

### 绘制与调度

叠加布局同时缩放预乘 RGB 和 alpha，通过原有 `UpdateLayeredWindow` 呈现，避免将 `SetLayeredWindowAttributes` 与逐像素透明窗口混用。分区布局将绘制内容混合到已有歌词背景色，隐藏文字时仍保留背景。

新增独立16ms定时器，不依赖音频进度或视觉FPS。XP软件渲染测试还复现了连续 `WM_PAINT` 延迟 `WM_TIMER` 的情况，因此在视觉帧绘制结束后也推进渐变，并呈现已更新的歌词帧。单次透明度变化限制为64/255，避免界面长时间阻塞后直接从全透明跳到全不透明；这种卡顿下渐变可能比200ms更长，实际流畅度仍取决于绘制速度。

动画状态仍由 `ttp_osu.dll` 提供，歌词合成在拥有歌词窗口的宿主完成。本次不改变DLL ABI，也无需重编插件。

### 验证与产物

私有 `tests/ui/osu_lyric_fade_tests.inc` 使用真实播放器窗口、皮肤和可选DLL，配合模拟音频状态验证：

- Windows 11、Win7、XP 均通过两种视觉 × 叠加/分区四组用例：暂停时开场淡出与恢复、停止时退场、重复退出、恢复普通窗口。

## 后续更新：共用全屏备用图片（2026-10-26）

“全屏显示 → 视觉全屏 → 备用图片”原先仅传入专辑背景效果，两种星环的异步图片加载器没有读取此设置。现将同一个 `AlbumFallbackImage` 设置接入“节拍星环”和“星环lazer”，适用于视觉全屏及歌词视觉同屏。

图片选择顺序为：歌曲提供的可解码封面/OSZ背景 → 用户配置的备用图片 → 原有场景背景色。损坏的歌曲图片也视为不可用；清空、丢失或损坏的备用图片不会残留上一张图片。进退场动画仍按各自场景的既有规则绘制。

实现位于宿主 `OsuVisualClient` 的资产加载线程：

- 复用已有WIC/GDI+图片解码和64MiB输入限制，支持中文路径；相对路径以EXE目录解析。
- 独立记录备用图片修订号，修改路径、文件大小或修改时间后重新加载；设置更新不会重新提交谱面节拍数据或播放开场动画。
- 图片解码完成后检查当前请求代次；快速更换歌曲、切换备用图片或清空设置时，过期任务不会覆盖新结果。
- 实际渲染继续由可选 `ttp_osu.dll` 完成，DLL和ABI均未改变，不新增配置项。

### 验证

Windows 11、Win7、XP均通过真实宿主窗口和DLL的两种视觉 × 两种全屏模式测试，覆盖无曲目/停止状态、暂停、歌曲封面优先、PNG、损坏图片、清空、文件缺失、中文相对路径、同路径替换、快速请求取消和停止后显示备用图。本机歌词进退场渐变回归通过。XP为CPU绘制，Win7运行Mesa/D3D并通过离屏CPU采样确认选图。

Win7的825×713画布还触发了stable原有的 `min(H, W×4/5)` 上下留黑布局。测试分别检查有效画布图片和黑边，没有为通过测试修改插件布局。测试以模拟音频状态驱动真实宿主，不涉及音频设备验证。
