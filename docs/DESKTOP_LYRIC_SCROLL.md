# 桌面歌词超长行滚动修复

2026-09-11。范围是 `DeskLrcPaintClass` 桌面歌词，不改变普通、迷你或全屏歌词窗口的滚动设置。

## 原版依据

对照 `reverse/decompiled/TTPlayer.exe.pseudo.c`：

- `00417B8B` 缓存当前及后续歌词行；`004B2B2E` 先测量完整字符串，再生成普通色/已播放色位图，宽度不受桌面歌词窗口限制。其横向留白为渲染倍率乘八，缩小后另加两侧各一个像素。
- `00417262` 得到当前行、开始/结束时间及已播放时间；第一句尚未开始时进度为零，最后一句按 60000 ms 处理。
- `00417342` 用 `MulDiv(完整位图宽度, 行内已播放时间, 行持续时间)` 算出完整歌词上的高亮分界。
- 同一函数在歌词超宽时使用窗口宽度的一半作为跟随点。超宽歌词不按居中、靠右或交错方式把开头移出窗口；这些对齐分支只处理能放进窗口的短句。
- 未启用卡拉 OK 时，仍计算同一个源图偏移，只是不再分成两种颜色。双行模式的下一句预览从源图零位置绘制，尚不滚动；当前行按奇偶索引交替占用上下行。

设完整位图宽度为 `T`，窗口宽度为 `V`，位图上的播放进度为 `P`，超宽行的源图偏移为：

```text
sourceX = clamp(P - floor(V / 2), 0, T - V)
highlightRight = P - sourceX
```

即句首停留 → 播放分界达到窗口中点后跟随 → 句尾到达右边界后停留。
不是匀速循环跑马灯，也不是把剩余歌词压缩进窗口。

## 原有问题与修复

此前 `BuildMask` 的位图就是窗口大小，直接按对齐方式 `DrawTextW`，未显示部分在缓存阶段已丢失。
`RenderLayered` 随播放时间只改变高亮裁切边界，`CompositeMask` 没有歌词源图位移。

现在按完整歌词宽度缓存单行 alpha mask，由独立的 `CalculateDesktopLyricViewport` 计算显示切片。
文字、渐变高亮、描边及阴影使用同一平移。每帧只遍历可见窗口区域，避免超长歌词每 30 ms 都遍历整行像素。
滚动位置直接由当前播放时间推导，暂停、前后跳转和换句不依赖累积的滚动偏移。
自动宽度达到 1000 像素上限后，超出部分继续按上述规则滚动。

## 验证

Release 构建成功；宿主机完整 CTest 回归 **25/25 通过**（55.07 秒）。

`tests/desktop_lyric_scroll_tests.cpp` 纳入现有 `desktop_lyrics_tests`：

- 检查开始跟随/停止跟随边界、奇数宽度、四种对齐以及恰好等宽。
- 只在测试进程内临时观察 `UpdateLayeredWindow`，读取实际提交给 Windows 的 DIB；不注入原版进程，不依赖屏幕截图或桌面遮挡。
- 用完整显示的歌词图像作为参照，逐像素检查窄窗口在句首、中段、句尾及回跳时的对应切片，包括描边/阴影。
- 用不同颜色检查高亮边界随文字平移，关闭高亮仍滚动。
- 检查双行预览不滚动、换句后行位置交替、LRC offset、最后一句 60 秒上限，以及超长中文/自动宽度。
- 运行真实 Windows 窗口及定时消息，验证播放时平滑更新、暂停后位置冻结。

本次依据伪代码恢复滚动及裁切逻辑。测试对比的是重建版完整图像与其显示切片，不声称已经与原版字体光栅化或所有桌面歌词样式逐像素一致。
