# PurpleMyth.skn 界面对照与恢复

日期：2026-09-27。

## 1. 对照对象与结论

对照仓库原版 TTPlayer 5.7.9、原版反编译伪代码，以及当前通用 x86 重建版。
皮肤名称为“炫紫神话”，作者 vivi，`Skin.xml` 版本 2。
原始文件 SHA-256：`b31784e0282c8b4c1a89b158919e480ebf7b461510b52f85102c2afb50d38b09`。

本次确认并修复四类问题：

1. 窗口歌词的右对齐按钮按 XML 区域宽度定位，导致位置错误；同时缺少原版的图片窗口区域，使置顶按钮的多余区域覆盖关闭按钮。
2. PurpleMyth 没有桌面歌词工具栏资源，重建版没有走原版的默认皮肤回退路径，出现背景、按钮图片缺失。
3. 空列表／停止状态下，主窗口停止按钮仍显示可用图像；原版根据播放状态显示第四帧禁用图像。
4. 读取的 `Lyric.DisplayMode` 没有应用到启动界面，运行中切换也没有同步保存值，导致重启后错误恢复为窗口歌词。

这些是通用皮肤加载和控件问题，修复不按 `PurpleMyth.skn` 文件名分支，也不修改皮肤包。

## 2. 先统一比较条件

皮肤有 `Skin.xml`、`Lyric.xml`、`Playlist.xml`、`Visual.xml`。主描述文件使用中文旧编码，其余描述文件使用 UTF-8。

原版和重建版均在独立测试目录运行。比较时固定相同的窗口尺寸、音量、可见状态、字体和颜色。
不能直接拿两个已有用户配置的截图判定皮肤解析失败：主 XML 和每皮肤 `.skn.xml` 都可能保存不同的外观设置。

## 4. 关闭按钮为何错位、为何只移动还不够

### 4.1 原版调用链

以 [TTPlayer.exe.pseudo.c](../../reverse/decompiled/TTPlayer.exe.pseudo.c) 为依据：

- `CSkinParser_ParseLyricWindow / 004A88D0` 读取歌词背景、缩放区、title、close、ontop、desklrc。
- `0044919C` 绑定各按钮图片，再通过 `004052F1` 按 XML 设置子窗口位置和大小。
- `004495C8` 在正常模式布局按钮，经 `0042912E` 取得图片单帧尺寸，传给 `0047A9C5` 计算对齐位置。
- 布局使用 `SetWindowPos(..., 0x15)`，即移动原点但不重设子窗口大小。
- `00452FFF → 0040A1DD` 为按钮安装按首帧和透明色生成的窗口区域。XML 矩形大于图片时，多余部分仍不能覆盖或接收相邻按钮输入。

### 4.2 PurpleMyth 的实际数值

关闭键声明 `(233,6)-(303,23)`，宽 70；置顶键声明 `(213,6)-(283,23)`，宽 70。
图片均为 68×15，横向四帧，单帧只有 **17×15**。

原版右对齐原点公式：

```text
x = XML.right - frameWidth + clientWidth - nativeWidth
```

在 310 像素宽的歌词窗口中：

- 关闭键 `x = 303 - 17 = 286`。
- 置顶键 `x = 283 - 17 = 266`。

旧实现得到 x=233 和 x=213。两个 70 像素宽的子窗口相互覆盖，而且没有首帧区域裁剪。
仅把 x 改对后，置顶子窗口仍延伸到关闭键的位置，实机截图仍缺少关闭键。

最终处理是同时恢复：**以单帧计算对齐原点、保留 XML 子窗口尺寸、以首帧透明区域约束绘制和命中**。
BMP 使用皮肤透明色；现有 PNG 扩展使用 alpha 覆盖区域，防止把不透明紫色误判为透明。
每次重新绑定皮肤重新设置区域，缺少图片时清掉旧区域。

相同的原版 SkinButton 绑定也用于均衡器，因此均衡器图片按钮复用同一恢复函数；不对滑块套用按钮四帧区域。

## 5. 桌面歌词工具栏回退

原版 `00449451` 调用 `004459CF` 检查皮肤 `+0x13B8` 的工具栏背景图片。
缺少背景时进入默认包加载路径，再由 `0041865A / 004186BC` 绑定背景、透明色、图标位置和各命令按钮。
`004A92A2` 是 `<desklrc_bar>` 解析入口。

因此，“没有 desklrc_bar”不表示“没有工具栏”。原版 PurpleMyth 实机显示的是默认工具栏。
旧重建版只保留默认按钮矩形，没有背景和按钮图片，造成透明的空工具栏／不可见按钮区域。

修复在加载外部皮肤时完成：

1. 检查实际加载的工具栏背景，而非只检查 XML 节点是否存在。
2. 缺少背景时读取资源 DLL 中 `<Default_Skin>`，复用已有解包缓存。
3. 只回退完整的 `DesktopLyricBarSkin`，不覆盖主窗口、歌词、列表配色和布局。
4. 图片使用共享所有权；临时默认皮肤销毁后，工具栏图片继续有效。
5. 已有有效自定义工具栏时不补入默认按钮，避免在作者故意留空的位置产生隐藏点击区域。

首个加载的就是外部皮肤时，也先记住资源模块，确保启动路径和运行中切换路径一致。

## 6. 停止按钮状态

`0045A04E` 根据播放对象状态启用命令 `0x7D02`，并同步 SkinButton。
无活动播放时禁用，正在打开、播放或暂停时可用。

旧 `IsSkinElementEnabled("stop")` 固定返回 true，PurpleMyth 的可用／禁用帧颜色差异明显。
修复后停止、失败状态绘制第四帧，活动状态恢复普通／悬停／按下帧；普通和迷你主窗口共用这条规则。

## 7. 桌面歌词模式保存与重启恢复

实机使用相同的 `Lyric.DisplayMode="1"` 配置启动时，原版进入桌面歌词，旧重建版仍显示窗口歌词。
检查发现设置读写层已经支持 DisplayMode，但 UI 没有消费该字段，Enter／Leave 也只修改运行时布尔值。

原版 `0044A91F` 更新全局显示模式 `DAT_00547B24`；`0044D434` 进入桌面歌词、`0044D48D` 返回窗口歌词都调用它。
CSettings 的 Lyric 读写分支序列化 `DisplayMode`。模式、窗口位置和当前模式的歌词可见性分别保存，不能互相替代。

修复后：

- 成功进入桌面歌词时同步保存值为 1，返回窗口时同步为 0。
- 启动时先应用普通／迷你模式对应的窗口位置，再按 DisplayMode 选择歌词表面。
- 恢复时保留 `LyricVisible`／`LyricVisible2`：上次隐藏桌面歌词，重启仍隐藏；不会因为复用“显示桌面歌词”命令而强制显示。
- 明确点击“返回窗口模式”仍显示窗口歌词，这是用户命令原有的行为。
- 窗口销毁只清理运行时状态，不把已保存的桌面模式误写成窗口模式。
