# TTPlayer 5.0.1 个人版文字及 5.0.1／5.7.9 版本显示

分析日期：2026-10-10。

## 结论与可直接使用的配置

`D:\Program Files (x86)\TTPlayer501\TTPlayer.exe` 已有个人版功能。
在它实际读取的 `TTPlayer.xml` 的 **`<Player>` 元素上**增加以下两个属性即可：

```xml
UserWord="Sonic853"
UserWordMD5="0deb84040dd5c32227e2c13009792f0a"
```

层级示意（将属性合并到已有的 Player 元素，保留其它属性和配置节点）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<ttplayer version="5.0.1">
    <Player UserWord="Sonic853"
            UserWordMD5="0deb84040dd5c32227e2c13009792f0a" />
</ttplayer>
```

先完全退出播放器，再编辑并保存 XML，随后重新启动。不要新建第二个 Player
元素，也不要把两个属性放在 General、About 或根元素上。首次检查该安装目录时
没有 TTPlayer.xml；若仍没有，应先运行一次对应版本并正常退出以生成自己的配置。

生效后：

- 没有当前曲目时：`千千静听 5.0.1 Sonic853 个人版`。
- 选项 → 关于：大标题右侧显示 `Sonic853 个人版`。
- 播放曲目时，窗口标题按“曲目名称 - 千千静听 Sonic853 个人版”组成；
  托盘提示复用该完整标题。这条播放分支由静态代码确认，本次未播放音频验证。

“个人版”由资源自动追加，**UserWord 只填写个人名**。该设置不修改作者 nanling、
程序文件版本或“千千静听 - 选项”的窗口标题栏。皮肤自己的固定标题图案也不会改变。

## XML 读取与 Cookie 优先级

`00488932` 在 Player 节点读写 `UserWord` 与 `UserWordMD5`：

| 字段 | 设置对象偏移 | 本版本全局地址 |
| --- | --- | --- |
| UserWord | `+0xF0` | `004D54E0` |
| UserWordMD5 | `+0xF4` | `004D54E4` |
| 验证后个人版显示文字 | `+0xF8` | `004D54E8` |

启动路径 `0048F743` 先调用 `0040259C` 加载 XML，再调用 `0048EDC2`
验证个人名。`0040259C` 通过 `004017B5` 取得与可执行文件对应的 XML 路径；
本次测试改名后实际读写的是 TTPlayer501Probe.xml。

`0048EDC2` 首先通过 `0049134C` / `InternetGetCookieW` 读取本机保存的
`http://www.ttplayer.com` Cookie：

- `tt_s`：编码后的个人名。
- `tt_m`：校验字符串。

如果 `tt_m` 为空，回退到 XML 的两个属性；否则将 Cookie 对写回内存设置并采用它。
因此，旧的非空定制 Cookie 可能盖过 XML，即使其校验值无效。此处是读取本机
Cookie，不是联网请求定制服务器；通常不存在旧 Cookie 时，XML 即可独立生效。

MD5 为空或为特殊值 `0000000000000000`（16 个零）时，返回空的个人名。
校验失败也返回空字符串，不显示个人版字样。

## 姓名编码与校验算法

### 普通名字

设 `B` 为个人名的 GBK 字节，名字不包含需要转义的反斜杠字节时：

```text
UserWord    = URL 百分号编码(B)
UserWordMD5 = 小写十六进制(MD5(B + ASCII("tt#$(@#*$!2")))
```

注意固定串是 `tt#$(@#*$!2`，没有末尾右括号。姓名大小写、空格都参与计算。
MD5 不包含字符串结尾 NUL，也不包含“个人版”三个字。

| 原始名字 | UserWord | UserWordMD5 |
| --- | --- | --- |
| xxx | `xxx` | `88ac44a8e632fdd880d989ef2d7f4df6` |
| Sonic853 | `Sonic853` | `0deb84040dd5c32227e2c13009792f0a` |
| nanling | `nanling` | `026ce93229024ad8508ea42527577d47` |
| 小明 | `%D0%A1%C3%F7` | `817d2e1502bfb584abc7a5bc3ad77d38` |

**改名字必须重算 MD5。中文名字使用 GBK，不是 UTF-8 百分号编码。**
XML 文件本身仍可保存为 UTF-8；属性中的百分号编码都是 ASCII。

### 关键调用证据

1. `0040172E(..., 0)`：将 UserWord 和 UserWordMD5 从 Unicode 转为系统 ANSI。
2. `004911F5`：解析 `%XX`，将 `+` 还原为空格。因此字面加号必须写为 `%2B`。
3. `004BF2A4`：固定 UTF-16 字符串 `tt#$(@#*$!2`。
4. `0048EA37` / `0048EB01` / `0048EBB5`：通过 `_bstr_t` 构造及连接，将
   URL 解码后的姓名与固定串组合，再转回 ANSI 字节。
5. `0048EFE0`：调用 ttpcomm.dll ordinal 400 生成 MD5 十六进制。
6. `0048EFEB` 调用 `00408794`，内部 `_mbslwr` **转成小写**；
   `0048EFF7` 使用 `_mbscmp` 与配置值比较，区分大小写。
7. 校验成功才调用 `004912C9` 去掉反斜杠转义，随后
   `00405F9C(..., 0x3A8)` 按 **CP936 / GBK** 转为最终 Unicode 姓名。

直接调用本版本 ttpcomm.dll ordinal 400 得到大写摘要；真正要求小写的是
EXE 在比较前执行的转换，不能只根据 DLL 的输出格式填写 XML。

### 反斜杠与字符范围

`004912C9` 按字节去掉反斜杠转义，不是只处理 UTF-16 的反斜杠字符。
如需保留字节 `0x5C`，应先把它写成两个 `0x5C`，再 URL 编码；
MD5 对这份**转义后、URL 解码后**的数据加固定串计算。
这也适用于 GBK 双字节字符中出现 `0x5C` 的情况。

该老实现最终固定用 CP936，不能把任意 Unicode / emoji 都当作可支持名字。
校验中间还经过系统 ANSI 与 BSTR 转换；本次中文实测为本机中文环境，
其它系统 ANSI 代码页的往返兼容性未逐一验证。

以下 Python 示例会打印配置属性，不修改安装目录：

```python
import hashlib
from urllib.parse import quote_from_bytes

name = "Sonic853"  # 改为自己的名字，不附加“个人版”
raw = name.encode("gbk").replace(b"\\", b"\\\\")
word = quote_from_bytes(raw, safe="")
md5 = hashlib.md5(raw + b"tt#$(@#*$!2").hexdigest()
print(f'UserWord="{word}" UserWordMD5="{md5}"')
```

## 补充：5.0.1 与 5.7.9 的空值和版本文字显示

补充日期：2026-10-10。这里的“空值”指 `<Player>` 的 `UserWord` / `UserWordMD5`，
不是根节点的 `version`。5.7.9 使用仓库根目录原版 EXE 和配套 ttpres.dll；
5.0.1 使用上述安装目录样本。以下地址均为对应 EXE 的虚拟地址。

### 1. 不填写个人版配置时，实际显示什么

在没有有效个人版 Cookie 覆盖 XML 的前提下：

| 位置或数据 | 原版 5.0.1 | 原版 5.7.9 |
| --- | --- | --- |
| 默认程序标题 | `千千静听 5.0.1` | `千千静听 5.7 正式版` |
| 关于页大字程序名称 | `千千静听` | `千千静听` |
| 关于页程序名右侧的个人版区域 | 空白 | 空白 |
| 关于页“版本”控件写入的完整文字 | `5.0.1 (Unicode)` | `5.7 正式版 (Unicode)` |
| 关于页作者 | `nanling` | `nanling` |
| EXE 的固定文件／产品版本 | `5.0.1.0` | `5.7.9.0` |

**个人版为空，不会抹掉程序版本，也不会自动变成“nanling 个人版”“XXX 个人版”或“社区版”。**
作者、个人版署名、程序版本是三个不同来源。关于页版本控件宽度有限，实际皮肤／字体／系统
下可能裁掉尾部；上表“完整文字”是 `SetDlgItemTextW` 写入的内容，不保证每个字符都可见。

还需区分这些情况：

- 两个属性都省略、都为空、校验失败：个人版显示串为空。
- 只填姓名、不填 MD5：不能通过校验，不显示个人版。
- 姓名最终解码为空：即使为其提供相符的校验值，也不会拼接“个人版”。
- XML 为空，但旧 Cookie 中仍有有效姓名及校验值：仍可能显示 Cookie 对应的个人版。
  5.0.1 查询 `http://www.ttplayer.com`，5.7.9 查询 `http://www.qianqian.com`；
  两版的键名均为 `tt_s` / `tt_m`。非空 `tt_m` 优先于 XML，随后才做验证。
- 校验值为特殊的 **16 个零** `0000000000000000` 时，走空个人版分支。

入口对应为 5.0.1 `0048EDC2 → 0048F743`，5.7.9 `004BFDCD → 004C0900`。
这里只分析读取现存本地 Cookie 的行为，没有连接这些历史网站。

### 2. 为什么 5.7.9 界面不一定出现“5.7.9”

原版至少分开维护以下三种文字／数值：

| 用途 | 5.0.1 来源 | 5.7.9 来源 |
| --- | --- | --- |
| 程序名 | ttpres.dll 字符串 `0x80`：千千静听 | 同左 |
| 界面显示版本 | EXE `004B800C`：`5.0.1` | ttpres.dll 字符串 `0x8299`：`5.7 正式版` |
| 精确程序版本 | 字面量 `5.0.1`、数值 `0x50001`、PE 版本资源 | 字面量 `5.7.9`、数值 `0x50709`、PE 版本资源 |

初始化时，5.0.1 `0048F5E5` 和 5.7.9 `004C077E` 使用同一个格式 `%s %s`
组成“程序名 + 空格 + 显示版本”。前者直接压入 `5.0.1`，后者先读取资源 `0x8299`。
可选个人版串校验成功且非空后，才追加到默认标题末尾。

| 全局字符串的含义 | 5.0.1 | 5.7.9 |
| --- | --- | --- |
| 程序名 | `004D51E0` | `005474FC` |
| 默认完整标题 | `004D51E4` | `00547500` |
| 可选的“姓名 个人版” | `004D54E8` | `00547880` |

例如配置有效的 Sonic853 后，默认标题分别成为：

```text
千千静听 5.0.1 Sonic853 个人版
千千静听 5.7 正式版 Sonic853 个人版
```

这不是从 `<ttplayer version="...">` 直接复制来的。XML 根节点的版本用于记录配置版本、
比较和迁移；修改这个属性不能把运行中的程序版本改成任意文字，反而可能影响旧配置迁移判断。

### 3. 已追踪到的版本显示位置及条件

以下清单覆盖两份 EXE 中默认标题全局、精确版本字符串的直接引用，以及其继续传递到的
标题、托盘、歌词和对话框。第三方皮肤自行画进位图的字样、插件自己的版本不属于这一清单。

| 位置 | 何时显示版本 | 何时不显示／限制 |
| --- | --- | --- |
| 主窗口皮肤内的曲目信息区 `0x7DD9` | 控件初建时使用默认完整标题；刷新时没有当前曲目，也恢复它 | 有当前曲目时显示曲目及配置的信息项；提示消息可能暂时覆盖。具体位置、宽度由皮肤决定 |
| 迷你模式中的同一类信息区 | 复用主窗口的信息状态；没有当前曲目时仍是默认完整标题 | 切换迷你模式本身不是切换版本文字的条件；还取决于迷你皮肤是否提供／显示该区域 |

| 系统托盘图标的鼠标悬停提示 | 图标存在且没有当前曲目时，提示使用默认完整标题 | 有当前曲目使用曲目标题。原版按 64 个 WCHAR 的缓冲上限复制，长署名可能被截断 |
| 窗口歌词的内容区 | 没有当前歌词对应的歌曲，且绘制分支没有歌词行、没有更优先的提示项时，显示默认完整标题 | 有歌曲但无歌词时显示曲目名；有歌词时绘制歌词；搜索等提示可遮住默认文字 |

| 点击关于页作者链接后，默认邮件的主题 | `mailto:%s?subject=About “%s”`，第二个参数为默认完整标题 | 作者链接表面仍显示 nanling；需点击并由可用的邮件程序处理才会在邮件窗口出现，播放器不会在这里直接发信 |
| 原版自己的未处理异常提示框标题及 `Application:` 段落 | 进入原版异常处理器时，使用默认完整标题，再加 Unicode 标识；正文还包含构建日期 | 不是普通播放失败路径，也不能等同于 Windows 自己弹出的“已停止工作”窗口 |

默认标题刷新主链：5.0.1 `0043D7FA`，5.7.9 `0045CA57`。
托盘提示提交：`004346A6` / `00451B82`，最终调用 `Shell_NotifyIconW(NIM_MODIFY)`。
主信息控件创建：`00443A65` / `00467B9B`。

其中最重要的判断可以整理为以下语义伪代码（变量名是本次整理，并非原始源代码）：

```cpp
track = explicitTrack ? explicitTrack : currentTrack;
if (!track) {
    windowCaption = defaultTitle;        // 包含版本；个人版可选
    trayTip = defaultTitle;
    skinInfo = defaultTitle;

    windowCaption = trackDisplay + L" - " + appName + L" " + personalEdition;
```

因此，**“播放列表为空”“停止播放”“没有当前曲目”不能当作同一个条件**：

- 列表里已有很多歌曲，但尚未设置当前曲目，仍可显示版本标题。
- 暂停或停止之后，只要当前曲目对象仍保留，就继续显示曲目信息。
- 仅切换左侧播放列表或删除某些条目，不必然释放当前正在播放的歌曲。
- 真正清掉当前曲目、随后刷新标题，才进入默认版本标题分支。
- 有歌曲但没有 LRC，不代表应该显示程序版本；歌词内容区的后备文字是该歌曲的显示名。

播放且开启任务栏文字滚动时，原版还会给曲目标题添加间隔并轮转文字；暂停、停止后恢复
完整的静态曲目标题。它不会因为停止了滚动，就自动追加／恢复程序版本。

### 4. 歌词窗口与桌面歌词不可混用

窗口歌词初始化及恢复：

| 行为 | 5.0.1 | 5.7.9 |
| --- | --- | --- |
| 创建 LyricCtrl，并写入默认完整标题 | `0042CF74` | `0044AD55` |
| 无歌曲写默认标题，有歌曲写歌曲显示名 | `0042C745` | `0044A0E8` |
| 无歌词的普通文字绘制器 | `0041E7DA` | `0043FB27` |

才取 LyricCtrl 的窗口文字绘制。因此“控件当前保存了默认标题”和“这一帧可见版本文字”
也不是完全相同的状态。

**5.7.9 的桌面歌词另走一条路径**：`0044A0E8 → 004170B3`。没有歌曲时拼接的是：

```text
资源 0x80 + 空格 + 资源 0x86
千千静听 尽听精彩
```

这里没有使用 `00547500`，没有版本号，也没有追加个人版姓名；有歌曲时改用歌曲显示名。
本次 5.0.1 样本的歌词创建和恢复代码没有 5.7.9 的 `DeskLrcCtrl` 分支，不能把后者的
桌面歌词行为反推为 5.0.1 已有实现。

### 5. 5.7.9 播放失败后，版本文字还有一个延迟恢复入口

`0045AD86` 的失败分支先显示错误原因和“状态: 无效”，设置：

```cpp
SetTimer(player, 0x10, 5000, nullptr); // 恢复信息区
// 条件允许时，另设 0x0B / 3000 ms 请求继续播放
```

`0046010E` 收到 `0x10` 后：

1. 撤销该一次性恢复计时器。
2. 如果已有新的声音对象，直接返回，避免盖掉新歌曲。
3. 否则清理信息滚动，用默认完整标题恢复皮肤信息控件，并清空状态文字。

**这一分支直接更新的是皮肤信息区和状态区，并没有在同一分支中调用主 HWND 标题或托盘
提示更新函数。** 不能据此声称失败后的每个标题位置都会在第 5 秒同步变化。

5.0.1 的默认标题直接引用和定时器代码中没有找到对应的 `0x10 / 5000 ms` 失败恢复路径；
5.7.9 的这条扩展行为不应标成两版共有。此处也不是“停止播放 5 秒后必定显示版本”。

### 6. 关于页资源中的占位文字为什么不会显示

实际读取两份 `ttpres.dll` 的对话框资源 200 后确认：

| 资源项 | 5.0.1 | 5.7.9 |
| --- | --- | --- |
| 个人版定位控件 | `0x3F4`，模板文字 `XXX 个人版` | `0x3FC`，模板文字 `XXX 个人版` |
| 个人版定位控件样式 | `0x40030000`，没有 `WS_VISIBLE` | 同左 |
| 程序名定位控件 | `0x3F1`，模板文字“千千静听”，隐藏 | 同左 |
| 实际版本值控件 | `0x3F3`，模板文字 `0.0` | 同左 |

程序名和个人版位置由隐藏控件提供矩形，再由 `WM_PAINT` 对应函数自行画字。
5.0.1 为 `0046AED8 → 0046AE43`，5.7.9 为 `0049227D → 004921CE`。
个人版字符串为空时，`DrawTextW` 得到空串，区域自然为空；不存在将作者名填入的回退。

版本控件则由 `0046AF92` / `00492337` 在关于页初始化时覆盖：
`0.0` 是资源设计时占位符，不是未配置个人版时的运行结果。

### 7. 精确版本还出现在哪里，但不是普通界面文字

| 位置 | 内容及条件 |
| --- | --- |
| Windows 文件属性 → 详细信息 | PE 版本资源给出 5.0.1.0 / 5.7.9.0，不受 Player 个性化设置影响；文本字段可能以逗号显示 |
| TTPlayer.xml、按皮肤保存的配置 | 写出／比较程序的精确版本，用于配置兼容迁移；不是界面版本文字来源。相关保存入口为 `00402A38` / `0040374B`，5.7.9 换肤迁移另见 `0045D5FA` |
| 原生播放列表 XML | 保存为该格式时，generator 使用 `TTPlayer -- 5.0.1` / `TTPlayer -- 5.7.9`；入口 `0044F99C` / `00475486`。两版根节点 `version="4"` 是播放列表格式版本，不是播放器 4.x |
| freedb 请求 | hello 字段包含客户端名 ttplayer 和精确版本；`0041756B` / `00438176`。与个人版显示无关 |
| 更新查询 | 保留实现使用数字版本与构建月日组成 `5.0.1.MMDD` / `5.7.9.MMDD`。不使用“5.7 正式版”进行数值比较 |
| 更新通知 | 通知入口 `00441022` / `00462D2A` 按返回版本、手动检查标志和 LastMessageVer 决定是否展示；内建标题为“最新版本／最新消息”，不是直接显示本地默认完整标题。通知正文是否出现具体版本，取决于服务端返回内容 |
| 异常报告／反馈邮件 | 异常对话框采用显示版本；诊断／邮件构造中还引用精确版本。此轮仅静态分析，没有触发崩溃或发送报告 |
| 进程间共享状态及模块检查 | 包含打包的数字版本值，供兼容判断。5.7.9 的部分模块 ABI 检查值 `0x50700` 不代表 UI 应显示 5.7.0 |

特别是本地 **5.7.9 样本的更新检查入口 `00458B9C` 首字节为 RET**：保留的联网更新代码
不能视为当前样本通过这个入口实际可达。详见
[原版更新器分析](ORIGINAL_UPDATER_ANALYSIS.md)。本轮没有尝试连接历史更新服务。

音频设备的驱动版本、编码器／音效插件版本、皮肤版本，以及歌曲标签里的版本文字，均是
各自数据来源，不能因为也叫“版本”就改成播放器版本。

## 2026-10-10 实施：日期构建版本与 5.7.9 显示条件

此阶段用户明确暂缓个人版，未增加 `UserWord` / Cookie 校验和个人版绘制；关于页现有
版本、作者及其它内容保持原样。仅统一播放器自身的构建版本，并修复没有当前曲目时
信息区残留旧曲名的问题。

### 版本来源与覆盖位置

`cmake/write_version.ps1` 在一次解析中生成 PE 版本资源及 `ttplayer/build_version.h`。
核心库通过 `ttplayer::build::Version()` / `VersionUtf8()` 读取相同值，避免 UI 再用
旧版资源或用完成日期重新拼接、丢失 `pN` 后缀。

- Action 继续传入既有 `TTPLAYER_BUILD_VERSION`，例如 `2026.10.02p1`。
- 未指定版本的本地构建使用北京时间日期，当前交付为 `2026.10.10`。
- 日期版本后不追加“正式版”。原版资源 `0x8299` 仅在关于页继续使用。

| 位置 | 修改后的来源及行为 |
| --- | --- |
| 普通／迷你主窗口的默认信息区 | 程序名 + 日期构建版本；由皮肤决定布局与截断 |
| 无当前曲目的主 HWND 标题、任务栏标题来源、托盘提示来源 | 使用相同的默认标题 |
| 无歌词对应歌曲的窗口歌词、迷你／全屏复用歌词控件 | 使用同一默认标题，仍服从歌词及提示文字的优先级 |
| 失败 5 秒后恢复的主窗口信息区 | 使用日期默认标题；失败消息、3 秒跳过与取消规则保持原有实现 |
| 选项 → 皮肤中的主窗口预览 | 使用资源程序名和相同日期版本，避免预览仍显示旧版文字 |
| 选项 → 关于 | 保留 `5.7 正式版 (Unicode)` 的既有写入逻辑，不替换版本资源 |
| EXE 文件／产品版本、更新器本地版本 | 继续使用日期版本；UI 与其共用构建输入 |
| 配置 XML 根节点 `version` | 新文件及已有配置再次保存时均写入当前构建版本 |
| 原生 XML 播放列表 `generator` | `TTPlayer -- 日期构建版本`；格式版本仍为 `4` |
| MusicBrainz 客户端标识 | 使用完整日期构建版本，包括 `pN` |

插件、驱动、皮肤自身的版本及格式／接口协议号属于其它对象，未替换成播放器构建号。
皮肤位图中固定画入的文字也不属于动态版本字符串。

### 恢复条件与原版对照

依据 `0045CA57`，判断依据是“是否仍有当前曲目”，不能只看是否停止播放：

1. **播放、暂停、停止但保留曲目**：继续显示歌曲名；不因停止而改成版本号。
2. **关闭当前文件或清除当前曲目**：同时恢复主窗口标题和皮肤信息区的默认标题。
   原实现仅刷新了部分状态，皮肤信息区可能残留旧曲名；现于 `RefreshPlaybackUi()`
   同步恢复，并在关闭文件命令结束时立即调用。
3. **有歌曲但无歌词**：窗口歌词显示歌曲名，而非程序版本。
4. **无歌曲的桌面歌词**：遵循 `0044A0E8`，继续显示“千千静听 尽听精彩”。
5. **播放失败**：遵循 `0045AD86 → 0046010E` 的错误文字与定时恢复；5 秒恢复只针对
   信息区，不把它扩展成所有标题同步切换。

### 本轮测试弹窗原因

`ttplayer_tests.exe` 曾在 `settings-roundtrip-advanced` 中断：旧断言要求读回
`https://freedb.test/`，但已实现的网络设置加载器会将旧 freedb 服务迁移到
`https://musicbrainz.org/ws/2/`。断言触发 CRT `abort`，继而出现 `0x40000015` 系统错误框；
不是播放器本体运行时发生的访问越界。

修复测试预期，并增加自定义服务器保存后不被迁移的检查。仅对本地测试程序设置断言输出
到标准错误、关闭 CRT/WER 交互报告；保留非零失败退出码，不吞掉测试失败。
已实际运行 `--verify-failure-reporting` 故意失败检查：立即写出日志并以退出码 `3`

### 配置和原版兼容

仅保存于已有 `<Player>` 属性：

```xml
<Player UserWord="Sonic853" UserWordMD5="0deb84040dd5c32227e2c13009792f0a" />
```

`personal_name` 只是运行时解码缓存，不写入 XML，没有新增 `PersonalName` 配置字段。
保存规则与前文分析一致：

1. 名称转为 CP936 / GBK 字节；反斜杠字节先加倍，包括双字节字符中的 `0x5C`。
2. URL 百分号编码后保存到 `UserWord`，字面加号使用 `%2B`。
3. 对“转义后字节 + `tt#$(@#*$!2`”计算 MD5，小写十六进制保存到 `UserWordMD5`。
4. 载入时先 URL 解码、校验，再去反斜杠转义并按 CP936 转成 Unicode。
   缺失、错误、非小写匹配的摘要及特殊 16 个零均不显示个人版。
5. 清空名称将两个字段同时设为空串；不会从浏览器 Cookie 恢复旧名称。

输入上限为 64 个 UTF-16 单元，并清理首尾空白、过滤控制字符。为避免保存后乱码或丢名，
CP936 无法准确表示的字符不替换成问号：保持先前有效名称，并在输入框下显示原因，
失去焦点时恢复先前值。名称全部来源于本地配置，无需联网。
