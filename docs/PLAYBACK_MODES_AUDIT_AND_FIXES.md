日期：2026-09-16。基准：工作区 TTPlayer 5.7.9.0，SHA-256：
`c7999ea5823469c1684148cac1bd196009824348ccac5cdd45978f8fb574e28c`。

## 1. 模式对照

以下“手动”指命令实际进入处理函数；按钮是否可点另见第 2 节。
自然结束表假定没有不同歌曲的“播放跟随光标”覆盖。

| 设置值／模式 | 手动上一首／下一首 | 自然结束，自动切换列表关闭 | 自然结束，自动切换列表开启 |
| --- | --- | --- | --- |
| 0 单曲播放 | 相邻项，命令首尾回绕 | 停止 | 停止 |
| 1 单曲循环 | 相邻项，命令首尾回绕 | 重播实际打开的歌曲 | 重播实际打开的歌曲 |
| 2 顺序播放 | 相邻项，命令首尾回绕 | 前进；列表末尾结束 | 列表末尾进入下个列表；整个目录末尾结束 |
| 3 循环播放 | 相邻项，首尾回绕 | 列表内循环 | 列表末尾进入下个列表；目录末尾回到开头 |
| 4 随机播放 | 在随机序列内前进／回退；越界时重建 | 完成本轮后重建下一轮 | 完成本轮后切换列表；目录末尾回到开头 |

- 空列表不会产生越界选曲。若解码器仍保有从列表移除的歌曲，原版在无自动换表时，
  单曲循环和顺序播放的空列表分支会重新播放该保留歌曲；修复保留此行为。
- 随机模式只有一首时，手动命令重新播放它；自然结束在关闭换表时重播，开启时换表。
- 自动换表从目标列表第 0 项开始，不恢复目标列表上次播放位置，不跳过空列表。
- 只有一个列表时，循环／随机允许换回自身并从第 0 项开始；顺序播放不回绕。

原版证据：`00465230`（上一首）、`0046528B`（下一首）、
`0045BD69`（自然结束）、`0045BF4B`（重播实际源）、`0047F5D6`（换表）。

## 2. 按钮状态与命令处理是两层规则

`0045A6xx` 的刷新代码另外判断按钮和菜单可用性：

| 状态 | 模式 0／1／2 | 模式 3／4 |
| --- | --- | --- |
| 空列表 | 上一首、下一首均不可用 | 均不可用 |
| 非空列表，尚无播放标记 | 上一首不可用，下一首可用 | 均可用 |
| 第一首 | 上一首不可用 | 上一首可用 |
| 最后一首 | 下一首不可用 | 下一首可用 |

因此不能把“命令内部支持回绕”解释为“单曲循环的首尾按钮始终可点”。
本次让皮肤、普通按钮、上下文菜单和任务栏控制使用同一判断，并用列表的播放标记
代替可能不一致的 `current_`。上一轮文档没有充分区分这两层，现予以更正。

**用户指定调整（2026-09-16）：**上表记录原版行为；重建版现将单曲循环（模式 1）
调整为非空列表的上一首、下一首始终可用。最后一首点击下一首回到第一首，第一首
点击上一首回到最后一首；只有一首时重新播放该曲，空列表仍禁用。此规则同步应用于
皮肤、普通按钮、上下文菜单和任务栏控件，切歌后保留单曲循环模式。

## 3. 随机播放恢复细节

### 原版的状态

`FUN_0045BBF6` 使用 PlayerWnd 中的一个序列，而不是每次独立抽取：

- `+0x4384`：歌曲行号数组。
- `+0x4388`：数组长度。
- `+0x4394`：序列游标。

`-1`／`1` 分别减／加游标，读取数组中对应的行号。游标越界或歌曲数量变化时重建。
重建从各行号组成排列，调用 `004725D6` 在指定范围内执行 Fisher–Yates 洗牌。
前进重建时把当前曲固定在开头，从其后开始；后退重建时把当前曲固定在末尾。

**原版的特殊边界：**清空序列后第一次“上一首”，或回退越过序列开头时，
重建后先返回末尾固定的当前曲，因此这一次会原地重播，下一次上一首才进入其余曲目。
不能为了让每次点击都换歌而省略该行为。

### 本次实现

新增 [RandomPlaybackOrder](../include/ttplayer/playlist/playback_order.h) 及
[实现](../src/playlist/playback_order.cpp)，由 PlayerWindow 持有一份，手动命令和
自然结束共享。移除了旧 `Playlist::Next/Previous` 中“每次抽取非当前项”的随机分支。

- 在列表不变、连续前进的一轮内，所有行号各出现一次。
- 在已有序列中上一首可以回退，之后下一首沿原序列前进。
- 不把普通列表的“随机排序”命令混入随机播放，两者相互独立。
- 数量变化时重建；与原版一样，纯粹修改标签或同数量排序不会因曲目身份比较而
  额外重建。序列保存行号，不是无限长度的实际播放历史。
- 主窗口／皮肤入口选择随机模式时清空序列，重选随机也清空（`004655FE`）；
  播放列表模式子菜单只赋值，保留序列（`00483AF8`）。
- 原版 `2000`／`2010` 请求用于初始化预览／查看下一项而不消费它。实现和测试
  保留该语义；本次未新增音频引擎的跨曲预解码链路。
- 洗牌仍使用现代随机数生成器，不承诺与原版按同一种子生成逐项相同的排列。

## 4. 跟随光标、播放来源与媒体库

### 跟随光标

`0047FCA6 → 0040EEBB` 用 `LVM_GETNEXTITEM(-1, 3)` 查找同时选中且有焦点的行。
处理时先按 `0x7F36` 清除选择，再决定是否覆盖通常的选曲。

- 手动上一首：不跟随。
- 手动下一首：五种模式均可跟随。
- 自然结束：单曲播放不跟随，其余四种可以跟随。
- 焦点未选中、行号无效或焦点已经是播放行：不跳转到该行，继续该模式的正常规则。

旧实现的媒体库自然结束缺少此逻辑，普通列表则误把未选中的光标也当成覆盖条件。
现在共用 `FollowPlaybackCursor()`。

### 当前列表与实际打开的歌曲

原版 `PlayerWnd +0x3294` 指向当前显示的列表；`0047F294` 在切换列表时替换它。
手动遍历及顺序／循环／随机的自然前进都读取该列表的 `+0x1C`。
单曲循环的 `0045BF4B` 则重播解码器实际持有的歌曲。

本次分别保留导航上下文和实际播放所有者，修复切到另一个列表后仍按旧列表遍历的问题。
媒体库 `0048A38E` 在查询重建后通过 `0047FC21` 把正在播放的歌曲映射到查询行号。
因此导航按当前显示的查询顺序进行，并按歌曲身份定位播放行，不盲用旧快照行号。

### 媒体库自动切换

`0047F5D6` 的媒体库分支使用 `TVGN_CARET → TVGN_NEXTVISIBLE`；找到目标后先展开
再选择。允许回绕时使用 `TVGN_FIRSTVISIBLE`。这不是“下一位歌手”或“下一个非空叶子”。

新增 `SwitchMediaLibraryCatalogue()`，恢复上述可见节点遍历。空分类会成为目标，
不会错误重播上一首。当前可见节点顺序取决于树的展开状态和滚动位置，保留原版规则。

## 5. 其他关联修复

- 自动换表不再因目标等于当前列表而直接停止。
- 选到空目标时不调用会回退到旧 `opened_track_` 的播放路径，避免错误重播。
- 歌曲间隔等待前即发布选中的播放标记；等待期间再按下一首，不再用旧标记重选同一首。
- 五种自然结束处理使用一个实现，普通列表与媒体库不再维护两套逐渐分叉的模式分支。

主要入口：[player_window.cpp](../src/ui/player_window.cpp)、
[player_window_library.cpp](../src/ui/player_window_library.cpp)。
