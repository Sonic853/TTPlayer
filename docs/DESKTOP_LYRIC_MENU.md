# 桌面歌词：播放曲目与控件悬停提示

## 问题原因

本次以 5.7.9 `TTPlayer.exe.pseudo.c`、对应 EXE 的局部反汇编及
`ttpres.dll` 资源为依据，不使用 TTPlayer6120 的非皮肤实现。

“播放曲目”不是静态资源中的歌曲列表：菜单资源 `0x97` 只有命令
`0x7ef4`、文字“空”的占位项。原版在弹出时替换它，重建版遗漏了以下两层：

1. `CPlayerWnd_OnInitMenuPopup`（00461BAE）识别首项 `0x7ef4` 或
   `10000`，调用 `CPlayerWnd_PopulateTrackMenu`（004813C1）。旧重建版
   仅在创建主菜单时直接填充歌曲，桌面歌词转发来的初始化消息没有处理。
2. `FUN_0041914F` 使用 `TrackPopupMenu(..., 0x100, ...)`；重建版额外
   使用了 `TPM_NONOTIFY`。宿主机真实弹出测试确认，该标志使这个顶层
   菜单没有收到用于填充歌曲的 `WM_INITMENUPOPUP`，仍显示占位项。

工具栏提示则被一次性保存为资源字符串：换行和卡拉 OK 的两种状态文字
被一起显示，置顶总是显示取消，播放按钮也不会按播放状态提示暂停。

## 恢复的菜单调用链

`DeskLrcBar 列表按钮 (0x803e)` → `FUN_0041914F` → 加载菜单 `0x97` →
`WM_INITMENUPOPUP` → `FUN_0041907F` 转交主窗口 → `00461BAE` → `004813C1`。

重建版现在由共用的 `PlayerWindow::PopulateTrackMenu` 填充主窗口及桌面
歌词的播放曲目菜单。菜单显示时重新读取当前列表，填充后重新应用已有的
菜单绘制样式。桌面歌词的应用回调和独立弹出路径均保留初始化消息；
`TPM_RETURNCMD` 负责返回所选命令，不需要再加 `TPM_NONOTIFY`。

填充规则对应 004813C1：

- 真正没有歌曲时，从字符串资源 `0x7ef4` 显示禁用的“无播放曲目”。
- 歌曲文字使用播放列表的标题格式，而非仅取 `Track.title`。
- 尊重 `TitleNumber`，序号按总条目数的位数补空格对齐。
- 已知时长追加 `\t[分钟:秒]`，未知时长不造一个 `0:00`。
- 标记当前正在播放的条目；不把另一列表的同号行误标为当前曲目。
- 尊重 `MenuBarPlayList` 的分栏设置，行数为工作区高度 / 22，至少 20。
- 原版最多生成 19999 项，命令为 `10000..29998`；所选命令回传主窗口
  的既有播放分发路径，不在桌面歌词再创建解码器。

## 悬停提示的原版规则

`FUN_00418B74` 为 12 个子控件调用 `0040EE49`，文字参数为 `-1`
（回调），不是固定文本。`FUN_00418958` 在提示请求到来时选择资源及状态；
反汇编确认换行、卡拉 OK 使用 `|` 分隔，置顶使用换行符分隔。

| 控件 | 资源编号 | 提示文字 / 状态选择 |
| --- | --- | --- |
| 图标 | 0x7dd8 | 主菜单 |
| 播放/暂停 | 0x7d00 / 0x7d01 | 非播放时“播放”；播放时“暂停” |
| 上一首 | 0x7d05 | 上一首 |
| 下一首 | 0x7d06 | 下一首 |
| 列表 | 0x803e | 播放曲目 |
| 换行 | 0x08d1 | 单行时“双行显示”；双行时“单行显示” |
| 卡拉 OK | 0x0866 | 未开启时“卡拉OK模式”；开启时“非卡拉OK模式” |
| 方案 | 0x803f | 预设方案 |
| 锁定 | 0x8040 | 锁定桌面歌词 |
| 置顶 | 0x8042 | 未置顶时“总在最前”；置顶时“取消总在最前” |
| 返回 | 0x8038 | 返回窗口模式 |
| 关闭 | 0x0008 | 关闭 |

表内中文来自本地 5.7.9 资源，代码不硬编码这些中文。普通命令取
“长说明\n短标签”的短标签；桌面歌词原版此处不附加快捷键。缺少资源时
返回空文字，不再统一替换成“TTPlayer”。

已恢复 `TTF_IDISHWND + LPSTR_TEXTCALLBACKW` 注册和 ANSI/Unicode
提示通知处理。提示窗口按 `0040EE16` 使用零样式创建并激活，去掉额外
指定的 360 像素折行宽度，不加入 TTS_ALWAYSTIP/TTS_NOPREFIX。

## 验证范围

新增 `src/ui/desktop_lyrics_menu_tests.cpp`：使用宿主机 Win32 窗口和
5.7.9 资源，加载与正式程序相同的公共控件 manifest。测试包含：

- 12 个回调提示注册、实际 `TTM_GETTEXTW` 请求、播放/暂停及双状态切换、
  ANSI 通知、提示窗口样式和默认折行设置。
- 空列表、12 首生成曲目、未知时长、序号对齐、当前条目标记、切换列表、
  返回命令、主窗口与桌面歌词共用初始化、动态项绘制样式。
- 真实 `TrackPopupMenuEx`，以及 `CreateDesktopLyrics` 安装的正式回调；
  由短定时器自动结束测试菜单。带 NONOTIFY 时曾复现仍显示占位项，去掉
  后正式回调成功填充 80 首生成曲目。另检查配置启用时的菜单分栏。

这些测试不播放真实音频、不修改用户配置；命令回传测试截获主窗口命令。
本次没有启动原版 EXE 做新的截图对比，原版依据是伪代码、反汇编及资源，
不将这些回归结果表述为整个播放器的二进制/像素完全等价。

Release 构建和以下 8 项测试通过：desktop_lyrics_menu_tests、
desktop_lyrics_tests、project_links_tests、skin_rebind_tests、skin_profile_tests、
skin_alignment_tests、skin_png_tests、ttplayer_tests。
