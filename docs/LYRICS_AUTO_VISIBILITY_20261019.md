# 歌词自动显隐与最小化／全屏恢复

日期：2026-10-19。

## 1. 反馈与原版依据

反馈：开启“有歌词时自动显示歌词秀，否则自动隐藏”后，主窗口最小化期间自动切到有歌词的歌曲，会重新弹出窗口歌词。

依据原版 5.7.9 `reverse/decompiled/TTPlayer.exe.pseudo.c`：

- `0045AD86 → 0044A370 → 0044A692`：播放成功后加载内嵌或本地歌词，并更新显隐。
- `0044BD57`／`0044BEED → 0044A692`：本地及在线异步结果进入同一自动显隐逻辑。
- `0044A692` 检查 `AutoVisible`、歌词窗口是否有效及 `DAT_00547760 == 0`（非全屏），比较实际窗口可见性与歌词行数是否大于 0；不检查主窗口是否最小化。需要改变时投递 `WM_COMMAND(0x7D64, 0)`。
- `004A3ACF → 0044A8AB → 0044E2FB`：处理开关命令并显示普通歌词窗口，或改为显示桌面歌词控制窗口。主窗口 `IsIconic` 检查发生在显示之后，不能阻止此弹出。
- `004615A6` 在最小化前保存状态；`0046162B` 在最小化后有意通过 `0x7D64/-2` 重新显示“置顶窗口歌词”或“桌面歌词”。
- `0044C2E7` 根据当前模式与可见意图屏蔽不应显示的窗口歌词。全屏 `0046228D` 另外管理普通窗口与分离后的全屏表面。

因此，普通非置顶歌词在最小化后自动弹出是原版逻辑也允许的交互缺陷。本次明确改进这一行为，同时保留原版置顶／桌面歌词独立显示的用途，不把所有歌词窗口随主窗口一起关闭。

## 2. 重建版此前的问题

`ApplyAutoLyricVisibility()` 直接执行 `ShowWindow(SW_SHOWNOACTIVATE)` 和 `BringWindowToTop`，既没有最小化／托盘门控，也漏掉了原版的全屏门控。本地结果、在线下载完成和内嵌歌词均能经过这条路径。

此前桌面歌词修复仅在桌面模式下同步 owner 恢复状态；普通模式恢复仍可能使用 Windows 保存的旧 owned-popup 状态。全屏退出又使用进入前的实际可见快照，未反映期间加载的新歌词。

历史桌面最小化与位置测试明确关闭了 `auto_visible`，因此其通过结果不能代表本次反馈已经覆盖。

## 3. 实现

### 3.1 显示意图与实际窗口分开

沿用 `ActiveLyricVisible()` 保存当前普通／迷你模式的显示意图；自动加载只根据当前歌词内容更新该值。`SynchronizeLyricVisibility()` 统一决定实际显示：

| 当前状态 | 普通非置顶歌词 | 置顶窗口歌词 | 桌面歌词 |
| --- | --- | --- | --- |
| 主窗口正常 | 根据当前意图 | 根据当前意图 | 根据当前意图 |
| 主窗口最小化／隐藏到托盘 | 保持隐藏，保留意图 | 根据当前意图 | 根据当前意图 |
| 全屏显示期间 | 普通宿主隐藏 | 普通宿主隐藏 | 桌面宿主隐藏 |
| 恢复主窗口／退出全屏 | 应用最新意图 | 应用最新意图 | 应用最新意图 |

全屏分离后的歌词内容控件不受普通宿主门控影响，仍能更新和显示全屏歌词。编辑器打开或歌词关联选择进行中，不使用自动内容结果覆盖正在编辑的窗口显示意图。

### 3.2 恢复与互斥

- 主窗口最小化和恢复后都合并投递一次内部同步消息。执行时读取最新状态，消息本身不携带旧显隐值，也不切换开关。
- `WM_SHOWWINDOW(SW_PARENTOPENING)` 依据当前意图阻止不合适的系统自动恢复，随后统一同步实际状态。
- 显示桌面歌词前先隐藏其普通 owner；切回普通／全屏时隐藏桌面表面，保留现有所有权链。
- 内部同步消息在文件标签写入屏蔽用户命令之前处理，避免消息被丢弃后合并标志永久挂起。
- 自动显示使用 `SW_SHOWNOACTIVATE`，移除自动路径的 `BringWindowToTop`。已经可见时不重复显示和抬升。
- 普通／迷你布局绑定及全量选项变更复用同步函数，位置、尺寸、吸附、窗口区域和字体安装流程保持原有职责。
- 只完成已失效的单个歌词窗口淡出。组淡入淡出保留原计时，新显示窗口加入当前组透明度，避免用过期 HWND 可见性覆盖新内容意图。

### 3.3 全屏退出

先恢复分离的控件及主窗口，再根据当前 `ActiveLyricVisible()` 同步窗口。进入全屏前的实际可见快照不再覆盖期间更新的歌词内容意图；退出后再排队校正一次系统 owner 恢复。

## 5. 窗口消失时差的边界

最小化仍通过原生 owner 机制完成，桌面歌词按原版设计在后续消息中恢复；各个 HWND 和独立的桌面 Paint／Bar 层不保证在同一个合成帧处理完成。本次修复状态不一致和自动弹出，不声称消除了所有系统窗口动画时差。若需要比较肉眼可见的延迟，应在原版与重建版上同时采集窗口消息时间戳及合成帧，区分消息顺序、皮肤淡入淡出和 DWM／非 DWM 的表现。
