# 皮肤标题定位修复

## 原因与原版依据

本次依据原版 5.7.9 的 `reverse/decompiled/TTPlayer.exe.pseudo.c`，
不采用 TTPlayer6120 的窗口行为作为参考。

`Classic.skn` 的播放列表和歌词标题都是图片，XML 均为
`position="0, 8, 55, 21" align="center"`。两张标题图像都是 `55 × 13`。
其背景位图宽度均为 268，而窗口的 `position` 还可以指定更大的显示高度。

- `004A8DC6` / `004A88D0` 分别解析播放列表、歌词窗口；
- `004A988C` 原样读取标题的 `position`、`image`、`align`；
- `004AA150` 将 `center` 解析为 2，`vcenter` 解析为 `0x20`；
- 标题绘制 `0047EC2F` / `004493DC` 通过 `0042912E` 取得图像尺寸，
  再调用 `0047A9C5` 计算位置，随后以原图尺寸绘制；
- 均衡器标题 `0042980D` 使用相同的定位路径。

旧重建版虽然正确读到了 `center`，却将它解释成
`XML.left + (当前窗口宽度 - 原始背景宽度) / 2`。
因此 Classic 初次显示时标题仍在 x=0；即使拉宽窗口，也一直少了初始居中偏移。

## 修正规则

共用 `ResolveAlignedRect` 对齐到当前客户区，不修改皮肤文件，也不按皮肤名称特判：

- 水平居中：`x = (当前宽度 - 元素宽度) / 2`，忽略 XML 的原始 x；
- 垂直居中：`y = (当前高度 - 元素高度) / 2`，忽略 XML 的原始 y；
- 右侧：`x = XML.right - 元素宽度 + 当前宽度 - 原始背景宽度`；
- 底部同理；未指定对齐的轴仍使用 XML 坐标；
- 当前客户区小于原始背景时，仅停用该轴的对齐，符合 `0047A9C5`；
- 标题提供实际图像尺寸用于定位和绘制；关闭按钮等原有控件保留其 XML 客户区尺寸。

Classic 两个标题在宽 268 时均为 `(106,8)-(161,21)`；宽 400 时均为
`(172,8)-(227,21)`。关闭按钮的右边距仍为 8 像素。

## 验证

宿主机 `skin_alignment_tests` 包括独立的对齐公式测试，以及真实 Classic 包的
解析、隐藏测试 HWND 的尺寸变化和播放列表/歌词绘制测试。宽度序列为
268 → 269 → 400 → 401 → 268，逐像素检查标题栏，覆盖初始居中、奇偶舍入、
拉宽与恢复、没有残留左侧标题、关闭按钮位置。另测组合对齐、负增量和图片与
XML 框尺寸不同的情况。测试不读写用户的 TTPlayer.xml，也不播放歌曲。

Release 构建及 `skin_alignment_tests`、`project_links_tests`、`skin_png_tests`、
`skin_rebind_tests` 均通过。这里验证的是恢复后的定位/绘制规则，不宣称原版二进制等同。
