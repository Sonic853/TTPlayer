# iZotope Vinyl 播放异常修复

日期：2026-09-28

## 结论

`dsp_iZVinyl.dll` 启用后播放时界面消失，首先由重建版的解码读块逻辑触发：程序把输出缓冲区剩余字节数直接当成源 PCM 的读取字节数。源文件为 24 bit、输出为 16 bit 时，缓冲区尾部反复换算，最终产生只有 1～2 帧的 DSP 输入。Vinyl 内部滤波器要求至少 3 帧，抛出 `Too few input samples` 异常；宿主随后禁用并卸载插件，其窗口随之消失。

本次修复按源格式计算稳定、整帧对齐的读取量，并沿用已有 `decoded_offset` 缓存处理后的剩余音频。无需修改插件 DLL、注册表或插件参数。

## 复现和二进制证据

- 插件：根目录 `Plugins/dsp_iZVinyl.dll`，iZotope Vinyl v1.0，1,110,528 字节。
- SHA256：`4607559be14a199e5685566df7b70361ee6aed28bcf84bb2da1b0475b3b02c99`。
- 测试歌曲：`蔡明希（不才）,三体宇宙 - 夜航星 (Night Voyager).flac`，48 kHz、24 bit、双声道，303.701 秒。本次使用本机 `Music/lrctest2` 下的文件。
- 输出：WASAPI 共享，48 kHz、16 bit、双声道。
- 修复前：前几次回调为 1024 帧，第 17 次回调缩小到 2 帧，触发 `0xe06d7363` C++ 异常；随后记录 `Winamp DSP ModifySamples raised an exception; disabled`。
- 解包后的内存映像以 `0x10000000` 为基址时，`ModifySamples` 在 `0x10003150`；内部滤波函数 `0x10005fc0` 检查输入长度是否小于 3，并在 `0x10005fe6` 抛出异常。异常字符串位于 `0x10115238`：`Too few input samples`。地址随 DLL 重定位改变，以上为首选基址地址。
- 2048 帧及连续 1024 帧的直接 SDK 调用正常；强制 DLL 重定位后也正常。因此没有通过固定插件加载地址来规避问题。

用户当日 15:43:51 的崩溃转储最终停在 `ntdll.dll+0x51f6a`，访问异常为 `0xc0000005`，此时 Vinyl 已被卸载。该转储可确认最终崩溃位置，但不能单凭此位置断言具体是哪条插件指令破坏了堆。本次通过首次异常捕获和输入帧数记录，定位并消除了此前可稳定复现的异常输入。

## 原版伪代码对照

来源：`reverse/decompiled/TTPlayer.exe.pseudo.c`。

| 原版函数 | 行为及本次恢复点 |
| --- | --- |
| `FUN_004b1375` | 从读取器取得源 PCM 后再进入音频处理；不把硬件输出剩余空间直接作为不同位深源 PCM 的读取大小。 |
| `FUN_004ac166` | 在调用 Winamp DSP 前转换为 16 bit，处理后再转换到输出位深；源数据量和输出数据量需要区分。 |
| `FUN_004280cd` | 按 `bytes / ((bits >> 3) * channels)` 计算帧数后调用插件；超大块按原逻辑拆分。此次保留现有回调顺序和帧数契约。 |

例如，1024 帧双声道 24 bit 源 PCM 占 6144 字节，转成 16 bit 后只有 4096 字节。旧实现不断用输出的剩余空间重新读取源数据，会使后续读取量越来越小；插件不应收到由这种单位混用人为生成的 2 帧片段。

## 代码调整

文件：`src/audio/audio_engine.cpp`。

1. 增加 `SourceReadBytes`：根据源/输出每秒字节数换算读取量，保留文件缓冲下限，并向上对齐到完整源帧。
2. 公共 WaveOut / WASAPI / KS / ASIO 路径在填充输出前确定稳定读取量，不再根据输出尾部剩余空间缩小解码读取。
3. DirectSound 使用同一计算函数，使用 64 位中间值避免 32 位乘法溢出，并限制分配上限。
4. 已处理但尚未写入输出的字节继续由 `decoded_offset` 保留，不丢弃、不重复处理，也不改变播放顺序。

修复针对中途人为切碎的输入块。没有对所有旧插件实施补零，也没有改变真实短文件或解码器末尾碎片的 DSP 语义。
