# 单曲循环下上一首／下一首的原版行为与修复

修复日期：2026-09-16。

**后续修订：**五种模式已进一步对照修复，见
[PLAYBACK_MODES_AUDIT_AND_FIXES.md](PLAYBACK_MODES_AUDIT_AND_FIXES.md)。下文是前一阶段记录：
随机序列现已补齐；导航按当前显示的列表／查询进行；首尾命令回绕与按钮置灰需分别理解。

## 结论

原版的“单曲循环”只控制自然播放结束后的处理。手动按“上一首／下一首”时，
仍然切换到相邻歌曲，并在列表首尾回绕；播放模式保持单曲循环，切换后的歌曲
自然结束时继续重复该曲。重建版此前误把自动重复规则用于手动切歌，导致原地重播。

例如列表为 A、B、C，当前 B：

| 操作 | 原版行为及修复后行为 |
| --- | --- |
| 上一首 | 播放 A |
| 下一首 | 播放 C |
| A 上按上一首 | 播放 C |
| C 上按下一首 | 播放 A |
| B 自然播放结束 | 再次播放 B |
| 尚无实际播放标记时按下一首／上一首 | 播放第一首／最后一首 |
| 空列表 | 无操作 |
| 只有一首歌曲 | 手动切歌重新播放该曲 |

上表假设没有不同歌曲的“播放跟随光标”覆盖，具体规则见下文。

## 原版证据

基准为工作区的 TTPlayer 5.7.9.0，分析文件为
`reverse/decompiled/TTPlayer.exe.pseudo.c`，并核对同目录原始 EXE 的 x86 汇编。
伪代码中部分寄存器参数和算术被遗漏，因此不能仅凭函数调用外观判断切歌行为。

### 1. 手动命令有独立入口

`FUN_004582D0` 的 `WM_COMMAND` 分发：

- `0x7D05`（32005，上一首）→ `FUN_00465230`。
- `0x7D06`（32006，下一首）→ `FUN_0046528B`。

两者读取 `CPlayList +0x1C` 的实际播放标记，最后调用
`FUN_0047FEA3(list, row, 1)` 发起显式播放请求；不调用自然结束处理函数。

### 2. 上一首：递减并回绕

`00465254..00465282`：

1. 从列表 `+0x1C` 读出播放索引。
2. `00465266: dec eax`，索引减一。
3. 仅当 `DAT_00547828 == 4`（随机播放）时调用随机序列函数
   `FUN_0045BBF6(-1)`。
4. `00465277..0046527B` 检查负数，负数时改为 `count - 1`。
5. 推入 `1`、目标索引、列表，调用 `0047FEA3`。

该路径没有“单曲循环返回当前索引”的判断，也不读取自动切换列表选项。

### 3. 下一首：递增并回绕，以及光标优先

`004652CF..0046533F`：

1. 如果启用 `DAT_00547830`（PlayFollowCursor），调用 `0047FCA6`。
2. `0047FCA6 → 0040EEBB` 发送 `LVM_GETNEXTITEM`（`0x100C`），参数为
   `-1, 3`；`3` 表示 `LVNI_FOCUSED | LVNI_SELECTED`。必须同时具有焦点和选中状态，
   只有光标位置并不足以覆盖下一首。
3. 获得有效行后，发送 `0x7F36` 清除选中／焦点等状态；若该行与播放行不同，
   直接播放它。若相同，继续正常切歌。
4. `00465325: lea eax,[ebx+1]`，实际播放索引加一。
5. 仅随机模式调用 `0045BBF6(1)`。
6. `00465334..00465339` 在目标超出末尾时清零，再调用 `0047FEA3`。

因此上一首不受 PlayFollowCursor 影响，下一首可以受其影响。
单曲播放、单曲循环、顺序播放、循环播放均采用同一手动回绕规则。

### 4. 自然结束：保留单曲循环

`FUN_0045BD69` 是另一条路径。它处理自然结束、播放跟随光标和自动切换列表：

- 模式 `0`：停止。
- 模式 `1`：调用 `0045BF4B` 重播当前歌曲。
- 模式 `2`：前进，列表末尾按自动切换列表配置处理，不无条件回绕。
- 模式 `3`：按循环播放及自动切换列表配置处理。
- 模式 `4`：按随机序列处理。

这说明不能通过修改持久化播放模式来修复手动切歌，也不能把两条路径统一成
“无论何时都重复当前歌曲”或“无论何时都前进”。

## 重建版修改

修改入口：[PlayerWindow::SelectRelative](../src/ui/player_window.cpp)。

- 合并普通列表和媒体库的重复判断；手动切歌使用随机或列表回绕规则。
- 以 `PlayingRow()` 作为起点，处理尚无实际播放标记的首／尾起播。
- 恢复下一首的选中焦点优先规则。
- 媒体库显示结果和正在播放的快照可能排序不同，使用歌曲路径和子曲目身份
  判断焦点是否已在播放，避免误用行号。选择另一首时从当前查询建立播放快照。
- 保留实际播放来源、持久化模式和 `AdvanceAfterNaturalEnd()` 的自动播放规则。
- 更新选中策略注释，明确手动下一首也会读取 PlayFollowCursor。
- Actions 的现代版和兼容版均增加独立切歌回归，无需私有 `tests/` 目录。

随机模式仍使用已有随机实现；本次没有重建原版完整随机历史队列。
