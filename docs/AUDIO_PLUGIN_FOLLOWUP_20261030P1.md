# 音频插件兼容修复：2026.10.30p1

本轮继续修正 `ttp_aac` 的容器与预测解码问题，保持原版宿主接口和 XP SP3／Win7 兼容。没有修改其它解码插件、原版播放器及其 AddIn，也没有把其它插件的历史边界算作已完成。

## 修复内容

| 范围 | 原问题与修复 |
|---|---|
| MP4 多音频配置 | 读取并验证多个 `stsd` 项，正确继承 `stsc`、`trex`、`tfhd` 的配置编号；允许实际使用第二个配置，未使用的不支持配置不再阻止有效轨道播放。 |
| AAC 配置切换 | 普通和分片 MP4 可在保持实际 PCM 采样率、声道数及布局不变时切换 ASC。等价的索引／显式频率不重置历史；真实配置变化重新初始化并按媒体时间处理预热，恢复定位、编辑列表和保存后播放。 |
| 无缝裁剪 | 先确认真实解码输出，再解释 `iTunSMPB`，不依赖可能错误的 `mp4a` 采样率提示。通过完整延迟、内容、填充总量与编码时长核对，兼容按核心时钟计数的 Nero HE／HEv2 文件，原有正确 PCM 参考保持不变。 |
| LTP 与 DRC | 原版及旧重建版均会把 DRC 处理后的音频反馈进长期预测历史，造成异常放大。现在为受 DRC 影响的 LTP 保留未缩放的重叠数据及历史；普通无 DRC 路径不增加分配或额外变换。 |
| LTP 独立耦合 | 恢复耦合源的完整合成和预测历史，目标先更新预测状态再混入时域耦合信号，避免静音及递归失真；兼容 DRC、增益排除和动态路由。 |
| 非法耦合目标 | 拒绝同一个 CCE 的重复目标，同时保留 SCE／CPE 各自命名空间中相同数字标签的合法用法。 |
| 7350 Hz LTP | 使用实际启用长期预测的音频，补足完整独立 PCM、容器、ADTS 定位及 Reset 验证，不再只依赖 AOT／配置初始化成功。 |

Win11、XP SP3、Win7 均通过 **1577／1577**，合计 **4731**。其中每系统 131 项为使用当前生产 `mp4.cpp` 重新编译的保存核心探针，其余通过公共接口加载冻结 DLL。LTP 的 64 条命令展开为 74 个场景及 54 次整段 Reset 重放；CCE 新 65 次调用包含 291 个展开场景，不能再把展开场景重复加到调用总数。

运行中曾发现虚拟机复制工具未复制容器测试的子目录，补齐样本并增加复制失败检查后重新执行；最初的缺文件日志仍留在本地。没有以修改 PCM 参考值的方式消除失败。

宿主矩阵为每系统原版与重建版各 22 次、共 44 次，检查加载模块完整路径、请求的文件、播放时间推进、错误窗口及正常退出。新增真实输入包含 7350 Hz LTP 的 MP4／ADTS、LTP＋DRC、独立 CCE 及 CCE＋DRC，以及 33 秒、15 次 LC↔HEv2 切换的 MP4。Win10 按用户约定由 Win11 代测，不声称实际运行过 Win10；这不是实体音箱听音或全部输出设备验证。

### 最终宿主结果与退出观察

- 固定的原版／重建版隔离副本：三个系统各 44 次，最终矩阵共 **132 次通过**。该重建版宿主为 `2026.10.24`，不能将其冒称当前主程序。
- 另复制当前 Release 的 `2026.10.29` 主程序及匹配的 `ttpcomm.dll`、`ttpres.dll`，三个系统各补测 6 种新增输入，共 **18 次通过**。当前主程序 SHA256：`d06fca5bd6ca3d8e3c8fe1ee4992395a79d3dfbfde960c895ace8ee3d50cb808`。
- 上述验收矩阵合计 **150 次成功播放与正常退出**，不是“所有尝试首次通过”。本机旧隔离副本曾在播放 `ltp-7350.aac` 后超过探针的 7 秒退出期限，被测试工具结束；播放时间及请求文件已正确保存。相同配置随后重试通过，再连续 5 次复测均正常退出，总运行时间约 3.65～3.68 秒（含 3 秒播放）。首败记录没有删除。
- **这一次旧宿主退出超时仍未定位，也没有声称修复。** 当前公开接口和当前 Release 宿主未复现。只读分析不能把它归因于 AAC、网络或 Discord；再次发生时需要捕获关闭阶段与线程栈。
- 当前宿主补测初次准备时漏带 `ttpres.dll`，产生明确资源缺失提示；补齐对应版本后重新执行。另增强测试探针的进程存活判断，避免仅凭 Toolhelp 名称快照判定已有运行实例。准备失败不计为播放通过。
- 全部测试播放器已退出，按用户要求不重新打开。证据、当前宿主完整文件身份及最终 DLL／源码校验见本地 `final-validation.json`。

## 保留边界

- LTP960 的合法配置及共享变换已有实现，但仍缺可信的真实有声 LTP960 码流验收。
- LTP 依赖 CCE、SSR CCE 是规范限制，继续明确拒绝；独立 LTP CCE 的工具级验证不等于 profile／level 认证。
- CCE＋SBR／PS、CCE＋PNS／960 帧的所有组合、7350／14700 Hz SBR、表外核心频率 SBR、扩展 AOT 等未据本轮成功扩大支持声明。
- 多配置 MP4 的实际 PCM 格式必须固定；没有新增动态格式协商、重采样或混音。配置首段过短、无法证明真实布局时保守拒绝。
- 分片 MP4 保存仍要求现有 metadata／padding 空间足够；不足时明确失败并保持文件不变，不支持任意扩容搬移分片。DRM、在线 DASH 和不可定位 MP4 网络流仍不在支持范围。
- 重封装后媒体时钟与原核心时钟分离、又保留含糊 SMPB 的文件不能保证准确推断。ADIF VBR 估算、未知长度流定位，以及其它插件历史范围仍沿用各自报告。
