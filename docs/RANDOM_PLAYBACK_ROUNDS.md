# 随机播放：三轮后台索引与大列表单轮循环

日期：2026-09-16。按用户最终指定规则调整随机播放（模式 4），普通版与 XP／Win7 版
使用不同的内部索引策略。

## 数量边界

以下数量阈值适用于普通版：

| 当前显示列表／媒体库查询的歌曲数 | 内部索引 | 播完一轮后的行为 |
| --- | --- | --- |
| 0 | 无 | 不选曲 |
| 1 | 无需洗牌 | 重播该曲 |
| 2–5000，含 5000 | 上一轮、当前轮、下一轮 | 进入下一轮，淘汰旧上一轮并在后台重新洗牌补到末尾 |
| 5001 及以上 | 一份完整的随机排列 | 返回这份排列的开头，沿同一顺序循环 |

**XP／Win7 版：无论数量多少，都只保留一份内部随机排列并在其中循环。**
编译开关 `TTPLAYER_LEGACY_WINDOWS` 将三轮阈值设为 0；不按运行时操作系统猜测，
因此兼容版 EXE 在新系统运行时也使用单轮。空列表／单首的处理相同。

单轮策略依然随机播放：例如内部索引为 `[3, 1, 4, 0, 2]`，则循环播放
`3 → 1 → 4 → 0 → 2 → 3 → 1 …`。轮尾不重新洗牌，也不改成界面行号顺序。
可见播放列表的排列始终不受内部洗牌影响。

“自动切换列表”保持现有规则：自然完成当前内部轮的最后一首后切到下个真实
播放列表／可见媒体库树节点，从目标第 0 行开始；手动上一首／下一首仍在当前列表内。
大列表的轮尾由内部索引游标决定，不能用可见列表的最后一行代替。

## 三轮滚动与回退

```text
[上一轮 A] [当前轮 B ▶] [下一轮 C]
                    ↓ B 播完
[上一轮 B] [当前轮 C ▶] [新洗牌 D，后台生成]
```

- 每一轮都是全部歌曲行号的完整排列；连续向前时，轮内每首恰好播放一次。
- 上一首越过当前轮开头会进入保留的上一轮，之后下一首仍沿保留的序列前进。
  反向越界也会反向滚动并补齐更早的一轮。
- 两轮交界不连续播放同一行。至少 3 首时，保留的三轮排列两两不同。
  只有 2 首时，为保证交界不重播，允许三轮使用相同排列；一首则直接重播。
- 只保留有限轮次，不记录无限播放历史。已经淘汰的更早／更晚轮次重新生成。
- 查看下一首不移动游标，支持跨轮预览。首次上一首直接进入上一轮末项。

## 线程和失效处理

`RandomPlaybackOrder` 按需启动一个后台工作线程，与 UI 线程并行。线程只接收
数量、当前行和不可变的索引快照，不访问歌曲对象、音频解码器或窗口。
两种策略的首次洗牌都在后台执行；三轮模式的后续补齐也在同一工作线程执行。
XP／Win7 版也在后台生成其唯一的一份索引。

UI 调用 `Prepare` / `TrySelect`，不等待线程完成。未就绪的切歌请求按到达顺序
暂存，现有 250 ms UI 定时器取回完成结果后继续。正常播放期间已经预生成下一轮；
首次生成或快速连续越界时可能短暂等待下一次 UI 检查，窗口仍可响应操作。
停止、直接播放另一首或改变播放模式会清除尚未执行的切歌请求。

普通播放列表使用行映射版本，媒体库在查询重建、插入、删除、排序及路径变更时
更新版本。取用结果前比较来源和版本，后台任务另有代次号：过期结果不能覆盖新状态。
数量变化（包括普通版跨越 5000／5001）、来源变化或直接选曲导致锚点变化时，
重新生成相应策略的索引。
普通列表的纯标签／评级修改不改变行映射版本。

大列表填充与 Fisher–Yates 洗牌每 1024 项检查取消，避免旧的大任务长期占用线程。
关闭时请求取消并回收线程。分配等后台异常不会悄悄改成顺序播放。

索引使用 `size_t`；当前两种分发均为 x86，三轮 5000 项的索引数据约 60 KB，
单轮 5001 项约 20 KB，未计容器和线程开销。后台任务共享保留轮，不复制 `Track`
或音频数据；大列表不会创建三份完整索引。

## 与原版的关系

原版 `0045BBF6` 使用一个随机数组和游标，越界重建，后退重建还会先重播当前曲。
本次按用户要求替换该策略：普通版小列表三轮滚动、大列表一轮固定循环，
XP／Win7 版始终一轮固定循环，首次上一首直接换曲。
这几项是明确的功能调整，不表示它们与原版伪代码逐项相同。原版对照和其他播放模式
见 [PLAYBACK_MODES_AUDIT_AND_FIXES.md](PLAYBACK_MODES_AUDIT_AND_FIXES.md)。

## 回归覆盖

`playback_navigation_tests` 覆盖 0／1／2／3／13／5000／5001 首、完整排列、三轮不同、
轮间不连播同一行、跨轮回退后前进、预览不消费、单轮循环多次顺序不变、
大列表后台任务失效／关闭、快速点击排队和停止、真实 UI 定时器继续选曲、
同数量排序和替换，以及普通列表／媒体库快照的手动与自然完成共享游标。
媒体库测试另覆盖真实查询及树节点切换。

构建和测试同时针对普通 Release 与 XP／Win7 Release；旧系统包还须通过导入表审计。
兼容版测试对小列表同样要求每轮保持同一排列，普通版测试则要求三轮排列不同。
本机测试不代替 XP／Win7 实机运行验证。

本次验证结果：普通版 6 项相关回归通过；最终分版后，两种构建各自的切歌与媒体库
回归均通过。兼容 EXE 的导入审计通过：x86、子系统 5.01、18 个 DLL、598 项导入。
