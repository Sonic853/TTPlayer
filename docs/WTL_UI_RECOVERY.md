# 按 WTL 界面审计顺序恢复

日期：2026-09-16。对应 [审计建议](WTL_UI_PARITY_AUDIT.md#6-建议后续顺序)。

## 1. 歌词保存策略与内嵌标签

- `SaveModifiedLyrics` 对应 `0044A6E6`：同时处理普通文档 dirty 标记和
  RichEdit 的 `EM_GETMODIFY`；模式 0 不保存、模式 1 询问、模式 2 自动保存。
- 保存普通文档时序列化当前调整后的歌词，不再要求先打开编辑器。
  策略保存使用现有／建议目标，对应原版带歌词 HWND 的 `0x8022` 调用；手动
  Save As 继续使用现有现代选择器。
- 编辑器退出而未保存时，将修改内容和 dirty 状态保留到普通文档。
  `0045B69B → 0044A09E` 的换歌／停止流程则在执行策略后清除修改标记；
  拒绝保存或保存失败不会变成“保存成功”，也不额外引入取消换歌的语义。
- 换曲目、关闭及停止先处理旧文档，再改变曲目身份或关闭 reader。
  停止保留当前编辑器。切歌销毁编辑器时不再次加载旧歌词，避免将其自动嵌入新曲目。
- 歌词文档保存自己的曲目快照，避免播放列表光标先移动后写错歌曲。
- 外部歌词加载成功，以及修改后成功保存外部文件，均按 `AutoSaveLyricTag`
  尝试写入标签；自动尝试失败不显示手动写入命令的错误框。
- 保存询问框的嵌套消息循环期间，暂缓主 UI 定时器的异步结果提交和自然切歌，
  保留待执行状态，防止正等待确认的文档被替换。

播放中的 `LegacyPluginSource` 通过音频工作线程队列复用当前 reader，调用 metadata
slot 6，成功后清理旧 `Lyric` 并更新快照。该操作在解码调用之间执行，支持暂停态；
UI 不直接持有插件对象，不执行 Stop／Pause／Seek 来换取可写句柄。

队列核对路径和 subtrack；来源关闭时完成尚未执行的请求，等待有 3 秒上限。
匹配的活动来源写入失败后，不再另开冲突的文件句柄。没有活动来源时才沿原有
`OpenReaderForMetadata` 路径写入。已进入第三方 DLL 的调用不能被安全强杀；
超时不表示 DLL 后续绝对没有写入，也不能当作保存成功。

**能力边界**：CUE 分段来源没有擅自把某一子曲目的歌词写到整张专辑的底层文件；
不提供 metadata 写接口的来源继续失败。FLAC 成功不代表所有插件、CUE 或 MCI 来源
都支持实时写入。这些边界与未接入保存选项是不同问题。

## 2. 播放列表专用查找框

重新沿 `00486056 → 0048ABBD` 使用原资源 **203**，经 ATL 适配调用
`DialogBoxParamW`，取代 `FindTextW`。保留无禁用父窗口的调用方式；播放器的其它
窗口和定时器继续分发，播放器销毁时结束查找对话框，最终销毁清除 HWND。

原控制器依据：`0045444A`、`004544FB`、`00454760`、`00454809`、
`004548D8`、`00454A06`。匹配依据：`0047FCB6`、`004826AD`、`0048287B`。

- 普通模式恢复标题 1009、艺术家 1021、专辑 1025，大小写 1103、完整匹配 1104、
  反向查找 1102、查找下一首 1002、选中全部 1107 和关闭。
- 多个非空条件按原代码 **OR** 合并；完整匹配比较整个字段，不误解为英文单词边界。
  标题检查显示标题和标题字段，另两栏各检查自己的缓存字段。
- 快速模式隐藏普通选项、显示提示 1052，将输入框移到 x=10、选中全部移到原
  查找下一首的位置，窗口客户区高度减半；输入变化实时更新全部匹配项。
- 恢复重复使用的查询条件和去重输入历史；仅艺术家／专辑条件也能启用和执行 F3。
- 快速模式无匹配时清除旧选择；普通下一首无匹配时使用 **0x8193** 提示。
  旧重建误用了 **0x8198**，该字符串实际是“正在查找文件…”，不是未找到提示。

当前匹配仍使用已加载的模型字段。原普通搜索的 `0042CA79/0042CB90` 通用进度工作
对话框没有在本轮复刻，不能宣称其进度窗口和取消时序也已完全一致。

## 3. 转换按钮绘制

`0047D682` 对配置按钮调用 `00434754`，与已恢复的 `0046E0C9` 图文按钮路径相同。
转换配置和进度窗口改用共用位图按钮安装器，移除独立的固定边距绘制路径及图像列表
清理代码。输入和默认按钮状态仍由原生 BUTTON 控件管理，主题、经典绘制、悬停、
焦点与图像列表所有权沿共用实现处理。

这次复用不等于已重新完成转换窗口所有 DPI 和所有像素的原版截图矩阵。

## 4. 跨窗口与异步生命周期

本地回归覆盖保存询问期间重入 UI 定时器、查找普通／快速模式连续打开、无禁用父窗、
关闭清理、搜索条件及选择状态；同时回归既有换肤、置顶、歌词搜索／关联、媒体库、
导航、选项、音频和转换路径。测试文件仅存放于被忽略的 `tests/`，Actions 保持
`BUILD_TESTING=OFF`。

XP／Win7 分发仍单独构建、检查静态导入；当前宿主运行不能代替旧系统实机或真实
混合 DPI 验收。本轮没有改变用户指定的随机索引策略及现代界面扩展。

## 5. 旧网络功能边界

FreeDB、Music Window／下载管理及报告服务没有可直接调用的完整重建后端。
保留原曲目筛选和不可用提示，不把这些菜单描述为已经恢复成功路径。

修复了报告窗口的误导行为：过去点击提交后，即使完全没有发送请求，仍显示
`0x84D0` 的感谢回执并启动三秒关闭计时器。现在保留原报告资源，明确提示
“报告服务不可用，尚未提交”，禁用提交和原因选项；直接派发 IDOK 也不会模拟成功。

歌词搜索／下载继续使用其已有代理设置。Media Foundation 的 URL 播放仍没有接入
原 netacc 的完整代理、缓存、鉴权及边听边下载协议；本轮未将保存配置冒充运行功能，
也没有替换成未经核对的新服务或发送真实报告。
