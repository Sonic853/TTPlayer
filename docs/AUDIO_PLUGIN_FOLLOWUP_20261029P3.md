# AAC 剩余兼容修复与 XP／Win7 验收

构建：`2026.10.29p3`。接续 [p2](AUDIO_PLUGIN_FOLLOWUP_20261029P2.md)，本轮更新 `ttp_aac` 的 ADIF、ER AAC LD、显式频率和分片标签保存。MOD、VQF、RM、OGG 等插件保持本轮开始时的版本，没有为未修改的插件重复发布。

## 修复结果

### ADIF 流与裸 AAC 定位后预热

本地 ADIF 原已能够解码，但未知长度 IStream 只经过 ADTS 同步头校验，打开时报格式无效。现在在可选 ID3 后识别 ADIF，使用最多 64 KiB 的前读窗口，按解码器实际消费量保留剩余压缩数据；短读与取消发生在解码之前，不破坏已建立的解码历史。

同时修复本地 Seek(0) 后的空成功读取。此前解码器消费预热帧却没有 PCM，Reader 返回 `S_OK`、长度 0；现在继续读取至有效 PCM 或真实 EOF。同一文件首次读取由 0 字节恢复为 8,192 字节。没有将取消错误改成 EOF，也没有为未知长度输入伪造可定位能力。

15 个合法构造 ADIF 覆盖单／双／六声道、44.1／48／96 kHz、CBR／VBR 和版权字段，完整输出与相同压缩帧的 ADTS 逐字节一致。原 DLL 也能正常播放其中的立体声文件；新旧 FAAD 数值差在 p2 已存在，本轮不宣称全部 ADIF 与原版数值一致。详见 [ADIF 修复记录](../../ttp_aac/docs/ADIF_STREAMS_20261029P3.md)。

### ER AAC LD：修复包尾消费和 TNS 频带

p2 的 LD 文件在第 35 包报告消费 553 字节、包长却只有 552。原因是 FAAD 在 ER 固定声道元素序列末尾仍尝试读取普通 AAC 的 `ID_FIL`，将包尾填充误当作附加元素。现在这两处解析只用于普通语法；原有 `consumed <= packet` 完整性保护继续保留。

进一步修正 LD 错用 LC／Main 长窗 TNS 上限的问题，按 LD 480／512 样本帧使用相应表。一个真实 44.1 kHz 六声道 LD 样本完整输出 154,624 帧，对 FATE 指定 PCM 金样的最大误差由 3537 降至 **1 个 PCM16 单位**，RMS 由 35.797 降至 0.614。标准条文、FATE 参考与独立解码证据相互印证；FATE 文件不被冒称为已证实来源的 MPEG 权威输出。

这会有意改变原 DLL／旧 FAAD 的错误 LD 输出，不能同时声称逐位复刻原版。LD480 目前仅有静音路径验证，其完整有声内容等组合仍未完成。详见 [LD／ASC 分析与证据](../../ttp_aac/docs/LD_ASC_20261029P3.md)。

### 显式频率与高采样率 SBR

此前 FAAD 读出 ASC index 15 的 24-bit 频率后将其丢弃，仍用索引 15 查表，导致有效配置初始化失败。现在对精确等于既有 12 项核心频率的值规范化，处理显式 SBR／同步扩展并验证缺失字段；不把任意频率四舍五入到邻近值。

核心频率和 SBR 输出频率分开校验。复核发现仅接受普通频率表会回退 p2 已有的 192 kHz 输出，因此保留受支持核心频率的精确二倍输出。64／88.2／96 kHz 核心配合 128／176.4／192 kHz SBR 上采样配置，与 p2 输出逐字节一致。它们是用真实 AAC-LC 帧构造的上采样路径测试，不宣称覆盖这些速率的全部历史高频 SBR 数据。

固定 FAAD2 版本仍为 2.11.4，兼容修正只应用到构建目录副本；原下载归档、共享缓存和原 AddIn 未改。补丁和修改声明均随对应源码提供。

### 分片 MP4 标签与封面保存

恢复现有标签区或连续 `free/skip` 足够时的保存，支持标签修改与 JPEG／PNG 封面。使用局部元数据槽，不移动 `trak`、`moof`、`mdat`、`sidx`、`mfra/tfra` 或音频包位置，也不把新 `moov` 追加到分片末尾破坏初始化顺序。

容量不足、无法放置合法 padding 的 1～7 字节残余，在写入前返回 `STG_E_MEDIUMFULL`，文件不变。部分写入、头写入和 Commit 失败均尝试恢复原内容；恢复本身失败返回真实错误。保存前核对预留区原头，防止覆盖打开后被其它写入者替换的同长度 box。

原接口仍在最后一个 Reader 引用释放时保存；支持可选 MetadataCommit 的宿主能收到实际结果。原版旧接口没有提交结果返回值，这个 ABI 限制仍存在。详见 [分片保存实现与限制](../../ttp_aac/docs/FRAGMENT_METADATA_SAVE_20261029P3.md)。

Windows 11 作为现代系统验证；按用户要求代为覆盖现代 Windows 路径，没有独立 Windows 10 实机结果。

| LD／ASC／SBR Decoder 工厂回归 | 69 | 通过 | 通过 | 通过 |

合计 **2,376 组**。其中每系统 661 组通过最终 DLL，131 组保存核心探针由相同生产 `mp4.cpp` 编译，不能把后者描述成 DLL 接口调用。九种保存布局的受保护 box、142 个样本的偏移／时序／压缩数据逐项不变，保存前后完整 PCM 摘要一致。

旧回归仅有明确的预期更新：两个显式 88.2 kHz ASC 文件由拒绝改为与已有索引式 PCM 比较；无提示的扩展 AOT 返回明确“不支持”；三项分片只读用例改为真实只读 IStream／Open 标志，继续要求拒绝修改且原字节不变。其它 PCM、时间轴和保存断言未放宽。

实际宿主在每个系统运行原版 5.7.9 与重建版，各播放 ADIF、LD、显式 88.2 kHz MP4、已成功保存中文标签的 20 秒分片 MP4，共 **24 次**通过。确认加载最终 DLL、请求文件进入播放、播放时间推进、无错误对话框且正常关闭；LD 在短文件结束前观察，分片文件观察超过 10 秒。宿主为静音隔离副本，未将这些检查计为实体扬声器听音或所有输出硬件验证。

私有测试与证据目录：`rebuild/tests/plugins_followup_20261029p3`。`final-validation.json` 核对了所有日志、XP／Win7 回传 DLL、构建／宿主／发行 DLL、ZIP 中 DLL、对应源码及摘要；并确认原版文件和其它已记录插件未变。测试、音频、PCM 和探针不进入 Actions、运行包或源码附件。

## 剩余兼容范围

- AAC Main channel coupling、SSR、任意显式核心频率／7350 Hz 和扩展 AOT 尚未补齐。
- LD480 有声内容、其它 LD 采样率／LTP 组合及更多历史编码器样本尚未完整验证。
- 分片写回不支持任意无预留空间的布局增长；保持真实失败结果，不自动重排所有分片索引。
- ADIF VBR 本地时长仍按码率估算；未知长度流不可任意定位，最多 64 KiB 前读也不等于低延迟直播。
- 动态 ASC、多 sample description、DRM／在线 DASH 仍不在已验证范围。
- MOD、VQF、RM 在 [p2](AUDIO_PLUGIN_FOLLOWUP_20261029P2.md)／[p1](AUDIO_PLUGIN_FOLLOWUP_20261029P1.md) 中记录的其它边界未被本次 AAC 修复自动解决。
