# Plugins-out：Winamp DSP 高规格 PCM 静态分析

日期：2026-10-20。

本轮按用户要求，**Winamp 音效插件链只做分析，分析对象限定为仓库根目录 `Plugins-out` 的 12 个 DLL**。没有修改 DLL、Winamp 宿主实现或插件配置，没有调用插件 Init／Config／ModifySamples，也没有启动播放器或发声。

## 1. 结论

不能统一向这些插件传入 24／32 位 PCM。按本次实际 DLL 的入口及转换分支：

| DLL／模块 0 | 整数 PCM 输入结论 | 声道边界 | 采样率、帧数及其它限制 |
| --- | --- | --- | --- |
| `dsp_compwide.dll`／压缩和展宽 | 仅 `bps=16` 进入处理，其他位深旁路 | 实际核心按单／双声道设计；不能传多声道 | 把采样率截成 16 位存储；96 kHz 等会使用错误值 |
| `dsp_DEE.DLL`／Dee | 仅 `bps=16` 进入处理 | 2 声道为立体声，其它值走单声道步长；不能据此支持多声道 | 分为 `20000 < rate < 30000` 和 `rate > 30000` 两条处理路径；并非任意采样率 |
| `dsp_DeFX.dll`／DeFX | **隐含 PCM16**；入口不检查 `bps`，效果核心按 `short` 读写 | 仅 2 声道调用效果 | 入口未转交采样率；不能认定效果随高采样率正确适配 |
| `dsp_enh.dll`／Enhancer 0.17 | `bps=16` 才处理，其他位深旁路 | 1 声道分支和立体声分支；没有完整多声道路径 | 采样率变化时重算系数，但没有完成高采样率数值验收 |
| `dsp_iZVinyl.dll`／iZotope Vinyl v1.0 | 存在 PCM24／PCM32 整数输入和写回，内部双精度；属于待验证候选 | 单／双声道实现；其它声道不能视为支持 | 初始化根据采样率生成资源；内存、极值、返回帧数和全部预设仍待验证 |
| `dsp_jammix.dll`／JammiX | 仅 `bps=16` 处理 | 仅 1／2 声道 | **`5000 < rate < 99000`，`100 < frames < 65535`**；192 kHz 等旁路 |
| `dsp_neq.dll`／250 段均衡器 | 核心存在 8／16／24 位整数读写；没有 32 位整数转换分支 | 按传入声道交错处理，但完整声道容量未验收；先限单／双声道 | 主回调中另有仅针对 16 位立体声的处理，不能宣称所有功能在 24 位相同 |
| `dsp_OctiMax.dll`／OctiMax | **隐含 PCM16**；包装层没有把 `bps` 交给核心，核心固定 word 读写 | 核心仅接受 1／2 声道 | 活动处理核心对 `<128` 帧返回 0；采样率向下转交，未完成高采样率效果验收 |
| `dsp_so3d.dll`／SoftAmp VirtualSound 1.01 | 仅 `bps=16` 处理 | 仅 2 声道 | 高采样率滤波／延迟等行为未验收 |
| `dsp_sps.dll`／Nullsoft SPS 0.36 | 8／16 位及 24 位分支；**24 位立体声读写有实际字节偏移错误**；32 位整数无完整处理 | 仅 1／2 声道 | 脚本能够改变输出帧数；正常返回不能证明高位深效果正确 |
| `dsp_superequ.dll`／SuperEQ | 明确接受 8／16／24 位，32 位旁路；24 位按 3 字节读写 | 仅 1／2 声道 | 采样率变化时更新滤波器；高采样率频响、延迟仍待验证 |
| `DSP_ViPER’s Audio.dll`／ViPER's Audio DSP | 入口仅接受 `bps=16` | 仅 2 声道 | 采样率变化会重建处理状态；内部 32／64 等数字不是输入位深能力 |

这里的“有路径”均为**静态代码事实，不是实际高位深运行通过**。

适合作为后续高位深验证候选的是 **SuperEQ、NEQ、Vinyl**。SPS 应先单独解决其实际 DLL 的 PCM24 立体声错误，再谈接入。其它插件仍应保持 PCM16 兼容边界。

上一份 [Winamp PCM 精度分析](WINAMP_DSP_PCM_PRECISION_20261019.md) 检查过 `Plugins` 中的 DFX、Ozone 等文件及另一份 SPS 源码。**它们不属于本轮这 12 个文件的身份或能力依据**。特别是：

- `dsp_DeFX.dll` 是 DeFX，不是 `Dsp_Dfx.dll`。
- `dsp_iZVinyl.dll` 是 Vinyl，不是 `dsp_izOzone.dll`。
- 新版 SPS 源码中的实现，不能替代这个旧版 SPS DLL 的字节级检查。

## 2. 证据方法和边界

1. 对 `Plugins-out` 全部 12 个 DLL 新算 SHA-256，逐个与先前恢复清单、静态分析清单核对。
2. 复用哈希相同的完整 Ghidra 伪代码，读取原 DLL 的 PE 数据及指令交叉确认。
3. 读取旧的、与当前哈希绑定的模块枚举记录。这 12 个 DLL 在该记录中均只有模块 0；本轮没有重新执行模块枚举。
4. 对 11 个文件，在当前磁盘字节中重新读取 module 结构并核对四个回调地址；JammiX 的 module 由初始化代码填充，另追到 `0066D5FC = 0047DE04` 的静态赋值。
5. 对 SPS／NEQ 核心用 REA 6.5.0 + Ghidra 12.1.3 做新鲜反编译。REA MCP 本轮未接入；只用现有 CLI／Ghidra，没有修改注册或安装分析服务。
6. 对伪代码未识别、或把运行时状态错误折叠为“不可达”的块，以 DLL 原始指令、栈参数和调用关系为依据。例如 SoftAmp 旧反编译删除了大量可达处理块，不能把那段输出直接当完整函数。

私有证据目录：`rebuild/tests/hires_pcm_20261020/plugins_out/`。`inventory.json` 记录本轮文件身份、回调、旧伪代码路径及摘要。测试／分析辅助代码不加入发行包或 Actions。

旧证据：`rebuild/tests/artifacts/dsp_restore/deletion_audit/decompiled/`、`validation.json`、`pec/validation.json`。本轮核对它们的目标哈希一致，不把旧运行结果写成本轮执行。

## 3. 接口本身不能当作能力查询

经典回调：

```cpp
int ModifySamples(Module* module, short* samples, int frames,
                  int bps, int channels, int sample_rate);
```

- `short*` 是历史声明。具体插件可用 `bps` 解释打包 24 位或 32 位整数，不能仅凭指针声明判断。
- `bps=32` 不代表 float32。经典接口没有整数／浮点枚举。
- 插件内部使用 double／float，不证明其入口接受对应高位深。
- 返回输入帧数可以表示旁路。需要区分效果生效、旁路、错误返回和变长输出。
- 一条链中只要经过一次 PCM16 量化，之后扩成 24／32 位容器也不能恢复丢失低位。
- 高位深、高采样率、多声道、任意块长是四个独立能力，不能用其中一项代表其它项。

## 4. 每个插件的关键证据

以下地址均为文件首选 ImageBase 下的 VA，实际加载重定位后地址可能变化。

### 4.1 CompWide：16 位和采样率截断

`ModifySamples = 10002CF7`。

- `10002D10`：比较栈上的 `bps` 与 `0x10`；不相等转到返回帧数。
- `10002D16` 取出 32 位 `sample_rate`，`10002D19` 仅将 `AX` 写入 `10004040`。
- `10001D9A` 的工作数组为两个整数，单／双声道处理使用这个数组；入口没有为大于 2 声道建立安全的通道布局。
- 其它处理代码确实读取 `10004040` 进行系数／计数计算，因而不是一个无关的显示字段。

推论：96,000 写成 30,464，192,000 写成 60,928；不能用“没有拒绝高采样率”证明它在按正确采样率处理。

### 4.2 Dee：16 位，且采样率分支不连续

`ModifySamples = 100052D0`。

- `10005305` 检查 `bps=16`，随后 `10005312` 比较采样率与 30,000。
- 另一处理分支要求 `20000 < rate < 30000` 且仍为 16 位。
- 采样读取和写回都是 16 位。2 声道之外走的是单声道步长，不是任意多声道实现。
- 返回 `frames`。24／32 位即便返回正常，也没有进入相应 PCM 音效处理。

高于 30 kHz 的分支能到达，不等于 96／192／384 kHz 具有已验证的相同频响、延迟和数值稳定性。

### 4.3 DeFX：忽略位深不等于支持所有位深

`ModifySamples = 10002AF0`。

- `10002AF9` 只检查 `channels=2`。
- 将 `frames*2` 和数据指针交给 `100017F0`，没有转交 `bps` 或采样率。
- 效果表位于 `1000B2D8`，四个处理回调为 `100027C0`、`10002140`、`10001F50`、`100023C0`。
- 这些核心直接按 `short` 读取和写回，限幅到约 ±32768。

结论：它需要 PCM16 立体声。向它传打包 PCM24 会把连续字节错误拆成 16 位样本；不是安全旁路。此插件不能与 DFX 的高位深转换代码混为一谈。

### 4.4 Enhancer 0.17：双精度内部、16 位入口

`100068F0 → 10001430`。

- 包装层转发帧数、位深、声道、采样率。
- `10001430` 中 `bps==16` 才进入样本处理，数据为 `short*`。
- 单声道有专门分支，其余活动分支按立体声读写。
- 采样率变化时更新状态并调用 `10002E60` 重算参数。

内部大量 double 运算不改变入口的 PCM16 限制。返回值低 32 位为输入帧数；Ghidra 所显示的 `undefined8`／额外寄存器参数不是另一个 Winamp ABI。

### 4.5 Vinyl：存在高位深转换，需要独立验收

`10003150 → 100031A0`，格式初始化 `10002CF0`，读入 `10001000`，效果 `100051C0`，写回 `100033F0`。

- 初始化将格式设为 `WAVE_FORMAT_PCM=1`，字节数为 `(bps+7)>>3`。
- 1、2、4 字节具有专门转换，3 字节走符号扩展及逐字节组合分支。
- `100010FF` 是 `FILD DWORD PTR [ECX]`：32 位输入按整数读取，再乘归一化系数，存入 double。不是把整数缓冲当 float32。
- 写回存在 4 字节整数和通用多字节路径。采样处理数组使用 double。
- 单声道复制到内部左右声道；其它处理按双声道布置，不应传入多声道。
- 初始化／分配失败可返回 0 或 HRESULT 数值；成功时取内部处理返回的帧数，并非所有路径恒等于输入帧数。

这使它成为 PCM24／PCM32 的静态候选，但还没有验证满幅边界、只在低位不同的输入、全部预设、内存分配失败、采样率变化及返回值。没有把它列为“高规格运行已通过”。

### 4.6 JammiX：有明确采样率和块长门槛

`0047DE04 → 0047DE28`。

原始指令依次检查：

```text
0047DE6C / 0047DE72  channels == 1 或 2
0047DE7C            bps == 16
0047DE86            frames > 100
0047DE90            frames < 65535
0047DE9D            sample_rate > 5000
0047DEA9            sample_rate < 99000
```

不满足条件走返回路径。96 kHz 只满足采样率门槛，仍不代表全部效果已通过；192 kHz 明确不满足。短尾少于或等于 100 帧时可能旁路，不能把这种行为误诊为宿主漏调用。

### 4.7 NEQ：24 位核心和 16 位附加处理应分开

`ModifySamples = 0040A330`，PCM 核心 `0040B274`。

- 核心分别处理 8、16、24 位；24 位输入按 3 字节组合，第三字节有符号扩展，写回也是三字节。
- 内部频域数据大量采用 float32。接受 PCM24 不代表整数全链无损。
- 在 `0040A60F`／`0040A619`，主回调另对“双声道＋16 位”开放一个附加样本处理分支。24 位不会进入它。
- 核心函数正常返回已处理块长和余量之和。没有发现对应的 32 位整数转换分支。

NEQ 可作为 PCM24 核心的候选；具体设置、附加功能一致性、滤波器在高采样率的响应以及多声道存储容量仍待验证。

### 4.8 OctiMax：包装省略 bps，核心实际为 16 位

`100010FA → 1000C950`。该包装将数据指针、帧数、声道和采样率交给对象虚表 `+0x18`，**没有传递 `bps`**。

对象链：

```text
1000BE10 初始化 → 10016500 分配 → 10016640 构造
→ 主虚表 1006A078
→ +0x18 = 10016B50
```

`10016B50` 的证据：

- 只接受 1／2 声道；不满足返回 0。
- `10016BEC` 检查输入帧数至少为 128；小于 128 返回 0。
- `10016C67`／`10016C74` 用 `MOVSX ... WORD PTR` 读取双声道，输入指针每次加 2。
- 写回也是 word。没有通用高位深布局。
- 正常尾部 `1001700C` 返回输入帧数。

推论：不能传 PCM24／PCM32；也不能用忽略返回帧数来掩盖短块返回 0 的情况。未来若扩展宿主帧队列，要区分插件的短块门槛和真正变长输出。

### 4.9 SoftAmp VirtualSound：明确只接受 16 位立体声

`ModifySamples = 10011FB0`。

- `10011FD9` 检查 `bps=16`。
- `10011FE2` 检查 `channels=2`。
- 其它格式跳到 `10012BC6` 返回路径。

这里采用原始指令证据。旧 Ghidra 伪代码对大量全局状态做了不适当的不可达折叠，不能据此说插件“完全不处理”。本轮没有建立其高采样率频响、延迟或所有内部固定缓冲容量的运行证明。

### 4.10 SPS 0.36：实际 DLL 的 PCM24 立体声有错位

`10003A70 → 10004B80`。包装传 `isfloat=0`，允许最大输出帧数约为输入两倍。

常规整数读取有 8、16、24 位路径；内部 float32／float64 分支依赖另一个 `isfloat` 参数，**Winamp 包装没有启用它**。32 位整数没有完整的样本读入／处理实现。

本轮新鲜反编译和原始机器码同时确认，24 位双声道路径将右声道放在错误的字节偏移：

```text
正确 PCM24 立体声一帧： L0 L1 L2 R0 R1 R2
正确偏移：             +0 +1 +2 +3 +4 +5
此 DLL 使用的右声道：      +1 +2 +3
```

读入证据：

- `10005146`／`1000514B` 计算帧基址偏移 `frame*6`。
- 左声道 `1000514F`／`10005153`／`10005156` 取 `+2/+0/+1`。
- 右声道 `1000518D`／`10005191`／`10005195` 取 `+3/+1/+2`，而不是 `+5/+3/+4`。

写回证据：

- `10005531`／`10005534` 同样计算 `frame*6`。
- 左声道写 `+0/+1/+2`。
- 右声道正常分支 `10005607`／`1000560B`／`10005612` 写 `+1/+2/+3`；限幅分支也使用相同错误布局。

这是**实际输入布局与指令访问不一致的静态缺陷**，不是“可能只因反编译类型错误”。但本轮没有执行 DLL，没有宣称某个用户预设已在运行中触发。

因此：

1. 此 SHA 的 SPS 不能进入“PCM24 立体声已验证”名单。
2. PCM24 单声道是另一分支，仍应单独验证，不能用它证明双声道正确。
3. `skip`／`repeat` 脚本会改变帧数；返回值必须单独建模。
4. 不修改用户要求“只分析”的链路或 DLL。后续修复需要单独授权和实际样本验证。

### 4.11 SuperEQ：明确的 PCM24 候选

`10003E70 → 10004A90`。

- 入口先检查 1／2 声道，再检查位深为 8／16／24，否则返回输入帧数。
- 采样率改变时执行 `10004580` 更新滤波器；格式改变时清理状态。
- 24 位核心采用每样本 3 字节步长，最高字节符号扩展，输出同样拆为三个字节。
- 内部有 float32 频域缓冲；32 位整数不在接受集合中。
- 包装最终返回原输入帧数。

应验收高采样率下滤波器频响、处理延迟和 24 位舍入，而不能从“支持 24 位”推导出“所有高规格完全保持”。

### 4.12 ViPER：内部处理精度不改变入口限制

`ModifySamples = 10009090`。

- `10009096` 检查声道为 2。
- `100090A9` 检查 `bps=16`。
- 不匹配即转向 `100092FB` 的返回路径。
- 后面的 `0x20`、`0x40` 等选择涉及内部处理分块，不能把它们当作 32／64 位 PCM 输入支持。
- 采样率改变会更新状态，并以双声道参数重新初始化处理。

## 5. 对当前高规格输出改造的约束

用户本轮限定 Winamp 只分析。因此高精度播放实现应：

1. 保留 Winamp 原有 16 位兼容桥接，不把这些静态候选直接变成启用名单。
2. “高精度内部处理／设备输出”与“Winamp 输入精度”分别报告。启用此链时明确存在 PCM16 边界。
3. 原样输出策略若要求样本不变，遇到启用的 Winamp 音效应明确拒绝该组合或要求关闭效果，不能悄悄处理。
4. 设备输出 24／32 位只能说明设备流格式，不能表示启用插件后仍保留同样的有效精度。
5. 不以高位深未知数据试探真实播放中的插件。

建议的未来验证顺序为 SuperEQ PCM24、NEQ PCM24、Vinyl PCM24，之后才考虑 Vinyl PCM32；SPS 单列缺陷处理。对应记录必须绑定 DLL SHA-256、模块编号、位深、采样率、声道、块长范围、是否改变帧数和验证结果。

不能将这里的顺序理解为已经修改宿主策略。

## 6. 尚未完成的运行验收

本轮“已完成”是 12 个确切文件的入口、格式转换、关键边界和部分错误路径静态分析，不是完整音效插件认证。

仍需单独执行：

- 启用实际效果后的 PCM16／PCM24／PCM32 数据验证，避免只测默认旁路。
- 全零、低位差异、正负满幅、削波、不同左右声道及长时间连续块。
- 96／192／352.8／384 kHz 的系数、频响、延迟、内存与 CPU 验证。
