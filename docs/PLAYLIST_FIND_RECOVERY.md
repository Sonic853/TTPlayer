# 播放列表“查找”功能恢复

日期：2026-09-25。

本次范围是播放列表“查找”菜单中的快速定位 `0x7F3B`、查找歌曲 `0x7F39`、
查找下一个 `0x7F3A`，包括资源 203 的输入、标记全部、反向、历史和关闭。
不把“添加 → 搜索本地文件”（资源 228）混入本次搜索。

## 1. 原版调用链与实际规则

依据 `reverse/decompiled/TTPlayer.exe.pseudo.c`，并用原始 `TTPlayer.exe`
的 x86 反汇编核对伪代码中遗漏的寄存器、参数和字段名。

| 原版函数 | 行为 |
| --- | --- |
| `00486056` | 关闭已经存在的查找框，记下首个选中行，设置普通/快速标志，再以无禁用父窗口的方式打开资源 203 |
| `004544FB` | 恢复三个组合框及历史。快速模式只留标题框、标记全部和提示，调整位置并将客户区高度减半 |
| `00454760` | 快速模式收到标题框 `CBN_EDITCHANGE` 后读取内容，发送 `0x7F3A` |
| `00454809` | 普通“查找下一个”读取三项文本和三个复选框、更新历史，以普通单项搜索执行 |
| `004548D8` | “标记全部”读取内容并更新历史；快速模式完成后关闭窗口，普通模式保留窗口 |
| `00454A06 / 00454381` | 关闭窗口时收集已使用的组合框历史，并返回播放列表窗口 |
| `0047AFDA` | 标题为空且没有有效的艺术家/专辑条件时直接返回；快速模式不考虑隐藏的另两栏 |
| `004860E5` | 快速模式固定传入“全部匹配”；普通模式通过 `0042CA79 / 0042CB90` 启动带进度的工作线程 |
| `004826AD` | 比较各字段并更新行的选择/焦点状态；单项搜索命中时清除其它选择并显示该行 |
| `0048287B` | 普通查找从首个已选中项的相邻行开始，支持正反向；全部搜索按行号从头处理 |

### 匹配条件

`004826AD` 先检查显示标题，再检查原始 `Title`。普通模式额外检查
`Artist`、`Album`，各个非空条件按 **OR（或）** 合并。
反汇编的 `0048272E / 0048278A / 004827D7` 分别引用这三个 ASCII 字段名，
不能仅根据伪代码里的三次 `0040A901` 猜测字段含义。

`0047FCB6` 的两个标志分别控制大小写和全字段匹配；“全字符匹配”比较整个
字段是否相同，不是英文单词边界。空白字符也是查询内容，不自动裁掉。

快速窗口中的“汉字拼音首字母”提示指的是**播放列表自身的键盘定位**。
那条路径是 `00488A1F / LVN_ODFINDITEMW`，重建版已有
`LegacyPinyinPrefixMatches`；不能据此把资源 203 的子串查找改成拼音匹配。

### 选择、焦点和滚动是三个状态

二进制 `00482981` 将 `2`（`LVNI_SELECTED`）传给 `LVM_GETNEXTITEM`，
不是 `1`（`LVNI_FOCUSED`）。因此多选时应从**第一个选中项**继续。

快速定位逐行写入 `state=3, mask=0xB`，最终保留全部匹配项，最后一个匹配项
持有焦点；随后 `00486142–0048615E` 再次找**第一个选中项**并执行
`LVM_ENSUREVISIBLE`。最终焦点在后面，不代表界面应该滚到最后一个结果。
这些程序化状态操作也不会重设鼠标/Shift 的选择锚点。

### 普通搜索的工作窗口

`0042CA79` 构造 240×65 对话框单位、9 磅宋体的动态模板；`0042CCAD`
创建当前文件文字、进度条和终止按钮。`0042CE94` 使用 `_beginthreadex`，
`0042CC1A` 查询取消事件。`0x8198` 是“正在查找文件…”的进度标题，
`0x8193` 才是未找到匹配文件的提示。

普通搜索在工作线程中调用 `004AE7FD(...,1)`，可以刷新歌曲信息；
快速定位的直接匹配路径使用缓存。此前仅复原查找框外形和部分匹配逻辑，
未复原此工作窗口，不等于搜索功能已经完整。

## 2. 本次发现及修复

| 重建版原有问题 | 本次修改 |
| --- | --- |
| 快速定位全选后滚到最后一个结果 | 保留全部选择和末尾焦点，单独显示第一个匹配项 |
| 普通下一首从焦点行继续，多选时跳错位置 | 按首个已选中行确定查找起点 |
| 快速模式的“查找下一个”只选一个；查找框开着时还会模拟默认按钮并关闭 | 按原版快速分支重新标记全部，保持查找框打开 |
| 空查询的下一项命令会新开查找框 | 按 `0047AFDA` 直接返回 |
| 标题查询使用 128 字符固定数组 | 改为动态字符串，三个组合框统一按实际文本长度读取 |
| 原始元数据包内的 `Title` 没有参与比较 | 与显示标题、模型标题一起参与匹配；艺术家/专辑规则保留 |
| 快速定位从历史下拉框选值后没有实时更新 | 处理 `CBN_SELCHANGE`，等组合框完成文字更新后再搜索 |
| 历史的内存去重与组合框的大小写规则不同 | 统一按组合框的不区分大小写规则去重 |
| 全部标记时重写 Shift 锚点，未同步当前行记录 | 恢复选择、焦点、锚点各自的语义，并更新播放列表当前行 |
| 普通搜索同步遍历，缺少进度和取消 | 增加原动态模板布局的进度窗口，匹配在后台线程执行 |
| 尚未读取的标题/艺术家/专辑无法命中 | 普通搜索经可复用的隔离读取会话加载标签，并安全更新模型缓存，供之后快速定位复用 |

普通搜索匹配失败时清除被扫描行的旧选择，完整无匹配时显示 `0x8193`；
快速定位无匹配时清除选择，不弹框。空查询继续保留现有选择。
查找和标记操作不调用播放入口，即使启用了“播放跟随光标”也不主动播放。

## 3. 并发和边界处理

- 搜索线程读取曲目值副本，不直接访问可变播放列表或跨线程修改 HWND。
  UI 线程分批应用结果、更新当前文字和进度；普通标记全部可以中途终止。
- 标签读取复用已有 `PlaylistInfoProbeSession`，沿用嵌入式子进程隔离、
  MP3 读取优先级、CUE 子曲目参数及取消机制。快速定位不进行磁盘标签读取。
- 应用结果前检查当前模式、播放列表槽位、行序版本和数量；媒体库还核对行
  对应的路径及子曲目。切换/重排/删除导致映射变化时取消本次结果投递。
- 标签读回后仅当当前曲目仍等于读取前的副本才写回，保留用户编辑或常规
  信息加载器的更新。读取完成的歌曲可立即被随后的快速定位查到。
- 阻止嵌套重复搜索。主窗口销毁会结束搜索进度框和查找框；线程退出前不销毁
  它使用的副本。取消保留已完成的选择变化，不继续修改其它行。

### 与原实现的明确取舍

保留匹配字段、模式分流和选择语义，但不声称所有内部时序完全相同：

1. 原 `0048287B` 的无匹配终止还依赖打开查找框时记录的 `+0x188`。
   重建版按**本次起点最多扫描一轮**设定终止边界，避免旧起点导致提前报告
   未找到或重复扫描；支持从末端回到开头、反向从开头回到末端。
2. 原线程直接访问窗口和曲目对象；重建版使用副本及 UI 线程分批投递，
   进度按本次已检查的数量增长，不复刻原版回绕时进度值回退的表现。
3. 对未读取的本地曲目补读标签；已加载曲目沿用重建版现有的信息更新机制，
   不复制原缓存刷新时间戳的所有内部策略。窗口布局已恢复，未宣称各系统
   主题下的外观逐像素一致。

## 4. 验证

Windows 11 普通版、XP 虚拟机及 Win7 虚拟机兼容版均通过同一组本地回归：

- 普通/快速窗口反复打开、退出及父窗口可用；普通三项条件 OR、大小写和
  全字段匹配；仅艺术家或专辑条件的下一项命令。
- 真实原生 ListView 的多选集合、单一焦点、Shift 锚点，以及首个匹配项可见。
- 正向、反向和两端查找；600 字符标题输入、元数据包 Title；历史下拉选择；
  快速模式下重复命令保持窗口打开；空查询、无匹配提示及选择清理。
- 20,000 多条曲目的搜索取消、嵌套命令保护，以及搜索期间重排列表不会应用
  旧行号结果。
- 真实 MP3 文件起初只提供路径，普通搜索读取并找到 `SMTC Fixture` 标题；
  确认缓存更新后快速定位也能命中。
- 普通搜索和快速定位均不会触发播放。宿主机既有框选/菜单回归通过。
- 普通版、兼容版 Release 构建通过；XP/Win7 导入审计通过：19 个 DLL、
  656 个导入项，子系统 5.01。
