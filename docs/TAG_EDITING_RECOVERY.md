# 标签编辑修复与验证

日期：2026-10-02。

依据：[原版标签编辑分析](ORIGINAL_TAG_EDITING_ANALYSIS.md)。本次按其中的建议顺序修复元数据映射、MP3 策略、保存完成判定及播放中编辑协调。原有界面、批量差异编辑、只读确认和隔离工作进程继续使用。

## 1. 原生字段与别名

补齐以下字段的读取、写入、修改和删除，不再将它们一律保存为自定义 TXXX：

| 字段 | ID3v2 帧 | 旧版帧 |
| --- | --- | --- |
| Subtitle | TIT3 | TT3 |
| Copyright | TCOP | TCR |
| Composer | TCOM | TCM |
| Conductor | TPE3 | TP3 |
| Publisher | TPUB | TPB |
| Encoder | TENC | TEN |
| WWWUSER | WXXX | WXX |

原版表 `0053CD70` 中 `TPE2` 的名称是 `Orchestra`。重建版将 `Orchestra`、`Album Artist`、`AlbumArtist` 归到同一字段，继续以 `AlbumArtist` 对接现有界面和 SMTC；SMTC 也接受插件直接提供的 `Orchestra`。

同一 ID3 标签同时包含专用帧和旧 TXXX 别名时，读取优先采用专用帧；保存会清理重复表示，只写一份对应的专用帧。这是明确的兼容规则，不声称复现原版所有重复帧顺序。自定义字段、未修改的未知帧仍按既有规则保留；压缩／加密帧等不能安全重写的结构拒绝改写。

`WWWUSER` 的描述与 URL 字节分别处理，避免把 URL 当成一般 TXXX 正文。`Lyric/Lyrics`、`Author/Artist`、`Track/Tracknumber`、`Year/Date` 也统一别名。

## 2. MP3 策略和 Lyrics3

### 2.1 自动追加 APEv2 与填充

- 对照 `004D9B56`、`004D9932`、`004D9979`：未选择 ID3v2，且有非空 ReplayGain 或歌词字段时追加 APEv2；仅有 Title、Composer 等不再自动触发。
- 对照 `004DCA1E`：启用填充时，普通 ID3v2 最低总空间为 1024 字节，仍含歌词的 ID3v2 为 2048 字节；保留更大的已有空间，实际帧更大时按实际需要分配。
- 封面单独处理。已有或新封面无法存入 ID3v1 时，保留 APEv2 封面载体，避免只改标题却丢掉图片。这是重建版保留的安全策略，不从原版文字字段条件推断封面规则。
- 修复 ID3v1 超长字段转换失败后写空：按完整字符填满定长区域，不截断多字节字符。ID3v1 仍有格式本身的长度及字符集限制；不能完整保存的值会被回读校验识别。

### 2.2 Lyrics3 读取与回写

`004DA9F2` 对应的 Lyrics3 v2 已纳入读取优先级类型 `2`：支持 `LYR`、`INF`、`ETT`、`EAR`、`EAL`，分别对应歌词、备注、标题、艺术家、专辑。逐项校验十进制长度、起止标记及文件边界；支持 APEv2／Lyrics3／ID3v1 等尾部组合。无效块不会被当作合法标签裁掉。

补充核对 `004DC39E`／`004DBBEF` 后，恢复了之前遗漏的写入分支：

1. 写入类型含 ID3v1 且有歌词时，将 Lyrics 从通用字段集合取出。
2. 按 `LYRICSBEGIN + IND00003110 + LYR + 五位长度 + 正文 + 六位块长度 + LYRICS200` 写出。
3. 顺序为 ID3v2、原音频载荷、APEv2、Lyrics3、ID3v1；已移到 Lyrics3 的歌词不再重复写为 USLT／APEv2 Lyrics。
4. 不选择 ID3v1 时，歌词由所选 ID3v2／APEv2 承载。
5. 编辑或删除时移除旧的已识别歌词块，避免低优先级旧值再次出现。

歌词正文保留空格和换行。可用系统 ANSI 编码表达时沿用该编码；发生替代字符时采用 UTF-8，由读取端检测。UTF-8 回退是保留 Unicode 的兼容改进。超过五位长度上限的正文拒绝写入，原文件保持不变。

## 3. 保存结果以重新打开后的内容为准

原版 `004D9E23 → 004D9A59 → 004D9B56` 说明 `SetValue` 与落盘不一定同时发生。现在隔离工作进程执行：

```text
设置字段及封面 → 释放写入对象 → 重新打开 → 读取实际字段／封面 → 返回逐项结果
```

插件、内置 MPEG 写入器和 CUE 路径均核对实际保存结果。部分插件只在 GetValue 暴露扩展字段，重新打开后还会逐个查询请求字段。

- 接口接受了字段，但重开后不存在、仍为旧值或内容被截断，按该字段保存失败处理。
- 已成功的字段更新编辑基线；失败的字段保留草稿，属性窗口不自动跳到下一首。
- 封面替换、删除分别按实际图片字节确认。
- CUE 删除分轨 Artist 后会继承全局 PERFORMER，按此有效值校验，避免误报失败；不会修改 FILE 指向的音频文件。
- 这不是跨文件事务。部分字段或前面的文件已经保存时，后续失败不会撤销已完成的保存。

MP3 仍使用同目录临时文件、刷新后替换原文件，不重编码音频。密集回归捕获到替换阶段偶发 `ERROR_ACCESS_DENIED`，因此针对拒绝访问／共享冲突／锁冲突增加有限重试（最多额外等待 200 毫秒），其余错误立即返回；持续失败保留草稿。写入错误码在关闭临时句柄前保存，避免被清理操作覆盖。未关闭系统保护或更改目录权限。

## 4. 播放中编辑

原版 `004AD25D` 可取得当前 reader；重建版使用隔离进程，无法直接共享该对象。本次采用以下协调方式：

| 操作 | 修复后的行为 |
| --- | --- |
| 保存正在播放的文件 | 保存进度与播放状态，释放对应读取句柄，完成写入及验证后重开并恢复 |
| 保存已暂停的文件 | 同上，恢复后继续处于暂停状态 |
| 保存其它歌曲 | 当前歌曲继续播放 |
| 对当前歌曲点击“重新读取” | 释放读取句柄并停止播放，按 `0043376F` 的显式重读路径处理 |
| 普通打开属性／保存后自动回读 | 不额外触发显式重读的停播动作 |

保存期间阻止切歌、关闭主窗口和自然结束推进等与写入冲突的操作，释放仍可能占用文件的淡出引擎。CUE 同时检查对应底层音频路径。恢复前核对播放引擎、已打开曲目和待播放曲目身份，防止恢复到已换掉的歌曲。

释放和重开可能带来短暂声音间断；这里恢复的是合理播放状态，不能称为无缝热更新，也不能保证所有第三方插件可按相同精度定位。
