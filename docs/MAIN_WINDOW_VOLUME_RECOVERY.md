# 主窗口滚轮与手动输入音量

日期：2026-09-25。

## 原版行为

依据 `reverse/decompiled/TTPlayer.exe.pseudo.c`，并核对原版 EXE 对应反汇编：

| 地址 | 已确认的行为 |
| --- | --- |
| `004582D0` | 主窗口收到 `WM_MOUSEWHEEL (0x20A)` 时分派到 `00460D1D`；`WM_HSCROLL/WM_VSCROLL` 共用 `00460AB1`。 |
| `00460D1D` | 读取 `wParam` 高 16 位的**有符号**滚轮量，整数除以 `0x28`（40），加到当前音量，限制到 0～100，然后同步音量滑块并发送 `SB_ENDSCROLL`。 |
| `004654D7`、`00465524` | 菜单/快捷键的增大、减小音量为 ±5，走同一滑块通知链；它们与滚轮的步长不同。 |
| `00460AB1` | 从音量滑块读取保存值。只有未静音时才向播放引擎设置该音量，调节滑块不会解除静音。 |
| `0046534B` | 静音独立于音量值；解除静音恢复**当前滑块值**，而不是进入静音之前的历史值。当前滑块值为零时仍恢复零。 |

因此，原版的常见滚轮输入如下：

| 输入 delta | 音量变化 |
| ---: | ---: |
| +120 / -120 | +3 / -3 |
| +240 / -240 | +6 / -6 |
| +40 / -40 | +1 / -1 |
| -39～+39 | 0 |

这里的整数除法向零截断，每条消息独立处理，不累计不足 40 的余量。
原版此分支也没有 Ctrl/Shift 改为快进、切歌的逻辑。

## 重建版问题与修复

1. 主窗口没有 `WM_MOUSEWHEEL` 分支，皮肤背景收到滚轮后无法调整音量。
   补齐原版的 `delta / 40` 处理、上下限和滑块刷新。
2. 先前只有播放列表的悬停滚轮转发；XP/Win7 焦点仍在列表或其它控件时，
   指针移到主窗口后可能继续滚动原控件。将路由扩展为 `RoutePlayerMouseWheel`，
   悬停主窗口及其视觉/音量子控件时交给主窗口音量处理；播放列表优先保留自身滚动。
3. 新路由只处理本线程收到的消息，使用消息内的屏幕坐标；命中已正确寻址的主窗口
   时不重复转发。不抢焦点，不绕过鼠标捕获、模态禁用、隐藏或其它窗口遮挡。
   这是重建版为 XP/Win7 输入派发增加的兼容处理，不宣称原版有同样的悬停转发器。
4. 增大/减小音量、皮肤滑块原先会强制取消静音，原生滑块则可能在静音标志仍为真时
   输出声音。新增 `SetPlaybackVolume`，统一保存音量、应用静音后的有效增益、同步原生
   滑块及刷新皮肤。菜单 ±5 步长保持不变。
5. 删除 `volume_before_mute_` 的旧值恢复逻辑，修复静音期间调到 0 后解除静音突然
   恢复旧音量的问题。

## 滚轮通知与状态提示补全

上一轮只同步了音量数值、滑块和输出，遗漏了原版滚轮最终发出的滑块通知。因此数值
虽然变化，主窗口却没有显示对应的音量文字。此外，拖动音量滑块时仍可被滚轮改值。

### 原版调用链

1. `00460D1D` 将有符号 delta 除以 40，更新全局音量，再调用 `00428DCD` 设置滑块。
2. `00428DCD` 在滑块 `+0x3C` 非零时拒绝程序改值。结合 `004521C5`、`00452326`、
   `00452295` 可确认这是滑块的拖动标记，并非禁用标记。
3. 随后发送 `WM_HSCROLL`（竖直皮肤为 `WM_VSCROLL`），通知码为
   `SB_ENDSCROLL (8)`。即使已经到上下限，或者 delta 不足 40，仍发送通知。
4. `00460AB1` 重新读取滑块值，应用未静音时的输出音量，以原版资源 `0x81BC`
   格式化音量百分比，写入主窗口状态控件 `+0x1A98`。
5. 原版滑块拖动只在数值变化时发送 `SB_THUMBTRACK (5)`；释放滑块时发送
   `SB_THUMBPOSITION (4)`。`00460AB1` 对 4 恢复 `+0x4380` 保存的播放状态，
   对 8 则显示音量提示，不能把这两种“结束”通知混为一谈。
6. `0045BF4B`、`0045C0C6`、`0045C198`、`00461F87` 在播放/停止/暂停/音频通知时
   重写状态；`0046010E` 还负责错误提示到期后的清理。没有发现原版专用的音量提示
   消失计时器，普通刷新不会主动清除该文字。

### 本次恢复与用户追加功能

- 滚轮、菜单音量增减、手动输入显示同一份音量百分比；保持静音、不累计小 delta、
  保持滚轮 ±3 与菜单 ±5 的区别。
- 拖动音量控件时阻止滚轮/菜单改写当前滑块值，但仍允许更新提示文字。
- 原生后备控件和皮肤绘制共用状态文字，刷新不再覆盖提示。均衡器和音量共用同一
  状态栏，释放滑块恢复播放状态，不会重新露出上一次音量提示。
- 新的播放、暂停、继续、停止、失败和错误提示清除会替换音量提示；同一状态下
  重新打开曲目也清除旧提示。
- **根据用户追加要求新增 2 秒消失计时器**：每次调整重新计时，超时恢复当前播放
  状态。拖动期间保留，释放后恢复。此计时器属于新增行为，并非原版恢复项。
- 原生 trackbar 的 `TB_ENDTRACK` 是真实鼠标/键盘操作结束通知，与原版皮肤用 8
  模拟的滚轮通知来源不同，因此后备控件按操作结束恢复文字，滚轮分支则显示提示。

## 新增“手动输入”

此项是用户要求的新增功能，不属于原版菜单。

- 在真正构建完成的主窗口菜单中，找到“静音”所在的音量子菜单，直接在其上方
  插入“手动输入...”。重复准备菜单不重复添加，继续使用现有菜单绘制样式。
- 命令 ID 为 `0xB670`，避开原版命令、动态曲目/皮肤、显示器和项目链接命令。
- 使用 WTL 模态资源对话框，标题为“更改音量”，只保留一个输入框、“更改”按钮和
  标题栏关闭按钮。默认显示当前保存音量并选中输入内容。
- 接受 0～100 的整数；空值、负数、小数、越界值及混合文本会禁用“更改”按钮。
  不会把 `50abc` 之类的文本部分解析为 50。
- 只有按“更改”才更新音量。Esc、标题栏关闭按钮均保持原值。
- 静音期间也可以输入数值，但保持静音；解除静音后使用新值。
- 继续保存现有的音量配置字段，无需迁移设置文件。
