# 强制使用重建核心与体积优化

实施日期：2026-10-08；本地版本：`2026.10.08p3`。

## 更新方式

按用户确认的方式，首次**退出播放器，手动解压完整播放器发行包到原安装目录**，同时替换 `TTPlayerRebuild.exe`、`TTPUpdater.exe`、`ttpcomm.dll`，合并 `AddIn`。包中的 `SHA256SUMS.txt` 用于校验，不是运行依赖。原安装中的资源、其他插件和设置继续使用。

新 EXE 已强制要求重建核心，不再支持搭配原版 DLL 或缺少运行接口的旧重建 DLL。不要只替换 EXE，也不要用只更新 EXE 的旧更新器完成本次升级。新版更新器后续会安装播放器包中除根目录 `SHA256SUMS.txt` 外的全部文件，具体事务和回滚规则见 [更新器实施记录](RELEASE_UPDATE_IMPLEMENTATION.md)。

Actions 默认仍解析 TTPlayerComm 的最新正式版，随后核验 SHA256、原有导出、新运行接口及 XP/Win7 导入。**发布顺序必须是先发布带新接口的 TTPlayerComm，再构建/发布播放器**。远端 latest 尚未包含新接口时，构建会明确失败，不会降级打出缺核心的包。本次只生成本地成品，没有提交、推送或发布远程 Release。

## 已实施的拆分

| 范围 | DLL 内的实现 | 宿主保留的职责 |
|---|---|---|
| 压缩与 CRC | 新增有边界的 raw/zlib 解压、输入/输出字节数、CRC32；标准压缩 ID3 帧也在 DLL 内解压 | ZIP 路径、SHA256、文件替换策略；皮肤继续走旧接口的兼容规则 |
| PCM | 8/16/24/32 位整数、32/64 位浮点解码；两种幅度域；有效位、帧填充；旧效果链编码和增益 | 分配块缓冲区、设备与插件调度、错误提示 |
| 最终量化 | 整数输出、浮点输出、原版噪声表和整形系数、抖动状态、Reset | SSRC 管线、队列排空和 EOF 调度；每块调用一次 DLL |
| 标准标签及封面 | ID3 帧边界、扩展头、反同步、压缩帧、PIC/APIC、FLAC PICTURE 原语 | GBK/ANSI 兼容策略、多值标签、文件事务、图片解码与显示 |
| 更新器链接 | 更新器继续静态包含独立 zlib | 将公共 SHA256 移至 `update_hash.cpp`，播放器不再因插件哈希间接带入解压器常量 |

没有将标准 ID3 解析替换成旧 ordinal 53 的 libid3tag 行为。两者历史规则不同，强行合并会重新引入中文编码、v2.4 尺寸或私有帧问题。新接口使用指针、固定宽度计数和不透明句柄；STL 容器不跨 DLL 边界。压缩标签产生的内存由 DLL 自己释放，普通未压缩帧可直接借用输入缓冲区。

Base64、UTF-8、ZIP 目录结构和少量格式描述仍为 SDK 小型辅助函数。视觉效果特有 FFT 没有改用普通频谱接口：两者精度和状态并不等价。没有为了缩小 EXE 把 UI、设置和文件保存事务塞进通用 DLL。

## 运行时约束

- 新增具名导出 `ttpcomm_query_runtime`，ordinal 501，运行 ABI 1，要求压缩、PCM、标签能力位全部存在，逐项检查函数指针。
- 原版 67 个导出、ordinal 500 能力查询、`ttpcomm_getversion() == 0x50700` 保持兼容。文件日期版本用于发行追踪，启动不要求 EXE/DLL 日期完全相等。
- 仅从 EXE 所在目录加载核心。成功后持有一个进程生命周期引用，避免静态对象或线程局部对象在 DLL 已卸载后销毁量化器。
- 继续保留 XP 必需的 ordinal 3 启动导入。DLL 完全缺失时 Windows 可能在进入应用前提示加载失败；DLL 存在但过旧时，应用显示手动整包替换说明并退出。
- 文件属性子进程同样检查运行接口，缺失时返回 `ERROR_REVISION_MISMATCH`，不会把解析失败当成“无标签”继续写文件。
- 独立 `TTPUpdater.exe` 不依赖 `ttpcomm.dll`，替换核心期间仍能解包、校验和回滚。

接口细节的唯一源码在 `ttpcomm/sdk`。`third_party/ttpcomm-sdk` 是带 SHA256 清单的固定快照；CMake 配置时校验，更新需显式运行 `ttpcomm/cmake/sync_sdk.py`。

## 音频精度修正

迁移时发现 `/O1` 与宿主热路径 `/O2 /Ob2` 下的 `tan` 运算存在 1 ULP 差异，例如输入 `0.5`、增益 `1.25`。已将 PCM 服务和量化器独立成源文件，保留宿主热路径的编译选项；标签与压缩服务继续优化体积。比较测试保持精确相等，没有扩大误差阈值掩盖差异。

保持两种编码规则：效果链的 `llround` 与最终量化器的 `nearbyint` 不互换；最终 float64 输出保留未裁剪幅度。seek 的 Reset 仍按原版清零预生成噪声与整形历史，未改成重新生成噪声。

|---|---:|---:|---:|
| TTPlayerRebuild.exe | 3,776,000 | 3,733,504 | -42,496（41.5 KiB） |
| ttpcomm.dll | 239,616 | 259,072 | +19,456（19 KiB） |
| TTPUpdater.exe | 425,984 | 425,984 | 0 |
| 三者合计 | 4,441,600 | 4,418,560 | -23,040（22.5 KiB） |

以私有目录重新链接 PDB/MAP 并读取实际段贡献，确认播放器内不再保留 zlib inflate/CRC 代码或查找表。正式 EXE 没有被分析用映像覆盖。这里记录磁盘文件大小，不把未初始化内存或理论源码行数算作体积收益。

播放器 ZIP 从 2,509,265 减至 2,493,389 字节，减少 15,876 字节。最终成品：`build/Release/TTPlayerRebuild-2026.10.08p3.zip`，SHA256：

```text
611bf86be86986946e3687c243b26ccbe2729c4979cfbc27513ec4a195ea1fc8
```

包内只有 `TTPlayerRebuild.exe`、`TTPUpdater.exe`、`ttpcomm.dll`、`AddIn/ttp_https.dll` 和 `SHA256SUMS.txt`。核心 ZIP、含许可证及相应依赖的源码包分别位于 `ttpcomm/build/Release/ttpcomm-2026.10.08p3.zip` 和 `ttpcomm-2026.10.08p3-source.zip`。本地组件使用真实构建 ZIP 加本地 Release 夹具走离线校验，没有把它记为已从远端下载的正式发布版。
