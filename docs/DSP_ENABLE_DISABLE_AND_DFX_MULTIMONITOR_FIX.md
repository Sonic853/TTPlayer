# 音效插件启停流程对照与 DFX 跨屏修复

日期：2026-09-30。

## 结论与证据范围

针对用户反馈的 **Ozone／DFX 在 WASAPI 播放中禁用时卡死**，确认了重建版与原版的两项关键差异：

1. 重建版在整条 PCM 处理链的锁内调用第三方 `Init`、`Quit`、卸载 DLL 和保存插件配置。原版单插件启停会把这些耗时动作放在相关锁之外。
2. 重建版选项界面及主窗口定时器通过同步消息查询插件线程。即使把禁用请求改为异步，后续状态查询仍可能再次等在 `Quit` 后面。

本次修复这两项宿主等待问题。真实测试复现了 Ozone 禁用约 1 秒的停顿；原样的永久卡死在本次压力测试中未复现，未取得该次故障的线程转储，因此不能断言所有偶发永久卡死都来自同一个原因。

另外，真实 DFX 窗口已复现负屏幕坐标下无法开始拖动，原因与音频启停不同：其窗口过程错误地把屏幕坐标扩展为无符号数。本次一并修复。

## 1. 原版启用流程

依据 [`TTPlayer.exe.pseudo.c`](../../reverse/decompiled/TTPlayer.exe.pseudo.c)：

1. `0049911C` 处理音效插件列表的状态图标变化。通过 `0042841A` 查询当前实例，勾选且尚未加载时调用 `00428471(manager, 1)`。
2. `00428471` 检查索引，创建大小为 `0x28` 的包装对象，通过 `00427E97` 初始化包装状态与临界区。
3. `00427EDC → 0042822F` 加载 DLL，查询 `winampDSPGetHeader2`，检查头版本大于 `0x1F`。
4. 排除不兼容的 Pacemaker；遍历模块槽位 `0..9`，选择第一个非空模块。
5. 写入模块的 `hwndParent`（`+4`）和 DLL 实例（`+8`），调用 `Init`（`+0x10`）。此时模块尚未发布到正在处理音频的实例槽位。
6. 初始化后，短暂锁定实例并写入 DLL、头、模块指针；随后在管理器锁内发布包装对象。
7. DFX／Dee2 窗口另有原版拖动集成入口 `00427E08`。

插件初始化发生在控制路径；PCM 由音频线程在 `0042898D → 004280CD` 中按列表顺序串行处理。配置窗口调用 `00428972 → 004280BE → Config`，不代表重新创建整个插件链。

## 2. 原版禁用流程

取消勾选且实例确实存在时，`0049911C` 调用 `00428471(manager, 0)`：

```text
管理器加锁
  取出旧包装对象
  将列表项的已加载实例指针置空
管理器解锁
  销毁旧包装对象（0042853A → 00427EAF）
    00428061：保存旧模块和 DLL 句柄
    实例加锁，清空已发布的模块／头／DLL 指针，解锁
    调用旧模块 Quit（+0x18）
    FreeLibrary
  删除临界区与包装对象
```

`0042898D` 的整链 PCM 遍历持有管理器锁，因此禁用先等待正在处理的一块结束，再把实例摘掉。之后的新 PCM 不会访问已摘除的实例，`Quit` 不再占据整条链的锁。

这里必须区分：`004282E4 → 00428B16` 是整个管理器清理流程，有外层锁；**选项窗口取消单个勾选**走的是 `00428471` 的先摘除、再解锁销毁路径，不能用全局清理流程替代它。

## 3. 与修复前重建版的差异

| 阶段 | 原版单插件流程 | 修复前重建版 | 本次处理 |
| --- | --- | --- | --- |
| 加载、Init | 对象尚未发布，锁外初始化 | 在 `processing_mutex_` 内调用 | 锁外初始化，暂存成功实例，在 PCM 边界发布 |
| 禁用 | 锁内移除，锁外 Quit／卸载 | 处理锁内 `CloseAll(false)` | 锁内移除并发布状态，锁外清理 |
| 剩余插件 | 可继续处理后续 PCM | 等待被禁用插件退出和配置保存 | 清理退休实例时继续处理存活实例 |
| 界面操作 | 原版控制线程直接调用插件 | 主 UI 同步等待独立插件线程 | 运行时启停请求排队执行，UI 不等待第三方回调 |
| 状态查询 | 管理器状态 | `IsActive` 同步进入插件线程 | 读取独立锁保护的状态快照 |
| 窗口查询 | 原版专门的窗口集成 | 定时器同步调用 `Windows()` | 读取快照，合并异步刷新请求 |
| 配置按钮 | 同步初始化后更新 | 同步检查是否加载 | 页面短周期刷新快照，初始化完成后可用 |

重建版保留独立插件界面线程，是为了维持插件的 Init／Config／Quit 线程归属及无模式窗口消息循环；不把第三方界面放到音频线程上。运行时 UI 异步请求是针对重建版多线程结构的适配，并非声称原版也使用这个消息队列。

## 4. 修复后的生命周期保障

- 等待正在执行的 PCM 或 Config 到安全边界后才移除实例，避免模块仍在调用栈中时卸载。
- 音频锁只保护活动链、排序、指针发布；不覆盖第三方生命周期回调或配置持久化。
- 新初始化完成的实例先进入 `prepared_`。音频正在处理时延后发布，避免插件界面线程阻塞等待查询它的 PCM 回调。
- 重排复用已加载实例；移除一个插件不会重新初始化其余插件。
- 移除时立即更新可见的活动状态；第三方仍在执行 `Quit` 时，UI 可以处理新的请求，剩余插件继续处理音频。
- 新的启用、禁用请求按插件控制线程顺序处理；模态 Config 或 PCM 忙碌时保留待应用的配置。
- 停机时同样先把活动链摘下，再执行清理；不在 PCM 锁内销毁实例。
- 保留已审核 Ozone 线程的合作退出兼容处理，未恢复 `TerminateThread` 强杀，也没有用超时后强行卸载 DLL 的方式掩盖问题。

进程内插件若在自身回调中永久不返回，宿主不能安全强杀该回调或卸载其代码。本次移除了 UI 状态查询和剩余音频链对清理回调的等待；完全退出程序时仍须等待合法的插件清理完成，这也是后续若再次出现永久卡死时需要具体线程转储的原因。

## 5. DFX 其他屏幕无法拖动

### 二进制依据

验证的 `Dsp_Dfx.dll` SHA256：

```text
987e7d531b92df9a582c1ab803f92856e948cc87f0a6b1ed900d3a7898a0eb03
```

窗口过程 `1001E9A0` 的 `WM_NCHITTEST` 分支：

```asm
1001EC76  movzx ecx, di    ; y 被当成无符号 16 位
1001EC7A  movzx edx, bp    ; x 被当成无符号 16 位
1001EC80  call 10033F80    ; 皮肤命中测试
```

负坐标会变成很大的正数。测试中，窗口放到 `(-800,100)` 或 `(100,-800)` 后，同一标题栏位置从 `HTCAPTION=2` 变成 `HTCLIENT=1`，原生标题栏拖动不会开始。

Windows 要求这些坐标按有符号数读取，明确指出按无符号 LOWORD／HIWORD 提取会破坏多显示器支持：[WM_NCHITTEST 文档](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-nchittest)。

### 修复方式

兼容层仅对上述已识别摘要和匹配的指令字节，在 Init 前将两处 `MOVZX` 改为 `MOVSX`。保留 DFX 原有的皮肤命中函数、按钮区域和客户区处理，继续使用宿主已有的目标显示器工作区吸附计算。

修改仅存在于加载后的内存，磁盘 DLL 不变。若卸载适配器时还有别的引用使模块留在内存，会恢复原始字节；未知版本不会按这个偏移修改。

## 6. 验证结果

实际歌曲仍为用户提供的《夜航星》FLAC，插件配置使用隔离副本，不修改原曲或用户原始配置。

| 测试 | 结果 |
| --- | --- |
| 修复前真实 Ozone＋DFX，20 轮启停 | 无永久卡死；Ozone 单次禁用约 1 秒 |
| 修复前完整 PlayerWindow／音效插件页，10 轮勾选 | 通过，未复现永久卡死 |
| 修复后完整 PlayerWindow／音效插件页，10 轮勾选 | 20 次取消勾选均快速返回，计时分辨率下记录为 0 ms；状态最终正确 |
| 修复后 WASAPI 共享模式，10 轮 | 单独禁用 Ozone／DFX、禁用全部、重新启用和播放推进通过 |
| 修复后 WASAPI 独占模式，10 轮 | 同上，退出码 0 |
| 人为阻塞第三方 Quit | 剩余 PCM、状态／窗口快照、诊断和新请求均不等 Quit；解除阻塞后重新启用成功 |
| PCM／Config／卸载既有回归 | 通过 |
| XP／Win7 虚拟机生命周期回归 | 均为 `DSP_DISABLE_EXIT=0`，包含阻塞 Quit 用例 |
| 真实 DFX 正坐标、负 x、负 y、混合坐标 | 标题栏全部返回 HTCAPTION；每处 832 点命中网格与基准一致 |
| DFX 仍有额外 DLL 引用时解绑兼容层 | 两处指令字节正确恢复 |

跨屏测试通过设置真实 DFX 窗口位置及发送原生命中消息验证坐标和控制区域；负坐标位置为合成布局覆盖，不声称已在用户每一种物理显示器／DPI 排列上进行鼠标拖动验收。

测试代码及证据均保留在本地 `tests`，主要结果位于 `tests/artifacts/dsp_disable/`；不加入 Actions 或发行包。
