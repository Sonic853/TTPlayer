# 媒体库修复与验证（2026-09-16）

对应 [修复前审计](MEDIA_LIBRARY_AUDIT.md)。此次保留原有编号播放列表与媒体库分离的设计，修复副本同步、恢复、监视和详细信息读写。

## 修复内容

| 问题 | 修复 |
| --- | --- |
| 扫描结果覆盖刚修改的评分／标签 | 请求携带修改版本；结果提交按歌曲身份合并较新的用户修改。评分只覆盖评分字段，不丢弃扫描得到的新标签 |
| 扫描期间新增／重命名后立即关闭丢数据 | 新增和重命名记录保留修改副本；拒绝旧路径结果；退出合并尚未提交的修改及已有持久化记录 |
| 删除后重新出现仍被隐藏 | 新增／重命名通知按路径清理移除标记，不依赖旧条目仍留在 `items` 数组 |
| 旧扫描结果复活刚删除的文件 | 文件事件也有版本；提交时应用扫描之后的删除／新增事件，早先的“已观察到文件”不能覆盖较新的删除 |
| 只在媒体库中的歌曲不能启动恢复 | 等待媒体库加载和初扫，按路径＋子轨查找歌曲并恢复独立播放快照；手动选曲、播放和停止会取消待执行的启动恢复 |
| WAV 等内建格式缺少时长／格式信息 | 通过现有 `playlist-read` 独立工作进程统一调用内建／AddIn 读取器，填充时长、标签、采样率、声道、位深与码率；每文件每次构建只读取一次 |
| 问题读取器阻止后续扫描 | 每次读取有 15 秒超时和停止令牌，故障留在独立工作进程；不再在播放器扫描线程内调用 AddIn／Shell 读取器 |
| Shell 评分覆盖媒体库评分 | 媒体库评分由歌曲对象维护，声音信息更新不导入 Shell `PKEY_Rating` |
| 目录复选框含义错误 | 改为 `recursive`；不勾选仍监视直接子项，勾选才监视子树。保留原配置的星号编码 |
| 单目录失效停止所有监视 | 只撤销失败目录的句柄，保留其他目录，并重试失败目录；重新打开及通知丢失时发送明确的补扫事件 |
| 缺少停机期间变化的核对 | 在启动扫描配置目录；刷新命令也扫描配置目录。按递归选项核对新增和确定已不存在的路径；不可访问不当作已删除 |
| 关闭媒体库后默认列表不再监视 | 监视开关独立于媒体库启用状态，异步结果可以更新配置的默认播放列表，不切换用户当前列表 |
| 盘符根目录包含关系错误 | 已以分隔符结束的根路径不再要求下一个字符也是分隔符，保留相邻同名前缀的边界检查 |
| TTBL 详细音频段丢失 | 恢复 `0x10` 段的格式字符串、采样率 DWORD、声道 WORD、位深 WORD、码率 DWORD，包括原始码率高位标记 |
| 保存失败损坏原文件 | 先写完相邻临时文件并检查输出，再替换目标；写入或替换失败保留旧文件 |
| 普通列表排序后修改同步遗漏 | 标签和评分通过歌曲身份匹配关联列表，不再只依靠可能过期的行号提示；完整标签替换也能删除已清空的旧字段 |

目录通知缓冲区采用 DWORD 元素数组保证对齐，且进行异步 I/O 时保持缓冲区和
`OVERLAPPED` 地址稳定；只等待已成功发起的 I/O 完成取消。相关接口约束与零字节
通知需要补扫的规则来自 [微软 ReadDirectoryChangesW 文档](https://learn.microsoft.com/zh-cn/windows/win32/api/winbase/nf-winbase-readdirectorychangesw)。

## 分类父节点的原版依据

这项不再只依赖反编译器生成的隐式函数参数。本次读取原始 EXE 的汇编：

- `0048A44C..0048A470`：Rating 分支调用 `00478D61` 创建空列表，再交给 `00466854`。
- `0048A48A..0048A49C`：初始化三个空字符串。
- `0048A4A8..0048A4C2`：把这些空字符串、当前字段名、输出列表和全局目录压栈，调用 `004AF46A`。
- `004AF46A` 对主字段做 `_wcsicmp` 相等比较。

因此 Artist／Album／Genre／Date 父节点查询缺少该字段的歌曲，Rating 父节点为
空列表；具体字段值与星级叶节点仍按精确条件查询。重建代码和回归断言已统一。

## 回归测试

本地测试 `tests/ui/media_library_tests.cpp`，通过现有测试访问入口调用实际媒体库协调器，使用确定的“构建结果 → 用户操作／文件事件 → 提交结果”顺序验证交错，不依赖随机压力测试。

覆盖：

- 扫描期间评分、标签、新增及重命名；新增通知复活旧移除记录；晚到的扫描不得复活新删除。
- 分类父节点语义；盘符／UNC 根路径及相邻路径边界。
- 无外部 AddIn 的有效 WAV 信息；递归／非递归初扫；离线删除核对。
- 媒体库独有歌曲的延后恢复；默认列表独立更新。
- TTBL 有／无标签两种布局的详细字段往返；目标文件被锁定时保留原数据。
- 真实文件通知：未勾选目录、递归子目录、一个根目录被删除后其他目录继续工作、根目录重新建立后恢复监视。
- 有原版资源时：创建完整窗口、启动前已有文件的扫描、库内歌曲恢复、扫描期间修改后立即关闭、持久化核对，以及停机期间重命名后重新打开。

通过 `TTPLAYER_BUILD_LIBRARY_TESTS=ON` 可在 `BUILD_TESTING=OFF` 时单独构建，
需要保留本地 `tests/` 源码；测试不上传且不在 Actions 中执行。缺少私有资源时
明确跳过完整窗口部分，核心测试仍可在本地运行。
