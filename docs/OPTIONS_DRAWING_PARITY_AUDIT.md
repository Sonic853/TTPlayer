# 选项窗口其它页面绘制一致性审计

> 2026-09-21 补充：相关功能已在 XP SP3 / Win7 SP1 虚拟机中执行回归。覆盖项、修复和未覆盖边界见 [虚拟机验证记录](XP_WIN7_VM_VALIDATION.md)。下文保留原日期的历史结论。

日期：2026-09-16。对照对象为随项目保存的原版 5.7.9 `TTPlayer.exe`、
`reverse/decompiled/TTPlayer.exe.pseudo.c`、`ttpres.dll` 资源和当前重建源码。

## 结论

**已按第 5 节的顺序修复已确认的差异，并补充按钮像素对照。**

常规页的输入框／箭头联动、颜色及图文按钮、网络子页生命周期和资源尺寸已恢复。
关于、常规、全屏、系统关联中的社区功能仍保留，不能把这些有意差异当作绘制故障。
当前宿主的回归通过也不能推导为所有系统、DPI 和主题下整页像素完全一致。

第 1–4 节保留修复前的审计快照；本次实施和验证见第 6 节。

## 1. 已确认的不一致

### 1.1 颜色／渐变按钮使用了简化绘制

涉及视觉效果、播放列表、歌词模式、全屏歌词及颜色配置对话框。

原版窗口颜色按钮的调用链包括：

- `00493750`：视觉效果颜色按钮；
- `00493F1B`：播放列表颜色按钮；
- `00496D3A`：窗口歌词颜色按钮；
- `00491FEF`：生成色块位图，画系统按钮背景和灰框，再向内缩 2 像素填色；
- `00434F8C → 0046E0C9`：通过图像列表和通用图文按钮处理绘制及交互状态。

`00493F1B` 的原始指令在 `00493F5C..00493F69` 同时把尺寸参数和 EAX 设为 15，
补足伪代码遗漏的寄存器参数，确认生成的是 **15×15** 色块。

当前 `player_window_options.cpp` 的 `DrawColorButton`、`DrawGradientButton`：

- 使用 `BS_OWNERDRAW` 和 `DrawFrameControl`，没有走原版通用按钮的主题分支；
- 固定向内缩 4 像素，色块宽度 14，高度随按钮尺寸变化；
- 色块后的文本在剩余区域居中，和原版图文间距算法不同；
- 只把 `ODS_SELECTED` 转成按下边框，未处理 `ODS_DISABLED` 的禁用绘制。

`player_window_visual_options.cpp` 还有另一份颜色按钮实现：它处理了禁用状态，
但色块边框用黑色，普通选项实现用灰色，两份代码本身也不一致。

**判断：存在确定的尺寸、边框、主题和状态绘制差异。** 不能因为颜色值正确，
就认定按钮外观已与原版一致。

### 1.2 常规页的输入框与上下箭头禁用状态不同步

原版 `0049257C` 同时对以下控件执行 `EnableWindow`：

| 功能 | 复选框 | 输入框 | 上下箭头控件 |
| --- | ---: | ---: | ---: |
| 窗口吸附距离 | 1076 | 1077 | 1078 |
| 标题滚动间隔 | 1083 | 1084 | 1044 |

重建版初始化和 `WM_COMMAND` 分支只更新输入框，没有同步箭头控件。
本轮以两项关闭的设置创建真实页面，结果为：

```text
general edit=1077 enabled=0 spin=1078 enabled=1
general edit=1084 enabled=0 spin=1044 enabled=1
```

**判断：这是程序的控件状态遗漏。** 它会造成置灰外观和可操作状态不符合原版。
播放页的淡入淡出设置则已经同时更新输入框及箭头，不能把此问题推广到所有数值控件。

### 1.3 网络连接子页仍然销毁重建，尺寸也不同

原版：

- `0049885A` 同时创建缓存页 381 和下载页 382；
- `00498BD1` 响应标签切换，仅对已有窗口显示／隐藏；
- `0049816D`、`0049846F` 通过 `004052F1(..., HWND_TOP, SWP_NOSIZE)` 定位；
- 两个原始对话框资源的尺寸均为 259×42 对话框单位。

重建版 `InitializeOptionsPage(258)`、`switch_nested` 只保留一个活动子页，切换时销毁再创建。
它仍调用会调整尺寸的 `PositionNestedDialog` 默认分支。

本轮实测四次切换均更换 HWND。当前字体／缩放下，重建页为 **391×64** 像素，
`MapDialogRect` 换算的资源尺寸为 **389×63** 像素。

**判断：生命周期和尺寸不一致。** 上一轮歌词页修复已把共用定位函数改为 `HWND_TOP`，
本轮网络页命中及层级检查通过，未复现同一标签遮挡空白；不能据此说网络页已完整恢复，
也不能把生命周期差异直接当作仍然空白的实测证据。

### 1.4 部分带文字图标按钮仍走系统默认排版

原版 `0046E0C9` 的横排图文分支使用：

```text
gap = (按钮宽 - 图像宽 - 文字宽) / 3
图像 x = gap
文字 x = 2 * gap + 图像宽
```

同时分别垂直居中，按下时图像、文字都偏移 1 像素。

重建版已把这一路径用于系统关联的四个图文按钮。但通用 `InstallButtonBitmap`
的带文字按钮仍设置 `BCM_SETIMAGELIST`、左对齐及 3 像素边距；
`OptionsImageButtonSubclassProc` 对普通带文字按钮直接交回原生按钮。
视觉效果页自己的 `InstallButtonBitmap` 也使用这一原生排版方式。

**判断：字体选择、配置文件等按钮尚未统一为原版排版。** 代码路径不同是确定的；
每个按钮在不同主题下的实际偏移量，还需要逐个像素比较，不应假定全部偏移相同。

## 4. 本轮验证与边界

本地入口：

```powershell
cmake --build build --config Release --target options_drawing_tests --parallel 4
build/Release/options_drawing_tests.exe .. --drawing-audit
```

结果保存在本地 `out/options-drawing-audit.log`：

- 15 页的可见性、几何、重复选择和公共外壳检查通过。
- 关于页背景、8 个纯图标按钮、关联页图文按钮检查通过。
- 关联页 2031／2032 的原位图 RGB 差异各为 0；设备图标 4 帧差异各为 0。
- 记录了常规页两组输入框／箭头的状态不一致，以及网络页四次重建与尺寸差异。

此前完整选项测试中的“系统关联文案”断言失败已查明：测试期待旧的“前往查看系统关联”，
生产资源已改为“Win7 以上系统需要手动关联”。本轮只同步了本地测试的文案预期，
这不是页面空白或文字没有绘制。绘制审计没有运行实际文件关联修改、创建快捷方式或网络配置操作。

测试仍只保存在本地 `tests/`，不上传，Actions 不运行测试。本轮是当前宿主上的普通 Release 检查；
没有重新运行 XP／Win7 实机、全部 DPI／主题或全部旧版动态像素对照。源码不同但输出相同的部分
不判为已发生的显示故障，未覆盖的状态也不标成“完全一致”。

2. 已完成：统一颜色／渐变按钮的位图、主题、悬停、禁用、按下、焦点绘制。

## 6. 本次修复

### 6.1 状态、绘制与资源所有权

- 常规页 1076 同时控制 1077／1078，1083 同时控制 1084／1044；创建时和点击时均同步。
- 普通颜色按钮恢复 `00491FEF` 的 15×15 位图、系统按钮底色、灰色外框和 2 像素内缩。
- 桌面歌词按钮按 `00494C9D` 使用 16×16 位图，内侧按颜色数量分成水平色带；
  它是预览色带，不能用平滑插值渐变代替。实际歌词文字的渐变渲染没有因此改变。
- 视觉效果页移除重复绘制，通过 `src/ui/options_buttons.h` 共用颜色、字体及配置按钮实现。
- 图文按钮统一到 `0046E0C9` 的三等分间距、各自垂直居中、按下偏移 1 像素。
  普通、悬停、按下、禁用、焦点及默认按钮使用同一状态分支。
- 颜色按钮保留原生 `BS_PUSHBUTTON`／默认按钮样式，通过子类转发绘制到页面颜色处理器，
  不再用 `BS_OWNERDRAW` 取代按钮类型；由对话框管理器维护默认按钮状态，经典默认按钮
  同时恢复原版偏移 1 像素的文字阴影。
- `0046E055` 的主题边缘在 `COLOR_BTNFACE` 上合成；不再额外绘制父窗口底色，
  避免圆角周围像素不同。经典分支恢复普通／悬停／按下的不同边框及焦点内缩。
- 独立跟踪鼠标进入／离开，补齐自绘颜色按钮缺失的悬停，按下时不沿用悬停文字颜色。
- 图像列表统一为原版的 32 位带掩码格式；重复安装时释放上一份自有图像列表，
  销毁控件时释放当前图像列表。绘图保存／恢复 DC，避免字体、文字色或画刷影响后续绘制。

### 6.2 网络子页

创建 381、382 两个子页，保存在 `options_network_pages_`；
`SelectOptionsNetworkMode` 只提交旧页并切换显示状态。定位保持 `HWND_TOP | SWP_NOSIZE`，
不再用标签内容区尺寸覆盖资源尺寸。当前宿主实测为 389×63 像素，与资源换算相同。

父页提交时读取两份控件，包括未显示页面的编辑值。正常关闭和直接销毁均清理子窗口引用；
再次打开会按目标模式创建新的两份子页。歌词页已有的常驻子页恢复不受影响。

### 6.3 验证方法与限制

本地测试仍全部位于 `tests/`，由 Git 排除，不上传；Actions 仍设置 `BUILD_TESTING=OFF`。
覆盖常规页两组开关、15 个外层页面、网络／歌词页鼠标及键盘切换、定向入口、资源尺寸、
保留编辑、隐藏页提交和关闭重开。另保留纯图标、关联图文及设备位图检查。

按钮对照使用相同原资源和 XML 设置。原版的自定义按钮不支持通常的 `WM_PRINTCLIENT`
离屏捕获，因此使用隔离运行目录中的原 EXE 实际窗口像素；重建版在本地测试进程内切换
主题、状态并捕获控件，避免跨进程主题设置和鼠标消息时序干扰。比对输入包含原版记录的
普通／默认按钮类型和焦点状态。按下态使用真实鼠标按下，再移出并松开取消点击，
避免人工消息和实际鼠标键状态不一致。空白捕获不计为通过。

宿主为 Windows 11 26200。几何缩放不是完整的 DPI 测试；动态硬件列表、任意皮肤、
社区新增界面和所有系统字体组合不属于固定像素基线。旧系统兼容性仍分别报告静态导入审计
和当前宿主运行结果，不把它们当作 XP／Win7 实机验证。

按钮矩阵结果：视觉效果、播放列表、窗口歌词、桌面歌词、全屏显示及关闭按钮共 24 个
按钮实例 × 2 种外观 × 4 种几何尺寸 × 5 种状态，**960／960 组 RGB 零差异**。
首次采样中 3 组未稳定进入按下态；加入输入状态校验后，仅重采这 3 组，全部对齐。
原始截图、对应重建捕获、焦点／默认按钮输入和结果保存在本地
`out/options-original-pixels/`，汇总为 `report.json`。

该结果验证的是上述按钮和状态，不代表全部页面或真实高 DPI 像素完全一致。

普通版与兼容版均完成 Release 构建。兼容版仍为 x86、子系统 5.01，最新静态导入检查
通过：18 个 DLL、641 个导入（移除了不再使用的父背景主题绘制调用）。
两个版本的页面审计、子页关闭重开及完整选项回归分别保留为本地

没有为测试改变生产提醒逻辑，也没有写入真实文件关联。
