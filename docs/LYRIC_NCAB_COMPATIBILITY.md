# NCAB 歌词搜索与下载兼容修复

2026-10-09。依据 5.7.9 `TTPlayer.exe` 伪代码、原版 `AddIn/ttp_lrcsh.dll` 的反编译与实际调用，以及用户提供的 NCAB 程序和本地服务 `http://localhost:99`。

## 结论与实际原因

两张截图对应的错误已在修复前的重建客户端复现。同机原版歌词插件可搜索、下载同样的歌曲。问题发生在客户端的传输、结果解析和会话管理，不是中文搜索参数或下载 Code 算错，也不是需要关闭 TLS 证书验证。

| 问题 | 实际证据 | 修复 |
| --- | --- | --- |
| `Invalid XML` | 《心里有针》的结果包含 `title="类似爱情（R&B氛围版）"`，其中 `&` 未转义；其它结果也可能有 `孙建平 & Sweet Style` | 仅对歌词搜索结果中的属性值补齐裸 `&` 的转义；已有 XML 实体不重复转义 |
| 搜索有结果，下载失败 | 搜索响应设置 `Set-Cookie: geiquname=...`；NCAB 开发模板的 `down(cookie, 编号)` 同时匹配 Cookie 和编号；原重建版每次请求重新创建会话，没有把搜索 Cookie 带入下载 | 每次搜索独立创建内存 Cookie 容器，由该次所有结果共同持有，后续下载复用 |
| `HTTP/TLS 12152` | 带正确 Cookie 后，NCAB 直接返回 UTF-8 LRC 正文，没有 HTTP 状态行和响应头；不带 Cookie 时实测直接断开，返回零字节 | HTTP 歌词搜索、下载使用原版的 WinINet 传输能力，接受该服务的无头响应；HTTPS 保持现有传输和证书验证 |
| XP、Win7 的裸服务器地址失败 | `http://host:99` 本身合法，但旧版 `WinHttpCrackUrl` 拒绝随后拼出的 `http://host:99?sh?...` | 拼接协议参数前补齐空路径 `/`；搜索、下载都处理 |
| 下载一次失败后按钮无法再用 | 重建版将下载异常作为整个搜索会话失败，工作线程退出；候选仍显示，但不能继续下载 | 增加下载失败状态，保留结果、Cookie 和工作线程；错误仍显示，可换来源或重试 |

12152 是 WinHTTP 的 `ERROR_WINHTTP_INVALID_SERVER_RESPONSE`。本例使用明文 HTTP，旧提示统一写成 `HTTP/TLS` 容易让人误以为是 TLS 故障。[微软错误码说明](https://learn.microsoft.com/en-us/windows/win32/winhttp/error-messages)

## 原版完整流程

### 1. 服务器与搜索对象

- 宿主 `004CABC0 / 004CD3F9` 枚举歌词 Creator，`00497AE5 / 0043BA1E` 填充服务列表。
- `004CD44E / 0043B9CE` 创建、初始化对象，传入宿主回调及 24 字节网络配置；失败时可回退第一个 Creator。
- 插件 `60351249` 读取与 DLL 同名的 UTF-8 XML INI，失败则取 DLL 字符串资源。原插件只保留两个服务。
- `60353428` 创建 WinINet 会话：直连、系统代理或指定代理。该会话属于歌词对象，搜索和下载并非两个不相关的请求。
- 原插件还有 `60351420` 的一次性 `svrlst` 刷新。重建版已有用户可编辑的服务目录，因此仍保留“不让远端刷新覆盖本地服务列表”的既定扩展。

### 2. 搜索参数与候选

- 宿主 `0043ADCB / 0043C2FF` 调用搜索接口 slot 4；插件进入 `6035249B`。
- `60352A6F / 603529F6` 清理编号、标点、括号附加信息，执行简体、小写映射。
- `60352BC0` 将 UTF-16LE 字节编码为十六进制，组成 `?sh?Artist=...&Title=...&Flags=0&`。
- `60351585` 使用 `InternetConnectA → HttpOpenRequestA → HttpSendRequestA`；`60351B14` 循环读取正文。
- `60355A62` 调用插件内置的 XML 解析器，`6035249B` 遍历 `lrc` 节点，保存编号和 UTF-8 的 artist/title，并回调宿主。
- `60355612` 处理已知实体；遇到未识别序列时保留当前字符继续。因此原版能显示裸 `R&B`，严格 MSXML 的直接解析会失败。
- 宿主 `0043B332` 复制候选，生成默认文件名并匹配当前曲目。`0044BEED` 处理自动下载和单结果直接下载；多结果的选择、倒计时见既有恢复文档。

### 3. 下载、保存与错误

- `0043B044` 取选中的**行索引**并调用 slot 5，插件 `60352301` 根据索引提取此前保存的结果。
- `60352C1E` 拼接歌手和歌名，交由 `603531E7` 生成有符号 32 位 Code，再发送 `?dl?Id=...&Code=...&`。
- 同一个 WinINet 网络环境保留搜索返回的 Cookie。NCAB 下载依赖它定位临时缓存中的记录，仅 Id/Code 不足以完成下载。
- 插件读正文并处理 `tt-title / tt-url` 附加头；下载返回 `<result ...>` 时按错误处理，否则转换为 Unicode 歌词并回调 slot 4。
- 宿主 `0043B6D4` 保存、通知歌词加载；`0043E3CF` 是歌词保存入口。重建版继续使用既有的编码选择、路径校验、覆盖确认、临时文件替换及关联逻辑。
- `0043B8A3` 在错误回调中清除忙碌状态并通知窗口，保留候选和搜索对象；这也是本次恢复失败后再次下载的依据。

相关流程原先已恢复的部分见 [在线歌词搜索恢复](LYRIC_SEARCH_RECOVERY.md) 和 [歌词服务器编辑与 HTTPS](LYRIC_SERVICE_EDITOR.md)。

## 实现范围与兼容约束

- 新增 `legacy_lyric_http.cpp/.h`，仅负责明文 HTTP 的歌词协议；更新器、CD 查询、通用 HTTP 调用不切换传输。
- `HttpLyricResult` 持有该次搜索的会话；两次搜索、两个在线窗口不会争用 NCAB 的同名 Cookie。
- 使用 `INTERNET_FLAG_NO_COOKIES` 禁止读写系统 Cookie 存储，手动处理该次搜索的 Cookie。微软说明该标志同时禁用自动发送和自动保存 Cookie。[WinINet 标志说明](https://learn.microsoft.com/en-us/windows/win32/wininet/api-flags)
- Cookie 按响应来源和路径限制；处理 Secure、Domain、Path、Max-Age、Expires；重定向重新校验，跨来源不携带原来源 Cookie。数量和请求头长度有上限。
- HTTP 重定向至 HTTPS 时进入既有 `ttp_https.dll / WinHTTP` 路径；本次没有为 HTTPS 组件新增 Cookie ABI，也没有放宽 HTTPS 的证书或降级限制。
- 保留工作线程、取消、读取超时、2 MiB 响应上限；不复制原版的 `TerminateThread` 强制杀线程逻辑。
- 裸 `&` 兼容仅用于歌词搜索 XML。服务列表 INI、其它 XML、DTD/外部实体限制均保持严格；缺失引号、错误结构、NUL、超限响应仍失败。
- 候选保持服务返回顺序，不按 Id 去重。NCAB 不同来源可能返回相同 Id，原协议按行选择，下载仍使用该行的原始 artist/title 计算 Code。
- 新增 `download_failed`，区分“搜索失败”和“单次下载失败”；下载失败后仍显示错误，允许换行下载，不自动循环重试失败来源。

## 验证

本地测试代码、抓包、原插件反编译和运行日志均在 `rebuild/tests/lyrics/ncab`，不加入发行包，不接入 GitHub Actions。

- 修复前：原插件可下载两首样本；重建版分别复现 12152 与 Invalid XML。
- 修复后：真实 NCAB 上《无人熟识的彼个人》《心里有针》的网易结果均可下载。首轮 Unicode 文本长度分别为 995、888，与原插件实测一致；《无人熟识的彼个人》进一步逐字比较和 SHA-256 比较也一致。
- 实时内容不是固定测试数据：《心里有针》另一次原插件请求得到 897 字符，末尾多出服务器拼入的 `歌词解析错误代码：`；随后重建版请求也出现过相同附加文字。客户端不应擅自删除正文中的文字；这不属于传输或 UTF-8 解码差异，不能将所有不同时间请求声称为字节一致。
- 离线回归覆盖：真实 NCAB 搜索响应回放、裸与已转义 `&`、数字实体、负数和重复 Id、无响应头正文、Cookie 隔离与作用域、失效 Cookie、重定向、错误状态、分块传输、非法 XML、空下载、超限、下载失败后重试、取消、显式 Basic 代理认证。
- 无头响应测试按 NCAB 实际的 LF 正文格式构造。WinINet 在旧系统上对含 HTTP 头分隔符的任意无头数据还有不同表现，不能据此宣称支持任意畸形 HTTP 数据。
- NTLM/Digest 的真实代理环境未验证；NCAB 上游其它来源的可用性、五分钟缓存过期等服务器行为不属于客户端修复保证。用户提供的插件开发模板会清理超过 300 秒的记录，过期后应重新搜索。
