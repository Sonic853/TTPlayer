# TTPlayer：韵动脉冲、水波荡漾恢复

分析日期：2026-09-27。

## 1. 音频输入与帧状态

输入为左声道 512 个有符号 16 位样本，无 Hann 窗、无左右声道平均、无 RMS 替换。
原版将它们组成 256 个复数对，执行四层四基 FFT，再重建实数频谱。
每一步中间结果保持单精度。幅值按以下顺序计算：

```text
square = float(real * real + imag * imag)
magnitude = int(float(sqrt(double(square)))) >> 8
```

`1002A29D CVTSD2SS` 是关键：必须先将平方根舍入为 float，再取整。
省略这一步会让部分临界频率值相差 1。

原版只写 0–255 格；第 256 格位于未使用的第二声道缓冲区。重建版明确保留一个
值为零的边界槽，不越界读取，也不把最后一段错误地钳到第 255 格。

`10002840` 的频率映射为：

```text
bin[i] = max(int(pow(2, i * 7.5 / 256)), bin[i - 1] + 1)
```

固定 256 段时，结果恰好是 1–256。先将幅值右移 5 位，然后取对数。
按从左到右的顺序，用已更新的左邻居、当前目标的两倍、尚未更新的右邻居求平均，
夹到 0–159。上升立即跟随；下降每次减 2，但数值不大于 2 时保留尾部。
因此静音输入后的细小残留也是原版算法的行为。

每段四个 `short` 的幅值、下落计数、峰值、上一峰值均恢复；两种效果实际绘制使用幅值。

### 首次调用的共享系数

`10002990` 在 DLL 全局 `1000C740/1000C748` 缓存第一次计算的缩放系数，
后续模式切换、停止和 Reset 都不重算：

- 先运行普通频谱：`100 × (4/3) / log(256)`。
- 首先运行韵动脉冲或水波荡漾：`160 / log(256)`。

重建版以进程共享且线程安全的初始化保留这两种顺序。主视觉频谱先运行时会初始化
前一种系数；直接进入新效果时使用后一种。比较截图时必须使用相同的初始化顺序。
原版主界面的小频谱也会触发这个缓存（`00464770`），不能只看歌词菜单当前选项。

## 2. 韵动脉冲

内部画布固定为 **512 × 160**，黑色背景，最后用 GDI `StretchBlt/SRCCOPY` 缩放。
第 `i` 段分别画在 `x=256+i` 和 `x=255-i`，形成左右镜像。

对于幅值 `v`，从外到内画四层竖线，层号 `k=4,3,2,1`：

```text
top = int(80 - k * v * 0.125)
bottom = int(top + k * v * 0.25)
base_channel = int(input_channel * v / 160)
channel = min(255, base_channel + (4 - k) * 16)
```

每层宽 1 像素，保持 `MoveToEx/LineTo` 不包含终点的行为。复用画布，但每次绘制前清黑，
不保留上一帧图像，也不添加模糊或虚构的脉冲动画。

## 3. 水波荡漾

这里没有水面高度场、随机雨点或按时间扩散的波纹。原版将 **不同的频谱幅值** 画成椭圆：

- 依频率顺序扫描 256 段，跳过零值及此前画过的相同幅值。
- 横向比例为目标宽度 / 256，纵向比例为目标高度 / 160。
- 幅值越大，椭圆越大、颜色越暗。
- 先画 3 像素外圈，再画亮 16 的 1 像素内圈，两层 Alpha 都为 `0xD5`。
- 使用原版 GDI+ `SmoothingMode=2`，保留整数截断、椭圆次序及混合结果。

位置计算中的负数乘法也保持原顺序，避免奇数尺寸下出现一像素偏移。

## 4. 宿主行为与设置

- 原版使用 **20 FPS / 50 ms**。按用户要求，重建版允许在“视觉效果”选项中调整 FPS，
  与现有视觉效果共用帧率设置（界面范围 10–40 FPS），切换效果、全屏后继续生效并保存。
  20 FPS 对应原版刷新节奏；其他帧率保留逐帧计算和绘制规则，更新及衰减速度随帧率变化。
- 颜色跟随窗口歌词高亮色；全屏跟随全屏歌词高亮色，与 BaiduMusic 的调用参数对应。
- 使用视觉区域中间一半高度，上下各保留四分之一；歌词叠加仍由宿主歌词层负责。
- 播放时更新，暂停冻结。重新布局/调整大小保持暂停帧；切换效果重置段状态。
  停止恢复宿主背景，保留下一次播放需要继续衰减的段状态。
- 内存画布一次提交，避免先清除可见窗口后再画效果造成闪烁。
- 嵌入区域点击按 0–6 轮换；纯视觉全屏跳过无效果和专辑封面，包含新增的两项。
- 主菜单、区域菜单和全屏歌词菜单使用同一命令范围 `0x8085–0x808B`。
- XML 和 `.ttvi_cfg` 接受 Type 0–6；全屏新增独立的
  `PosRelationPulse/PosRelationRipple`、`LrcSizePulse/LrcSizeRipple`。
  默认两项均允许歌词与效果重叠，占满歌词区域。
- 皮肤宿主接口接受视觉编号 5/6；同时显示的主窗口与歌词视觉区域统一跟随用户帧率设置。

- 3,000 组 PCM：静音、正负直流、逐位置脉冲、正弦、随机信号。

- 原先考虑复用的 `ttpcomm.dll` 在同批输入有 57 个频谱值不同，因此新效果使用已恢复的
