# 全屏歌词：允许拖拽歌词

“选项 → 全屏显示 → 歌词全屏显示”新增 **允许拖拽歌词**，位于字体选择按钮旁。
适用于单独歌词全屏、歌词视觉同屏（包括专辑图片背景），不控制桌面歌词或
普通／迷你模式的歌词拖拽。

- 开启后，在整个歌词显示区域（文字及透明空白处）按住拖动可预览进度，释放鼠标后跳转。
- 垂直滚动模式按上下位移计算，水平滚动模式按左右位移计算。
- 沿用现有 `LyricDragTime → SeekWithoutFade` 路径，不启动音频淡入淡出；
  在解码器确认前保留目标进度，不短暂跳回原位置；暂停状态保持暂停。
- 至少两行歌词才启动拖拽。没有移动的单击不跳转。
- Esc、丢失鼠标捕获、取消操作或拖动中关闭开关，取消拖拽，不提交进度。

## 配置及兼容性

独立全局属性为 `TTPlayer.xml/Lyric/@DragLyricFS`，保存值为 `0` 或 `1`。
新配置默认开启；读取没有该属性的旧文件时继承原 `DragLyric` 值，之后独立保存。
普通／迷你模式继续使用原 `DragLyric`，皮肤加载不会覆盖新的全屏选项。

原 `004425F7` 只在 `00442360` 返回 `-1` 时进入拖拽。进一步追踪 `00441FEF`
可见它测量的是 `+0x110/+0x114` 的提示／链接条目和 `+0x130/+0x134` 的提示项，
并非所有带时间戳的歌词行；`00442671` 将命中条目的链接传给 `0x7F9`，或打开链接。
此前将这一路径误写为“命中任何歌词文字就禁止拖拽”，导致普通／迷你模式只有空白能起拖。
已修正为：普通歌词的文字与空白都走同一个拖拽分支，空闲时使用箭头，拖拽时使用方向光标。

全屏歌词另外使用 `LWA_COLORKEY`，背景透明像素会穿透鼠标输入。
仅放开文字命中规则仍不能在透明空白区域起拖：该区域根本收不到
`WM_LBUTTONDOWN`，直接对歌词 HWND 发消息的测试也绕过了这一系统命中问题。

现由 `player_window_lyric_input.cpp` 在透明全屏歌词上创建专用鼠标接收窗口：

- 使用 `WS_EX_NOREDIRECTIONBITMAP`，没有背景刷、颜色键或半透明绘图面，
  外观完全透明，但整个矩形都可接收鼠标；不修改歌词或专辑背景的绘制方式。
- 只覆盖歌词客户区，转发客户坐标给原歌词控件，由原控件捕获鼠标、预览及直接 seek。
  空白处的右键也进入歌词全屏菜单，不误触下面的视觉切换或其它程序。
- 跟随歌词窗口移动、缩放、屏幕切换和 Z 序；不覆盖歌词之上的其它应用。
  关闭拖拽、取消透明、隐藏或销毁歌词、退出全屏时清理，不留透明鼠标阻挡层。
- 无任务栏／Alt-Tab 项，不主动激活。此空白区输入扩展需要 Windows 8+ 和 DWM 合成；
  旧系统仍保留原歌词窗口及文字起拖行为。

这是全屏拖拽开关的社区扩展。普通／迷你状态继续由原 `DragLyric` 开关控制，
不再把歌词文字误当作链接。原位置计算、鼠标捕获和释放后的直接 seek 流程继续复用；
未实现的提示链接并不等同于可拖动的时间歌词，不能用歌词行矩形替代其命中测试。
系统行为参考 [Layered Windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)
和 [Windows Composition Engine](https://learn.microsoft.com/en-us/archive/msdn-magazine/2014/june/windows-with-c-high-performance-window-layering-using-the-windows-composition-engine)。

## 测试

宿主机 `fullscreen_lyric_drag_tests` 使用真实 HWND、5.7.9 皮肤、歌词命中计算和
鼠标消息，测试独立开关、文字起拖、两种全屏模式、两个滚动轴、播放／暂停、
直接 seek 和时钟交接、无位移单击、关闭／Esc／取消／捕获丢失，以及 XML 兼容读写。
使用已有测试接口模拟解码器状态，不播放用户歌曲或调用真实音频设备。
另增加宿主机 **真实 `SendInput`** 测试：先确认关闭开关时颜色键空白处确实穿透到
测试背景，再确认开启后的矩形命中；实际从文字／空白起拖、捕获后移出边界、
两种全屏／滚动方向、播放／暂停和空白右键菜单均经过 Windows 输入分发。
底层两种背景色的屏幕取样完全相同，排除透明输入层造成染色或黑矩形。
在宿主机两台显示器逐个移动／缩放，验证边界、Z 序以及隐藏／重新显示／禁用／
透明切换／退出全屏清理。该测试需要交互桌面，串行运行，结束恢复鼠标位置及前台窗口。
普通／迷你文字起拖的新增断言在修复前失败，修复后通过；另外对恢复为子窗口的歌词控件
执行真实鼠标测试，覆盖文字／空白、两种滚动方向、播放／暂停、无位移单击、箭头／方向光标，
以及普通／全屏开关互不影响。现有歌词行几何测量仅用于测试定位，不再用于阻止拖拽或显示假链接光标。
`fullscreen_album_tests` 另外验证实际选项模板上的复选框、写回及控件布局，
并生成选项页截图。连同 `progress_seek_tests`、基础测试、皮肤配置与窗口重绑定，
六项回归全部通过；测试不修改用户的配置、DLL 或皮肤文件。
