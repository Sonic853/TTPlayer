# 桌面歌词颜色设置恢复

日期：2026-09-25。

## 结论与问题根源

问题来自重建版错误解释原版对话框资源，不是 XP、Win7 或 Windows 10/11
的主题兼容问题。资源 `386` 的 `2263` 是静态占位控件，原版会在其位置
创建颜色列表。此前代码向它发送 ComboBox 消息，并把“添加、删除、更改”
三个按钮改成颜色按钮，还隐藏了“上移、下移”。因此无法完成原版的颜色编辑。

预览也有两个问题：`1068` 原本是静态控件，重建版没有接通自绘消息；其绘制
代码本身画的是整块渐变矩形。预设方案的预览则用两行单色 `TTPlayer`，
均不符合原版。

## 原版证据

分析来源为 `reverse/decompiled/TTPlayer.exe.pseudo.c`、原版 `TTPlayer.exe`
的反汇编，以及 `reverse/ttpres/root/verified/5__386__2052.bin`、
`5__387__2052.bin`。对伪代码丢失的寄存器参数使用反汇编核对。

## 修复实现

实现位于 `src/ui/player_window_options.cpp`，颜色选择器接口位于
`src/ui/player_window_internal.h`。

- 保留原版对话框资源布局，在占位位置创建真实颜色列表；通过原生 ListView
  的固定行高自绘绘制色块。原版使用通知自绘，两者的控件角色、行高、边距及
  选择显示规则一致。
- 添加、更改共用现有 `ColorSelectCtrl` 48 色选择器和自定义颜色对话框。
  为选择器增加可选锚定矩形，将弹层放在对应颜色行下方；其它调用仍按原按钮定位。
- 恢复列表选择、上下交换、拖动交换、激活编辑、数量边界，以及确认/取消的工作副本。
  对话框销毁时关闭所属选色弹层，避免延迟回调访问已经退出的编辑器。
- 将预览静态控件接为自绘，使用 GDI 字形蒙版、3 倍缩采样和分段渐变着色。
  预览字体独立于桌面歌词的用户字体、透明度、描边及阴影设置。
- 修复预设方案编辑后丢失尚未保存名称的问题：更新颜色不再重置命名输入框。
- 恢复确定、取消、保存修改的原版按钮图像。
- 确认直接颜色编辑后沿用现有 `MatchDesktopProfile` 和
  `ApplyOptionsPageRuntime(385)` 更新当前配置及桌面歌词；未播放和已播放的
  颜色组独立保存，XML 格式及既有默认配色保持兼容。

## 验证

本地测试位于 `tests/ui/desktop_color_tests.inc`，通过
`options_drawing_tests --desktop-colors` 运行。测试文件只保留在本地 tests
目录，不上传、不更新 tests 子模块指针，Action 不运行测试。

验证项目包括真实 HWND 控件类型、五个按钮、25 像素行高、1～3 条颜色边界、
上下移动及越界、拖动交换、选色取消与确认、条目激活、更改、两组颜色独立提交、
取消回滚、XML 保存重载、文字预览，以及从真实预设菜单进入的嵌套编辑、名称保留、
恢复默认、左右配色和保存方案。

### 比较边界

颜色编辑的控件结构、数据操作和预览内容已按上述原版证据恢复。原版另外含有
专用字形边缘平滑处理；本次采用 GDI 缩采样，不声称字形边缘逐像素相等。
系统缺少“幼圆”时仍由 GDI 选择替代字体，和原版调用 `CreateFontIndirectW`
时的条件相同。本次宿主 Windows 11 没有 `simyou.ttf`，其预览会使用替代字体；
因此不能将它与装有“幼圆”的系统截图作字形逐像素比较。这不影响颜色列表
和渐变顺序。
