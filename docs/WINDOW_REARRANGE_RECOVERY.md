# “重新排列”恢复（2026-09-23）

## 原版依据

命令 `0x7DD6` 在部分资源中显示为“重置窗口”。原版公共命令分发
`004685D7` 将它交给 `0046C7F3`，重建版此前没有对应处理。
依据为 5.7.9 的 `TTPlayer.exe.pseudo.c`，并交叉核对原 EXE 反汇编。

| 分支 | 原版行为及恢复结果 |
| --- | --- |
| 主窗口最小化 | 先恢复窗口，再计算布局，避免保存最小化矩形。 |
| 普通皮肤 | 主窗恢复到 `(100,100)`，使用当前皮肤主窗尺寸；歌词、均衡器、播放列表恢复皮肤 `position` 矩形，并以主窗位置为原点。包括当前隐藏的辅助窗。 |
| 迷你皮肤 | 主窗恢复到 `(100,0)` 和迷你皮肤尺寸；歌词紧贴右侧，宽 200 像素、高度与主窗相同。普通模式的主窗缓存、播放列表及均衡器位置不改动。 |
| 无皮肤 | 请求主窗 `400×300`，读回实际窗口尺寸，在工作区中央排列为主窗／歌词、播放列表／均衡器的两行两列。重建版无皮肤界面保留其现有最小尺寸约束。 |
| 桌面歌词 | 独立恢复：宽度限制在 640～1000，高度限制在每行 24～150；按 `SM_CXFULLSCREEN/SM_CYFULLSCREEN` 水平居中，底部留 50 像素。保留原版 `InflateRect` 整数舍入。 |

### 寄存器参数校验

伪代码的 `0044AA0C(param_1 + 0x1C24)` 没有显示矩形参数。
反汇编 `0046C9E2..0046C9E5` 明确把桌面矩形地址放入 EAX，再调用 `0044AA0C`。
后者向桌面歌词控件发送 `0x52C`，因此不能把预先计算的桌面矩形当作无用变量删掉。
普通歌词、均衡器和播放列表矩形分别来自皮肤对象 `+0x91C`、`+0xA3C`、`+0xD64`。

原版还存在可选音乐窗 `+0x36EC` 的独立位置处理：使用皮肤布局或相邻窗口定位。
重建版尚无该原版音乐窗组件，本次不把现有可视化子窗口当作它来移动。

## 实现

- `player_window_layout.cpp` 集中实现布局恢复，主窗口公共命令路由接入 `0x7DD6`。
- 先完成窗口淡入淡出、退出独立全屏布局并结束拖动，避免后续定时器或拖动覆盖新位置。
- 不切换皮肤、不改显示／隐藏偏好、不重置音频设置或曲目；刷新区域、控件及可视化布局。
- 更新正常／迷你活动窗口缓存和保存用矩形；沿用现有退出、切换皮肤时的配置持久化流程。
- 桌面歌词通过自身布局函数同步控制窗、绘制窗和工具栏，保持当前显示模式。

外部皮肤是重建版扩展，没有可直接照搬的原版分支。
恢复采用现有提供者 API：保存布局，Detach，提交空的默认布局，重新 Attach。
不解析提供者私有状态文本，保留 HWND 和内容显示模式；失败时恢复旧布局。
这样不会将原生皮肤尺寸强行套在外部皮肤的窗口子类上。

## 验证范围

本地回归代码在 `rebuild/tests/ui/rearrange_window_tests.cpp`，使用隔离运行目录和实际播放器 HWND。
覆盖普通／迷你／桌面歌词、隐藏窗口、最小化恢复、重复执行、模式切换后的矩形缓存。
宿主机有外部皮肤 DLL 和测试包时，额外验证提供者默认布局、卷起状态恢复、重复接入及返回原生皮肤。
测试代码不加入发行包，Actions 不执行这些测试。

### 实测结果

- 普通 Release：共享菜单回归、重新排列回归均通过；后者使用真实窗口并包含外部皮肤测试。
- XP SP3（5.1.2600）与 Win7 SP1（6.1.7601）：同一旧系统 Release 构建的两个回归程序均通过。
  两台虚拟机覆盖原生皮肤普通／迷你／桌面歌词、最小化恢复、隐藏状态、模式缓存和无皮肤布局；
  外部皮肤生命周期在宿主机验证，没有据此声称其所有提供者在 XP／Win7 上均已测试。
- 旧系统 EXE 的静态导入检查通过：19 个 DLL、655 个导入项，子系统版本 5.01。
- 测试使用独立配置与播放列表目录，未改动虚拟机里原有的播放器配置。

本次验证范围是窗口布局、菜单和状态同步；不代表原版尚未重建的音乐窗及历史在线服务已经恢复。
