# AAC、MOD、VQF 后续修复与三系统验收

后续 AAC 的 ADIF、LD、显式频率／高采样率 SBR 与分片标签修复见 [2026.10.29p3](AUDIO_PLUGIN_FOLLOWUP_20261029P3.md)。下文保留 p2 历史结果和当时边界。

构建：`2026.10.29p2`。接续 [2026.10.29p1](AUDIO_PLUGIN_FOLLOWUP_20261029P1.md)，本轮更新 `ttp_aac`、`ttp_mod`、`ttp_vqf`。RM 沿用已经验收的 p1 DLL，OGG 及其它插件不在本轮修改范围。

## 本轮修正

### AAC：部分读取取消与 MP4 格式提示

实时 ADTS 的 IStream 可能在返回取消错误前已经消费并交回一部分字节。此前 `fill_live()` 先抛出 HRESULT，再保存返回数据，不可回退的输入因而丢失这些字节。现在先检查返回长度并保留实际收到的数据，再传播错误；重试从相同压缩数据继续，不吞掉取消状态。

MP4 的 AAC sample entry 可能将采样率或声道提示留空；16.16 采样率字段也不能直接表示 88.2／96 kHz。此前在交给 AAC 解码器前要求两个字段都非零，导致有效 Main 88.2 kHz、PCE 文件被提前拒绝。现在缺失频率时从受支持的 ASC 索引恢复核心时钟，允许声道配置由 PCE 指定，再由解码器确认实际输出频率和声道。HE／HEv2 的扩展频率与 iTunSMPB 时间换算仍保持既有行为。MPEG 音频分支仍要求其必要字段有效。

真实 Main 88.2 kHz 单声道文件完整输出 5,780,480 帧；LTP 48 kHz 文件完整输出 911,360 帧。原版的 Open 返回 `S_FALSE` 后仍可取得格式并解码，不能将非 `S_OK` 一概判为不支持。

发行核对同时修复 AAC 源码包误包含 `cmake/__pycache__/*.pyc` 的问题。打包仍以允许目录为范围，递归复制时排除缓存、编译产物和重解析点；完整项目源码、固定 FAAD2 对应源码和许可证继续单独提供。

详见 [AAC 流取消与 Profile 边界](../../ttp_aac/docs/STREAM_PROFILE_BOUNDARIES_20261029P2.md)。

### MOD：UMX 容器读取范围

固定 libmodplug 0.8.9.0 的 UMX 加载器在名字表、导出记录和音乐对象读取中缺少统一范围检查，错误偏移可能触发访问异常。本轮用 `src/umx_reader.cpp` 替换上游 UMX 加载器，在读取前检查剩余长度，并验证紧凑整数范围、名称终止符、对象与采样长度、类型签名。

保留已支持的 Unreal 包版本、首个导出对象规则，以及 IT 被标作 S3M 的兼容处理。既有混音算法、末端延拓和安全零前缀保持不变；真实 UMX、两个 XM 及其它既有格式的完整 PCM 均未偏离本轮前的基线。

子任务的底层验证流程曾被自动安全审核中止，提示可能涉及网络安全风险。后续没有继续该被中止的流程；父任务改用普通 Reader 接口执行 111 组独立回归，不调用内部函数或使用内存保护区探针。三系统结果只统计这套公开接口验收，未将较早底层观察重复计入。

详见 [UMX 输入范围检查](../../ttp_mod/docs/UMX_INPUT_BOUNDS_20261029P2.md)。

### VQF：预热取消与解码错误状态

原 `SetCallback` 路径在播放前丢弃两帧。此前只在预热全部成功后记录完成状态，预热中途取消再恢复时可能把这两帧重新交给宿主。真实文件负对照出现多出 32,768 字节 PCM。本轮单独保存预热请求，重建解码状态时恢复相同播放起点；回调重试、Read、Seek 和连续取消后均恢复到正常基线。

对解码器确认的不可恢复帧损坏，保留错误直到重新建立相应解码历史。重复 Read、Start 或缓存回放到错误位置不再悄悄返回后续 PCM；有效前缀仍可读取。可恢复 I/O 取消、最后不完整帧的既有 EOF 兼容规则与真正的帧语法错误分开处理。初始化失败时释放未成功打开的 context，避免下次把残留指针误认作可用解码器。

固定 TwinVQ 算法和正常文件 PCM 不变。同期检查 RM 的对应错误路径，没有发现需要更改当前 p1 DLL 的问题。

详见 [VQF 错误恢复](../../ttp_vqf/docs/ERROR_RECOVERY_20261029P2.md)。

## 最终验收

同一套最终 DLL 在 Windows 11、XP SP3、Win7 SP1 分别运行以下验收。Windows 11 按用户要求代为验证现代系统，没有单独的 Windows 10 实机结果。

| 回归项 | 每系统组数 | Windows 11 | XP SP3 | Win7 SP1 |
| --- | ---: | --- | --- | --- |
| AAC 部分读取取消、Main／PCE／零提示及不支持 ASC | 133 | 通过 | 通过 | 通过 |
| AAC 既有时间轴、定位、保存与只读回归 | 105 | 通过 | 通过 | 通过 |
| MOD：60 个有效 UMX 组合、36 个无效边界、15 个既有回归组 | 111 | 通过 | 通过 | 通过 |
| VQF：预热恢复、正常 PCM、错误帧及既有定位恢复 | 28 | 通过 | 通过 | 通过 |
| 合计 | **377** | **通过** | **通过** | **通过** |

合计 1,131 组通过。这里按各验收脚本的组数统计，不额外叠加组内子场景；例如 VQF 的四个预热组包含 64 个取消恢复子场景。

原版 5.7.9 与重建版宿主在每个系统分别播放真实 UMX、VQF、Main 88.2 kHz AAC 和 20 秒分片 AAC，各系统八次，合计 **24 次**通过。确认实际加载最终插件、请求的文件进入播放、播放时间推进、没有错误对话框且正常响应关闭。分片 AAC 的观察超过 10 秒，跨过空白区间。原版关闭返回值为 1，重建版为 0，均未强制关闭。

宿主使用隔离目录和静音设置，这些结果不是实体扬声器听音测试，也不表示所有硬件输出后端均已验证。Windows 11 上旧兼容清单下的探针可能记录 `6.2.9200`，该值不代表实际在 Windows 8 上运行。

所有测试、探针、样本、参考 PCM 和日志仅放在私有 `rebuild/tests/plugins_followup_20261029p2`，没有加入 Actions、运行包或对应源码包。最终核对结果保存为其中的 `final-validation.json`，包括：

- 构建、私有宿主、XP／Win7 回传、发布目录及运行 ZIP 的 DLL 摘要完全一致。
- 三个运行 ZIP 只含对应 `AddIn/ttp_*.dll` 与 `SHA256SUMS.txt`。
- AAC／VQF 源码附件中的项目源码与工作区一致，排除私有测试、二进制和 Python 缓存。
- 工作区原版 EXE、已记录的原 AddIn／RealCodec，以及本轮未改的 RM／OGG 发布 DLL 摘要保持不变。

## 尚未完成的范围

- AAC Main channel coupling 在当前 FAAD2 中仍不支持，SSR 分支未启用；显式频率索引 15 与扩展 AOT 31 仍按当前库能力受控拒绝。
- 一个真实 ER AAC LD 样本在第 35 包报告消费 553 字节，但包长只有 552，当前继续拒绝这种不一致。直接 FAAD 输出与原版相近，却与 FFmpeg 存在差异；尚无标准参考足以判定哪方正确，不能通过放宽包长检查宣布 LD 已恢复。
- ADIF、其它历史 AAC Profile／声道组合、分片标签写回未因此补齐。
- MOD 本轮覆盖 UMX 读取范围及既有八格式回归，未扩展所有 Unreal 包版本、多对象选择，也未宣称所有 Tracker 指令或损坏组合都已穷举。
- VQF 未扩展 TwinVQ 模式、丢包隐藏、任意无历史跳转或小时级状态快照；不可定位流不具备任意回退能力。
- [p1 报告](AUDIO_PLUGIN_FOLLOWUP_20261029P1.md) 中的 RM 网络错误隐藏、历史曲库覆盖及实际硬件听音限制仍成立。不能将本批通过等同于所有音频插件完全复刻。
