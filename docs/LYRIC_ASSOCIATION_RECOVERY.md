# 歌词读取与“关联歌词”恢复

> 2026-09-21 补充：相关功能已在 XP SP3 / Win7 SP1 虚拟机中执行回归。覆盖项、修复和未覆盖边界见 [虚拟机验证记录](XP_WIN7_VM_VALIDATION.md)。下文保留原日期的历史结论。

本次只以根目录 5.7.9 的 `reverse/decompiled/TTPlayer.exe.pseudo.c`、
`TTPlayer.exe` 及 `ttpres.dll` 为依据，不引用 6.1.2 的非皮肤行为。

## 原因与修复范围

旧重建版将命令 `0x802D` 直接接到打开文件对话框，所选路径只保存在
`associated_lyric_path_`。这既遗漏了原版“指定歌词文件”窗口，也无法在切歌、
重新启动或下载后保留关联；“撤消关联”还会立即重新搜索并载入刚撤消的歌词。

现在恢复原版资源 206 和 205 的对话框、控件、列标题、按钮图，并将文件显示状态
与跨会话关联表分开。原版类布局不能由不完整的反编译 C 逐字重编译；下面记录的是
可以定位的分支及对应实现，不声称整个歌词子系统已经达到二进制等价。

## 原版命令与实现

| 原版位置 | 行为 | 重建实现 |
| --- | --- | --- |
| `0044C930 / 0044ED42` | 捕获当前歌曲，模态打开资源 206，根据返回值更新关联 | `ShowLyricAssociation`，`ChooseLyricAssociation` |
| `0044788E / 00447A2E` | 控件消息分派、“不关联”状态禁用、按钮图片 | `AssociateProc`，资源 206、位图 1/7 |
| `00447CF3 / 00444CCD` | 输入歌词标题、部分匹配、本地文件搜索 | 可取消的后台本地搜索；列表列名来自 `0x8158` |
| `00447FC2 / 004481B7` | 浏览选择后直接确认关联；列表双击/关联按钮确认 | 浏览保留此前明确要求的现代 `IFileOpenDialog` |
| `004480B3 / 0044829A` | ListView 原地重命名，`MoveFileW`，失败消息 `0x8187` | 同样的通知与文件移动；额外拒绝路径穿越/ADS |
| `004480E8` | 删除所选歌词文件，使用系统回收站/确认 | `SHFileOperationW(FO_DELETE, FOF_ALLOWUNDO)`；不静默删除 |
| `00448204 / 0044E004` | “查看所有关联”打开资源 **205** | 嵌套原生模态窗口，歌曲文件/歌词文件两列 `0x8159` |
| `00445CD3 / 00445E50 / 00445ED0` | 重新关联、撤消选中关联、删除错误关联 | 修改独立关联表；撤消只删映射，不删歌曲或歌词 |
| `0044CB0C` | 右键“撤消歌词关联”删映射并清除当前歌词 | 不再立即自动搜索同一文件 |

206 的结果码不是一律“选了一个文件”：

- `1`：为弹窗打开时捕获的歌曲保存所选文件；仍为当前歌曲才更新显示。
- `0x844`：删除映射，清除当前歌词。
- `7`：保存单个反斜杠 `\`，表示“不关联歌词”，清除当前歌词。
- `6`：移除上述标志，清除当前歌词；按钮文字来自 `0x803A`“撤销不关联”。
- `2`：取消选择，不提交该窗口的关联草稿。通过“查看所有关联”做出的修改、
  已经确认的重命名/回收文件是独立操作，不因关闭外层选择窗口而回滚。

模态窗口由真实入口窗口持有，使用 `DialogBoxParamW` 的禁用所有者、激活提示、
关闭恢复及置顶继承机制，不创建替代主窗体。搜索线程只持有数据副本，不持有 HWND、
PlayerWindow 或 DLL。关闭对话框不会等待目录扫描；过期扫描结果不会投递到新窗口。

## 关联文件

`00411C72 / 0041B553` 的键为“歌曲路径（不区分大小写）+ 子曲目编号”，不是
歌词标题、服务器 ID 或文件内容摘要。CUE 的不同子曲目不能共用一个默认零号键。

`00401829` 根据 EXE 路径替换扩展名，`004C038B -> 004BE9C8` 读取，
`004616BD -> 00453AF6` 在退出时检查 dirty 并保存：

```text
歌曲完整路径|子曲目编号|歌词完整路径
C:\Music\album.cue|2|C:\Lyrics\track2.lrc
C:\Music\no-lyric.flac|0|\
```

- 读取支持 UTF-8 BOM、无 BOM 的系统 ACP，以及旧的 `歌曲路径|歌词路径`（子曲目 0）。
- 保存为 UTF-8 BOM + CRLF；没有变更不写文件。表变空时只移除该关联文件。
- 重建版实际使用 **`TTPlayerRebuild.rll`**，与 EXE 同目录；不修改/自动迁移原版
  `TTPlayer.rll`，也不在 `TTPlayerRebuild.xml` 或歌词服务器 INI 中保存歌曲关联。
- 使用同目录临时文件并原子替换，写入失败保留旧文件；不覆盖无法读取的数据库。

## 播放时的选择顺序

`0045AD86 -> 0044A370` 在成功打开音频、得到元数据后选择歌词。重建版此前在音频
打开前便搜索文件，现在打开完成后会重新执行该顺序：

```text
AutoLoadLyric（强制重新加载/手动操作除外）
  → 未设置 DontLoadLyricTag：读取 Lyrics；空/缺失才尝试 Lyric
  → 有效内嵌同步歌词：显示，结束
  → 查找 当前歌曲路径 + 子曲目 的关联
      \：停止外部搜索
      普通文件：读取成功则显示；丢失/解析失败继续
  → 按设置目录顺序搜索本地 lrc/txt
  → 本地未找到有效歌词，才按 AutoDownLoad / DownLoadWhenFullInfo 进入在线搜索
```

内嵌文本的查询补到了已有音频 reader 工作线程中，UI 使用已返回的元数据，
不会为了自动查歌词再同步打开一次解码插件。

`00401C0F` 中目录前的 `*` 是“搜索子文件夹”，**不是启用开关**。
未带 `*` 的目录照样搜索；`<Sound Folder>` 为歌曲目录，
`<Lyrics Download Folder>` 仅在配置的下载目录非空时参与。
`00444F71` 优先 `歌手 - 歌名` 精确文件（9 分），原音频文件名精确匹配为 4 分；
后面的目录仍可用更高分替代它。同分保留先遇到的结果；递归最多根目录加三层。
手动搜索接受全部候选，普通/部分匹配门槛分别为 4/1 分。

`0043E237` 的无 BOM 文件编码回退也已修正：先严格 UTF-8 检测，再在 ACP=950
时使用 Big5、其余系统使用 936，而不是盲目使用英文系统的 ACP。保留此前的
UTF-16 BE 兼容扩展，不改变歌词时间偏移及滚动代码。

## 下载和拖入

在线下载仍经过已有 AddIn/HTTP(S) 工作线程及安全保存流程，详见
[LYRIC_SEARCH_RECOVERY.md](LYRIC_SEARCH_RECOVERY.md)。

`0044BEED` 中 `AutoAssociate` 现在接入同一张持久关联表，使用下载开始时捕获的
歌曲路径/子曲目；文件保存失败不创建关联。取消关联、切歌和手动选文件后，旧的
自动请求不能覆盖新歌词。自动搜索等待本地扫描完成，不与它争抢显示结果。

`0044AC70` 的拖入歌词仅替换当前显示/编辑内容，不自动向 `.rll` 插入记录。
这与下载对话框中明确勾选“下载后与歌曲文件进行关联”不同。

## 验证与仍需单独恢复的部分

`lyric_association_tests` 在宿主机使用根目录 **5.7.9** 的资源 DLL，测试唯一临时目录中的
文件及真实原生模态对话框，不修改生产歌曲、原版 `.rll` 或设置。
覆盖：关联键/子曲目、两种行格式、BOM、空表、重启读取、禁止关联、搜索排序/递归/
部分匹配/取消、206/205 控件及列标题、原生禁用/恢复所有者、置顶、双击关联、重命名、
撤消关联、内嵌优先、拖入不持久化，以及弹窗期间切换 CUE 子曲目。
`lyric_search_tests` 使用 loopback 和真实原版插件，补测下载关联的保存及重新读取。

最终宿主机验证：上述两项及 `options_drawing_tests`、`desktop_lyrics_menu_tests`
共 4/4 通过（12.27 秒）；关联输入另连续运行 3 次通过，基础测试中的
`lyric-settings`、`runtime-ui-settings`、`lyric-shift` 分组通过。
构建输出为 `out/png-6120/Release/TTPlayerRebuild.exe`，未替换已部署的播放器。

```powershell
cmake --build out/png-6120 --config Release --target ttplayer_rebuild lyric_association_tests lyric_search_tests
ctest --test-dir out/png-6120 -C Release -R '^lyric_(association|search)_tests$' --output-on-failure
```

206 初始化函数的部分路径被反编译器误标成不可达，已额外读取原版 EXE 的反汇编：
`00447B3C..00447C98` 确认列初始宽度 80/200、`0x8158`、
`00447C18 -> 0042BC90` 的“查看所有关联”链接绑定、歌词标题填充及投递搜索命令。
资源 STATIC 2087 本身没有 `SS_NOTIFY`，现在补齐实际鼠标点击、键盘激活和链接字体，
不只测试向父窗口直接发送 `WM_COMMAND`。重建没有照搬反编译器生成的异常跳转。

边界：目录搜索采用后台线程，
额外跳过 reparse-point 目录，避免链接循环；清理错误关联时保留有意设置的 `\` 标志。
尚未在真实用户文件上执行“删除文件”按钮，以免破坏歌词数据。
`AutoSaveLyricTag` 的自动写入及其 writer 失败/播放占用处理不属于本次已完成验证的
关联表恢复；原有手动写标签入口不作为它已经等价实现的证明。歌词上传、音频文件改名时
迁移关联键、所有特殊文件名的原版评分一致性仍需单独核对。
