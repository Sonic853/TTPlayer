# 任务栏滚动标题：原版对照与修复

日期：2026-09-28。分析对象为仓库中的 TTPlayer 5.7 原版、
`reverse/decompiled/TTPlayer.exe.pseudo.c` 及对应 x86 反汇编。

## 结论

重建版原先已有 250 ms 定时器和 `CharNextW` 左移逻辑，主要偏差在于：

1. 错把皮肤中的 `display_title_` 用作窗口标题，带入 `1.` 等列表序号，
   缺少播放器名称，并且没有使用原版任务栏所用的歌曲显示格式。
2. 拖动进度条时继续滚动，缺少原版定时器的拖动状态判断。
3. 仅比较字符串和播放状态；重播、切换至同名曲目时，文字相同便不重置滚动。
4. 滚动选项的控件编号没有传到运行时处理层，遗漏原版的立即重置分支。
5. 媒体库选曲缺少立即刷新标题；托盘提示也误用了带序号的皮肤文字。

此次修复分别处理窗口标题、皮肤信息文字和托盘提示，保留现有定时器。

## 原版调用链

| 入口 | 原版行为 | 重建版对应处理 |
| --- | --- | --- |

| `0045CA57` | 建立完整窗口标题，再另行给皮肤信息加列表序号；将完整标题交给托盘 | `MainWindowCaptionText()`；皮肤继续使用现有 `display_title_` |
| `0046010E` | Timer 10，间隔 `0xFA`，仅正在播放且进度条未拖动时调用滚动 | 现有 250 ms UI 定时器；补上进度拖动及实时播放状态判断 |
| `0045D434` | 读窗口当前文字，按 `CharNextW` 取开头一个字符，移至末尾 | 保留相同的字符循环算法 |
| `0045BF4B` | 开始／再次播放时，将完整标题加两个空格重新写入窗口 | 成功打开曲目后强制重置，即使标题内容相同 |
| `0045C198` | 暂停恢复完整静态标题；继续播放从完整标题重新开始 | 播放状态变化时重新写入标题 |

| `00451B82` | 托盘提示使用完整标题，不跟随滚动 | 托盘复用完整标题生成函数 |

### 标题内容与空格

原版 `0045CA57` 的组成是：

```text
曲目显示名称 + " - " + 程序名称 + " " + 可选附加字样
```

播放且启用滚动时，再追加两个空格。**播放标题的尾部不是版本号。**
无曲目时才使用包含版本信息的默认标题。

伪代码中的 `DAT_00547880` 是可选附加字样；反汇编显示其由
`004C0900` 调用 `004BFDCD` 后的分支赋值，并非版本字符串。
原版还涉及 `UserWord` / `UserWordMD5` 的校验。本次标准版实测该值为空，
修复按此标准标题恢复；未新增该历史校验及附加字样机制，也未将原始
`UserWord` 无条件拼入标题。

下面用 `␠` 表示空格，实际窗口中没有此符号：

```text
完整静态标题：Caption ABC - 千千静听␠
开始滚动：    Caption ABC - 千千静听␠␠␠
第一个计时：  aption ABC - 千千静听␠␠␠C
第二个计时：  ption ABC - 千千静听␠␠␠Ca
```

不存在开头等待数秒、到尾部停留、按像素平移或滚动整个标题后才重新计时的
逻辑。`TitleSlideInterval` 控制皮肤信息项的切换，不是任务栏滚动速度。

### 状态切换

| 操作或状态 | 结果 |
| --- | --- |
| 无曲目 | 默认播放器名称与版本，静止 |
| 正在播放，开启滚动 | 完整标题加两个空格，每次计时左移一个字符 |
| 暂停或停止 | 恢复完整静态标题，保留歌曲名称 |
| 继续／重播／换曲 | 从完整标题重新开始，包括相同标题的不同文件 |
| 拖动进度条 | 保持当前字符位置，松开后从该位置继续 |
| 关闭滚动选项 | 立即恢复完整静态标题 |
| 暂停／停止时开启选项 | 原版仍追加两个空格，但不开始滚动；保留这一分支 |
| 迷你模式、最小化 | 仍按同一播放状态与计时规则处理 |
| 删除播放列表中的当前项但仍保留已打开曲目 | 从独立曲目快照生成标题，避免索引失效 |

## 修改文件

- `include/ttplayer/ui/player_window.h`：增加完整标题生成函数及强制重置参数。
- `src/ui/player_window.cpp`：修正标题来源、托盘提示、进度拖动判断，以及选曲、
  重播和停止时的重置。
- `src/ui/player_window_library.cpp`：媒体库选曲立即刷新标题。
- `src/ui/player_window_options.cpp`：保留滚动标题控件编号并恢复原版通知行为。

## 实测与回归

### 原版独立运行

本地脚本 `tests/ui/taskbar_caption_original.py` 将原版及其资源复制到独立目录，
生成静音 WAV 和独立配置，分别开启、关闭 `ScrollTitle`，记录播放、暂停、
恢复、停止时的真实窗口标题。原版 EXE 的 SHA-256：

```text
c7999ea5823469c1684148cac1bd196009824348ccac5cdd45978f8fb574e28c
```

观测结果与上述字符序列和状态转换一致。25 ms 采样间隔下，标题变化间隔约为
228–254 ms；原版定时器参数通过伪代码和反汇编确认是 250 ms。
原始记录：`tests/artifacts/taskbar-caption-20260927/original/observations.json`。

### 重建版真实播放测试

本地专项入口：`skin_rebind_tests.exe --caption`，测试代码位于
`tests/ui/taskbar_caption_tests.inc`。使用独立配置和两个同名、不同目录的
静音 WAV，运行真实播放器窗口及 WaveOut 播放状态切换。

| 环境 | 结果 | 实际标题更新间隔中位数 |

| XP 虚拟机 | 通过 | 250 ms |

检查范围：默认标题、标签格式、自定义格式、文件名回退、序号隔离、字符循环、
周期刷新不重置、暂停／继续、重播、同名换曲、真实鼠标拖动进度条、开关选项、
迷你模式、最小化、停止、曲目快照、清空以及媒体库选曲。

这是窗口标题与消息行为的专项验证；未在独立 Windows 10 环境运行测试，
也未改变或检验各版 Explorer 的任务栏合并、标签显隐和文字截断设置。
