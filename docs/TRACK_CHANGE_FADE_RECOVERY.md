# 上一首／下一首声音淡化恢复

分析与修复日期：2026-09-19。原版样本为项目根目录 `TTPlayer.exe`（5.7.9.0，x86），
依据 `reverse/decompiled/TTPlayer.exe.pseudo.c`，并用原始指令和虚表交叉核对。
下文地址为原版虚拟地址。

## 结论与故障原因

原版手动切歌会先让符合条件的旧播放对象执行**停止淡出**，保留其输出和读取线程，
同时打开新播放对象，按**播放淡入**设置起播。两段淡化可以重叠，时长分别取各自选项。

重建版此前一直复用同一个 `AudioEngine`：上一首／下一首最终进入 `PlayCurrent()`，
随后 `AudioEngine::Play()` 首先调用立即取消的 `Stop()`，旧曲及淡化任务随即结束。
因此，即使选项已经正确读取，旧曲也没有机会完成停止淡出。
新曲淡入本身已有实现；本次补齐的是切歌时旧、新播放对象的交接与生命周期。

**原版的重叠淡化有输出限制：DirectSound 的类型值是 1，WaveOut 是 0，只有类型 1
进入旧曲保留分支。** 不能仅因两者都有设置音量的 API，就对 WaveOut 开启双路淡化。

## 原版调用链

| 阶段 | 地址 | 已核对的行为 |
| --- | --- | --- |
| 上一首／下一首 | `00465230` / `0046528B` | 选择目标项并进入播放请求；随机模式影响目标选择 |
| 列表播放请求 | `0047FEA3` → `00461E35` | 如果请求的仍是当前播放项，临时清除 `SoundFadeMode` 的 `0x08`，停止旧对象后恢复设置 |
| 停止旧曲 | `0045B69B` → `0045B78E` | 清理当前播放的 UI 状态；符合条件时保留旧对象，再发送 Stop |
| 保留条件 | `0045BB61`—`0045BB89` | `SoundFadeMode & 8`、读取器能力 `(flags & 9) == 0`、输出类型 `== 1`、状态 `== 2`（播放中） |
| 保留旧对象 | `00467520`、`0045BB8B` | 替换 `CPlayerWnd+0x4348` 的引用；当前对象保存在 `+0x4344`；更早的旧对象被释放 |
| 退出全局 DSP | `0045BB9D` → `004ABBCB` | 通过 CSound 虚表 `+0x60(0)` 将 `CSound+0xAC` 设为 0 |
| Stop 命令 | `004ABA2F` → `004AC009` | 给声音线程发命令 3，等待命令确认；不在窗口线程等待整段淡化 |
| 停止淡出 | `004AC605`，状态 7 / `004AC8BD` | 使用 `FadeDuration[3]`，约每 10 ms 更新输出音量，完成后停止并发通知 |
| 打开新曲 | `0045AB01`、`00454D7F` | 创建新的读取／播放对象 |
| 新曲打开完成 | `0045AD86` | 设置音量、平衡、`SoundFadeMode` 和四个时长，再开始播放 |
| 新曲播放淡入 | `004AC605`，状态 5 | 普通起播使用 `FadeDuration[0]`；只有 seek 过渡使用 `[2]` |

### 输出类型不是推测

- CSound 构造函数 `004AB58B` 通过输出虚表 `+0x0C` 取得类型，缓存到 `+0x1C`；
  `004AAC05` 返回该值。只有类型 1 会建立它的淡化辅助对象。
- DirectSound 构造函数 `004C30D1` 设置虚表 `00522160`，其 `+0x0C` 是
  `004C3516`，明确向输出参数写入 **1**。
- WaveOut 构造函数 `004E2414` 设置虚表 `00524D64`，其 `+0x0C` 是
  `004E25B4`，明确向输出参数写入 **0**。
- WaveOut 的 `004E263A` 调用 `waveOutSetVolume`。本地及虚拟机的双句柄实验还观察到
  两个句柄的音量读数相互影响；这种输出不能用两条设备音量曲线实现独立交叉淡化。

### 旧曲为何要退出 DSP

`004AC166` 根据 `CSound+0xAC` 决定是否进入全局 Winamp DSP 调用 `0042898D`。
旧曲保留分支把这个字段清零，因此旧曲后续解码块绕过该插件链，已经提交的音频继续淡出。
这不是销毁旧曲的解码、均衡器或输出对象。全局 DSP 实例仍由新曲使用，避免重复 Init/Quit。

## 哪些选项控制手动切歌

| 设置位 | 时长 | 作用 |
| --- | --- | --- |
| `0x01` | `FadeDuration[0]` | 新曲播放淡入 |
| `0x02` | `FadeDuration[1]` | 暂停淡出 |
| `0x04` | `FadeDuration[2]` | 普通 seek 的淡化；不是上一首／下一首时长 |
| `0x08` | `FadeDuration[3]` | 旧曲停止淡出，包含符合条件的手动切歌 |
| `0x10` | `TrackFadeDuration` | 接近歌曲自然结尾的淡出；不是手动切歌的替代设置 |

例如，播放淡入设为 300 ms、停止淡出设为 800 ms，下一首成功打开后从低音量起播，
旧曲继续自己的 800 ms 淡出；并不是等待 800 ms 后才打开下一首。
只启用播放淡入时旧曲直接停止；只启用停止淡出时新曲直接按设定音量播放。

## 重建版实现

1. `PlayerWindow::PrepareTrackChange()` 在打开新曲前检查旧曲和播放项，
   创建继任 `AudioEngine`，保留旧实例执行停止淡出。新实例复制输出、音量、平衡和处理选项。
2. `CanRetainForTrackChange()` 限制为正在播放且支持重叠的 DirectSound 来源，
   使用停止淡化开关和 `[3]` 时长。原版插件读取器直接检查实际 `Capabilities() & 9`；
   CUE 传递底层读取器的限制，网络来源和 CDA 不重叠，MIDI／KS／ASIO 不进入该路径。
3. 新旧实例共享全局 DSP 生命周期；旧曲进入保留状态时关闭自身后续 DSP 调用。
   插件入口加锁，保护切换瞬间仍在执行的回调与新曲初始化检查。
4. 旧曲淡出完成后由现有 UI 定时器回收，旧曲的停止或失败不会触发新曲的自动下一首，
   也不会覆盖新曲歌词、进度、封面和错误文字。
5. 连续切歌先取消更早的旧曲。取消中的线程仍保持所有权；最多保留两个尚未回收的实例，
   达到上限时通过现有 Stop/Play 路径切换，避免慢驱动导致线程无限累积。
6. 重复播放当前项、暂停状态切歌、停止淡化关闭／时长为零时不创建旧曲保留对象。
   同一路径的两个不同列表行仍可正常交接。
7. 可视化线程在锁内取得当前音频实例的共享引用，防止切歌更换实例时访问已释放对象。
   停止和关闭会取消更早的旧曲，退出前等待所有播放实例释放后再卸载插件。
8. 停止淡出从当前实际衰减值开始；打断播放淡入或自然结尾淡出时，不跳回满音量。

### 恢复边界

- 本次恢复切歌对象交接，没有把 WaveOut 原有单路播放／停止淡化扩展成重叠淡化；
  若需要原版式的旧曲淡出与新曲淡入重叠，应选择 DirectSound 输出。
- 可选 mp3PRO 输入 DLL 的回调只有一个活动解码器。增强解码正在使用时先释放旧实例，
  再打开下一首，避免新曲因解码器被占用而悄悄退回普通 MP3；普通 MP3 回退路径仍按底层能力判断。
- 重建版仍采用已有的文件打开就绪等待和 C++ 工作线程，并非原版 CSound 对象的二进制复刻。
  淡化本身不会在窗口线程等待其设定时长，打开慢文件仍受现有打开流程影响。

## 验证

本地回归代码位于 `rebuild/tests`，不加入发行压缩包，Actions 继续使用 `BUILD_TESTING=OFF`。
回归覆盖真实 DirectSound 输出音量、两种时长及独立开关、上一首／下一首命令、快速连续切歌、
暂停、重复项、失败文件、停止回收、可视化实例切换，以及旧曲退出 DSP 后的实际插件调用计数。
同时检查 WaveOut 不重叠、读取器限制和零停止时长。

最终结果：

- 普通版与 XP／Win7 版均完成 Win32 Release 构建。
- 本机 9 项回归全部通过：播放导航、切歌淡化、MIDI、mp3PRO、音频引擎、进度定位、
  任务栏播放状态、皮肤重绑定、Winamp DSP。
- 同一份兼容版切歌回归在 XP 和 Win7 虚拟机均通过。DirectSound 的两份缓冲区实际音量
  分别下降／上升；例如 XP 下一首采样旧曲从 `0` 降到 `-111`，新曲从 `-10000` 升到
  `-1526`（DirectSound 的百分之一 dB 单位）。这不是只检查内部计时变量。
- 兼容版静态导入审计通过：x86、子系统 `5.01`，19 个 DLL、648 个导入项，
  同时对照 XP 与 Win7 导出清单。
- 测试使用生成的静音 PCM 验证播放输出 API、曲线方向和生命周期，未做与原版的逐样本录音比对。
- 本地运行日志保存在 `rebuild/out/track-fade-check-20260919`，不进入发行包。
