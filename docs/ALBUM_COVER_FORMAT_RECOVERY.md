# 多种音频格式的专辑封面补充与修复

日期：2026-09-19。

## 原版依据与分析修正

核对对象是 `reverse/decompiled/TTPlayer.exe.pseudo.c`、原版主程序导出表和
仓库 `AddIn/` 中插件的接口、类型信息及调用代码。插件没有对应的伪代码导出，
因此插件结论使用的是二进制证据。

- `004AF074` 查询 `ISoundThumbnail`
  `{B5E770AF-DFB0-43E5-9B0C-3EE98E7B6248}`。
- `004AD83E` 调用槽 6，取索引 0，只接受 `S_OK`。
- `004AD663` 先检查 reader 能力位 `4`，然后删除旧图片、添加新图片。
- `004DA091` 导出 `CreateStdContent(IStream*, DWORD, ISoundContent**, ULONGLONG*)`。
  APE 插件 `6010250D` 传入写标签类型 `4`（APEv2），`60102AC1` 再向该服务
  查询封面接口。

**修正此前“APE 插件存在接口即支持封面”的推断：** APE 有封面转发接口，
但依赖主程序标签服务。当前原版主程序的 `004DA04D` 只放行 `IUnknown` 和
`ISoundContent`；虽然对象还有封面虚表，也没有公开对应查询分支。因此接口标识
存在不能证明这套原版组合的 APE 封面实际可用。

本次重建补上主程序导出，并公开标签服务的封面接口，是沿原版接口结构补齐缺口。
APEv2 二进制封面和 PNG 支持按重建版兼容能力处理，不称为与原版逐字节一致。

## 问题及修复

1. **APE 缺少主程序服务。** 恢复 `CreateStdContent` 名称导出（序号 2），保留
   `CreateStreamOnFile`（序号 3）。原始插件无需修改。
2. **属性保存使用只读播放流。** 增加不启动解码器的只读
   `OpenReaderForInspection`，供属性和列表信息读取使用；保存改用可写
   `OpenReaderForMetadata`。归档成员禁止写回。
3. **封面按钮误用文本标签能力。** 属性读取协议升至版本 4，单独传递
   `cover_writable`，同时检查封面接口和写入能力。MP3 内置封面编辑保持可用。

共用标签服务复用 ID3v2 / APEv2 / ID3v1 解析器，支持文件和内存流，提供自有封面
字节及用 `CoTaskMemAlloc` 分配的文本。通过 `ISoundContent` 提供文本枚举、查询、
修改，通过 `ISoundThumbnail` 提供图片计数、读取、替换、删除。

沿用一张图片及 60000 字节的写入限制，读取不增加这个小尺寸上限。APEv2 修改保留
音频、前置 ID3 数据、已有 ID3v1、无关二进制字段、自定义文本和 ReplayGain；
写入失败尝试恢复旧尾部，不改动数据时不新建空标签，写入后恢复借用流的位置。
实际写入支持本次插件请求的 APEv2 模式；其它显式写入模式返回 `E_NOTIMPL`，
没有宣称完整恢复原版所有标签写入策略。

主窗口、全屏、任务栏和普通版 SMTC 继续复用音频元数据中的封面及共用图像解码器。
插件存在封面接口却返回空数据时，保留无封面结果，不另找图片替代。

## 验证范围

| 文件 | 插件 | 验证内容 |
| --- | --- | --- |
| M4A / MP4 | `ttp_aac.dll` 的 `CMP4Reader` | JPEG、PNG 读取、替换、删除 |
| APE / MAC | `ttp_ape.dll` + 主程序标签服务 | JPEG、PNG 读取、替换、删除 |
| WMA / ASF | `ttp_asf.dll` | JPEG、PNG 读取、替换、删除 |
| RM / RA | `ttp_rm.dll` | JPEG、PNG 读取、替换、删除 |
| 裸 AAC | `ttp_aac.dll` 的 `CAACReader` | 无封面接口，禁用编辑 |
| TTA | `ttp_flac.dll` 的 TTA reader | 无封面接口，禁用编辑 |

测试调用真正的插件和属性 worker，检查首图字节、图像尺寸、任务栏位图、重新打开
后的持久化、删除、只读文件和无接口格式。APE 样本由仓库插件编码；其它音频样本
由本机 FFmpeg 生成。图片复用前次 PNG 修复的本地样本。

M4A、WMA、APE 检查改封面前后的 PCM；另检查 M4A、WMA、RM 的音频包哈希和 APE
完整音频前缀。RM/AC3 样本的原版解码器读帧返回 `E_FAIL`，对它确认的是封面通路
和音频负载不变，不将其列为音频播放通过。

### 环境

- 普通版 Release：封面、任务栏、全屏、属性协议、内置标签、列表信息 7 / 7 通过。
- 兼容版 Release：多格式封面、图像解码、任务栏、全屏 4 / 4 通过。
- XP SP3 和 Win7 SP1：使用链接生产代码的兼容测试程序，检查实际插件的封面读写。
  表中全部扩展名通过；XP 使用 GDI+ 后备解码。
- 兼容 EXE 静态导入审计：x86、子系统 5.01，19 个 DLL / 645 项导入，保留
  `ttpcomm.dll!#3` 的 XP TLS 启动依赖。

仓库的 AAC / ASF / RM 等插件依赖 `MSVCR110.dll`。XP 虚拟机缺少该运行库时插件
不能加载；测试把本机 x86 VC++ 2012 运行库放入独立诊断目录后通过。重建 EXE
本身未新增此依赖，也未将微软运行库加入发布包。使用这些插件仍需要其配套运行库。

测试代码和样本生成器在 `tests/`，不提交测试子模块、不加入压缩包。Actions
继续设置 `BUILD_TESTING=OFF`。本地日志存于 `out/cover-formats-check-20260919/`。
