# 主窗口曲目信息区单击／双击恢复

## 问题与结论

主窗口曲目信息区（皮肤 XML 的 `info`）此前只参与绘制，没有参与鼠标命中检测。它被当作主窗口背景：按下进入窗口拖动，双击进入迷你模式，缺少原版的手动切换信息和打开文件属性功能。

本次按原版消息链恢复：

- **单击松开**：立即显示下一项曲目信息，末项后回到第一项；重置当前横向滚动／纵向过渡，再按新文本长度启动计时器。
- **双击**：进入现有“文件属性”命令，沿用其当前播放曲目／播放列表焦点的目标选择规则。
- 信息区保留普通箭头光标，不捕获鼠标、不拖动主窗口。真正的窗口背景保留原有拖动和双击切换迷你模式行为。
- 关闭自动轮换不会禁用手动单击。只有一个长文本时，单击从开头重新滚动；空信息不会越界。

## 原版伪代码依据

依据本地 `reverse/decompiled/TTPlayer.exe.pseudo.c`（TTPlayer 5.7.9）。以下是静态伪代码调用链，不把截图中的坐标作为实现依据。

| 入口／地址 | 原版行为 | 重建版对应 |
| --- | --- | --- |
| 创建主窗口信息控件，ID `0x7DD9` | 独立子窗口，类样式启用 `CS_DBLCLKS`；皮肤绑定其位置、字体、颜色 | `kInfoControlId` 与当前皮肤 `info` 的虚拟命中区域 |
| `004096AE` → `00409AC8` | `WM_LBUTTONUP` 停止旧计时器，清空方向与横纵偏移，递增信息项索引并回绕 | `WM_LBUTTONUP` → `InvokeSkinAction(info)` → `StartSkinInfoItem()` |
| `004092FC` | 测量新文本；超宽使用计时器 9（40 ms、端点停留 25 次），否则按自动轮换设置启动计时器 7 | 复用已有信息滚动与自动轮换实现 |
| `004347EE` | 文本按下只对带 `WS_TABSTOP` 的控件设置焦点；不启动父窗口拖动／捕获 | 信息区按下不走背景拖动，也不夺取焦点 |
| `0040FB3A` | 松开另发 `WM_COMMAND(0x7DD9, notification=0)`；主窗口不把它作为属性请求 | 单击切换与双击属性分离 |
| `0040FA41` → `004582D0` → `00464B54` | 双击发通知 1，主窗口转发命令 `0x7D67` | `STN_DBLCLK` → `kCmdFileProperties` |
| `00464A94` | 退出全屏，根据播放对象及播放列表焦点决定文件属性目标 | 沿用现有公共属性命令，不另造属性窗口 |
| `00460CF5` | 主窗口背景双击检查迷你布局并发送 `0x7DD4` | 仅非交互背景继续切换迷你模式 |

原版双击前会先收到一次单击松开；因此没有增加等待双击判定的延迟，也没有吞掉第一次信息切换。

## 换肤与迷你模式

命中检测遍历 `ActiveSkinElements()`：普通模式读取 `Elements()`，迷你模式读取 `MiniElements()`。信息区直接使用该布局解析得到的 `SkinElement::bounds`，与绘制使用同一套布局。

没有保存截图坐标、固定标题高度或默认皮肤热区。更换皮肤后自动使用新布局；没有 `info` 的布局不会凭空产生可点击区域。信息区没有加入通用按钮类型，因此不会新增按钮位图、按钮动画或手形光标。

## 停止状态下的歌曲信息补充修复

### 原版依据

单击 `00409AC8` 递增信息项索引，双击经 `0040FA41 → 00464B54 → 00464A94` 打开属性；这两条链都没有要求“正在播放”。

更关键的是信息建立的时机：`0045AD86` 在成功取得当前 `CPlayItem` 和格式信息后，**先调用 `0045CA57` 建立标题、艺术家、专辑、格式、长度等信息项，再判断是否开始播放**。参数表示不播放时直接设置停止状态文字；只有另一个分支才调用 `0045BF4B`。因此“曲目已经载入／恢复”与“正在播放”是两件事。

停止命令 `00465169 → 0045C0C6` 停止声音、更新播放状态和进度，没有清空 `+0x434C` 的当前曲目对象，也没有删除信息控件中的条目。停止后仍能单击轮换和双击打开属性。`00464A94` 关闭当前曲目属性后还会调用 `0045CA57`，让修改过的标签重新显示。

### 重建版遗漏与修复

1. **未播放的恢复路径只有一项标题。** `SelectTrackFrom(..., false)` 和媒体库的 `SelectMediaLibraryPlaybackTrack(..., false)` 原先调用 `RebuildSkinInfoItems(false)`，直接跳过其他信息项。上一次修复恢复了点击入口，但没有覆盖这条数据建立路径。现在两处均建立完整的已知信息。
2. **格式／长度原先只来自音频引擎。** 停止启动时引擎尚未打开，新选择的曲目也可能与引擎残留数据不一致。现在先使用当前曲目的缓存标签、`media_type`、采样率、码率和时长；只有音频源已打开且路径与子曲目编号都一致时，才使用该解码器的格式／时长。类型说明的 `|` 后附加描述不会混入简短格式文字。
3. **后台读取只刷新播放列表。** 当前恢复曲目尚未读取时，复用原有异步歌曲信息队列，给予当前曲目优先级并允许读取不在可视范围的这一项。保留原有读取模式设置；不在鼠标处理函数中同步读文件，也不为查看信息启动音频输出。
4. **当前信息读取完成后同步主窗口。** 只有结果确实更新了当前播放目录的当前曲目，才调用 `RefreshTrackInformation()` 更新标题、信息项和显示；其他曲目的结果不会重置正在查看的信息。已有过期结果校验继续生效。
5. **关闭当前曲目属性后刷新信息。** 沿用原版 `00464A94 → 0045CA57` 的行为，重新获取当前曲目对象，更新刚修改的标签；保留播放列表焦点分流规则。

未知字段仍不伪造。关闭歌曲信息读取、未读取的网络地址或读取失败的文件，只显示已有内容。原版的信息区坐标及普通／迷你皮肤命中规则继续使用前述修复。

本次补充修改 `include/ttplayer/ui/player_window.h`、`src/ui/player_window.cpp`、`src/ui/player_window_library.cpp`、`src/ui/player_window_playlist_info.cpp`。
