# TTPlayer 选项窗口恢复证据与行为基线

> 2026-09-21 补充：相关功能已在 XP SP3 / Win7 SP1 虚拟机中执行回归。覆盖项、修复和未覆盖边界见 [虚拟机验证记录](XP_WIN7_VM_VALIDATION.md)。下文保留原日期的历史结论。

本文记录从 `reverse/decompiled/TTPlayer.exe.pseudo.c` 静态恢复，并由历史
Windows Sandbox 证据及当前宿主机双版本对照确认的选项窗口行为。地址均为
原版 `TTPlayer.exe` 的虚拟
地址；伪代码行号会随重新导出而变化，因此实现和评审时应优先使用函数地址。

## 2026-09-14：本地搜索和服务器列表的图标偏移

两处原先共用 `InstallButtonBitmap`，把所有位图拉伸到 16×16，再按带文字按钮
设置左对齐和 `{3,0,3,0}` 边距。5.7.9 的 1027/1039/1042/1045 位图实际均为
**16×15**，所以既改变了图形本身，也没有采用原版无文字按钮的坐标。

- `0046E787`：按按钮控件 ID 读取对应图标/位图，透明色为 `0xC0C0C0`。
- `00434754 → 00434F8C`：位图按资源原始尺寸载入，再以 `GetObjectW` 的宽高建立图像列表。
- `0046E0C9`：无文字时，`x=(客户区宽-图宽+1)/2`、`y=(客户区高-图高+1)/2`；
  按下状态再分别加 1。支持主题时使用 `DrawThemeIcon`；经典禁用态采用
  `DrawStateW(DST_ICON | DSS_DISABLED)`，普通态采用透明图像列表绘制。

重建版保留原位图尺寸，纯图标按钮复用上述坐标与状态分支。原生 `BCM_SETIMAGELIST`
的 CENTER 仍有取整及主题留白差异，因此不依靠该标志完成实际定位，而在原按钮
子类中绘制纯图标分支；原生输入、禁用、热态、捕获与按钮命令处理不替换。
屏幕绘制先完成内存缓冲再提交，不分开擦除背景和绘制图标。
带文字按钮继续使用现有布局，没有改为纯图标按钮，也没有移动/重建 HWND。

`options_drawing_tests` 对两个窗口的 8 个按钮进行实际 `WM_PRINTCLIENT` 像素检查，
覆盖原尺寸、四种奇偶客户区尺寸、Windows 主题/经典外观、普通/按下/禁用状态，
同时验证带文字“关闭”按钮布局未改变。测试使用 5.7.9 的本机 `ttpres.dll`；
并非宣称已逐像素重建所有选项按钮的边框和其它类型按钮。

## 1. 总体结构

原版不是十五个互不相关的对话框，而是一个模式无关属性表外壳，加十五个固定
顺序的页面。核心调用链如下：

- `FUN_0045D531`：销毁已有选项对象，记录目标页，构造新的选项对象并显示；
- `FUN_0049F4AD`：构造完整页面集合并按固定顺序加入属性表；
- `FUN_00468BE7`：创建/显示模式无关属性表；
- `FUN_0049F9BE`：把标准属性表改造成原版外壳，创建左侧导航、页标题、
  “全部保存”“全部重置”和相关链接；
- `FUN_004345B4`：切换当前属性页；
- `FUN_0049FD89`：定位普通控件，或切换歌词/网络页内部的子页后再聚焦控件；
- `FUN_0049FE39`：处理全部保存、全部重置、关闭和属性表生命周期。

`FUN_0049F4AD` 在伪代码约 150982--151048。它先构造系统关联对象
`FUN_00491213(puVar1 + 0x32f)`，再构造全屏对象 `FUN_00491516`；但是
`FUN_004A15BD` 的实际加入顺序是全屏在前、系统关联在后。因此不能按构造顺序
推断最后两页。

## 3. 所有已确认的进入路径

### 3.1 主命令入口

主窗口 `FUN_004582D0` 的 `WM_COMMAND` 分派位于伪代码约
88660--88950。已确认的命令和目标页如下：

| 命令 | 十进制 | 目标索引 | 页面 | 入口语义 |
|---:|---:|---:|---|---|
| `0xE140` | 57664 | 记忆页或 `lParam` 指定页 | 通用选项 | 先退出全屏，再打开完整选项 |
| `0x8084` | 32900 | 4 | 视觉效果 | 直接定向打开，不先退出全屏 |
| `0x7EFD` | 32509 | 5 | 播放列表 | 直接定向打开，不先退出全屏 |
| `0x7FEF` | 32751 | 6 | 媒体库 | 直接定向打开，不先退出全屏 |
| `0x8023` | 32803 | 7 | 歌词秀 | 直接定向打开，不先退出全屏 |
| `0x7918` | 31000 | 12 | 皮肤 | 直接定向打开，不先退出全屏 |

`FUN_004658A3`（约 98791）是通用 `0xE140` 的包装：先调用
`CPlayerWnd_ExitFullscreenBeforeMenu`，再调用 `FUN_0045D531`。这是这些入口中
唯一固定先退全屏的路径。定向命令在 `FUN_004582D0` 中直接走
`FUN_0045D531`，不应为了代码复用而统一调用退全屏逻辑。

通用入口的 `lParam` 有私有页索引语义：值在 1..15 时传给选项构造；普通菜单
传 0 时使用 `Histroy/@LastActivePage`。属性表实际只有 15 页，所以索引 15
最终不能命中页面并回落到第 0 页。实现不可把 15 强行夹成第 14 页。

原版默认快捷键表的第一项是 `F1 -> 0xE140`，所以 F1 与普通“千千选项...”走
同一入口并恢复记忆页。主窗口右键菜单、托盘菜单和皮肤菜单中的普通选项项也
应汇入这一命令，而不是各自创建另一份属性表。

### 3.2 定位到子页或控件的入口

主窗口私有消息 `0x7F4` 的语义为：

- `wParam`：要聚焦的控件 ID，或歌词/网络内部子对话框资源 ID；
- `lParam`：外层的零基页索引；
- 主窗口在 `FUN_00464900` 中打开目标页，再调用 `FUN_0049FD89` 完成定位。

已确认实例：

- 桌面歌词菜单命令 `0x8046` -> `FUN_00419372` ->
  `PostMessage(main, 0x7F4, 0x181, 7)`；`0x181` 即子模板 385；
- `FUN_004251C0` -> `PostMessage(main, 0x7F4, 0x17E, 9)`；
  `0x17E` 即子模板 382；
- 独立歌词搜索对话框的“相关设置”控件 `0x889` -> `FUN_0043C28E` ->
  `PostMessage(main, WM_COMMAND, 0xE140, 9)`，定向到网络连接页；
- 选项窗口“歌词搜索”页内的同 ID 控件则走 `FUN_00497F63`：直接向
  当前属性表发送 `PSM_SETCURSEL(9)`，保持同一个属性表 HWND。

跨窗口入口使用 `PostMessage` 是生命周期要求；已经位于选项属性表内部时则应
原地切页。把后者错误地改为重新打开选项，会从当前子页回调中同步销毁属性表，
从而重入 `comctl32`，造成未响应或访问已销毁页面。

## 4. 外壳、关闭、Apply 与持久化语义

原版底部可见按钮是：

- `0x4D2`：全部保存（资源 `0x8141`）；
- `0x4D3`：全部重置（资源 `0x8140`）；
- `IDOK`：文本改为“关闭”；
- 标准 Cancel 隐藏，标准 Apply 不是正常可见工作流。

`FUN_0049FE39`（约 151505--151559）的精确行为：

1. `0x4D2` 调用 `FUN_0040374B`，把当前内存设置立即写入配置。
2. `0x4D3` 先用资源 `0x8143` 询问。确认后保存当前页索引，销毁窗口，调用
   `FUN_004282E4`、`FUN_0043A26B`、`FUN_00401E96` 重建默认配置和相关对象，
   然后依次投递 `main, 0x7F0, 0xFFFF, -2` 与
   `main, WM_COMMAND, 0xE140, 0` 重新打开。
3. `IDOK` 与 `IDCANCEL` 完全走同一关闭分支：投递
   `main, 0x7F0, 0x100, -1`，记录当前页到 `DAT_00547E70`，再销毁属性表。
   Cancel 没有事务回滚语义。
4. 页面控件通常在点击、选择变化或编辑提交时就写入进程内设置并通知对应
   子系统；关闭属性表本身通常不立即改写 `TTPlayer.xml`。应用退出时统一保存，
   “全部保存”才是窗口内显式立即落盘入口。

最后活动页必须按原版拼写保存为 `Histroy/@LastActivePage`，不能改成
`History`，否则旧配置不能往返。

## 5. 页面运行时通知边界

原版通过主窗口私有消息 `0x7F0` 的位掩码按子系统即时应用。下列映射有直接
伪代码证据：

| 功能域 | 掩码 | 证据示例 |
|---|---:|---|
| 视觉效果 | `0x0001` | `FUN_004939E9` 等 |
| 常规 | `0x0002` | `FUN_004927D5` 附近的页面处理器 |
| 播放 | `0x0004` | `FUN_00492E..` 页面处理器 |
| 快捷键 | `0x0008` | 快捷键页离开时发送 `(8, -1)` |
| 普通歌词 | `0x0010` | `FUN_00496E12` 等 |
| 播放列表 | `0x0040` | `FUN_0049413B` 等 |
| 媒体库 | `0x0080` | `FUN_00494750`、`FUN_0049498D` 等 |
| 网络/下载 | `0x0100` | `FUN_00498705`；整个属性表关闭也发送 `(0x100, -1)` |
| DSP 插件 | `0x0200` | `FUN_00498E25`、`FUN_00498F7B` |
| 音频设备 | `0x0400` | `FUN_0049989D`、`FUN_0049A08A`..`0049A33E` |
| 皮肤 | `0x0800` | `FUN_0049AEA3` |
| 桌面歌词 | `0x4000` | `FUN_00495DEC`、`FUN_004963C3` 等 |

通知的 `lParam` 常保留触发控件 ID，用于局部刷新。实现若每次控件变化都执行
“重载所有设置/重启所有子系统”，既不等价，也容易造成 UI 长时间未响应。

## 6. 关键页面的不可省略行为

### 6.1 快捷键页 252

- ListView `1064`，列资源 `0x815A`，宽度为 90/145/145；原版有 54 条记录。
- 全局快捷键总开关 `2053`；应用内 HOTKEY 控件 `2054`；全局 HOTKEY 控件
  `2055`；“设置”按钮 `1098`。
- 选中行时仅按“是否有选择”启用三个编辑控件；关闭全局总开关并不禁用
  `2055`。
- 点击设置时分别用 `HKM_GETHOTKEY` 读取两个值并更新当前 12 字节记录；原版
  在这里不做冲突对话框。
- 页面激活时注销已注册的全局热键，离开时通过 `0x7F0/0x8/-1` 重建注册，
  防止 HOTKEY 控件与播放器自己的全局注册互相抢占。
- 菜单资源标签应取第一个换行符之后的命令文本；命令 32000 还要与 32001
  的文本以 `/` 合并。

### 6.2 DSP 页 259

- 控件：目录编辑框 `1028`、浏览 `1023`、列表 `1064`、配置 `1015`、上移
  `1042`、下移 `1045`。
- 列资源 `0x815B` 的文本顺序为“描述|文件名”；实际列顺序是空白勾选列、
  描述、文件名，宽度 20/256/100。
- 同时扫描配置目录与 `exe\Plugins`（两者不同时），只接受 `dsp_*.dll`。
- 候选 DLL 必须可加载、导出 `winampDSPGetHeader2`，且头版本大于 `0x1F`；
  描述来自 DSP header，不能直接用文件 stem 伪造。
- 勾选/取消立即加载或卸载；配置按钮和双击调用已激活模块的配置回调；上移、
  下移和自定义通知 `-197` 修改实际 processor 顺序。
- `Plugin/@Folder` 保存插件目录；`Modules_Count` 和 `Modules_N` 保存活动模块。
  `Modules_N` 是完整 DLL 路径。界面第三列仅裁出文件名，不代表持久化只存
  文件名。
- 实时链已按 `FUN_00427EDC`、`FUN_00428061`、`FUN_004280CD` 和
  `FUN_0042898D` 接通：校验 header 版本、拒绝 PaceMaker、在模块槽 0..9
  中取第一个有效模块，依次调用 `Init/ModifySamples/Quit`。ABI 是不含
  `userData` 的旧 Winamp 结构；Win32 偏移分别为 `+0x10/+0x14/+0x18`。
- 原版在送入 DSP 前把 PCM 转成有符号 16 位，并在帧数大于 `0x3FFF` 时只拆成
  前后两段；`ModifySamples` 的返回帧数不参与调整。重建链保留这一行为，同时
  用 SEH/C++ 异常边界把出错模块从当前链摘除。DLL 内部永久阻塞仍不能在
  in-process 实时 ABI 中安全强杀；文件发现和配置窗口继续由限时辅助进程隔离。

### 6.3 音频设备页 260

- 输出组合框 `0x423` 枚举 Wave Mapper/全部 waveOut、DirectSound、
  Kernel Streaming、ASIO；选项携带原版 16 字节设备键。
- waveOut 顺序为 Wave Mapper 后接 `waveOutGetNumDevs` 的所有实体设备；
  DirectSound 使用 `DirectSoundEnumerateW`。KS 不能用设备实例 ID 的简单交集
  代替：原版先枚举 `KSCATEGORY_AUDIO`，再用
  `SetupDiGetDeviceInterfaceAlias(KSCATEGORY_RENDER)` 验证 render alias。
- KS 打开方式与 `FUN_004F28A8` 一致：`GENERIC_READ | GENERIC_WRITE`、不共享、
  `OPEN_EXISTING`、`FILE_ATTRIBUTE_NORMAL | FILE_FLAG_OVERLAPPED`，失败后不降级
  到共享或只读句柄。只有 communication=`KSPIN_COMMUNICATION_SINK`、
  dataflow=`KSPIN_DATAFLOW_IN`，并同时具有 standard-streaming interface 0 和
  standard-devio medium 0 的 PCM/WAVEFORMATEX pin 才作为输出设备发布。
- KS 属性探测继续使用 overlapped I/O；重建版给单次属性设置 1500 ms、给
  SetupAPI alias 枚举之后的 KS capability walk 设置 3000 ms 有界预算。取消后，
  请求/输出缓冲、事件和 `OVERLAPPED`
  由完成收口持有，不能在驱动仍可能完成 I/O 时释放栈内存。这防止选项页无限
  卡住，同时不放宽原版的设备接纳条件。当前宿主机原版和重建版的设备组合框
  均为 8 项、选中索引均为 4。
- `SetupDi*`、同步 `CreateFileW`、waveOut/DirectSound 驱动回调本身没有可靠的
  线程内取消边界。因此四类目录与当前已恢复的能力字段由同位数隔离工作进程
  一次生成版本化快照；2026-09-11 起改用主 EXE 自身的
  `--ttplayer-output-device-worker` 模式，不再依赖旁侧辅助 EXE。父进程用 kill-on-close
  Job 管理它，整个 helper 最多等待 4000 ms，终止后再给 1000 ms 有界收口。
  页面随后只消费快照，切换设备时不再重新进入驱动。该隔离是防未响应的安全
  边界，不改变成功探测时的原版顺序和设备键。
- worker 启动失败、超时、异常退出或快照损坏时，页面发布一个携带当前
  `Device/@DeviceType` 的不可推断行；关闭/Apply 因而不会把原设备静默改成
  Wave Mapper。当前实现仍在页面首次创建时同步等待 helper：正常等待期限为
  4000 ms，故障终止后还可占用最多 1000 ms 收口，因此故障路径约为 4+1 秒，
  并非后台异步刷新。
- 原版把 ASIO 注册发现与能力探测分开：发现阶段只接受
  `HKLM\SOFTWARE\ASIO` 下具有有效 `{CLSID}`、且对应
  `HKCR\CLSID\{...}\InprocServer32` 默认字符串可读的子键，不加载驱动；选择
  设备后才懒探测四行详情，即输出通道数 `%d Channels`、13 档
  `canSampleRate == 0` 的采样率列表加 `Hz`、首个输出通道有效位 `%d Bits` 和
  preferred buffer `%d Samples`。当前同位数 helper 已恢复 `004E207B` 的只读
  `init -> getChannels -> getBufferSize -> getChannelInfo(output 0) ->
  004E14BD -> 13*canSampleRate` 调用链和四行精确格式；它不调用
  `setSampleRate/createBuffers/start`。为避免 UI 线程进入可能挂死的旧驱动，helper
  在发布快照前物化这些原本懒计算的字段，这一点是有意的隔离时序差异。选定 CLSID
  的 ASIO 播放后端已恢复，并且失败时不会转到 waveOut。
- waveOut `dwSupport == 0` 时三个支持详情行保持空白，避免把“无能力位”错误显示
  成三个“否”；最终宿主机矩阵没有直接捕获这三行文本，因此这是实现审计结论，
  不是该报告单独证明的结果。
- 设备键的后端标记：GUID 尾部全零且首 DWORD 高字 0 为 waveOut，高字 2 为
  Kernel Streaming，高字 3 为 ASIO；DirectSound 使用其非零设备 GUID，不能
  仅凭首 DWORD 高字归入 waveOut。不要互换 KS 与 ASIO。
- 选择变化进入 `FUN_0049989D`：比较并复制设备键，重建能力列表，然后发送
  `main, 0x7F0, 0x400, 0x423`。
- 原始输出位数组为“原始比特”、8、16、24、32，实际存储值为选择索引乘 8，
  因而 0 是合法值。
- 重采样率精确集合：8000、11025、16000、22050、24000、32000、44100、
  48000、64000、88200、96000、176400、192000。
- Dither 取值 0=关闭，1..4=四种模式；不是布尔字段。
- 详情行必须按后端使用资源 `0x812A`（waveOut）、`0x812B`
  （DirectSound）、`0x812C`（KS）、`0x812D`（ASIO）构建。DirectSound 才
  显示硬件缓冲和主缓冲相关控件。
- buffer、输出位、dither、重采样开关/频率/质量、硬件缓冲、主缓冲的各个
  处理器 `FUN_0049A08A`..`FUN_0049A33E` 都即时发送 `0x400` 通知。

#### 系统关联勾选图与现代 Windows 默认程序（2026-09-14）

仅对照 5.7.9 的伪代码与资源；关联方式按 Windows 的现行限制适配，不声称
现代系统的注册流程与原版提升写注册表的流程逐指令一致。

原版勾选框不是 TreeView 的原生 checkbox/state image：

  单帧宽 16、增长数 0、白色透明掩码、加载标志 0，再发送

- `004A4BC0` 以 `mask=0x22` 更新 `TVIF_IMAGE | TVIF_SELECTEDIMAGE`。
  两个字段使用相同的零基索引：0 未选、1 全选、2 混合。
- `0049EBA4` 用 `GetMessagePos` 和 TreeView hit-test，仅接受 `flags & 2`
  （`TVHT_ONITEMICON`），然后按 `state != 1` 切换状态。

3. 树中勾选状态使用 `AssocQueryStringW(ASSOCSTR_EXECUTABLE)` 查询实际处理
   程序，不再把候选注册成功显示为已关联。返回选项窗口时刷新未编辑的节点，

## 9. 重复点击当前页的残影修复（2026-09-13）

本次对照的是 5.7.9 的 `TTPlayer.exe.pseudo.c`，不是 6.1.20 的窗口代码。
此前重建外壳的切页、背景裁剪与原版并不一致：

- `FUN_004A3651`：收到左侧列表的 `LBN_SELCHANGE` 后，先比较
  `LB_GETCURSEL` 和实际活动页索引，只有不同才调用 `FUN_004345B4`。
  `FUN_004345B4 -> FUN_0042A848` 最终发送 `PSM_SETCURSEL (0x465)`。
  重复点击当前项不会重走页停用、激活和定位。
- `FUN_004A2F66`：初始化时移动隐藏的标准 Tab 和属性页，建立导航区；随后
  `FUN_004053CD(0, 0x02000000)` 给外壳加入 `WS_CLIPCHILDREN`，使外壳
  绘制不覆盖已有子控件。`004053CD` 的掩码实现是 `old & ~remove | add`。
- `FUN_004A3706`：真实切页成功后才同步左侧选择并使页上方标题区域失效。
  `FUN_0049FD89` 仍允许在同一外层页面内定向切换歌词／网络子页或聚焦控件。

修复前，宿主机原生 `options_drawing_tests` 对全部 15 页各重复点击 3 次，
每页均观察到 3 次 `PSM_SETCURSEL`、3 次 `PSN_KILLACTIVE`、3 次
`PSN_SETACTIVE` 和 12 次 `WM_WINDOWPOSCHANGING`；外壳的
`WS_CLIPCHILDREN` 为 0。这不是重新创建 HWND，而是反复移动、重画同一页面。
标准属性表的旧 Tab 原点与重建外壳的页面原点不同，反复移位时沿用旧像素，
会带来把导航选中块留在右侧页面的风险，符合报告中的残影形态。

修复后，`SelectOptionsPage` 先比较实际活动页 HWND；同页不发送切页消息，
导航和标题内容不变时不重复设置。`PositionOptionsPage` 在矩形、可见样式
已正确时直接返回，确需调整时使用 `SWP_NOCOPYBITS`，不搬运旧位置的像素；
外壳补上原版的 `WS_CLIPCHILDREN`。`SWP_NOCOPYBITS` 是针对重建外壳现有
布局适配的保护措施，不声称该标志逐字来自原版。没有销毁或重建选项窗口／页面，
也没有增加整窗定时刷新或改变保存语义。

回归测试直接给真实 ListBox 发送按下／抬起消息，不移动宿主机鼠标：

- 全部 15 页重复点击时，上述切页、激活、停用、定位事件均为 0，HWND 和矩形不变；

## 2026-09-25：选项页标题统一为 XP 字号

用户指出选项窗口顶部渐变条内的页说明文字（如“‘千千静听’的简明介绍”）
在 Windows 10/11 上比 XP 小。本次调整针对全部 15 页共用的标题绘制函数。

### 原因及修正

原版 `004A3209` 从左侧导航取 `WM_GETFONT`，复制 `LOGFONTW`，仅将
`lfHeight` 设置为正数 `14`。重建版此前照此实现，导航与标题又都继承原生
属性表关闭按钮的字体。因此绘制算法相同，并不保证不同系统的实际字号相同。

在本机 Windows 11 和 XP 虚拟机中实测：

| 项目 | XP | Windows 11（修复前） | 修复后的 Windows 11 |
| --- | --- | --- | --- |
| 标题实现字体 | 宋体 | Microsoft YaHei UI | 宋体 |
| `tmHeight` | 14 | 14 | 14 |
| `tmInternalLeading` | 0 | 5 | 0 |
| 九个汉字的排版宽度 | 126 | 81 | 126 |

正数 `lfHeight` 指定包含内部留白的字格高度；微软雅黑 UI 在 14 像素字格中
只有 9 像素的 em，导致文字明显缩小。不能仅将高度改为负数就认为与 XP 等价。

`DrawOptionsHeaderContent` 现在明确使用 `SimSun`，仍保留原版的正数高度
`14`，不再让属性表的系统字体决定标题大小。其余字体属性、渐变、垂直居中、
`(1,1)` 阴影、分隔条和双缓冲路径沿用原实现。此次适配优先满足 XP 字号基准，
有意不再继承新版 Windows 的标题字体名称。

### 验证

- Windows 11 普通版、XP 和 Win7 兼容版，各检查全部 15 页的真实 HWND 绘制。
  九个汉字测试串的实际着墨区域为 XP `124×13`、Win7/11 `125×14`；
  字格及排版宽度相同，边缘约 1 像素的差异来自系统宋体版本/栅格化。
- XP“关于”页标题修改前后 BMP 完全一致；Windows 11 修复前后标题截图确认
  已恢复 XP 的字号。导航、标题边距、渐变和阴影检查通过。
- 普通版与兼容版 Release 构建成功；XP/Win7 静态导入检查通过
  （19 个 DLL、656 个导入项，子系统 5.01）。
- 没有 Windows 10 测试环境，未宣称已在 Windows 10 实测；该版本使用同一条
  显式宋体绘制路径，没有依赖 Windows 11 专用接口。
