# 原版均衡器实现分析与重建版差异

分析及修复日期：2026-10-03。范围：原版 5.7.9 播放器、配套 `ttpcomm.dll`，以及重建版工作树（分析开始时 HEAD 为 `46d8c6e`）。第 1～10 节保留修复前的分析结论；用户确认后实施的修复及验证见第 11 节。

## 1. 结论

原版均衡器分为三个层次：皮肤窗口与滑块、配置状态、音频处理。十段均衡器由 `ttpcomm.dll` 的 ordinal 103 实现；环绕效果由 ordinal 104 实现；左右平衡走另一路控制。

最重要的新发现是 **重建版传给 ordinal 103 的十一项参数顺序错误**：

```text
XML 文本：           前置增益:频段1,频段2,...,频段10
原版内存 / DLL：    [频段1,频段2,...,频段10,前置增益]
重建版内存：       [前置增益,频段1,频段2,...,频段10]
当前重建版桥接：    直接传递重建版内存，没有转换顺序
```

已经通过原版解析函数、DLL 机器指令、当前调用代码，以及真实 DLL 的脉冲响应探针相互验证。这会改变实际声音，而不仅影响界面显示：重建版的前置增益作用到最低频段，最后一段被当作全频前置增益，其余各段发生错位。

此外，原版的 `Current`、`Custom`、`ProfileLast` 有独立的更新规则；重建版对它们进行了简化。以前的界面、菜单和鼠标测试不能证明 DSP 参数映射及这些状态细节完全一致。

## 3. 窗口、控件和鼠标消息

### 3.1 皮肤驱动的独立窗口

均衡器是独立的工具型弹出窗口，内部使用原版的皮肤按钮和滑块子窗口。布局由皮肤中的位置、图片和间距决定。

- `004A8B73`：读取均衡器皮肤属性，包括 `eq_interval`。
- `0042955B`：由频段滑块模板扩展为十段，横向步进为模板宽度加间距。
- `00429AAA`：创建、初始化按钮与滑块及数值范围。
- `00453D7E`：窗口消息及命令分派。

所以，恢复行为时既要保留皮肤位置，也要保留子控件的捕获、焦点、通知顺序，不能只根据默认皮肤画十个滑块。

| 控件 | 原版 ID | 范围 / 功能 |
| --- | --- | --- |
| 启用均衡器 | `0x7E2C` | 切换启用状态 |
| 配置按钮 | `0x64` | 弹出配置菜单 |
| 重设按钮 | `0x65` | 清空当前十一项 EQ 参数 |
| 左右平衡 | `0x66` | `-10..10`，传给音频控制时乘 10 |
| 环绕 | `0x67` | `0..16`，0 关闭 |
| 前置增益 | `0xC8` | `-12..12 dB` |
| 十个频段 | `0xC9..0xD2` | 每段 `-12..12 dB` |

关闭 EQ 时，原版禁用前置增益和十个频段滑块；平衡与环绕仍可工作。隐藏均衡器窗口本身不等于关闭音效。

### 3.2 滑块的操作过程

滑块公共实现位于 `004521C5`、`00452326`、`00452295`、`00452413` 等函数：按下滑块时捕获鼠标并保留按下位置偏移；点击轨道移动数值；拖动时通知父窗口；松开完成操作；Escape 恢复操作开始时的数值。它也处理方向键。

`00429DDB` 接收 `WM_HSCROLL` / `WM_VSCROLL` 后，先把通知及控件 HWND 转发给主窗口，再更新 EQ 状态，最后发送私有消息 `0x7EE`。

主窗口 `00460AB1` 根据控件 ID 显示平衡、环绕或 dB 数值；跟踪和结束通知使用不同分支。`0x7EE` 则触发播放器接口的参数更新。界面提示和 DSP 更新属于两条相关但不同的路径。

在均衡器窗口分派中未发现独立的 EQ 滚轮或双击调整分支；不能从主窗口音量的滚轮行为类推到均衡器。

## 4. 配置状态与保存格式

### 4.1 五组状态

| 状态 | 原版地址 | 含义 |
| --- | --- | --- |
| `Profile` | `00547DF4` | `-2` 关闭，`-1` 自定义，`0` 推荐，`1..12` 分类预设 |
| `ProfileLast` | `00547DF8` | 关闭 / 部分切换操作保存的状态，并非每次选择都更新 |
| `Surround` | `00547DFC` | 独立环绕强度 |
| `Custom` | `00547E00` | 保存的自定义十一项参数 |
| `Current` | `00547E2C` | 当前使用的十一项参数，前置增益位于 `00547E54` |

左右平衡及主音量另行保存，不属于十一项 EQ 参数。

### 4.2 操作的准确分支

| 操作 | 原版行为 | 入口 |
| --- | --- | --- |
| 关闭 EQ | `ProfileLast = Profile`，`Profile = -2`，保留当前参数 | `00429E86` |
| 重新启用 | `Profile = ProfileLast`，使用保留的当前参数 | `00429E86` |
| 推荐 / 分类预设 | 只覆盖十个频段，保留前置增益；设置 `Profile`，不在该函数中更新 `ProfileLast` | `0042A137` |
| 选择自定义 | `Custom` 复制到 `Current`，设置 `Profile = -1`；不在该函数中更新 `ProfileLast` | `0042A113` |
| 重设均衡器 | 清零 `Current`；若启用则保存原 `Profile` 到 `ProfileLast` 并进入自定义；**不直接清零 `Custom`** | `0042A0DC` |
| 从文件加载 | 读取十一项到 `Current` 和 `Custom`，进入自定义 | `0042A179` |
| 保存到文件 | 保存当前十一项参数 | `0042A28A` |

拖动通知还存在一个容易忽略的细节：`00429DDB` 只有在进入函数时已经是自定义状态，才把 `Current` 复制到 `Custom`。如果先前是某个预设，该次通知只切换成自定义并记录 `ProfileLast`；后续通知才进入复制分支。

平衡和环绕滑块虽然跳过十一个 EQ 值的赋值，却仍会经过上述共同的 Profile 分支。菜单直接切换环绕的 `0042A08C` 是另一条路径，不能把滑块行为套用到菜单。

这些是已确认的静态分支；一次完整鼠标动作可能发出多条通知，最终用户可见结果需要结合通知序列验证，不应概括为“第一次拖动永远不会保存”。

### 4.3 XML 与内存布局必须分开

`0042906A` 使用如下文本格式解析十一项：

```text
preamp:band1,band2,band3,band4,band5,band6,band7,band8,band9,band10
```

但 `sscanf` 第一个输出地址是最后一个本地槽位，随后从十段的第一个槽位连续复制十一项。因此文件中前置增益在首位，内存中前置增益在末位。

主设置保存 `Profile`、`ProfileLast`、`Surround`、`Custom`、`Current`；独立 `.tteq_cfg` 使用 `ttplayer_eq/Equalizer` 的 `Custom` 属性承载导出的参数。布局兼容需要同时核对文本字段、内部数组以及 DLL 接口，不能只比较 XML 字符串。

## 6. 播放器怎样调用均衡器

相关音频数据路径可概括为：

```mermaid
flowchart LR
    A[解码 PCM] --> B[转换为 double 样本]
    B --> C[增益分析及 ReplayGain 处理]
    C --> D[ordinal 103 均衡器]
    D --> E[ordinal 104 环绕]
    E --> F[后续重采样、插件与输出处理]
```

这是相关处理阶段的顺序概括；某个功能关闭或当前格式不需要转换时，相应步骤可以跳过。

- `004B182C` 配置 EQ：在临界区中创建或销毁 ordinal 103 对象；启用时先初始化采样率和声道数，再设置十一项参数。
- `004B1B81` 处理样本：进入同一临界区，先向 EQ 提交数据，再读取可用输出，随后把实际输出交给环绕处理器。
- `004B16FE` 重置：调用 EQ 虚表槽 6 和环绕槽 3，清除此前流的处理历史。
- `004B1375` / `004B1950`：解码后转换、增益处理与后续处理的调用关系。

EQ 会缓存输入，接口允许返回比输入更少的样本数。不能把“提交一块就必须得到相同长度输出”作为接口前提。声道交错样本数也不等于音频帧数，例如立体声一帧有两个样本。

原版在每次启用状态的参数配置中调用初始化；重建版只在创建对象时初始化，后续直接设置参数。二者调用顺序不同，但仅凭这一点还不能断定声音存在差异，需分别验证采样率、声道切换及已有缓存的生命周期。

## 7. ordinal 103 的实际滤波算法

### 7.1 对象和接口

工厂 `60006930` 分配 0x90 字节对象；虚表位于 `60027518`。

| 槽位 | 函数地址 | 已确认用途 |
| --- | --- | --- |
| 0 | `60007830` | 析构及释放 |
| 1 | `60006380` | 初始化采样率、声道数；两者读取为 32 位参数 |
| 2 | `60007710` | 设置十段增益及前置增益 |
| 3 | `600067E0` | 当前未确认业务用途，不作为重建接口依据 |
| 4 | `60007520` | 提交交错 double 样本 |
| 5 | `60006800` | 读取处理结果，回写实际样本数 |
| 6 | `600068E0` | 重置输入、输出及滤波历史状态 |

对象 `+0x10` 保存十个线性增益，`+0x60` 开始保存最多十个声道处理器指针。每个声道使用相同 EQ 曲线和独立历史；EQ 本身不通过混合左右声道产生环绕。

### 7.2 dB 换算及前置增益

`60007710` 的关键机器指令为：读取 `params[i]`，加上 `params[10]`，乘 0.05，以 10 为底求幂。因此：

```text
gain[i] = 10 ^ ((band[i] + preamp) / 20), i = 0..9
```

前置增益加在每个频段上。例如某段 +3 dB，前置增益 -2 dB，该段设计目标为 +1 dB。这里没有根据最高频段自动减小前置增益的逻辑；最终输出端的限幅与此处的参数换算是不同阶段。

### 7.3 十段边界与滤波器构造

DLL VA `6002E918` 中的九个 double 常量为：

```text
32, 64, 125, 250, 500, 1000, 2000, 4000, 8000 Hz
```

`60006460` 把它们作为分段边界建立目标增益曲线：第一段从 0 到 32 Hz，最后一段从 8000 Hz 延伸到可表示的最高频率。`60006220` 在采样率一半处限制计算范围。这些是内核使用的分界值，不能直接解释为十个滑块的中心频率标签。

`60006220` 用低通 sinc 项的差构造分段频响对应的理想冲激响应；`600063E0`、`60006DD0` 再进行窗函数处理。根据 Bessel I0 形式、21/50 的分支阈值、0.1102 等常量，可判断它使用 Kaiser 形式的窗构造；设计参数为 96。这里的 96 是滤波器设计参数，不是音量上限，也不是本轮测得的最终阻带指标。

工厂创建声道处理器时使用参数 10，得到：

- FFT 长度：`1 << 10 = 1024`。
- 滤波器长度：`(1 << 9) - 1 = 511` 个系数。
- 每声道通常累计 511 个输入样本形成一个处理块。

有限长度滤波器会使频段边界出现过渡和波纹。因此，滑块设定的目标 dB 与过渡区域实测 dB 不必完全相等；不能据此直接判为参数错误。

### 7.4 分块卷积、参数更新及重置

`60006FE0` 的处理过程是：收集输入 → 补零到 1024 点 → 实数 FFT → 与滤波器频响作复数乘法 → 逆 FFT → 按 `2/N` 归一化 → 与前块尾部相加 → 输出入队。

这是 FFT 实现的 FIR 分块卷积。滤波器相当于把每个输出样本与附近一段输入相结合，FFT 用于批量加速这个运算。

`60006DD0` 把新频响写入备用缓冲区，处理函数开始时切换到它；这是双缓冲更新，不是对两套参数逐样本做淡入淡出。

第一次处理块会跳过 255 个起始样本，和 511 系数的中心位置相对应；44.1 kHz 下 255 个样本约为 5.78 ms。这个数不是播放器总输出延迟，完整延迟还受分块和输出设备缓冲影响。

本轮一次提交 8192 个单声道样本、未补尾时得到 7921 个输出，等于 `16 × 511 - 255`，与块处理和起始跳过行为一致。内部存在空输入补尾分支，但本轮尚未确认原版播放器的所有 EOF 路径是否都会调用它，不能据此宣布曲尾排空已完整恢复。

## 8. 环绕与左右平衡

“启用杜比环绕”菜单切换强度 0 与 8；滑块允许 0 到 16。播放器另行创建 ordinal 104，对应工厂 `60005FF0`。

`600058D0` 在至少双声道时处理前两个声道：构造左右声道和的延迟信号，经过递归滤波，再将效果信号加到左声道、从右声道减去。结构上可写为：

```text
effect = Filter(Delay(L + R))
Lout = L + effect
Rout = R - effect
```

上式省略比例系数和内部状态，仅表达通路关系。初始化 `60005E80` 按约 16 ms 计算延迟长度，并限制到 1024 个样本；强度参与系数计算。它与十段 EQ 是两个独立对象，关闭 EQ 不应顺带关闭环绕。

这段实现显示的是立体声拓宽处理，不能仅根据菜单名称推断它在解码 Dolby 编码音轨。左右平衡则是另行调节声道音量，不属于 FIR 频响配置。

| 6000 Hz | +2.993 dB | +5.013 dB |

因此这不是仅凭代码排列推测的风险：原 DLL 的实际滤波输出也体现了错误排列。探针验证范围是当前桥接所用的参数内容及 DLL 行为，尚不等同于整套播放器、所有采样率或多声道回归通过。

## 10. 重建版对照与建议顺序

### 10.1 已确认的差异

| 项目 | 当前结论 | 主要代码位置 |
| --- | --- | --- |
| 十三组预设 | 数值已与原表一致 | `src/ui/player_window_internal.h:388` |
| DSP 参数顺序 | **错误，直接影响声音** | `audio_engine.cpp:1662`、`:1911` |
| 重设 | 同时清空 `Custom`，原版直接分支只清 `Current` | `player_window_equalizer.cpp:1014` |
| 自定义切换 | 重建版立即复制，并在选择自定义 / 预设 / 导入时额外更新 `ProfileLast` | 同文件 `:828`、`:982` |
| 平衡 / 环绕滑块 | 未经过原版共同的 Profile 状态分支 | 同文件 `:830`、`:834` |
| EQ 内核 | 当前复用原 DLL，不是源码独立重写的 FIR 内核 | `audio_engine.cpp:1658` |
| 线程更新机制 | 重建版通过处理器版本号在解码线程应用；原版使用临界区更新 | 同文件 `:1643`、`:3922` |
| 初始化参数声明 | 重建版声道数声明为 `WORD`，DLL 读取 32 位栈槽，需要统一桥接声明并验证 | 同文件 `:1903` |

上述 `WORD` / 32 位参数问题应作为 ABI 审核项。现有文档曾记录 `/O2` 下初始化异常并使用 `noinline` 规避，但本轮没有证明两者之间的因果关系，不能把旧问题归因于此，也不应贸然移除已有规避。

主窗口、均衡器窗口的菜单共享，以及用户此前要求增加的“重设均衡器”菜单项，应继续保留。菜单增加属于明确要求的功能扩展，与本次发现的参数错位无关。

### 10.2 建议实施顺序

1. **先修 DSP 桥接排列。** 保留现有设置和 XML 的前置增益在首位布局，仅在调用 ordinal 103 前构造 `[band1..band10, preamp]`。无需迁移用户设置，也不应修改正确的预设表来补偿错位。
2. **补参数到声音的回归。** 单独改变前置及每一个频段，检查目标增益和频响；覆盖推荐、归零、单 / 双声道及常用采样率。仅检查“有输出”或“XML 保存正确”无法发现该问题。
3. **恢复状态分支。** 对齐 `Current`、`Custom`、`ProfileLast`，并对按下、拖动、松开、Escape、平衡 / 环绕滑块的完整通知序列做原版对照。
4. **核对 ABI 与流生命周期。** 校正调用签名，验证 Release 优化、连续改参数、禁用 / 启用、跳转、采样率和声道变化、短音频及 EOF 排空；保留已有保护，直到证据支持替换。
5. **最后进行系统与界面回归。** 本机、XP、Win7 覆盖菜单、预设加载保存、输出设备，以及皮肤滑块；按既有约定将测试留在本地 `tests`，不接入发行 Actions。

相关历史文档：[Equalizer recovery](EQUALIZER_RECOVERY.md)、[Shared menu parity](SHARED_MENU_PARITY.md)。其中已有的界面测试结论仍有参考价值，DSP 排列和状态细节以本次更细的证据为准。

### 11.4 曲尾处理核对

进一步检查 `004B1375`：已恢复的 EOF 分支对重采样器调用 `004B1BF4(..., 0, 0)`，没有向 EQ 提交空指针；EQ 调用位于非空 PCM 分支。本轮保留这一调用方式。
