# 原版 WTL 窗口行为恢复

本文记录最初通过 C++/Win32 恢复原版 WTL/ATL 窗口行为的对照依据。
后续已接入 WTL 10.01，迁移范围和验证见 [WTL 10.01 接入](WTL_10_01_MIGRATION.md)。
仍不依赖原程序的私有对象布局。

## 菜单访问键

原版 `00466C65` 的 `WM_MENUCHAR (0x120)` 调用 `004699C5`：读取自绘菜单项
保存的文字、寻找第一个 `&`、不区分大小写匹配；唯一匹配返回 `MNC_EXECUTE`，
重复匹配返回第一项位置和 `MNC_SELECT`。没有匹配时保留原版忽略/Enter 关闭规则。
这是菜单已经打开时的字母访问键，不是应用快捷键表。

`PlayerWindow::PopupMenuChar` 恢复这一分支。主窗口、播放列表、歌词、均衡器
和桌面歌词栏共用它。只识别本程序保存的自绘菜单项；系统菜单和其他组件的菜单
继续由其原有窗口过程处理。

## 播放列表的原生基础

原版 `00425DEC` 将 `SysListView32` 作为窗口基类，`00482BAF` 创建
`PlayLists (0x2801)` 和 `Files (0x2802)` 两个 owner-data 列表。
此前重建版把 `ListCtrl` 注册为普通自绘窗口，未处理的消息进入 `DefWindowProc`，
因而丢失原生列表状态、方向查找、选择锚点等接口。

现在 `RegisterPlaylistListClass` 从 `SysListView32` 获取窗口类信息，保留其
额外窗口存储和原始窗口过程，以 `ListCtrl` 注册。创建和销毁进入系统控件过程，
未被皮肤处理的消息经 `CallWindowProcW` 交回原生控件。

歌曲数据仍由播放列表/媒体库模型持有。进入原生默认处理前，按需同步行数、选择、
焦点、选择锚点和视口；原生状态修改后回写模型。同步期间的通知不触发播放或列表
切换；`LVN_GETDISPINFOA/W` 按需提供显示文字，不读取音频文件。

- `LVM_GET/SETITEMSTATE`、方向性 `LVM_GETNEXTITEM` 使用原生实现；修正清除其他
  行的焦点标志时错误清空当前焦点的问题。
- `LVM_SCROLL`、`WM_VSCROLL`、选择锚点和 `LVM_GETITEM` 等默认接口恢复。
- 目录列表的方向键、Home/End、PageUp/PageDown、空格交由原生单选列表处理，
  选择变化才切换当前列表，Ctrl 导航可以只移动焦点。
- 保留经过对照验证的皮肤绘制、鼠标选择/拖动、歌曲列表业务键、16 像素行高、
  无焦点滚轮、底部余量、搜索和编辑入口。它们仍是应用自定义行为。
- 原生列避开内部滚动条宽度，防止多出水平滚动条并减少一行可见区域。
- 系统控件本身的非客户区滚动条不重复绘制，皮肤继续负责滚动条外观。

原生控件内保存的是模型投影，不是第二份歌曲数据。鼠标移动和自绘消息直接走
皮肤处理；不会在这些高频消息上重新复制全部选择状态。

## 线程钩子的复核与修正

### Tooltip

原版 `004B5713` 只在尚无计时器时创建 `0x7B/50 ms` 计时器。之前重建版每次
`WM_PAINT` 都重新设置它，频繁重绘可能持续推迟隐藏状态检查。现在只设置一次，
窗口销毁时清理，保留绘制时置顶、隐藏后去除置顶样式的行为。

### CBT 菜单边框

此前文档将 `004B5B13` 笼统标为 shadow/theme wrapper，并用主窗体的
`CS_DROPSHADOW` 解释替代关系，这不准确。

结合原始 EXE 指令和字符串可确认：

- `00450E44` 查询 `0x1022`，即 `SPI_GETFLATMENU`；
- `004B5B13` 在 `HCBT_CREATEWND` 比较 `0051E874` 的窗口类字符串 `#32768`；
- 仅在平面菜单关闭时，为弹出菜单安装 `00450E67` 包装；
- `00450EF7/00450F71/0045102B` 处理 `WM_NCPAINT/WM_PRINT`，排除客户区后填充
  `COLORREF 0x00F9FCFC`，并以 `COLOR_BTNSHADOW` 绘制边框。

重建版现在按同样条件安装独立菜单子类，处理非客户区绘制及打印，并在销毁时
解除子类。GDI 裁剪和画笔状态会保存、恢复，不修改系统菜单设置。

## 保留的实现边界

原版命令栏的私有绘制由现有自绘菜单及本文补充的菜单输入行为承担；普通按钮
继续使用 ComCtl32 v6，皮肤按钮使用自己的窗口过程。消息循环保留已恢复的排队、
预处理与 idle 调度规则，命令状态仍在菜单打开时更新。没有复刻二进制 C++ 布局、
ATL heap thunk 或完整的 WTL 模板继承关系，不应把本轮描述为“WTL 源码全部恢复”。

## 本地验证

测试源码仅放在被忽略的 `tests/` 中，默认关闭测试构建，Actions 不编译或运行测试。
`tests/ui/wtl_behavior_tests.cpp` 覆盖：

- 菜单大小写、重复访问键、原版第一个 `&` 规则、未匹配和外部菜单；
- 与真实 `SysListView32` 对照行高、滚动、方向查找、选择/焦点/锚点和目录翻页；
- 模型状态投影、owner-data 文字回调，以及同步不改变播放状态；
- 持续重绘下的 tooltip 计时器；
- 经典菜单边框打印的边框色、底色和客户区保护。

同时回归滚轮、底部余量、框选、媒体库、菜单绘制和换肤生命周期。
兼容版需要另外通过 XP/Win7 静态导入审计；当前宿主测试不能代替 XP/Win7 实机验证。

本轮结果：普通 Release 的上述行为/回归及启动检查共 8 项通过；兼容 Release
的行为测试及启动检查 2 项通过。兼容 EXE 为 x86、子系统 5.01，18 个 DLL、
607 项静态导入通过 XP/Win7 审计。启动检查需要先暂时启用
`TTPLAYER_STAGE_RUNTIME`，准备原程序的运行 DLL；发行 ZIP 仍按现有规则只包含
重建 EXE、说明、许可证与校验文件。

参考：[Windows 窗口类扩展](https://learn.microsoft.com/en-us/windows/win32/winmsg/about-window-procedures#window-procedure-superclassing)、
[WM_MENUCHAR 返回值](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-menuchar)。
