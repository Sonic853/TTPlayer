# 音频插件后续修复与验收（2026-10-25）

接续 [2026-10-24 后续修复](AUDIO_PLUGIN_FOLLOWUP_20261024.md)。本轮处理 AAC 呈现时间、RM ATRAC3 原版差异、MOD 混音兼容，并补测 OGG 的真实 HTTP 链路。未修改原版播放器二进制。

## AAC：普通与分片 MP4 呈现时间

原重建版在分片路径跳过编辑列表，并拒绝编辑与非零 composition offset／时间空隙组合。本轮将每个包的媒体呈现区间与解码顺序分开，支持有符号 CTS、`tfdt` 空隙以及 rate=1 多段编辑。时间空隙输出静音，反向／重复编辑保持所需解码历史；分片单条零长度编辑可延续到已索引媒体末尾。

无编辑的普通 Nero 文件保留原版兼容路径，普通文件保存保留时间表与压缩载荷。分片标签仍只读。重叠或倒退的呈现区间、变速／驻留编辑、在线 DASH 和分片写入未实现，不以静默忽略代替错误返回。

详见 [AAC 呈现时间修复](../../ttp_aac/docs/PRESENTATION_TIMELINE_20261025.md)。

## RM：ATRAC3 起始延迟与极性

上轮仅搜索正相关，遗漏了两个同时存在的差异：RM 格式头声明每声道 2,190 个预热采样，历史 RealCodec 会消耗它们；FFmpeg 的 ATRAC3 输出还与历史后端相反。按头部信息裁剪开头，并在量化前反相后，四个不同码率真实样本与原版等长，全部 PCM16 误差不超过 1 LSB。

修复覆盖初次读取、重新打开、精确定位、取消后恢复和小缓冲读取。已验证样本均为 coding mode 2，不能据此宣称所有 ATRAC3 模式均已覆盖。

Cook、DNET、SIPR 的差异继续保留：低码率噪声合成、模式相关延迟和部分算法差异尚未完全恢复。旧版提前报错且丢失有效声音的路径没有被复制。详见 [RM 修复与剩余边界](../../ttp_rm/docs/DECODER_PARITY_FIX_20261025.md)。

## MOD：混音参数与原版算法

原版创建模块时的主音量／默认前级增益是 256／100，所用 libmodplug 默认值是 128／48。此外，原版使用 Kaiser 8-tap 重采样及特定的高倍率／立体声插值路径，当前库使用的窗函数不同，并缺少原版 16 位抖动和量化取整步骤。这些是多个格式共用的混音差异，不是某一首 XM 的专门补偿。

本轮恢复这些初始化、系数生成、插值、抖动和取整规则，并将抖动状态纳入每 Reader 的状态保存／恢复及引擎锁。99,328 个系数与实际原 DLL 的初始化结果逐项相等；2,048 个抖动输入对照也一致。

两个 XM 样本仅剩少量首段／边界差异，其中绝大部分落在原 DLL 重复运行自身的波动范围；仍有额外 ±1 LSB 差异，不标为完全相等。真实 UMX 的不同采样值数量从约 3,158 万降至约 149 万，平均绝对差约 1.15 个 PCM16 LSB，但局部最大差仍约 2,680 LSB，不能用平均值掩盖未恢复的边界。

原函数地址、系数对照、并发隔离及剩余差异见 [MOD 混音兼容修复](../../ttp_mod/docs/MIXER_PARITY_20261025.md)。

## OGG：真实 HTTP 验收

将重建版实际 `HttpStream`、`ttp_https.dll` 与 OGG 插件连接到临时 HTTP 服务，验证 Vorbis／Opus 的 Range、忽略 Range、chunked、未知长度、ETag 续传、资源变化、取消和超时。每系统 20 项通过；没有因此修改 OGG DLL，继续使用 `2026.10.24p1`。

Opus 定位后的浮点值与从头连续解码有短暂差异，但与直接调用上游 libopusfile 的独立定位输出逐字节相同。测试据此区分“定位采样位置正确”和“所有解码历史状态逐位相同”，没有让每次定位退化为从头解码。

详见 [HTTP 验证及上游依据](../../ttp_ogg/docs/HTTP_VALIDATION_20261025.md)。这不代替公共服务器、TLS、实时无限流或原版网络界面验收。

## 验证范围

使用本机 Windows 11、XP SP3 x86 与 Win7 SP1 虚拟机。依用户要求以 Windows 11 代为现代 Windows 验证，没有单独 Windows 10 实机结果。

| 核心回归组 | 每系统用例 | Windows 11 | XP | Win7 |
| --- | ---: | --- | --- | --- |
| AAC 时间轴、定位、保存、只读及旧基线 | 105 | 通过 | 通过 | 通过 |
| RM 历史 PCM、定位、取消与边界 | 22 | 通过 | 通过 | 通过 |
| OGG 真实 HTTP | 20 | 通过 | 通过 | 通过 |
| MOD 完整 PCM、并发、原版系数／抖动及定位隔离 | 14 组 | 通过 | 通过 | 通过 |
| 原版／重建版实际宿主播放 | 10 | 通过 | 通过 | 通过 |

AAC 合法输出与明确构造的期望 PCM 逐字节比较，预期拒绝项核对 HRESULT。RM 每个历史 PCM 用例另包含 9 次定位和 128 次小缓冲；部分缓存内定位没有触发 I/O，明确跳过的故障注入不计作已覆盖。

MOD 的 14 组由 11 个完整解码样本、1 个并发组、1 个原版系数／抖动对照组、1 个定位隔离组组成，覆盖 MOD／S3M／XM／IT／MTM／STM／FAR／UMX。并发组执行 40 次 Reader 与 20 次扫描；定位隔离组执行 10 轮 Seek、Stop／Start 及其它 Reader 干扰检查。原版对照所需的 `msvcr110.dll` 只放在私有测试目录，重建 DLL 和运行包没有增加该依赖。

实际原版与重建版宿主使用隔离副本，检查 DLL 路径、播放时间前进、无错误弹窗和正常退出。每种宿主分别播放普通 AAC 多段编辑、新分片 AAC、ATRAC3 RM、XM、UMX，三系统共 30 次运行通过。AAC 新样本包含约 5.790～6.823 秒内部静音，测试越过该区间继续播放。静音输出测试不等同于实体扬声器听音。

所有测试、样本及日志仍位于私有 `rebuild/tests/plugins_followup_20261025`；没有加入 Actions 或运行包。虚拟机测试 DLL 已取回核对 SHA-256，与本机最终构建一致。

## 剩余边界

- 原版 EXE 的 3／5／7 声道掩码及 WaveOut 有效位数问题仍需要宿主输出层修复，解码插件无法保证宿主保留布局，详见上一轮报告。
- RM Cook／DNET／SIPR 和 MOD 的少量历史算法差异仍需独立定位，不能声称所有插件已与原版完全一致。
- AAC 反向编辑、RM／VQF 缓存外远距离定位仍可能需要恢复较长的解码历史。
- AAC 历史 Profile、DTS Express 其它布局、真实历史浮点 TTA 存档及 ASF 系统 DMO 可用性仍有覆盖边界。
- OGG 实际超大流、逐次 E_PENDING 异步约定及复杂代理／服务器变体尚未穷尽。
